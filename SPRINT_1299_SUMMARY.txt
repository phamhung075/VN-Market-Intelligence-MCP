SPRINT 1299 — MCP Tool Context Optimization
===============================================================================

STATUS: Planning phase complete. Ready for BA → Developer → QA execution.

PROBLEM
-------
Current system loads ALL 106 MCP tools (~65k tokens = 32.4% of context budget)
into every agent session, even though each agent only uses 10-25 tools.

Impact: Massive context waste → truncated message history → weak analysis.
  • Agent reasoning: ~50k tokens (should be ~90k)
  • Message depth: 2-3 turns (should be 5-7)
  • User impact: Briefings cut short, /ask answers incomplete

SOLUTION
--------
Implement skill-gated tool loading in 3 phases:

  Phase 1299a (BA, 2-3h): Create tool index + skill manifest
    → docs/TOOL_INDEX.md (all 106 tools, 1-liner each)
    → docs/SKILL_MANIFEST.md (skill → tools mapping)
    → Update agent README + tool-loading memory

  Phase 1299b (Dev, 3-4h): Smart bootstrap refactoring
    → Filter tools by declared skills (from manifest)
    → Backwards compatible (no skills param → load all)
    → Integration tests: verify skill filtering works

  Phase 1299c (Dev, 2-3h): Session cache + analytics
    → LRU cache (sessionId → tools loaded)
    → Cron job: aggregate usage every 8h
    → Track patterns for future optimization

IMPACT
------
Token savings: 65k → <30k (45k+ tokens freed)
  • Reasoning budget: +40k tokens (80% increase)
  • Message history: 2-3 → 5-7 turns
  • Analysis depth: complex chains now feasible

Timeline: Thu 2026-04-24 kickoff → Mon 2026-04-28 delivery (4.5 days)
Effort: 7-10h total (20% of sprint capacity)

DESIGN DECISION
---------------
Why skill-gated loading (vs alternatives):
  ✓ High impact (40-50k tokens)
  ✓ Low risk (backwards compatible)
  ✓ Fits architecture (reuses Sprint 1297 skill system)
  ✓ No infra additions (pure code + docs)
