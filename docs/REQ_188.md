## User Story

As a Vietnamese stock investor using Claude,
I want the cascade engine to receive VIX, S&P500, DXY, Hang Seng, Shanghai, CNY/VND, copper, silver, and JPY/VND alongside existing brent/gold/usdVnd,
So that global risk-off signals (VIX spike, DXY surge, Asia equity selloff) are detected before they hit HOSE.

## Non-Functional Requirements

- Performance: All 12 fetches run concurrently via `Promise.allSettled` — no sequential penalty. Timeout per symbol unchanged (30s).
- Data freshness: Same cycle cadence as existing commodityPricesJob (no scheduler change in scope).
- Backward compat: `DEFAULT 0` on new DB columns — no migration, no data loss on existing production DB.
- Type safety: `bun tsc --noEmit` must pass after all changes.
- Test baseline: 5629 pass before this sprint.

## Edge Cases & Data Quality

- [ ] VIX weekend/holiday — Yahoo returns last close price, not 0. Store as-is; 0 guard not needed.
- [ ] Shanghai Composite (`000001.SS`) — 15-min delay on Yahoo free tier. Acceptable for macro cascade context.
- [ ] DXY symbol `DX-Y.NYB` — NYB venue. If unresolvable, store 0 and skip cascade rules that require dxy != null.
- [ ] `CNHVND=X` offshore CNY/VND — low liquidity on Yahoo; 0 stored when unavailable, cascade rule guards null.
- [ ] All 12 fields = 0 — return null (no change to existing early-bail behavior).
- [ ] Schema deploy order — schema.ts changes MUST be in same commit as yahooFinance.ts changes. Otherwise `storeCommoditySnapshot` throws column-mismatch on first cycle after partial deploy.
- [ ] `tracked_indicators` mirroring — existing code mirrors brent+gold (lines 343-347). Copper/silver candidates for same treatment. Architect to decide scope (out of FR-5 but noted).

## Implementation Notes for Architect

1. **MacroContext locality**: Interface extension at `cascadeEngine.ts:96` (domain layer). Population at `runImpactChain.ts:138-145` (application layer). Zero infra imports in domain — enforced by existing test suite.

2. **Column naming**: DB snake_case (`hang_seng`, `cny_vnd_rate`). TypeScript camelCase (`hangSeng`, `cnyVndRate`). Map explicitly in `storeCommoditySnapshot` parameter bindings.

3. **Deploy atomicity**: `schema.ts` + `yahooFinance.ts` changes must ship in same commit. Staggered deploy breaks `storeCommoditySnapshot` column binding count.

4. **market_prices mirror**: Existing code mirrors BRENT+GOLD into `market_prices` (lines 289-295). VIX and DXY are index levels — do NOT mirror. Copper/silver are prices — architect may choose to mirror.

5. **tracked_indicators**: Existing code at lines 343-347 mirrors brent+gold. Copper/silver are natural additions. Out of this spec's scope — Architect decides.
