## REQ-1967-1 — Inter-Agent Communication Layer Contracts

**Surface:** 1 (signal-bus payload schemas, MCP tool enums, DASHBOARD r/w contracts, caveman handoff format, signal-file naming)
**DDD Layer:** Infrastructure (signal bus) + Interface (MCP tool schema)
**Seed evidence anchors:** E-4 (alert-commander `verified_decision` enum rejected), E-3 (pm signal timing race)

### Goal statement
Every signal written by any agent must conform to a schema contract validated at write-time, and every signal-file name must follow the declared naming convention so that readers can locate and dedup signals without scanning all files.

### Testable check-list

- [ ] REQ-1967-1a: `post_agent_signal` MCP tool schema declares an exhaustive `signal_type` enum. Every value documented in any agent `.md` or flow `.md` as a send-able signal type MUST appear in that enum. Gap = bug. Architect must enumerate which documented types are absent from the live schema.
- [ ] REQ-1967-1b: Signal-file naming follows a declared contract (currently `{from}-{ISO-timestamp}.json`). Architect must confirm: (i) the contract is written somewhere authoritative, (ii) every agent that drops a file follows it, (iii) no files exist in `docs/signals/` (unprocessed) or `docs/signals/processed/` that violate the pattern.
- [ ] REQ-1967-1c: DASHBOARD row read/write contract is declared: writer format, reader scan pattern, prune condition. Architect must confirm all agents that write DASHBOARD rows do so via the same skill (`signal-dashboard` skill) and that no agent writes raw rows bypassing the skill.
- [ ] REQ-1967-1d: Caveman handoff format (caveman ultra tier for agent-to-agent signals) is consistently applied. Architect must confirm no agent-to-agent payload exceeds 120 chars summary without a pointer.
- [ ] REQ-1967-1e: The `verified_decision` and `signal_feedback` signal_type values (E-4) are either added to the live schema enum OR documented as DEPRECATED with a replacement. Silent degradation with no fallback is not acceptable.

### Done-criteria for architect
Architect produces per-item CONFIRMED / DEFERRED / NOT-FOUND verdict. At minimum: enumerates every signal_type in live MCP schema vs every signal_type mentioned in agent/flow files; lists each gap as a finding. "No gaps" must be stated explicitly.

## REQ-1967-2 — Flow File Race, Idempotency, and Spawn Discipline

**Surface:** 2 (race/idempotency in flows/*/main.md, JUMP-TO/RETURN discipline, recursive spawn risk, identity declarations)
**DDD Layer:** Application (flow orchestration) + Interface (agent spawning)
**Seed evidence anchors:** E-1 (market-watcher identity recurrence after MW-identity fix), E-5 (capability vs execution drift)

### Goal statement
Every flow file must have deterministic step ordering with no unguarded re-entrant entry, explicit RETURN blocks on all exit paths, no self-referential spawn loops, and an identity declaration consistent with what the agent actually executes.

### Testable check-list

- [ ] REQ-1967-2a: Every flow `main.md` that uses JUMP-TO must have a matching RETURN block on all reachable exit paths. Architect must enumerate: (i) flows using JUMP-TO, (ii) whether each JUMP-TO site has a corresponding RETURN, (iii) any path where RETURN is absent.
- [ ] REQ-1967-2b: Recursive spawn risk. Architect must confirm no flow spawns an agent type whose flow in turn spawns the original agent type without a base-case guard. Specifically: `dev-team/main.md` (dispatcher) and `cowork-team/main.md` (dispatcher) must be run by main terminal, NOT spawned inside another agent, and must contain an explicit guard against self-spawn.
- [ ] REQ-1967-2c: Market-watcher identity recurrence (E-1). Architect must confirm whether the market-watcher fix (1963-MW-IDENTITY) addresses the root cause structurally or only at the symptom level. Specifically: the fix must survive re-instantiation of the agent across multiple cowork cycles without re-triggering the "cannot directly call MCP tools" error. Test: consecutive cycle pairs (163840Z SUCCESS -> 170504Z FAIL pattern re-occurred post-fix — E-1 evidence).
- [ ] REQ-1967-2d: Idempotency guards in cowork flows. Any flow that reads a signal file and then writes a response must not re-process the same signal on a second run if the response was already written. Architect must enumerate which flows lack an idempotency guard and whether repeated cowork ticks could cause duplicate outputs.
- [ ] REQ-1967-2e: Flow identity declarations (agent `identity:` stanza in agent `.md`) must match what the flow actually does. If the stanza says "produce X" but the flow only produces Y, that is a drift finding. Architect must scan for declared-but-not-executed responsibilities (extends E-5 beyond just capability text).

### Done-criteria for architect
Per-flow table: flow path | JUMP-TO present | RETURN complete | spawn-loop risk | identity-match. "No risk" must be stated per surface; silence ≠ pass.

## REQ-1967-3 — Dispatch Routing Coverage and Task-Lock Symmetry

**Surface:** 3 (dispatch/SKILL.md table coverage, hidden general-purpose fallbacks, dispatcher-wrap vs inner self-claim symmetry, task-lock acquire/release)
**DDD Layer:** Application (dispatch routing) + Infrastructure (task-lock coordination.db)
**Seed evidence anchors:** (no direct seed evidence row — structural coverage gap)

### Goal statement
The dispatch skill table must be the exhaustive, authoritative routing table for every agent type. No hidden fallback to `general-purpose` or `claude` agent types exists. Every dispatched task has a matching inner self-claim, and every dispatcher-wrap claim is released on all exit paths.

### Testable check-list

- [ ] REQ-1967-3a: `.claude/skills/dispatch/SKILL.md` table coverage. Architect must enumerate every agent type referenced in any flow `.md` file (spawn statements, Agent() calls, DISPATCH blocks) and confirm each has a row in the dispatch skill table. Any agent type spawned but absent from the table = routing gap.
- [ ] REQ-1967-3b: Hidden general-purpose fallbacks. Architect must grep all flow files for `general-purpose`, `claude`, or unnamed agent type defaults. Any occurrence that is not an explicit "this is forbidden" comment = bug.
- [ ] REQ-1967-3c: Dispatcher-wrap vs inner self-claim symmetry. For every task spawn site that uses Phase 4 dispatcher-wrap (outer `task_claim` before `Agent()` call), confirm: (i) the spawned agent's flow does an inner `task_claim` on entry, (ii) the outer claim is released (`task_release`) on ALL exit paths (success, failure, timeout), (iii) the TTL values are consistent (outer TTL >= inner TTL to avoid outer expiry before inner finishes).
- [ ] REQ-1967-3d: Task-lock acquire/release path completeness. Architect must confirm for each flow that does inner self-claim: (i) claim on entry, (ii) heartbeat at major step boundaries, (iii) release on all exit paths including crash / EXIT / error. Any path where release is absent = leak.
- [ ] REQ-1967-3e: Dual-claim conflict. Confirm no two agents can simultaneously hold the same `task_id` lock in `coordination.db`. Specifically: what happens when a task crashes mid-cycle (no release), the dispatcher re-fires, and tries to claim the same `task_id` with the original TTL not yet expired? Is the stale-lock takeover path covered per task-lock Phase 3 protocol?

### Done-criteria for architect
Per-dispatch-site table: flow | spawn target | dispatch table row present | dispatcher-wrap present | inner claim present | release-on-error present. Each gap = finding.

## REQ-1967-4 — Signal Bus and DASHBOARD Race Conditions

**Surface:** 4 (writer-prune vs reader-scan race, stale-race, dedup, processed/ migration)
**DDD Layer:** Infrastructure (signal bus file system) + Application (DASHBOARD state)
**Seed evidence anchors:** E-3 (pm `plan_blocked` signal after PO sprint close), E-6 (cowork dispatcher drift, `silent=true matched_slots=[]`)

### Goal statement
Signal files written to `docs/signals/` must be deduplicated on read, migrated to `processed/` atomically, and the DASHBOARD must reflect the current state without stale rows surviving past their valid window.

### Testable check-list

- [ ] REQ-1967-4a: Writer-prune vs reader-scan race. Architect must determine the exact sequence when: (i) a writer agent drops a signal file, (ii) the cowork dispatcher scans `docs/signals/`, (iii) a pruner (or the same writer) moves the file to `processed/`. Is there a window where the scanner reads a file that is concurrently being moved? Result: FileNotFound at read time or double-process.
- [ ] REQ-1967-4b: Stale-race (E-3). The pm `plan_blocked` signal (1962-B-01) landed at 22:30Z after PO closed the sprint at 20:48Z. Architect must determine: (i) does any sprint-state consumer perform a CAS (compare-and-swap) or version-check before acting on a signal? (ii) can pm read a stale TASKS.md snapshot and act on stale state? What prevents this?
- [ ] REQ-1967-4c: Dedup key completeness. Signals in `docs/signals/` processed by the cowork dispatcher must have a dedup key (e.g. file name, ISO timestamp + from + type). Architect must confirm: (i) which field(s) are used as dedup key, (ii) whether two signals with the same from+type but different ISO timestamp would be double-processed or correctly deduplicated, (iii) whether processed/ migration is the sole dedup mechanism or if there is an additional in-memory check.
- [ ] REQ-1967-4d: Processed/ migration races. Multiple cowork slots may fire within the same scheduler tick. Architect must confirm: (i) only one slot processes a given signal file, (ii) the move to processed/ is atomic (rename vs copy+delete), (iii) if two slots both read the same file before either moves it, what is the outcome?
- [ ] REQ-1967-4e: DASHBOARD stale rows. Confirm that DASHBOARD rows have a declared TTL or prune condition, and that rows emitted for a now-closed sprint or completed task are pruned within a defined window. "Silent=true matched_slots=[]" cowork tick (E-6) — architect must clarify whether this is correctly idle or indicates a wasted / missed signal pick-up.
- [ ] REQ-1967-4f: Cross-sprint note from Sprint 1965 token-economy brief (committed eb1238b3): signal payload pointer discipline (payload >120 chars → truncate to 80 + pointer). Architect must note whether any existing signals in the bus violate this and flag those as a finding (or defer to Sprint 1968 L-3 per PO reconciliation decision — see OUT section).

### Done-criteria for architect
Per-race scenario: scenario | current mechanism | gap identified | severity. Explicit "no race found" when clean.

## REQ-1967-5 — Cron Schedule and Cowork Dispatcher Overlap

**Surface:** 5 (overlap windows, `crashed` status blocking re-fire, watchdog grace-period vs tick collision, master cowork dispatcher fire-drift)
**DDD Layer:** Infrastructure (cron scheduler) + Application (cowork dispatcher)
**Seed evidence anchors:** E-2 (OBSERVE-1955d: weekly crons crashed, never re-fired), E-6 (cowork dispatcher drift_min=5)

### Goal statement
Every scheduled job must have a verified re-fire path after crash, no two jobs may occupy the same scheduler slot without a collision guard, and the cowork master dispatcher must fire within an acceptable drift window.

### Testable check-list

- [ ] REQ-1967-5a: `status=crashed` blocks re-fire (E-2). `vnstockTradingStatsRefresh` and `vnstockFundamentalsRefresh` crashed on 2026-05-18 and never re-fired. Architect must confirm: (i) what `cronJobRepo.markCrashed()` does to the schedule slot, (ii) whether `status=crashed` permanently blocks the scheduler from picking the job up at the next cron tick, (iii) how many other jobs share the same crash-state path and are thus at risk.
- [ ] REQ-1967-5b: Overlap guard for concurrent job runs. For all jobs that have an `isRunning` guard, architect must confirm: (i) the guard is checked before every invocation, (ii) what happens if the guard is set and the cron fires again (skip vs queue vs error), (iii) whether the guard is properly cleared on crash (if crash leaves `isRunning=true`, next invocation is permanently blocked).
- [ ] REQ-1967-5c: Watchdog grace-period vs scheduler tick collision. The cron scheduler ticks at defined intervals. Docker watchdog health check `start_period` values (watchdog-2: 60s RAG, watchdog-7: 60s flaresolverr) define a window where the service is starting up. Architect must confirm that no cron job targets a service during its watchdog start_period window. Specifically: does the 03:00Z system-auditor pass or any other early-morning job fire while the RAG service is in its 60s start window after a container restart?
- [ ] REQ-1967-5d: Cowork master dispatcher fire-drift (E-6). `cowork-team-20260521T185005Z.json` shows `drift_min=5`. Architect must: (i) determine if drift accumulates over multiple ticks or resets each tick, (ii) assess whether 5-minute drift is within acceptable bounds or indicates a scheduling resource-contention issue, (iii) determine if drift correlates with the market-watcher MCP-tool-awareness failures (E-1 / E-6 same root?).
- [ ] REQ-1967-5e: OBSERVE-1955d evidence scope. The OBSERVE-1955d gate was set after the weekly cron crash. Architect must confirm whether the gate was lifted or is still constraining re-fire, and whether the constraint applies only to those two jobs or to all jobs in the weekly slot.

### Done-criteria for architect
Per-job-class table: job | crash-path | re-fire mechanism | overlap guard | guard-on-crash cleared. Drift analysis with threshold verdict.

## REQ-1967-7 — Drive-to-Fix Invariant: Owner + Fix-Size + Dependency Chain

**Surface:** 7 (lock contention + race — task-lock TTL, dispatcher-wrap leak, inner-claim missed on agent crash, dual-claim conflict, TASKS.md / DASHBOARD / pipeline-state.json concurrent-writer last-writer-wins)
**DDD Layer:** Infrastructure (coordination.db, task-lock) + Application (pipeline state)
**Seed evidence anchors:** (structural — cross-cutting all surfaces)

### Goal statement
Every CONFIRMED finding produced by the architect must carry enough information for PM to create an actionable TASK_NNN without further architect involvement: an owner (agent + zone), a fix-size (XS/S/M/L), and an explicit dependency chain. Lock-specific findings must additionally identify the exact contention scenario.

### Testable check-list

- [ ] REQ-1967-7a: Task-lock stale-claim TTL. When an agent crashes mid-cycle without calling `task_release`, the lock expires at `TTL` seconds. Architect must confirm: (i) the TTL for each task_kind (cowork-slot=900s, sprint-task=3600s, dashboard-row=1800s), (ii) whether the cowork dispatcher re-fires a task within the TTL window (creating a dual-claim scenario), (iii) what the outcome is when two sessions try to claim the same task_id simultaneously (only one should succeed; verify).
- [ ] REQ-1967-7b: Dispatcher-wrap leak on error. If the dispatcher-wrap outer `task_claim` succeeds but the `Agent()` spawn fails (tool error, ENOSPC, timeout), the outer claim may not be released. Architect must trace every Phase 4 dispatcher-wrap site and confirm: (i) release is in a `finally`-equivalent block or all error exit paths, (ii) what happens if release also fails (TTL expiry is the fallback — confirm TTL is short enough).
- [ ] REQ-1967-7c: Inner-claim missed on agent crash. If an agent's inner self-claim is in the flow but the agent crashes before reaching that step (e.g. during notebook read), no lock is held and no lock release is needed. - [ ] REQ-1967-7d: Concurrent last-writer-wins on TASKS.md / DASHBOARD / pipeline-state.json. These files are plain text/JSON. When two agents write concurrently (e.g. two dev-team slots finishing simultaneously), the second write silently overwrites the first. Architect must: (i) enumerate which files have no write serialisation, (ii) assess whether concurrent writes have occurred in the commit log (look for <30s commit pairs on same file), (iii) determine which file is highest risk.

## Glossary / Disambiguation

| Term | Definition for this audit |
|------|--------------------------|
| **Race** | Two concurrent agents / processes reading+writing the same resource where outcome depends on timing |
| **Idempotency** | A flow step that produces the same observable result if run twice on unchanged input |
| **Recursive spawn** | Agent A spawns Agent B whose flow spawns Agent A again (directly or transitively) — creates infinite loop unless guarded |
| **Dispatcher** | The main terminal or cowork-team flow that selects an agent type and calls Agent() — NOT itself a spawnable agent |
| **Dispatcher-wrap** | Phase 4 outer task_claim held by dispatcher before Agent() call; released after spawn returns |
| **Inner self-claim** | Phase 3 task_claim made by the spawned agent inside its own flow, before doing exclusive work |
| **DASHBOARD** | `docs/signals/DASHBOARD.md` — structured signal-bus summary file with ## sections per agent class |
| **Signal bus** | The `docs/signals/` filesystem directory used for agent-to-agent async handoff |
| **CAS** | Compare-And-Swap — optimistic concurrency check: read current version, write only if version unchanged |
| **Dead-handoff** | A signal emitted to `docs/signals/` that no downstream agent ever reads (orphaned signal) |
| **Stale-race** | A write based on a state snapshot read before a concurrent write changed the state |
| **TTL** | Time-to-live for a task-lock entry in coordination.db; after expiry, another claimer can take over |
| **Caveman ultra** | Token-compressed agent-to-agent comms tier per `.claude/skills/caveman/SKILL.md` — summary ≤80 chars + pointer |
| **BCTC freeze** | Active policy: no Sprint 1967 fix tasks touch BCTC paths until sprint 1954c closes |
| **always_load** | Knowledge files loaded unconditionally at every agent cycle start |
| **lazy_load** | Knowledge files loaded only when a specific trigger condition is met during the cycle |
