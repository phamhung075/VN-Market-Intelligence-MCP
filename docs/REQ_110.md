# REQ-110: fix(news-pipeline) — topStories always empty in evening report

status: READY_FOR_ARCHITECT
sprint: 110
po_vision: Fix topStories: [] and newsCount: 0 in every evening report — users never see news-driven analyses at market close

## User Story

As a Vietnamese stock investor using Claude,
I want the evening report to show the top news stories since midnight Vietnam time,
So that I get a curated, news-driven close-of-day summary every evening.

---

## Problem Statement

Production evening reports consistently show `topStories: []` and `newsCount: 0`.
The VPS pushes news every 15 minutes (9 sources, Sprint 103 wired). The pipeline is:

```
VPS POST /api/push-news
  → server.ts handler (setImmediate)
    → pollNews({ fetchers: bySource })
      → isVnRelevant() filter          ← CANDIDATE ROOT CAUSE A
        → normalizeNews()
          → tryInsertEntry()            ← CANDIDATE ROOT CAUSE B
            → INSERT rag_analyses (created_at = new Date().toISOString())
              → assembleEveningSummary()
                WHERE created_at >= midnightVietnamAsUtc()   ← CANDIDATE ROOT CAUSE C
```

Three root cause candidates identified by code inspection:

### RC-A — VN relevance filter silently drops VPS-pushed sources

`isVnRelevant()` whitelists only `["cafef", "vnexpress", "vneconomy"]` as always-relevant (Rule 1).
The six VPS-only sources (`vietstock`, `vietnambiz`, `vnbusiness`, `tuoitre`, `nhandan`, `nld`) fall
through to Rule 2 (keyword scan). The `item.source` field in VPS-pushed items is set to
`(item.source || "vps").toLowerCase()` in the push handler — if the VPS script sends items with
`source: "vietstock"` then the source passes through; but if any item arrives with `source`
missing or set to `"vps"`, the keyword-scan fallback runs against the title/content. If the
content field is empty (common for short RSS summaries), and the title lacks explicit VN geo/
exchange keywords, the article is silently discarded before `tryInsertEntry` is ever called.
This is the highest-probability root cause given that `newsCount === 0` (not just `topStories` empty).

### RC-B — INSERT OR IGNORE triggered by title-dedup over-firing

`tryInsertEntry()` applies two dedup layers:
1. `INSERT OR IGNORE` on UNIQUE index (`source_url`) — safe for VPS items that have real URLs.
2. `isTitleDuplicate()` — checks the first 50 chars of title against the last 24 h. The check
   runs `LOWER(SUBSTR(REPLACE(source_title, '  ', ' '), 1, 50))` in SQLite vs the JS fingerprint
   `title.toLowerCase().replace(/\s+/g, " ").trim().slice(0, 50)`. These normalizations differ
   (`REPLACE` only handles double-spaces, the JS regex collapses all whitespace runs). Under edge
   cases the JS fingerprint matches an existing row that the SQL would not (false positive → skip),
   or vice versa (missed dedup). Low probability for zero-rows scenario but contributes to low
   insertion rates.

### RC-C — Timezone mismatch between created_at format and midnight query

`normalizeNews()` sets `createdAt: new Date().toISOString()` → format `2026-04-16T10:23:45.123Z`.
`midnightVietnamAsUtc()` returns `2026-04-15T17:00:00.000Z`.
SQLite `TEXT >= TEXT` comparison on ISO strings is lexicographic. Both strings are in the same
ISO 8601 UTC format so the comparison is correct in principle. However, the SQLite schema for
`rag_analyses.created_at` has **no DEFAULT clause** — the column is `TEXT NOT NULL` with the
value explicitly bound from `entry.createdAt`. If a code path accidentally omits `createdAt` or
passes `undefined`, SQLite would reject the INSERT (non-null constraint) or bind a null string.
This is a lower-probability cause but worth a direct assertion in TDD.

## Functional Requirements

### FR-1: Extend VN_SOURCE_IDS to include all VPS-pushed source keys

- Description: Add the 6 VPS-only source identifiers to `VN_SOURCE_IDS` in `vnRelevanceFilter.ts`
  so they always pass the relevance gate (Rule 1) without needing VN keyword content.
- Input: `item.source` one of `vietstock | vietnambiz | vnbusiness | tuoitre | nhandan | nld`
- Output: `isVnRelevant()` returns `true` immediately, item proceeds to `normalizeNews()`
- Business rule: These sources exclusively publish Vietnamese financial/business content.
  They must never be discarded by the relevance filter regardless of title content.
- DDD layer: domain

### FR-2: Assert created_at is always a valid ISO string in tryInsertEntry

- Description: Add a guard in `tryInsertEntry` (or `normalizeNews`) that validates `entry.createdAt`
  is a non-empty string before binding. If undefined/empty, fall back to `new Date().toISOString()`.
- Input: `entry.createdAt` (set by `normalizeNews`)
- Output: `created_at` column always contains a valid ISO 8601 UTC string
- Business rule: A missing timestamp silently drops the row; the guard must log a warning and
  substitute the current UTC time rather than letting the INSERT fail silently.
- DDD layer: domain (normalizeNews guard) + application (tryInsertEntry guard)

### FR-3: TDD diagnostic test suite — 4 test cases (task 1336, written FIRST)

- Description: Write `src/__tests__/1335-news-pipeline-rag-insert.test.ts` with 4 failing tests
  that prove the production gap before any fix is applied.
- Input: In-memory SQLite DB, simulated push-news items for VPS source keys
- Output: All 4 tests FAIL before fix, all 4 PASS after fix
- Business rule: Tests are the acceptance gate — no fix ships without all 4 passing.
- DDD layer: test

| Test | Assertion |
|------|-----------|
| TC-1 | Push 3 news items with `source: "vietstock"` → `rag_analyses` has 3 rows with `created_at >= midnightVietnamAsUtc()` |
| TC-2 | `assembleEveningSummary({ db })` with those 3 rows → `topStories.length === 3` AND `newsCount === 3` |
| TC-3 | Push same URL twice → exactly 1 row in `rag_analyses` (URL dedup, not title dedup) |
| TC-4 | `newsCount === 0` and `topStories === []` when `rag_analyses` is empty (baseline sanity) |

## Non-Functional Requirements

- Performance: `isVnRelevant()` is called per-item in a hot loop; the fix (array append) is O(1)
  with zero regression on throughput.
- Data freshness: Fix must ensure VPS-pushed items land in `rag_analyses` within the same
  `pollNews` call that processes them (synchronous INSERT, not deferred).
- Language: No user-facing strings changed. Log messages may be English.

## Edge Cases & Data Quality

- [ ] VPS item with `source` missing → `(item.source || "vps")` in push handler sets it to `"vps"`.
  `"vps"` is NOT in `VN_SOURCE_IDS` and has no VN keywords → still silently discarded.
  FR-1 fix covers named source keys; a follow-up may add `"vps"` to the whitelist or the push
  handler should always set a valid source key from the VPS script.
- [ ] VPS item with empty `title` → `titleFingerprint` returns a short string (<10 chars), dedup
  skips. `normalizeNews` will set `sourceTitle` to an empty string. INSERT proceeds; row visible
  with `source_title = ""`. Not a blocker for topStories (rows are returned) but may yield ugly
  display. Out of scope for this fix.
- [ ] `created_at` timezone edge case at midnight VN boundary (17:00 UTC): items pushed at exactly
  17:00:00.000Z land at `created_at = "2026-04-16T17:00:00.000Z"` and `midnightVietnamAsUtc()`
  returns `"2026-04-16T17:00:00.000Z"`. Lexicographic `>=` passes — correct.
- [ ] Items pushed before midnight VN (e.g. 16:59 UTC) have `created_at` before the midnight
  boundary → excluded from today's evening report. Correct and expected.
- [ ] DB_PATH in tests must be `":memory:"` — set `process.env["DB_PATH"] = ":memory:"` as the
  first line of the test file (before all imports) to prevent accidental writes to production DB.

## Acceptance Criteria

### AC-1: VPS-pushed items appear in rag_analyses

**Given** a push-news call with items having `source: "vietstock"` (or any other VPS key)
**When** `pollNews` processes those items
**Then**

- `isVnRelevant()` returns `true` for each item without scanning title/content
- `tryInsertEntry()` is called for each item
- `rag_analyses` row count increases by the number of non-duplicate items
- Each inserted row has `created_at` matching `new Date().toISOString()` format (ISO 8601 UTC)

### AC-2: Evening summary reflects inserted rows

**Given** `rag_analyses` has N rows with `created_at >= midnightVietnamAsUtc()`
**When** `assembleEveningSummary()` is called
**Then**

- `topStories.length === Math.min(N, 5)`
- `newsCount === N`
- No rows are silently excluded by the midnight query

### AC-3: URL dedup works correctly

**Given** two push-news calls with the same `link` (URL)
**When** both are processed by `tryInsertEntry`
**Then**

- Exactly 1 row exists in `rag_analyses` for that URL
- Second call returns `changes === 0` (INSERT OR IGNORE)

### AC-4: Zero-news baseline

**Given** `rag_analyses` has no rows since midnight VN
**When** `assembleEveningSummary()` is called
**Then**

- `topStories === []`
- `newsCount === 0`

### AC-5: No regressions

- `bun tsc --noEmit` exits 0
- Full test suite: 0 new failures vs Sprint 109 baseline
