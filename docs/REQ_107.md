# REQ-107: fix(ta): defaultComputeTa reads daily_ohlcv instead of market_prices_history

status: READY_FOR_ARCHITECT
sprint: 107
po_vision: Fix taSummary always empty in evening reports — switch defaultComputeTa data source from intraday ticks to official daily OHLCV.

## User Story

As a Vietnamese stock investor using Claude,
I want the evening report to show RSI and MA20 signals for my watchlist tickers,
So that I can assess technical momentum at market close and act on it the next morning.

## Functional Requirements

### FR-1: Rewrite defaultComputeTa to query daily_ohlcv

- Description: Replace the `market_prices_history` query (intraday ticks, only 1 day of data in production) with a `daily_ohlcv` query (official daily OHLCV, 10+ days and growing in production).
- Input: `code: string`, `db: Database` (injected — same signature, no change)
- Output: `TaSignal | null` (same return type, no change)
- Business rule: Return `null` when `daily_ohlcv` has fewer than 15 rows for the ticker. This preserves the RSI(14) minimum-data guard.
- Business rule: Use `close` column from `daily_ohlcv` as the price series. Do not average intraday ticks.
- Business rule: Row ordering is `ORDER BY date ASC LIMIT 60` — oldest-to-newest so RSI and MA windows compute correctly.
- DDD layer: application

### FR-2: Remove GROUP BY / AVG aggregation from the function

- Description: The old query used `AVG(price) GROUP BY date(fetched_at)` to simulate a daily close from intraday ticks. `daily_ohlcv` already has exactly one row per trading day with the official close price. The aggregation step must be removed.
- Input: raw `daily_ohlcv` rows — one row per day, `close REAL`
- Output: `number[]` prices array passed unchanged to `computeRSI` and `computeMA`
- Business rule: The `CandleRow` interface alias (`day`, `close_price`) must be updated or a new inline type used — `daily_ohlcv` schema columns are `date TEXT` and `close REAL`.
- DDD layer: application

### FR-3: Preserve all downstream TA computation

- Description: `computeRSI(prices, 14)`, `computeMA(prices, 20)`, and the `rsiStatus` / `priceVsMa20` classification logic are correct and must not change. Only the data-source query changes.
- Input: `number[]` close prices (sourced from `daily_ohlcv.close` after FR-1/FR-2)
- Output: `TaSignal` — `{ code, rsi14, rsiStatus, ma20, priceVsMa20, currentPrice }` unchanged
- DDD layer: application (no change)

### FR-4: TDD test written before production fix (task 1331 first)

- Test cases:

  | TC-3 | `daily_ohlcv` has 20 rows with known close prices | returns non-null `TaSignal` with all fields defined |

## Non-Functional Requirements

- Performance: Single SQLite query per ticker, LIMIT 60. Index `idx_daily_ohlcv_code_date` (code, date DESC) already exists — query is index-covered.
- Data freshness: `daily_ohlcv` is populated by the VPS price-fetch service (`vn-price-fetch.service`, 60s interval). Evening report runs after market close; data is current within 60s of the last VPS push.
- Language: No user-visible strings change in this task. TA signal labels are set by `rsiStatus` and `priceVsMa20` enum values — unchanged.
- TypeScript: `bun tsc --noEmit` must produce zero errors after both tasks land.

## Edge Cases & Data Quality

- [ ] Ticker has 0 rows in `daily_ohlcv` — guard `rows.length < 15` returns `null`. No crash.
- [ ] Ticker has exactly 14 rows — returns `null` (RSI needs 15 minimum: 14 deltas + 1 seed).
- [ ] Ticker has exactly 15 rows — returns non-null. RSI(14) computes on exactly 15 prices.
- [ ] `close` value is 0.0 — treated as valid price by computeRSI/computeMA. Not filtered. Acceptable: 0.0 close is data-quality issue upstream (VPS), not BA scope here.
- [ ] Vietnamese number format: `daily_ohlcv.close` is stored as `REAL` (SQLite native float). No parsing of dot/comma VN format needed — VPS service normalises before insert.
- [ ] `LIMIT 60` with only 20 rows — SQLite returns 20 rows without error.
- [ ] Two tickers share same date rows — query is `WHERE code = ?` parameterised; no cross-ticker contamination.

## Implementation Notes for Architect

**Current query (to be replaced):**
```sql
SELECT date(fetched_at) AS day, AVG(price) AS close_price
  FROM market_prices_history
 WHERE code = ?
   AND fetched_at >= datetime('now', ?)
 GROUP BY date(fetched_at)
 ORDER BY day ASC
```
Called with params: `[code, "-60 days"]`

**Replacement query:**
```sql
SELECT date AS day, close AS close_price
  FROM daily_ohlcv
 WHERE code = ?
 ORDER BY date ASC
 LIMIT 60
```
Called with params: `[code]` (no date filter needed — LIMIT 60 trading days is the window)

**Schema confirmed** (`src/infrastructure/db/schema.ts` lines 152–164):
- Table: `daily_ohlcv(code TEXT, date TEXT, open REAL, high REAL, low REAL, close REAL, volume REAL, updated_at TEXT, PRIMARY KEY(code, date))`
- Index: `idx_daily_ohlcv_code_date ON daily_ohlcv(code, date DESC)` — exists, query benefits from it

**Return type** `TaSignal` and helper calls `computeRSI` / `computeMA` are unchanged. The `CandleRow` interface column aliases (`day`, `close_price`) are preserved in the SELECT aliases so no downstream destructuring breaks.
