# REQ-077: Replace TE stream.ashx with Public RSS Feeds

status: READY_FOR_ARCHITECT
sprint: 077
po_vision: Restore reliable Level 1/2 global macro intelligence by replacing the broken
session-gated Trading Economics stream endpoint with three free, no-auth public RSS feeds.

---

## User Story

As a Vietnamese stock investor using Claude,
I want the intelligence cycle to always have global macro context (Fed decisions, oil
prices, inflation, USD/VND moves),
So that my evening reports are never empty due to a geo-blocked or session-gated API
failing from the France server.

---

## Background & Root Cause

`tradingEconomicsStream.ts` calls `https://tradingeconomics.com/ws/stream.ashx`, a
session-authenticated AJAX endpoint. From the France production server the endpoint
returns an HTTP error or an empty JSON array. This has silently produced the
`log_warn:reuters_trading_economics_zero_items` warning since 2026-04-12.

When this failure coincides with a delayed VPS `vn-news-fetch.service` push, the
intelligence cycle executes with zero news items, `rag_analyses` stays empty, and the
evening report is blank (observed 2026-04-13).

The Atom RSS fix shipped in sprint 074 made `parseRssFeed()` handle Atom 1.0 feeds
correctly. `fetchReuters()` (reuters.ts) already demonstrates the correct pattern for
public Google News RSS with injectable `httpClient` and sequential fallback. Task 1191
replicates that pattern at the Level 1 (global macro) layer.

## Functional Requirements

### FR-1: Remove stream.ashx call

- Description: Delete all code in `tradingEconomicsStream.ts` that references
  `https://tradingeconomics.com/ws/stream.ashx` — the URL constant, the `TEStreamItem`
  interface, the JSON parse branch, and the country/category/importance metadata
  enrichment logic. None of these have production value since the endpoint never returns
  data from France.
- Input: n/a (deletion only)
- Output: File no longer references `stream.ashx` anywhere.
- Business rule: The exported function signature `fetchTradingEconomicsStream(httpClient?)`
  must remain identical so `pollNews.ts` and `circuitBreakerRegistry.ts` need no changes.
- DDD layer: infrastructure

### FR-2: Define three public RSS feed constants

- Description: Replace the single `TE_STREAM_URL` constant with three named constants
  covering global macro topics at Level 1/2 of the causal cascade.
- Constants (exact URLs):

  ```
  MW_RSS_URL =
    "https://feeds.marketwatch.com/marketwatch/topstories/"

  GNEWS_MACRO_URL =
    "https://news.google.com/rss/search?q=global+economy+OR+central+bank+OR+interest+rate+OR+inflation&hl=en"

  GNEWS_MARKETS_URL =
    "https://news.google.com/rss/search?q=financial+markets+OR+commodities+OR+USD+VND+exchange+rate&hl=en"
  ```

- Feed selection rationale:
  - MarketWatch Top Stories: no-auth, public, broad macro coverage, RSS 2.0 format.
  - Google News macro query: covers Fed/ECB/BOJ decisions, CPI, GDP — direct Level 1
    cascade triggers.
  - Google News markets query: covers oil, gold, USD/VND — directly used as Level 2
    inputs for VN sector impact (energy, materials, banking).
- DDD layer: infrastructure

### FR-3: Sequential fallback logic

- Description: Try each feed in order. Return the first non-empty result. Never call
  a later feed if an earlier one returns items.
- Fallback chain:
  1. Fetch `MW_RSS_URL` — if `items.length > 0`, return items tagged
     `source = 'tradingeconomics'`.
  2. Otherwise fetch `GNEWS_MACRO_URL` — if `items.length > 0`, return items tagged
     `source = 'tradingeconomics'`.
  3. Otherwise fetch `GNEWS_MARKETS_URL` — if `items.length > 0`, return items tagged
     `source = 'tradingeconomics'`.
  4. If all three are empty or failed, return `[]`.
- Error handling: Any HTTP error or parse error on a single feed is treated as empty
  (logged at WARN level) and falls through to the next feed. The outer function never
  throws.
- DDD layer: infrastructure

### FR-4: Backward-compatible source tag

- Description: All items produced by `fetchTradingEconomicsStream()` must carry
  `source = 'tradingeconomics'` regardless of which feed URL actually returned them.
- Business rule: The cascade engine (`intelligenceCycleJob`, `pollNews`) filters and
  routes news by source tag. Changing the tag would silently drop Level 1 items from
  the cascade. The tag value must not change.
- DDD layer: infrastructure

### FR-5: Rate limiter host key

- Description: Replace the current host key `"tradingeconomics.com"` with
  `"tradingeconomics-rss"`. This isolates the RSS fetcher's rate-limit budget from
  the separate `fetchMacroIndicators()` function in `tradingEconomics.ts` which uses
  the same host domain for HTML scraping.
- Rate-limit guard pattern (same as `fetchReuters`):
  - If `httpClient` is injected (test mode), skip the rate-limit check entirely.
  - In production (no injected client), call `globalRateLimiter.canCall("tradingeconomics-rss")`;
    if false, log DEBUG and return `[]` immediately without any HTTP call.
  - Call `globalRateLimiter.recordCall("tradingeconomics-rss")` once before the first
    fetch attempt.
- DDD layer: infrastructure

### FR-6: Injectable HTTP client

- Description: Add an optional `httpClient?: HttpClient` parameter to
  `fetchTradingEconomicsStream()`. The `HttpClient` interface is imported from
  `./ssc.js` (same import used by `reuters.ts`). When `httpClient` is undefined,
  create the default axios-backed client via a lazy `makeDefaultHttpClient()` helper
  (identical pattern to `reuters.ts`).
- Business rule: Injectable client allows unit tests to mock all three feeds without
  real network calls. The axios import must remain lazy so tests that inject mocks
  never load axios.
- DDD layer: infrastructure

### FR-7: Shared private helper `tryFetchFeed()`

- Description: Extract a `tryFetchFeed(url, sourceTag, client)` private async function
  (same signature and semantics as the one in `reuters.ts`). Log prefix for this file
  is `[te-rss]` (distinguishable from `[reuters]` in production logs).
- Input: `url: string`, `sourceTag: string`, `client: HttpClient`
- Output: `Promise<RssItem[]>` — tagged array or `[]` on any failure.
- Business rule: Uses `parseRssFeed()` imported from `./rss.js`. The `parseRssFeed`
  function already handles both RSS 2.0 and Atom 1.0 (sprint 074 fix) — no additional
  format detection needed.
- DDD layer: infrastructure

### FR-8: Update cron-registry.json lastUpdated field

- Description: Set `lastUpdated` to `"2026-04-14"` in `docs/data/cron-registry.json`.
  No count change — no scheduler file is added or removed by this task.
- DDD layer: infrastructure (data maintenance)

## Non-Functional Requirements

- Performance: Each feed fetch uses a 15-second HTTP timeout (same as the current
  stream.ashx call). Total worst-case latency with all three feeds failing is 45 seconds,
  which is acceptable within the 15-minute intelligence cycle interval.
- Data freshness: MarketWatch RSS updates every few minutes. Google News RSS updates
  continuously. Both are sufficiently fresh for the 15-minute intelligence cycle.
- Language: All log messages in English. Feed content arrives in English — no
  translation required at this layer (cascade engine handles language routing).
- Reliability: Never throws. Returns `[]` on total failure. Circuit breaker
  (`breakers.tradingEconomics` in `circuitBreakerRegistry.ts`) remains in place at
  the call site in `pollNews.ts` — provides a second layer of protection.
- Backward compatibility: `fetchTradingEconomicsStream` export name unchanged.
  `source = 'tradingeconomics'` tag unchanged. `pollNews.ts` and
  `circuitBreakerRegistry.ts` require zero changes.

## Edge Cases & Data Quality

- [ ] MarketWatch RSS may include sponsored content with `<item>` tags but no meaningful
      `<link>` — `parseRssFeed` skips items with empty title AND url, which is sufficient.
- [ ] Google News RSS returns article redirect URLs in the `<link>` tag (e.g.,
      `https://news.google.com/rss/articles/...`). This is acceptable — the cascade
      engine stores the URL for display, not for further scraping.
- [ ] Google News may return Atom 1.0 format for some query results — `parseRssFeed()`
      already handles this via the sprint 074 fix (`$("item, entry")`).
- [ ] MarketWatch RSS may be temporarily unavailable (CDN outage) — the fallback chain
      to Google News feeds handles this transparently.
- [ ] All three feeds empty simultaneously — possible during off-hours or network issues.
      Return `[]`, log WARN `[te-rss] all RSS sources failed`. The downstream circuit
      breaker records a zero-item result but does not open (non-error path).
- [ ] Rate limit hit (e.g., intelligence cycle runs unexpectedly fast) — return `[]`
      immediately without any HTTP call. Normal behavior.
- [ ] Feed returns malformed XML — `parseRssFeed` catches the cheerio parse error and
      returns `[]`, which triggers fallback to the next feed.

## Reference: Pattern from fetchReuters()

The implementation must replicate the `fetchReuters()` pattern exactly:

1. Guard: if no injected client AND rate-limited → return `[]`.
2. Build client: `httpClient ?? (await makeDefaultHttpClient())`.
3. Record rate limit call only in production (no injected client).
4. Call `tryFetchFeed(url, tag, client)` for each feed in sequence.
5. Return first non-empty result; fall through on empty/error.
6. Log WARN if all sources failed.

The axios `makeDefaultHttpClient()` implementation is identical to the one in
`reuters.ts`: browser User-Agent, `Accept: text/html,...`, 15s timeout, text
responseType, `maxRedirects: 5`. MarketWatch RSS and Google News RSS both require
the browser User-Agent to avoid 403 responses.
