# REQ-104: Direction-Aware Level Label in classifyDeviation

status: READY_FOR_ARCHITECT
sprint: 104
po_vision: Fix misleading macro alert label — "cao bất thường" shown even when value is BELOW the moving average

## User Story

As a Vietnamese stock investor using Claude,
I want macro alert messages to say "thấp bất thường" when a value is below its rolling mean,
So that I do not misread a below-average USD/VND rate as an above-average (high) condition and make a wrong trading decision.

---

## Production Bug — Confirmed Evidence

**Source:** `reports/2026-04-15-evening.json` (2026-04-15 evening report)

```
"Macro alert [HIGH]: USD/VND: 26302 — cao bất thường (-2.61σ dưới TB 26333.2)"
```

- zScore = -2.61 (BELOW mean) → direction = "below"
- Alert label = "cao bất thường" (abnormally HIGH)
- Correct label = "thấp bất thường" (abnormally LOW)

**Root cause (line 138 — `src/domain/services/macroThresholds.ts`):**

```ts
const levelVi = LEVEL_VI[level];   // always reads LEVEL_VI, direction ignored
```

`LEVEL_VI` maps `"high"` → `"cao bất thường"` regardless of whether deviation is above or below mean.

---

## Functional Requirements

### FR-1: Add LEVEL_VI_BELOW map

- Description: Create a second Vietnamese label map for below-mean deviations.
- Input: DeviationLevel key ("elevated" | "high" | "extreme")
- Output: Vietnamese label string
- Business rule:

  | Level    | LEVEL_VI (above)  | LEVEL_VI_BELOW (below) |
  |----------|-------------------|------------------------|
  | normal   | "bình thường"     | "bình thường"          |
  | elevated | "cao hơn TB"      | "thấp hơn TB"          |
  | high     | "cao bất thường"  | "thấp bất thường"      |
  | extreme  | "cực cao"         | "cực thấp"             |

  Note: existing "cực đoan" label for `extreme` is renamed to "cực cao" in LEVEL_VI (direction-explicit, consistent with LEVEL_VI_BELOW naming convention).

- DDD layer: domain

### FR-2: Select label based on direction in classifyDeviation()

- Description: Replace the unconditional `LEVEL_VI[level]` lookup with a direction-conditional lookup.
- Input: `direction: DeviationDirection` (already computed in classifyDeviation)
- Output: correct `levelVi` string used in `summary`
- Business rule:
  - `direction === "below"` → use `LEVEL_VI_BELOW[level]`
  - `direction === "above"` OR `direction === "at_mean"` → use `LEVEL_VI[level]`
  - `level === "normal"` path is unchanged — summary uses the word "bình thường" directly.
- DDD layer: domain

### FR-3: TDD test — 6 cases covering direction × level combinations

- Description: Written FIRST (all failing), then FR-1 + FR-2 applied to make them pass.
- Input: crafted `MacroStats` objects passed to `classifyDeviation()`
- Output: assertions on `summary` string content
- Business rule: pure unit test, no DB, no HTTP, no Telegram
- DDD layer: test

- Language: Vietnamese labels must be valid UTF-8 with diacritics
- Type safety: `LEVEL_VI_BELOW` must use the same `Record<DeviationLevel, string>` type as `LEVEL_VI` so TypeScript exhaustiveness is enforced
- Compile: `bun tsc --noEmit` 0 errors after change

---

## Edge Cases & Data Quality

- [ ] `direction === "at_mean"` (zScore between -0.1 and +0.1) — level will be "normal" in almost all cases; if somehow level is "elevated" at_mean, label falls back to LEVEL_VI (above), which is acceptable and consistent with existing "cao hơn TB" semantics.
- [ ] `stdDev < 0.001` or `sampleCount < 5` — early return path is unchanged; no label is emitted; not affected by this fix.
- [ ] Indicator names not in `INDICATOR_NAME_VI` — fallback to raw `name` already present; unaffected.
- [ ] Vietnamese diacritics in label strings ("thấp bất thường") — must not be mangled by TypeScript string literal; test must use exact UTF-8 comparison.
