## User Stories

### US-1: Tinh toan que cho moi co phieu watchlist
As a Vietnamese stock investor,
I want the system to encode 6 market signals per stock into I Ching hexagrams using the Lao/Thieu 4-state system,
So that each stock has a meaningful state representation capturing sentiment, fundamentals, price, flow, sector, and macro dimensions.

**Acceptance Criteria:**
- 6 hao mapped: Hao 1=sentiment, Hao 2=fundamentals, Hao 3=price, Hao 4=foreign flow, Hao 5=sector, Hao 6=macro
- Each hao classified as LAO_DUONG/THIEU_DUONG/THIEU_AM/LAO_AM using percentile-based thresholds
- Lao states auto-detect reversal conditions (overbought/oversold)
- Binary value derived: DUONG(1) or AM(0) for hexagram lookup

### US-2: Doc 3 lop — Que chinh, Ho que, Bien que
As a Vietnamese stock investor,
I want each reading to include 3 hexagram layers: surface state, hidden dynamics, and predicted future,
So that AI agents can distinguish what appears to be happening vs what's really happening vs where it's going.

### US-3: Ngu Hanh interaction scoring
As a Vietnamese stock investor,
I want the system to compute Five Element (Kim/Moc/Thuy/Hoa/Tho) interaction between upper and lower trigrams,
So that I know if internal forces support (tuong sinh) or conflict with (tuong khac) external forces.

### US-4: Markov transition matrix — hoc tu lich su VN
As a Vietnamese stock investor,
I want the system to track hexagram transitions over time and learn which transitions historically predict price movements,
So that predictions improve with accumulated data from the Vietnamese market.

### US-5: MCP tool cho agent su dung
As an AI analysis agent,
I want `get_kinhdich_reading(code)` to return a full Vietnamese Kinh Dich reading with all 3 layers,
So that I can frame my analysis using hexagram interpretation.

### US-6: Backtest framework — do luong do chinh xac
As a system operator,
I want the system to backtest hexagram readings against actual price outcomes,
So that I know which hexagram states and transitions are predictive vs random.

## Functional Requirements

### FR-1: Hao Encoder (`haoEncoder.ts`)
- Input: stock code + current market data
- Computes 6 normalized scores [-1.0, +1.0] from existing system signals
- Classifies each into 4 states using percentile thresholds:
  - LAO_DUONG (>90th pct) = overbought, reversal coming
  - THIEU_DUONG (55th-90th) = stable bull
  - THIEU_AM (10th-55th) = stable bear
  - LAO_AM (<10th pct) = oversold, reversal coming
- Hybrid thresholds: fixed initially (+0.75/+0.10/-0.75), adaptive after 90 days

### FR-2: Hexagram Resolution (`hexagramResolver.ts`)
- Port from Python: 8 trigram lookup + 64 hexagram lookup tables
- Input: 6 binary values → hexagram number (1-64)
- O(1) lookups via pre-built maps

### FR-3: Nuclear Hexagram (`nuclearComputer.ts`)
- Hao 2-3-4 → lower trigram, Hao 3-4-5 → upper trigram → Ho que
- Pure computation, no I/O

### FR-4: Transformed Hexagram (`transformedComputer.ts`)
- Flip all Lao lines (Lao Duong→Am, Lao Am→Duong)
- Stable Thieu lines unchanged
- Result = Bien que (future state)

### FR-5: Five Elements (`nguHanhClassifier.ts`)
- Trigram → element mapping (from que_shared.py TRIGRAMS)
- Generation cycle: Moc→Hoa→Tho→Kim→Thuy→Moc
- Destruction cycle: Moc→Tho→Thuy→Hoa→Kim→Moc
- Score: tuong_sinh=+0.3, tuong_khac=-0.3, same=+0.1

### FR-6: Hexagram Library (`hexagramLibrary.ts`)
- Port all 64 hexagrams from Python rewrite_*.py files
- Each hexagram: name, chinese, core_meaning, judgment, image, state, 6 lines
- Each line: position, type, name, chinese, vietnamese, outcome, action, interpretation
- Trigram metadata: name, chinese, element, image, symbol

### FR-7: Markov Transition Store (`hexagramTransitionStore.ts`)
- SQLite table: hexagram_transitions (from, to, count, avg_price_change_5d, win_rate)
- Record transitions each intelligence cycle
- Query: P(to|from), top-N next states, win rates

### FR-8: Reading Orchestrator (`kinhDichReading.ts`)
- Combines all services into a full KinhDichReading
- Three layers: queChiNh + hoQue + bienQue
- NguHanh interaction
- Markov prediction
- Vietnamese prose summary

### FR-9: Backtest Engine (`hexagramBacktester.ts`)
- Input: historical readings from kinhdich_readings table
- For each reading: check price 5d/10d/20d after
- Compare predicted direction vs actual
- Compute: accuracy %, avg return per hexagram, best/worst transitions
- Weekly cron job

### FR-10: MCP Tools
- `get_kinhdich_reading(code)` — full reading for a stock
- `get_market_hexagram()` — market-wide hexagram (VN-Index + macro)
- `get_hexagram_history(code, days?)` — timeline of transitions
- `get_transition_probabilities(hexagram_number)` — Markov predictions
- `run_hexagram_backtest(days?)` — accuracy report
- `explain_hexagram(number)` — full Vietnamese explanation

### FR-11: Conviction Scorer Integration
- Add kinhDich as 6th dimension (15% weight)
- queChiNhSignal + bienQueSignal + markovSignal + nguHanhHarmony
- Contradiction flag when hexagram contradicts quantitative signals

## Non-Functional Requirements

### NFR-1: Pure Domain Layer
- All Kinh Dich logic in `src/domain/services/kinhDich/` — zero I/O
- Hexagram library is static data, no database reads
- Only infrastructure touches: SQLite store for transitions + readings

### NFR-2: No Python Dependency
- Port everything to TypeScript — no Python bridge
- Hexagram data compiled into TypeScript constants
- Transition matrix uses SQLite (not numpy/pandas)

### NFR-3: Performance
- Hexagram resolution: O(1) via lookup maps
- Full reading computation: <10ms per stock
- Transition query: O(1) SQLite index lookup
