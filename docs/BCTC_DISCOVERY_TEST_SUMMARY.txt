ROOT CAUSE ANALYSIS
================================================================================

ISSUE #1: Non-existent API Endpoints
──────────────────────────────────────
The current discovery script (vps-scripts/discover-bctc-urls-browser.py) 
attempts to call HTTP API endpoints that do not exist on HOSE/HNX/UPCOM portals.

Expected Endpoint:    https://www.hsx.vn/api/bctc
Actual HTTP Response: 404 Not Found

IMPLICATION: All discovery attempts fail immediately at the first portal (HOSE),
fall back to HNX (also fails), then UPCOM (also fails), then return "No PDF found".

EVIDENCE:
  - Direct curl test returns HTTP 404
  - Portal returns HTML error page, not JSON
  - No AJAX endpoint found that matches assumed schema

ISSUE #2: Script Implementation Mismatch
──────────────────────────────────────────
The current repository contains Option B (Direct API) implementation, but:
  - Ops session (2026-04-23) documented deployment of Playwright browser automation
  - Actual script in repo: Uses aiohttp for HTTP API calls (NOT Playwright)
  - Git commit: 01880421 "feat(1289f): Implement Option B direct API discovery"
  - No Playwright dependency, no browser automation code

IMPLICATION: Either Playwright version was deployed to VPS but repo differs,
or Option B was deployed but never validated against actual portal.

ISSUE #3: Async JavaScript Rendering Not Handled
──────────────────────────────────────────────────
HOSE portal is a React SPA (Single Page Application):
  1. Initial HTTP response = HTML shell (no PDF links)
  2. JavaScript renders page in browser
  3. AJAX request fetches PDF list from backend
  4. PDF DOM elements inserted ~500-2000ms after initial load

Option B (Direct API) assumes synchronous API endpoints exist (they don't).
Option A (Playwright) handles async rendering via browser automation.
