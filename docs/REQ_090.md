## Product Vision

**Goal:** Give agents (market analyst, alert commander, Kinh Dich layer) access to classical TA signals computed on-demand from existing price history — RSI, MACD, MA stack, and Bollinger Bands — so they can cross-validate momentum, overbought/oversold, and trend direction without manual calculation.

**Scope:**
- IN: New MCP tool `get_technical_indicators(actionCode, days?)` — pure math, no new data sources
- IN: Domain service `technicalIndicators.ts` (pure functions, fully testable)
- IN: MCP handler `technicalIndicatorTools.ts`
- IN: TDD test file `NNN-technical-indicators.test.ts`
- IN: Registry update: 97 → 98 tools
- OUT: New data fetchers, new DB tables, new VPS jobs, streaming/real-time computation
- OUT: Charting, graphical output
- OUT: Automated signal firing or alert triggers (read-only tool)

**Success metric:** `get_technical_indicators("VCB")` returns RSI(14), MACD(12,26,9), MA(5/20/50), and BB(20,2σ) with a plain-text Vietnamese-friendly conclusion block. All indicator math passes unit tests against known reference values.

---

## Problem Statement

Agents currently receive only raw price arrays from `get_price_history`. When writing buy/sell analysis they cannot determine:
- Whether RSI is overbought (>70) or oversold (<30)
- Whether MACD line has crossed above/below its signal line
- Whether price sits above its key moving averages (bullish stack)
- Where price sits within the Bollinger Band range

This means agents recommending entries cannot verify whether TA confirms or contradicts the fundamental/news signal. Cross-validation with Kinh Dich Hao 3 (price/technical) is currently skipped.

## Functional Requirements

### Tool signature

```
get_technical_indicators(actionCode: string, days?: number = 60)
```

- `actionCode`: uppercase VN stock ticker (e.g. "VCB", "HPG", "FPT")
- `days`: look-back window for raw data fetch (default 60, min 35 required for MACD)

### Indicators

| Indicator | Parameters | Min candles needed |
|-----------|-----------|-------------------|
| MA | 5, 20, 50 periods | 50 |
| RSI | 14 periods | 15 |
| MACD | 12, 26, 9 (signal EMA) | 35 |
| Bollinger Bands | 20 periods, 2σ | 20 |

### Data source

Query existing `market_prices_history` table — same table used by `get_price_history`. One daily closing price per ticker per day (most recent price of each date). No new DB tables. No new VPS jobs.

### Output format

```
[VCB] Chi bao ky thuat — 2026-04-15

MA:   MA5=94,200  MA20=93,500  MA50=91,800  → Xu huong TANG (bullish stack)
RSI(14): 62.4 → Trung tinh (vung 40-70, con du room)
MACD:  Line=+180  Signal=+95  Hist=+85  → TANG (bullish crossover)
BB(20):  Upper=96,800  Mid=93,500  Lower=90,200
         Price=94,500 → 62% cua dai BB (trung binh-cao)

Ket luan: 3/4 chi bao TANG — co the xem xet MUA khi RSI < 70
```

### RSI interpretation bands

| RSI value | Label |
|-----------|-------|
| > 70 | Qua mua (overbought) |
| 40–70 | Trung tinh |
| < 40 | Qua ban (oversold) |

### MACD interpretation

- MACD Hist > 0 and rising → TANG (bullish)
- MACD Hist < 0 and falling → GIAM (bearish)
- Crossover event (sign change) → note in output

### MA stack interpretation

- Price > MA5 > MA20 > MA50 → Xu huong TANG manh
- Price < MA5 < MA20 < MA50 → Xu huong GIAM manh
- Mixed → Trung tinh / Dao dong

### BB position

Express as `(price - lower) / (upper - lower) * 100` percent of band width.

### Conclusion block

Count how many of the 4 indicators are bullish/bearish/neutral. Output plain-text verdict: TANG / GIAM / TRUNG TINH.

### Insufficient data handling

If fewer than 35 candles are available: return a clear error message stating which indicators could not be computed and how many candles were found. Do not crash.

## Architecture

```
interface/mcp/tools/technicalIndicatorTools.ts   ← MCP registration + DB query
      ↓ calls
domain/services/technicalIndicators.ts           ← pure math (MA, RSI, MACD, BB)
      ↑ tested by
src/__tests__/NNN-technical-indicators.test.ts   ← TDD, in-memory DB
```

### DB query contract

```sql
SELECT date(fetched_at) as day, AVG(price) as close_price
FROM market_prices_history
WHERE code = ?
  AND fetched_at >= datetime('now', ? || ' days')
GROUP BY date(fetched_at)
ORDER BY day ASC
```

Returns one `close_price` per calendar day, oldest → newest (required by EMA rolling calculation).
