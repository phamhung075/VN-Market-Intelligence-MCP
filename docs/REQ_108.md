# REQ-108: fix(source-health): pollNews SOURCE_DISPLAY_NAMES — eliminate pre-existing test 1227 failures

status: READY_FOR_ARCHITECT
sprint: 108
po_vision: Fix 2 test failures in 1227-source-health-empty-result.test.ts that have been failing since Sprint 104 — root cause is a key mismatch between what pollNews records and what tests/health UI checks.

## User Story

As a Vietnamese stock investor using Claude,
I want the source health dashboard to accurately reflect news fetcher status under human-readable names (e.g. "Reuters RSS"),
So that I can tell at a glance which data sources are operational without interpreting internal fetcher keys.

## Root Cause Analysis

`pollNews` iterates over `resolvedFetchers` keyed by raw fetcher keys (`"reuters"`, `"cafef"`, etc.) and calls `globalSourceTracker.recordSuccess(name)` / `recordFailure(name, ...)` using those raw keys directly.

The `globalSourceTracker` singleton (in `sourceHealthTools.ts`) is pre-seeded with display names: `"Reuters RSS"`, `"CafeF RSS"`, `"VnExpress RSS"`, `"VnEconomy RSS"`, `"Trading Economics"`. The health UI reads buckets by these display names.

Result: `pollNews` writes to the `"reuters"` bucket; the health UI (and test assertions) read from the `"Reuters RSS"` bucket. They are two separate singleton buckets — the display-name bucket never gets updated by `pollNews`, so its status remains stale from prior test state (often "degraded"). This causes 2 tests in `1227-source-health-empty-result.test.ts` to fail deterministically since Sprint 104.

## Functional Requirements

### FR-1: SOURCE_DISPLAY_NAMES constant in pollNews

- Description: Add a `const SOURCE_DISPLAY_NAMES: Record<string, string>` map immediately before the health tracking loop in `pollNews`.
- Input: Raw fetcher key string (e.g. `"reuters"`, `"cafef"`).
- Output: Display name string (e.g. `"Reuters RSS"`, `"CafeF RSS"`); falls back to raw key via `?? name` for unknown/future keys.
- Business rule: Map must cover all 5 known fetcher keys. Any key not in the map passes through unchanged (forward-compatible for future VPS sources).
- DDD layer: application

Map values:

| Raw key            | Display name            |
|--------------------|-------------------------|
| `reuters`          | `Reuters RSS`           |
| `cafef`            | `CafeF RSS`             |
| `vnexpress`        | `VnExpress RSS`         |
| `vneconomy`        | `VnEconomy RSS`         |
| `tradingeconomics` | `Trading Economics RSS` |

Note: `sourceHealthTools.ts` seeds `"Trading Economics"` (no "RSS") but the SPRINT_GOAL.md spec uses `"Trading Economics RSS"`. The display name used in `SOURCE_DISPLAY_NAMES` must exactly match the string used in `seedKnownSources`. Verify before coding — see Blockers.

### FR-2: Use display name in all health-tracking call sites

- Description: Replace the bare `name` variable with `SOURCE_DISPLAY_NAMES[name] ?? name` at every `globalSourceTracker` call in the health tracking loop.
- Input: `name` (raw fetcher key) from `sourceResults` iteration.
- Output: Health events recorded under display name, not raw key.
- Business rule: Three call sites must all be updated — `recordSuccess`, `recordFailure` (empty-result path), `recordFailure` (exception path).
- DDD layer: application

Call sites (lines 455, 464, 472 of `pollNews.ts` as of Sprint 107):

| Line (approx) | Current call                              | Fixed call                                                       |
|---------------|-------------------------------------------|------------------------------------------------------------------|
| 455           | `globalSourceTracker.recordSuccess(name)` | `globalSourceTracker.recordSuccess(SOURCE_DISPLAY_NAMES[name] ?? name)` |
| 464           | `globalSourceTracker.recordFailure(name, "empty result...")` | `globalSourceTracker.recordFailure(SOURCE_DISPLAY_NAMES[name] ?? name, "empty result...")` |
| 472           | `globalSourceTracker.recordFailure(name, errorMsg)` | `globalSourceTracker.recordFailure(SOURCE_DISPLAY_NAMES[name] ?? name, errorMsg)` |

## Non-Functional Requirements

- Performance: No additional I/O — the `SOURCE_DISPLAY_NAMES` lookup is an in-memory `Record` access, O(1).
- Data freshness: No impact — health tracking is in-process singleton state.
- Language: Display names are English (matching existing `seedKnownSources` strings).
- Test isolation: `globalSourceTracker` is a module-level singleton. Tests must reset state between cases using `globalSourceTracker` reset or fresh tracker injection. The existing `1227` tests already demonstrate the pattern — follow it.

## Edge Cases & Data Quality

- [ ] Unknown future VPS fetcher key (e.g. `"vietstock"`) — `?? name` fallback ensures it passes through unchanged and does not break health tracking.
- [ ] `"tradingeconomics"` display name mismatch — `sourceHealthTools.ts` seeds `"Trading Economics"` (no "RSS suffix"); `SPRINT_GOAL.md` specifies `"Trading Economics RSS"`. Exactly one of these is authoritative. If they differ, a new bucket will be created rather than updating the seeded one. Must be resolved before coding (see Blockers).
- [ ] Singleton state leakage between tests — `1227` tests use `failuresBefore` snapshots + delta assertions. New `1332` tests must use the same defensive pattern.
- [ ] `pollNews` called with a fetcher key not in `resolvedFetchers` known-keys set — already handled by the `knownKeys` guard upstream of the health loop; no change required.
