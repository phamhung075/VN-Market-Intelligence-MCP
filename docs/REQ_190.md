# REQ-190: feat(ohlcv-foreign-flow) — add foreign buy/sell/net/put-through vol to daily_ohlcv + evening summary

status: READY_FOR_ARCHITECT
sprint: 190
po_vision: Surface foreign investor flow inside daily_ohlcv and evening digest — VPS already pushes data, columns are missing.

## User Story

As a Vietnamese stock investor using Claude,
I want to see which stocks foreigners are net-buying or net-selling each day (top 5 movers by |net_vol|) in my evening summary,
So that I can act on a key VN market signal (foreign flow direction) that is currently siloed and invisible.

## Context

`vn-foreign-flow.service` on Vinahost VPS pushes `{ code, foreignBuyVol, foreignSellVol, foreignRoom }` every 60s via `POST /push-foreign-flow`.
Current endpoint maps payload → `ForeignFlowUpsertItem` and writes to `vnstock_trading_stats` only.
`daily_ohlcv` has no foreign flow columns; cascade engine and evening digest cannot see the data.
Sprint 189 fixed the parse error (tasks 1491/1492) so the payload is now correct.

## Functional Requirements

### FR-1: daily_ohlcv schema — +4 columns + idempotent migration

- **Description:** Add 4 new nullable REAL columns to `daily_ohlcv`.
- **Columns:**

  | Column | Type | Default | Meaning |
  |--------|------|---------|---------|
  | `foreign_buy_vol` | REAL | NULL | Foreign buy volume (shares) for the day |
  | `foreign_sell_vol` | REAL | NULL | Foreign sell volume (shares) for the day |
  | `foreign_net_vol` | REAL | NULL | `foreign_buy_vol - foreign_sell_vol` (computed at write time, stored) |
  | `put_through_vol` | REAL | NULL | Put-through/negotiated trade volume |

- **Migration:** For existing DBs (production + test), run 4 idempotent `ALTER TABLE daily_ohlcv ADD COLUMN IF NOT EXISTS ...` statements immediately after the `CREATE TABLE IF NOT EXISTS daily_ohlcv` block in `initDatabase()`.
- **Fresh DBs:** 4 columns present in `CREATE TABLE` DDL.
- **Backward compat:** All 4 columns nullable; existing OHLCV rows unaffected.
- **DDD layer:** infrastructure
- **File:** `src/infrastructure/db/schema.ts:1109-1121`

### FR-2: push-foreign-flow endpoint — write 4 cols to daily_ohlcv

- **Description:** Extend the `push-foreign-flow` request handler to also write the 4 new columns to `daily_ohlcv` for the matching `(code, date)` row.
- **Input fields from VPS payload (camelCase):**

  | Payload field | Mapped to |
  |---------------|-----------|
  | `foreignBuyVol` | `foreign_buy_vol` |
  | `foreignSellVol` | `foreign_sell_vol` |
  | computed: `foreignBuyVol - foreignSellVol` | `foreign_net_vol` |
  | `putThroughVol` (optional, 0 if absent) | `put_through_vol` |

- **Write strategy:** `ON CONFLICT(code, date) DO UPDATE SET` — update only the 4 new columns; never touch `open`, `high`, `low`, `close`, `volume`, `updated_at`.
- **Idempotent:** Re-pushing the same payload for the same `(code, date)` overwrites with identical values; no duplicate rows.
- **No daily_ohlcv row yet:** If `(code, date)` does not exist in `daily_ohlcv` (VPS push arrives before price push), insert a stub row with `open=0, high=0, low=0, close=0, volume=0` plus the 4 foreign cols. Price columns are filled later by the price push upsert. Alternatively, skip if no OHLCV row exists (simpler; accepted trade-off: foreign data silently lost if price not yet pushed). **Decision: skip (do not insert stub) — foreign flow without price context is misleading. Write only when `(code, date)` already exists in `daily_ohlcv`.**
- **DDD layer:** infrastructure (store function) + interface (endpoint wiring)
- **Files:**
  - `src/infrastructure/db/vnstockStore.ts:373` — new function `writeForeignFlowToOhlcv(items, db?)`
  - `src/interface/mcp/server.ts:691-703` — call `writeForeignFlowToOhlcv` after `upsertForeignFlow`

### FR-3: assembleEveningSummary — foreignFlowMovers field

- **Description:** Add `foreignFlowMovers` section to `EveningSummary` — top 5 stocks by `|foreign_net_vol|` for the latest trading day in `daily_ohlcv`.
- **Interface extension:**
  ```typescript
  export interface ForeignFlowMover {
    code: string;
    foreignNetVol: number;   // positive = net buy, negative = net sell
    foreignBuyVol: number;
    foreignSellVol: number;
  }
  // In EveningSummary:
  foreignFlowMovers: ForeignFlowMover[];
  ```
- **Query:** `SELECT code, foreign_net_vol, foreign_buy_vol, foreign_sell_vol FROM daily_ohlcv WHERE date = (SELECT MAX(date) FROM daily_ohlcv) AND foreign_net_vol IS NOT NULL ORDER BY ABS(foreign_net_vol) DESC LIMIT 5`
- **Empty case:** When no rows have `foreign_net_vol IS NOT NULL`, return `foreignFlowMovers: []` (no crash, no warning).
- **DDD layer:** application
- **File:** `src/application/usecases/assembleEveningSummary.ts:79` (interface) + `assembleEveningSummary.ts:474-504` area (query block)

### FR-4: eveningSummaryJob.ts — Telegram formatter for foreignFlowMovers

- **Description:** Add `foreignFlowMovers` section to evening Telegram message, after the existing `watchlistMovers` / `formatMoversSection` block and before TA signals.
- **Format:** Vietnamese, vol in thousands (÷1000, suffix "k"). Positive = mua ròng, negative = bán ròng.
  ```
  Khối ngoại (5 cp):
    FPT: mua ròng +12.350k (B:15.000k / S:2.650k)
    VHM: bán ròng -8.200k (B:1.100k / S:9.300k)
    ...
  ```
- **Omit:** Section skipped (no blank line) when `foreignFlowMovers` is empty.
- **hasContent guard:** `foreignFlowMovers.length > 0` must count toward `hasContent` (so a day with only foreign flow data still triggers a send).
- **DDD layer:** interface/scheduler
- **File:** `src/scheduler/eveningSummaryJob.ts`

## Non-Functional Requirements

- **Performance:** `writeForeignFlowToOhlcv` runs inside existing transaction; no extra round-trips.
- **Data freshness:** Columns updated every 60s when VPS push fires; evening query uses `MAX(date)` to always use latest trading day.
- **Language:** Telegram section header in Vietnamese: "Khối ngoại".
- **Type safety:** `ForeignFlowMover` interface exported from `assembleEveningSummary.ts`; `AssembleEveningSummaryOptions` gains optional `getForeignFlowMoversFn` injectable for tests.
- **Test baseline:** 5681 pass. Sprint target: same baseline + 5 new assertions GREEN. `bun tsc --noEmit` clean.

---

## Edge Cases & Data Quality

- [ ] `putThroughVol` absent from payload → default 0 (not null)
- [ ] `foreignBuyVol` or `foreignSellVol` is 0 → `foreign_net_vol = 0 - 0 = 0`; row still written
- [ ] No OHLCV row for `(code, date)` → skip silently (FR-2 decision)
- [ ] All 5 top movers have `foreign_net_vol = 0` → section still rendered (valid signal: no net flow)
- [ ] `foreign_net_vol IS NULL` for all rows → `foreignFlowMovers: []`, section omitted from Telegram
- [ ] ALTER on fresh DB (column already in CREATE TABLE) → `ADD COLUMN IF NOT EXISTS` is no-op on SQLite 3.37+; safe
- [ ] Existing `daily_ohlcv` rows (thousands) unaffected by ALTER — NULL default, no rewrite

## Acceptance Criteria

### AC-1: Schema migration

**Given** an existing `market.db` with `daily_ohlcv` created without the 4 new columns
**When** `initDatabase()` runs
**Then**
- `PRAGMA table_info(daily_ohlcv)` returns rows with `name` in `['foreign_buy_vol','foreign_sell_vol','foreign_net_vol','put_through_vol']`
- Existing data rows untouched

### AC-2: writeForeignFlowToOhlcv — update-only semantics

**Given** a DB with a `daily_ohlcv` row for `(VCB, 2026-04-20)` and no row for `(FPT, 2026-04-20)`
**When** `writeForeignFlowToOhlcv([{code:'VCB',date:'2026-04-20',foreignBuyVol:5000,foreignSellVol:2000,putThroughVol:300}, {code:'FPT',date:'2026-04-20',foreignBuyVol:1000,foreignSellVol:500,putThroughVol:0}])` is called
**Then**
- VCB row: `foreign_buy_vol=5000`, `foreign_sell_vol=2000`, `foreign_net_vol=3000`, `put_through_vol=300`; `open/high/low/close/volume` unchanged
- FPT: no row inserted (update-only)

### AC-3: push-foreign-flow endpoint writes to daily_ohlcv

**Given** a `daily_ohlcv` row for `(FPT, today)` exists
**When** `POST /push-foreign-flow` receives `[{code:'FPT',foreignBuyVol:15000,foreignSellVol:2650,putThroughVol:500}]`
**Then**
- `daily_ohlcv` row for FPT has `foreign_buy_vol=15000`, `foreign_sell_vol=2650`, `foreign_net_vol=12350`, `put_through_vol=500`
- `vnstock_trading_stats` row also updated (existing behavior unchanged)

### AC-4: assembleEveningSummary — foreignFlowMovers populated

**Given** `daily_ohlcv` has 6 rows for today with non-null `foreign_net_vol` (values: 12350, -8200, 5000, -1000, 3000, 500)
**When** `assembleEveningSummary()` runs
**Then**
- `foreignFlowMovers.length === 5`
- Order: `|12350| > |8200| > |5000| > |3000| > |1000|`
- Row with `foreign_net_vol = null` excluded

### AC-5: Telegram message format

**Given** `foreignFlowMovers = [{code:'FPT', foreignNetVol:12350, foreignBuyVol:15000, foreignSellVol:2650}]`
**When** `runEveningSummary` formats the message
**Then**
- Message contains "Khối ngoại"
- Message contains "FPT"
- Message contains "mua ròng" (positive net)
- Message contains volume formatted with "k" suffix (12.350k or similar)
