## User Story

## Functional Requirements

### FR-1: Skip live-fetch test in 296-ocr-pipeline-e2e.test.ts

- Description: The first `it()` block in the describe suite calls `extractAndStorePdfPages`, which triggers a live HTTP fetch to `congbothongtin.ssc.gov.vn` — a geo-blocked endpoint from France. The test has an explicit 30s timeout. It cannot pass without VPS proxy routing. Convert the `it(...)` call to `test.skip(...)` with an explanatory comment.
- Input: `src/__tests__/296-ocr-pipeline-e2e.test.ts` line 68–102 (the `it("extracts VNM PDF via OCR...")` block)
- Output: Same block annotated as `test.skip(...)`, suite shows SKIP not FAIL/TIMEOUT for that case
- Business rule: The skip comment must state: `geo-blocked from France — requires VPS proxy, run manually on VPS`
- DDD layer: interface (test file only — no production code touched)

### FR-2: Verify remaining tests in the file still run

- Description: Tests 2, 3, 4 in the describe block use fully stubbed deps and no live network calls. They must remain as `it(...)` (not skipped). The diagnostic test (line 177) must also remain.
- Input: Tests at lines 109–175 (`reparseSingleWithOcrFallback` stubs) + line 177 diagnostic
- Output: 3 stubbed tests pass, 1 diagnostic test passes, 1 live test skipped
- Business rule: Never skip a test that can pass without network access
- DDD layer: interface (test file only)

### FR-3: Full suite reaches 0 failures

- Description: After the skip annotation, `bun test` full suite must report 0 failures. Prior baseline (Sprint 133): 5010 pass, 20 skip, 1 fail. Target: 5010 pass, 21 skip, 0 fail.
- Input: Full test suite
- Output: Exit code 0, no timeout line for test 296
- Business rule: `bun tsc --noEmit` must remain clean (no type changes needed — `test.skip` is a Bun built-in)
- DDD layer: interface
