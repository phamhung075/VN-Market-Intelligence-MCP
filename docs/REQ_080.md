## Functional Requirements

### FR-1: Fix sentiment polarity inversion in `sentimentClassifier.ts` (Task 1197)

- **Description:** `classifySentiment()` returns BEARISH for bullish-dominant headlines.
  The JSDoc comment on the function states the decision threshold as
  "bullishScore >= bearishScore + 2 → bullish" but the implementation code
  at line 397 uses `bullishScore > bearishScore` (margin of 0). When a
  headline contains one low-weight bullish keyword (e.g. "tăng", weight=1)
  alongside one low-weight bearish keyword (e.g. "giảm", weight=1), the
  scores tie at 1 vs 1 → neutral. When one side leads by 1, it wins — which
  is correct. The observed inversion is a different scenario: articles about
  interest-rate cooling ("lãi suất hạ nhiệt") contain the word "giảm"
  (weight 1, bearish) in "lãi suất giảm" which scores correctly as bearish
  at the macro level, but the same word also appears in bullish phrases
  ("giảm lãi suất" = rate cut = bullish for real estate). Because the
  classifier uses substring match without phrase-boundary awareness for the
  single-word keyword "giảm", it double-counts: "giảm lãi suất" triggers
  "giảm" (bearish, weight 1) AND "lãi suất giảm" (bearish, weight 1) for
  a total bearishScore of 2, while "phục hồi" or "tích cực" scores bullish
  2 — a tie → neutral, not bullish. In practice the inversion is worse:
  multi-keyword bearish phrases ("giảm mạnh", weight 2) that share the
  substring "giảm" cause double-scoring.
- **Root cause:** The `findOccurrences()` function does not suppress shorter
  phrase matches when a longer overlapping phrase has already matched at
  the same position. ALL_BULLISH and ALL_BEARISH are sorted longest-first,
  but a shorter phrase that starts at a different character offset within
  the longer phrase's span still fires independently.
  Concrete example: text = "lãi suất giảm mạnh"
    - "giảm mạnh" (bearish, weight 2) fires at idx=10
    - "giảm" (bearish, weight 1) fires at idx=10 as well (same start position)
  Both are counted → bearishScore = 3, not 2.
- **Fix:** In `classifySentiment()`, after finding all occurrences for a
  keyword, skip occurrences whose `[start, end]` span is already covered by
  a previously matched (longer) keyword of the same polarity. Maintain a
  covered-ranges list per polarity (bullish and bearish separately) and skip
  any occurrence whose start falls within a covered range.
- **Input:** Free-text financial article summary (Vietnamese / English).
- **Output:** `SentimentResult` with correct `direction` and `confidence`.
- **Business rule:** No single-character substring of a longer matched phrase
  should contribute independently to the score.
- **DDD layer:** domain

### FR-2: Fix interest-rate cooling seed sentiment (Task 1212)

- **Description:** Headlines of the form "lãi suất hạ nhiệt" ("interest rates
  cooling") are classified as NEUTRAL or BEARISH by `classifySentiment()`,
  causing the cascade seed entry to inherit the wrong sentiment. The
  downstream domain entries then apply the sentiment-alignment penalty
  (`-0.10` at line 1861 of `cascadeEngine.ts`) because the real-estate rule
  `direction: "up"` contradicts a BEARISH seed — suppressing a genuine
  bullish signal.
- **Root cause (direct):** The phrase "hạ nhiệt" does not appear in
  `VN_BULLISH`. The classifier sees no bullish keywords and only the
  substring "giảm" from any co-occurring phrase, producing neutral or
  slightly bearish.
- **Root cause (indirect):** Once FR-1 is fixed, double-counting is eliminated
  and "lãi suất giảm" produces a correct bearishScore = 1 for "giảm" only.
  However "hạ nhiệt" still contributes nothing bullish — so for a headline
  that reads "lãi suất hạ nhiệt, ngân hàng nhà nước giữ lãi suất ổn định"
  the result remains neutral at best.
- **Fix:**
  1. Add "hạ nhiệt lãi suất" (weight 2) and "lãi suất hạ nhiệt" (weight 2)
     to `VN_BULLISH` in `sentimentClassifier.ts`. These phrases uniquely
     describe a dovish monetary environment — bullish for banking and real
     estate.
  2. Add "interest rate cooling" (weight 2) and "rates cooling" (weight 1)
     to `EN_BULLISH`.
- **Depends on:** FR-1 must be implemented first — the double-counting fix
  changes score baselines. The new keywords must be validated against the
  corrected scoring engine.
- **Input:** Free-text summary containing "lãi suất hạ nhiệt".
- **Output:** `direction: "bullish"`, `confidence >= 0.6`.
- **Business rule:** A monetary easing / rate-cooling headline must never
  classify as BEARISH or NEUTRAL when no genuinely bearish keywords
  co-occur.
- **DDD layer:** domain

### FR-3: Fix VND currency false positive in `detectStocksInText` (Task 1198)

- **Description:** Articles that mention "VND" as Vietnamese currency (e.g.
  "tỷ giá USD/VND", "1.000 tỷ VND") cause `extractStockTickers()` in
  `newsNormalizer.ts` to add the ticker VND (VNDirect Securities) to the
  article's `affectedActions` list. Downstream, the cascade engine and
  alert generator raise a signal for VNDirect on every USD/VND exchange-rate
  article.
- **Root cause:** `extractStockTickers()` uses a simple word-boundary regex
  `\b([A-Za-z]{2,5})\b` with case-insensitive matching against
  `KNOWN_VN_STOCKS`. The set `KNOWN_VN_STOCKS` contains "VND". The regex
  matches the ISO 4217 currency code "VND" that appears in almost every
  macro/forex article. No context filter exists to distinguish the currency
  abbreviation from the ticker.
- **Fix:** Add a currency-context exclusion guard inside `extractStockTickers()`.
  After a candidate match of "VND", inspect the surrounding 40-character
  window (before + after the match position). If the window contains any of
  the following currency-context signals, discard the match:
    - "USD/VND", "vnd/usd", "tỷ giá", "exchange rate", "đồng/usd",
      "billion vnd", "tỷ vnd", "nghìn tỷ vnd", "triệu vnd",
      "tỷ đồng", "nghìn tỷ đồng", "mệnh giá", "currency",
      "/vnd", "vnd/"
  Apply the same guard pattern to other ambiguous 3-letter codes that could
  collide with common abbreviations (currently only VND is a confirmed
  false-positive, but the guard mechanism should be extensible via a
  `CURRENCY_CONTEXT_MAP: Map<string, string[]>` constant).
- **Input:** Article text containing "USD/VND tăng 150 điểm".
- **Output:** `extractStockTickers()` returns [] for VND when currency context
  is detected.
- **Business rule:** A ticker match is valid only if the token is not
  immediately surrounded by currency-context tokens.
- **DDD layer:** domain

### FR-4: Fix keyword false matches for sector routing (Task 1206)

- **Description:** Two confirmed false matches cause wrong sector routing:
  1. "đất vàng" (prime land / golden land) is not in the construction or
     real-estate keyword list, yet articles about prime urban land are
     sometimes routed incorrectly because "vàng" (gold) alone triggers the
     `gold_mining` rule (if such a single-word keyword exists) or fails to
     trigger `real_estate` at all, causing the article to be dropped from
     the cascade.
  2. "cầu" (bridge) appears in the CAPEX/infrastructure rule at line 1438:
     `keywords: [..., "cầu", ...]`. The Vietnamese word "cầu" also appears
     inside the common word "toàn cầu" (global) and "nhu cầu" (demand). Any
     article mentioning "nhu cầu thép tăng" (steel demand up) or "toàn cầu"
     (global) incorrectly fires the construction sector rule because the
     keyword match in `findKeyword()` uses `text.includes(kw)` — a pure
     substring check with no word-boundary enforcement.
- **Root cause:** `findKeyword()` at line 480 of `newsNormalizer.ts` and the
  parallel `findKeyword()` inside `cascadeEngine.ts`'s SECTOR_RULES loop
  both use `text.includes(kw)` — no word boundary, no context filter.
  Single-word Vietnamese keywords are particularly dangerous because the
  language is syllable-based: a standalone syllable "cầu" is a valid
  sub-token of compound words "nhu cầu" and "toàn cầu".
- **Fix (two-part):**
  Part A — "cầu" in CAPEX rule:
    Replace the bare "cầu" keyword in the SECTOR_RULES CAPEX entry
    (line 1438 of `cascadeEngine.ts`) with the more specific phrases:
    "xây cầu", "cầu đường bộ", "cầu vượt", "cầu cao tốc".
    Remove bare "cầu" from the list.
  Part B — "đất vàng" in real-estate routing:
    Add "đất vàng" (weight = direct phrase match, confidence 0.75) to the
    real-estate up-direction SECTOR_RULE under a new or existing real-estate
    keyword group. Also add "quỹ đất vàng", "vị trí đất vàng".
    Verify that no gold_mining rule contains a bare "vàng" keyword (it
    should not — the existing gold rules use "giá vàng", "vàng thế giới",
    etc.).
- **Input (regression A):** Text "nhu cầu thép toàn cầu tăng mạnh" must NOT
  trigger construction rule.
- **Input (regression B):** Text "dự án đất vàng trung tâm TP.HCM" MUST
  trigger real-estate rule.
- **DDD layer:** domain

## Non-Functional Requirements

- **Performance:** All four changes are pure in-memory keyword/regex operations.
  No measurable latency regression expected. `findOccurrences()` covered-range
  tracking adds O(n × m) comparisons where n = keywords, m = matches per
  keyword; for typical article lengths (300–600 chars) this is < 1 ms.
- **Language:** Vietnamese primary, English secondary (both classifier and
  sector rules must be verified).
- **Correctness bar:** After all four fixes, the existing test suite must remain
  green. New tests must cover every root-cause scenario described above.

## Edge Cases & Data Quality

- [ ] "giảm" substring inside "không giảm" — negation handler already flips it;
      covered-range guard must not interfere with negation logic (negation
      operates at the token level before scoring, covered-range operates after).
- [ ] Article containing both "lãi suất hạ nhiệt" AND "lo ngại lạm phát" —
      bullish and bearish co-occur; result should be neutral or slight bullish
      depending on weight balance.
- [ ] VND ticker legitimately mentioned: "VNDirect (VND) công bố lợi nhuận tăng"
      — the parenthetical match pattern fires first (Pattern 1 in
      `extractStockTickers`); the currency-context guard must NOT suppress
      parenthetical matches, only standalone word-boundary matches (Pattern 2).
- [ ] "cầu đường" (road bridge, legitimate construction keyword) must still
      trigger the construction rule — "xây cầu" and "cầu đường bộ" cover this.
- [ ] "toàn cầu hóa" (globalisation) — "cầu" is sub-token; after fix, must NOT
      trigger construction.
- [ ] "nhu cầu tiêu dùng" — same sub-token scenario; after fix, must NOT trigger
      construction.

## Acceptance Criteria

### AC-1: Sentiment inversion fixed (FR-1)

**Given** text = "lãi suất giảm mạnh, kinh tế phục hồi mạnh mẽ"
**When** `classifySentiment(text)` is called
**Then**
- `bearishScore` counts "giảm mạnh" (weight 2) only once — not also "giảm" (weight 1) at the same position.
- `bullishScore` counts "phục hồi" (weight 2).
- `direction` is "neutral" (2 vs 2 tie) or "bullish" if other bullish words are present.
- The function does NOT return "bearish" for this input.

### AC-2: No overlapping match double-counting (FR-1)

**Given** text = "thị trường giảm mạnh"
**When** `classifySentiment(text)` is called
**Then**
- "giảm mạnh" (weight 2) is matched and its range [idx, idx+9] is marked covered.
- "giảm" (weight 1) at the same position is skipped (covered).
- `bearishScore` = 2, not 3.

### AC-3: Interest rate cooling classified bullish (FR-2)

**Given** text = "lãi suất hạ nhiệt, NHNN giữ nguyên lãi suất điều hành"
**When** `classifySentiment(text)` is called
**Then**
- `direction` = "bullish"
- `confidence` >= 0.55
- "hạ nhiệt lãi suất" or "lãi suất hạ nhiệt" appears in `keywords`

### AC-4: Interest rate cooling cascade sentiment correct (FR-2)

**Given** a seed `AnalysisEntry` with summary = "lãi suất hạ nhiệt, tích cực cho thị trường"
**When** `buildCausalChain()` produces domain entries
**Then**
- The real-estate domain entry has `sentiment = "bullish"` (not "bearish")
- The banking domain entry has `confidence >= 0.60`
- No sentiment-contradiction penalty (`-0.10`) is applied to these entries

### AC-5: VND currency false positive suppressed (FR-3)

**Given** text = "tỷ giá USD/VND tăng 150 điểm lên 25.450"
**When** `extractStockTickers(text)` is called
**Then**
- Returns [] or a list that does NOT contain "VND"

### AC-6: VNDirect ticker still detected when named explicitly (FR-3)

**Given** text = "VNDirect (VND) công bố lợi nhuận quý 1 tăng 45%"
**When** `extractStockTickers(text)` is called
**Then**
- Returns a list containing "VND" (matched via parenthetical Pattern 1, which is not subject to the currency-context guard)

### AC-7: "cầu" in "toàn cầu" does not trigger construction (FR-4)

**Given** text = "nhu cầu thép toàn cầu tăng mạnh theo đà phục hồi kinh tế"
**When** `buildCausalChain()` processes this text
**Then**
- The `construction` domain entry is NOT created for this seed
- The `steel` domain entry IS created (keyword "thép" still matches)

### AC-8: "đất vàng" routes to real estate (FR-4)

**Given** text = "dự án đất vàng trung tâm TP.HCM ra mắt"
**When** `buildCausalChain()` processes this text
**Then**
- A `real_estate` domain entry is created with `direction = "up"`
- No `gold_mining` entry is created

### AC-9: Legitimate bridge/CAPEX keywords still route to construction (FR-4)

**Given** text = "dự án xây cầu vượt cao tốc Bắc-Nam được giải ngân"
**When** `buildCausalChain()` processes this text
**Then**
- A `construction` domain entry is created with `direction = "up"`
