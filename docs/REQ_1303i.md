# REQ-1303i: Cascade Rule Gaps — Geo/BCTC-Overdue/Trade-Map

status: READY_FOR_ARCHITECT
sprint: 1303
po_vision: Close three silent cascade gaps so geopolitical events, BCTC overdue alerts, and export-sector news produce correct downstream watchlist impacts.

---

## User Story

As a Vietnamese stock investor using Claude,
I want cascade chains to fire correctly for Taiwan/Hormuz geo events, BCTC overdue filings, and pharma/logistics/construction/steel trade exposure,
So that I receive actionable watchlist alerts — not silent no-ops — when these events occur.

---

## Gap Analysis (Root Cause)

| Gap | Root Cause | Effect |
|-----|-----------|--------|
| G1: Geo routing | `cascadeEngine.ts` has Hormuz supply-shock rules but **no Taiwan/semiconductor rules**; `COUNTRY_KEYWORDS` missing `taiwan` entry; `tradeRelationships.ts` has no pharma/logistics/construction/steel export profiles | Taiwan strait news → 0 watchlist impacts |
| G2: BCTC overdue chain | `bctcOverdueCheckJob.ts` inserts alert to DB then returns — **never calls `runImpactChain`**; alert commander picks up signal but cascade chain is absent | `bctc_overdue` alert dispatched without causal chain |
| G3: Trade map coverage | `TRADE_PROFILES` in `tradeRelationships.ts` covers 5 tickers (VNM/FPT/VCB/HPG/VEA); `COUNTRY_KEYWORDS` has no `taiwan` entry; 4 sectors have no export exposure seeds | `analyzeTradeImpact()` returns `[]` for pharma/logistics/construction/steel tickers |

## Functional Requirements

### FR-1: Taiwan geo keyword routing in cascadeEngine

- **Description:** Add Taiwan-specific `SectorRule` entries to `SECTOR_RULES` in `cascadeEngine.ts`. Taiwan strait tension → semiconductor/tech (FPT, supply chain disruption), retail (consumer electronics cost), securities (risk-off). Taiwan de-escalation → reverse.
- **Input:** News text containing `"taiwan"`, `"taiwan strait"`, `"đài loan"`, `"eo biển đài loan"`
- **Output:** `CausalChain` with domain-level entries for `tech`, `retail`, `securities` (escalation) or reversed (de-escalation)
- **Business rules:**
  - Escalation rules placed AFTER de-escalation block (first-match-wins, consistent with existing geo pattern at line ~1337)
  - Confidence: escalation `tech` = 0.80, `securities` = 0.75, `retail` = 0.68 (mirrors Hormuz confidence tiers)
  - Must add `taiwan` key to `COUNTRY_KEYWORDS` in `tradeRelationships.ts` with keywords: `["taiwan", "taiwanese", "đài loan", "taipei", "tsmc", "taiwan strait", "eo biển đài loan"]`
- **DDD layer:** domain

### FR-2: Taiwan semiconductor → trade map lookup in tradeRelationships

- **Description:** `analyzeTradeImpact()` must detect `taiwan` country from news text and route to `tech`-domain watchlist stocks. Add `taiwan` to `COUNTRY_KEYWORDS` (required by `detectCountries()`). Add `STOCK_RELEVANCE_KEYWORDS` entries for any tech/semiconductor stocks in watchlist.
- **Input:** `analyzeTradeImpact(text, watchlistCodes)` where text mentions Taiwan
- **Output:** Impacts array for tech-domain stocks with `country: "taiwan"`, `revenuePct` from their profile
- **Business rule:** FPT already has no `taiwan` exposure in `TRADE_PROFILES` — the route here is via the **cascade sector rule** (FR-1), not via `analyzeTradeImpact`. `analyzeTradeImpact` handles the direct trade-exposure path. Both paths must work independently.
- **DDD layer:** domain

### FR-3: BCTC overdue → runImpactChain trigger

- **Description:** After `bctcOverdueCheckJob` inserts batch overdue alert, call `runImpactChain` for each overdue ticker to produce a cascade chain stored in `analyses` table.
- **Input:** `overdueTickers` array (already assembled at line ~224 of `bctcOverdueCheckJob.ts`)
- **Output:** One `CausalChain` per overdue ticker written to DB via existing persistence path. Chain seed: `"BCTC overdue: <CODE> Q<N>-<YEAR> — statutory filing deadline missed by <N> days"`
- **Business rules:**
  - Call `runImpactChain` AFTER the batch alert insert (fire-and-forget, non-blocking — `void promise`)
  - Import path: `runImpactChain` lives in `src/application/usecases/runImpactChain.ts`. Scheduler layer may import application layer (layer order: domain ← application ← interface ← scheduler).
  - Watchlist passed from already-loaded `watchlist` rows (already in scope at line ~142)
  - If `runImpactChain` throws, log warn and continue — do NOT break alert insertion
  - Seed news text format: `"BCTC filing overdue: ${code} has not filed Q${quarter}-${year} BCTC. Deadline was ${deadline.toISOString().slice(0,10)}, ${daysOverdue} days ago. Impact: governance risk, potential earnings uncertainty."`
- **DDD layer:** scheduler (trigger) → application (runImpactChain) → domain (cascadeEngine)

### FR-4: Trade exposure seeds — 4 missing sectors

- **Description:** Add seed `StockTradeProfile` entries to `TRADE_PROFILES` in `tradeRelationships.ts` for representative tickers across 4 uncovered sectors.
- **Sectors and seed data:**

| Sector | Representative Ticker | Key Trade Exposure |
|--------|----------------------|-------------------|
| pharma | DHG (Dược Hậu Giang) | Import: API/raw materials from China (~40% cost), India (~20% cost); domestic revenue 85% |
| logistics | GMD (Gemadept) | Export: regional sea freight ASEAN 25%, China port calls 15%; import: equipment from Korea/Japan |
| construction | CTD (Coteccons) | Domestic 90%; import: steel/machinery from China 8%, Korea 2% |
| steel | HPG already exists — add: NKG (Nam Kim Steel) | Export: ASEAN 20%, EU 10%; import: HRC coil from China 35%, Taiwan 15% |

- **Business rule:** These are SEED data only (documented in file header). SQLite is SSOT after first run. Seeds initialize the `trade_exposures` table.
- **Note on DomainType:** `bctc-schema.ts` has BOTH `'pharma'` (legacy alias) and `'pharmaceutical'` (sprint 044). `tradeRelationships.ts` `StockTradeProfile` does not carry a domain field — it uses `market` (country). No type conflict. `SECTOR_RULES` in cascadeEngine uses both `"pharma"` and `"pharmaceutical"` as separate entries — leave as-is, do not unify (separate task).
- **DDD layer:** domain

## Non-Functional Requirements

- Performance: `runImpactChain` call in FR-3 is fire-and-forget (`void`) — must NOT add latency to `runBctcOverdueCheck` return
- No new DB schema changes — uses existing `analyses` + `alerts` tables
- TypeScript strict: no `any` casts, parameterized SQL only
- DDD: scheduler (`bctcOverdueCheckJob.ts`) may import application layer — already precedented in `intelligenceCycleJob.ts`

---

## Edge Cases & Data Quality

- [ ] `runImpactChain` called with overdue ticker not in watchlist — watchlist rows already loaded in scope, pass full watchlist
- [ ] Taiwan news also mentions Hormuz in same article — both rule sets fire independently (correct by design, first-match-wins per domain)
- [ ] `overdueTickers` empty after batch — FR-3 call wrapped in `if (overdueTickers.length > 0)` block (already exists)
- [ ] NKG added to TRADE_PROFILES but not in user's watchlist — `analyzeTradeImpact` filters by `watchlistCodes` param, no impact
- [ ] `"pharma"` vs `"pharmaceutical"` DomainType — `SECTOR_RULES` already has both; `tradeRelationships.ts` profiles use `market` (country string), not domain — no collision

## Acceptance Criteria

### AC-1: Taiwan geo → cascade chain (RED test first)

**Given** news text `"Taiwan strait military exercises escalate — TSMC warns supply chain disruption"`
**When** `buildCausalChain(seedEntry, watchlist, [], nullMacro, [], 6)` is called
**Then**
- Chain contains domain-level entry with `affectedDomains` including `"tech"`
- Entry `direction` = `"down"` (escalation = supply disruption risk)
- At least one `MatchedRule` with `sector: "tech"` and keyword matching `"taiwan"`

### AC-2: BCTC overdue → runImpactChain called (RED test first)

**Given** `runBctcOverdueCheck` runs with mock DB having 2 overdue stocks (VCB, HPG) past deadline
**When** `overdueTickers.length > 0` branch executes
**Then**
- `runImpactChain` is called once per overdue ticker (spy/mock verification)
- Call is non-blocking (does not await before returning `RunResult`)
- If `runImpactChain` rejects, `RunResult` is still returned normally (no throw propagation)

### AC-3: Trade map complete — 4 sectors covered (RED test first)

**Given** `analyzeTradeImpact(text, ["DHG", "GMD", "CTD", "NKG"])` with text mentioning `"china"` (DHG imports API from China)
**When** function executes
**Then**
- Returns non-empty array (at least DHG with `country: "china"`)
- `detectCountries(text)` returns `["china"]` for this input
- `getTradeProfile("DHG")` returns non-null `StockTradeProfile`

### AC-4: Taiwan in COUNTRY_KEYWORDS

**Given** text `"tsmc taiwan strait tensions escalate"`
**When** `detectCountries(text)` called
**Then** returns array containing `"taiwan"`

### AC-5: Existing tests unbroken

**Given** `bun test`
**When** all new rules added
**Then** all pre-existing cascade + trade-impact tests still pass (no regression on Hormuz/Middle East rules)
