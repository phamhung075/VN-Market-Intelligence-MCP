# REQ-019: Know What You're Watching

status: READY_FOR_ARCHITECT
sprint: 019
po_vision: Wire company-name aliases and market-wide broadcast into the cascade pipeline so Vietnamese trade names resolve to watchlist tickers and index-level events alert every portfolio stock.

---

## User Story

As a Vietnamese stock investor using Claude,
I want news about "Vinamilk" to automatically trigger alerts for VNM and "VN-Index mất điểm" articles to notify all my watchlist stocks,
So that I never miss portfolio-relevant news simply because a headline uses a company's trade name rather than its ticker symbol, or covers the whole market instead of a single stock.

---

## Context: two observed intelligence failures (2026-04-01)

**Failure 1 — alias gap**: "Vinamilk lên kế hoạch doanh thu 2026 cao kỷ lục" scored impact 5/10 in `run_impact_chain` but produced zero watchlist-stock alerts. The cascade engine scanned for "VNM" (the ticker) in the headline; it did not find it; VNM was silently excluded from `affectedActions`. VNM is in the watchlist. The company name "Vinamilk" is not mapped to its ticker anywhere in the current codebase.

**Failure 2 — market-wide gap**: "VN-Index 4 năm liên tiếp mất điểm tháng 4" scored impact 8/10 and resolved to cascade level `country`. The cascade engine produced no action-level entries because no individual stock ticker appeared in the text. A market-wide bearish pattern of that magnitude represents contextual risk for every portfolio stock and should broadcast to all of them.

Both gaps are in `buildCausalChain()` (`cascadeEngine.ts`), specifically in the stock-matching step (Step 3) and the absence of a broadcast path.

---

## Current stock detection mechanism (as-is analysis)

Two detection surfaces exist today:

1. **`newsNormalizer.ts` — `extractStockTickers()`**: scans article text for tokens that match the 40-code `KNOWN_VN_STOCKS` set using word-boundary regex. Populates `AnalysisEntry.affectedActions`. Only recognises uppercase/parenthesised tickers; does not know trade names.

2. **`cascadeEngine.ts` — Step 3**: iterates `deduplicatedWatchlist`; for each watchlist stock, looks up whether its domain had a matched SECTOR_RULE. If yes, adds an `action`-level entry. No text scan for stock codes or trade names at this step.

3. **`pollNews.ts` — Gate 3 (task 152)**: uses `titleAndSummary.includes(impact.actionCode.toLowerCase())` to decide whether a cascade impact is a "direct mention". This guard will currently miss "Vinamilk" entirely.

Alias resolution must plug into all three surfaces to close the gap.

## Functional Requirements

### FR-1: Static alias dictionary (`stockAliases.ts`)

- **Description**: A new domain service that maps VN stock tickers to their known Vietnamese trade names, abbreviations, and brand names, and exposes two pure functions for lookup and detection.
- **Input to `getAliasesForCode(code: string)`**: an uppercase stock ticker such as `"VNM"`.
- **Output**: `string[]` — all known aliases for that ticker, already lower-cased and accent-normalised. Returns `[]` for unknown codes.
- **Input to `detectStocksInText(text: string, watchlistCodes: string[])`**: a free-text string (news headline + summary) and a list of watchlist ticker strings to check against.
- **Output**: `string[]` — deduplicated list of watchlist tickers whose aliases appear in the text. Order is not significant. Returns `[]` if no alias matches any watchlist code.
- **Business rule — accent normalisation**: both incoming text and alias keys are normalised to NFD + diacritical marks stripped before comparison. This makes "Vinamílk" (source typo) match "Vinamilk" in the alias map.
- **Business rule — case**: comparison is fully case-insensitive.
- **Business rule — alias resolution is additive**: `detectStocksInText` must NOT replace the existing ticker scan. It is a supplementary pass called only when the primary token scan finds zero matches.
- **Business rule — minimum alias coverage**: must include at minimum all default watchlist stocks (VNM, FPT, VCB, VEA) and the 20 most-liquid HOSE stocks listed in the PO spec: HPG, VIC, VHM, MSN, MWG, TCB, BID, CTG, ACB, VPB, HDB, STB, GAS, PLX, SAB, REE, PNJ, DHG.
- **Business rule — alias content per stock**: each entry must cover at minimum: (a) the full Vietnamese company name (e.g. "công ty cổ phần sữa việt nam"), (b) the common short trade name (e.g. "vinamilk"), (c) known brand names if distinct from company name (e.g. "sữa vinamilk"), (d) English common name where applicable (e.g. "viet nam dairy").
- **Storage**: pure TypeScript `const` object inside `stockAliases.ts`. No SQLite table. No `mcp.config.json` key. No runtime mutation.
- **Extensibility**: a developer adds a new stock by appending one entry to the const object — no other file changes required.
- **DDD layer**: domain/services — zero imports from infrastructure or application.

### FR-2: Wire alias detection into cascade engine

- **Description**: Modify `buildCausalChain()` to fall back to alias detection when the primary ticker scan produces no direct-mention hits for a given watchlist stock.
- **Input**: the existing `buildCausalChain` signature remains unchanged — no new parameters.
- **Processing change — Step 3 enrichment**: after domain-level entries are built (Step 2), when generating action-level entries for a watchlist stock, if the stock's `actionCode` does not appear in `entry.affectedActions` (i.e. no direct ticker mention was found by the normaliser), call `detectStocksInText(seedEntry.sourceTitle + ' ' + seedEntry.summary, [stock.actionCode])`. If this returns a non-empty result, treat the stock as having a direct mention for the purpose of Step 3 processing.
- **Processing change — domain bypassing for alias-matched stocks**: if `detectStocksInText` resolves a watchlist stock but no SECTOR_RULE triggered for that stock's domain, still create an action-level entry for it using a fallback confidence of 0.55. This mirrors the behaviour of `uncoveredDomains` handling in Step 2 and ensures alias-detected stocks are not silently dropped when no sector keyword matched either.
- **Output tag on intermediate signal**: alias-resolved action entries must carry `resolvedViaAlias: true` in their `reasoning` string as an annotation (e.g. `[AliasResolved: "vinamilk" → VNM]`). This is for log traceability only; no change to the `CausalChainEntry` or `Signal` type signatures.
- **Output contract**: `CausalChain` type signature unchanged. `watchlistImpacts` gains new entries for alias-resolved stocks. No breaking change.
- **DDD layer**: domain/services (cascadeEngine.ts) — the import of `detectStocksInText` from `stockAliases.ts` is a same-layer import, which is permitted.

### FR-3: Wire alias detection into `pollNews.ts` Gate 3

- **Description**: The current Gate 3 direct-mention check uses `titleAndSummary.includes(impact.actionCode.toLowerCase())`. This string search also misses trade names. It must be extended to use alias detection.
- **Processing change**: replace the `directMention` boolean computation with:
  1. Check for ticker token: `titleAndSummary.includes(impact.actionCode.toLowerCase())` (existing).
  2. If step 1 is false, call `detectStocksInText(titleAndSummary, [impact.actionCode])` and treat a non-empty result as a direct mention.
- **Business rule**: alias-resolved direct mentions receive the same treatment as ticker direct mentions — they always pass Gate 3.
- **DDD layer**: application/usecases (pollNews.ts) — imports `detectStocksInText` from domain/services, which is a permitted downward import.

### FR-4: Wire alias detection into `signalDetector.ts` news-mention path

- **Description**: `detectSignals()` receives a `SignalContext.recentNews` array of `{ title: string; source: string }` items. Currently, the signal fires for every item in `recentNews`. After task 152, the relevance filter in `pollNews.ts` decides which articles enter `recentNews`. No change needed inside `signalDetector.ts` itself for alias detection — the wiring in FR-2 and FR-3 ensures alias-resolved stocks are included in the signals that reach the detector. This FR documents the boundary explicitly to prevent redundant work.
- **Conclusion**: `signalDetector.ts` requires no changes for alias detection. FR-4 is informational.
- **DDD layer**: domain/services — no change.

### FR-5: Market-wide broadcast path in cascade engine

- **Description**: Add a classification step inside `buildCausalChain()` that detects market-wide articles and, when the article meets the impact threshold, emits one `news_mention` signal per watchlist stock.
- **Input**: existing `buildCausalChain` signature. One new config value read from `mcp.config.json`: `alerts.marketWideCascadeMinImpact` (integer, default 6).
- **Market-wide classification criteria** — an article is classified market-wide if it satisfies ANY of the following (checked against `seedEntry.sourceTitle + ' ' + seedEntry.summary`, lowercased):
  - Contains `"vn-index"` (case-insensitive)
  - Contains `"toàn thị trường"` or `"thị trường chứng khoán"` combined with at least one of: `"giảm"`, `"tăng"`, `"mất điểm"`, `"điểm"`, `"%"` (indicates a price/percentage event, not just a generic mention)
  - The `seedEntry.level` resolves to `"country"` or `"global"` AND `seedEntry.impactScore >= marketWideCascadeMinImpact`
- **Broadcast trigger**: article is classified market-wide AND `seedEntry.impactScore >= marketWideCascadeMinImpact`.
- **Broadcast output**: one `WatchlistImpact` entry added to `watchlistImpacts` for EACH watchlist stock that does not already have an action-level entry from the regular SECTOR_RULES path. Fields:
  - `actionCode`: the watchlist stock code
  - `domain`: the stock's domain from the watchlist
  - `impactDirection`: derived from `seedEntry.sentiment` (`"bullish"` → `"up"`, `"bearish"` → `"down"`, `"neutral"` → `"neutral"`)
  - `confidence`: `Math.min(0.7, seedEntry.impactScore / 10)` — capped at 0.7 to rank below direct-mention confidence
  - `reasoning`: `"market-wide cascade: " + seedEntry.sourceTitle.slice(0, 80)`
- **Business rule — no double broadcast**: stocks that already have an action entry from the regular SECTOR_RULES path must not receive an additional broadcast entry (avoid duplicate signals for the same stock).
- **Business rule — config, no hardcoding**: `marketWideCascadeMinImpact` must be read from `mcp.config.json`. No hardcoded threshold in production code.
- **DDD layer**: domain/services (cascadeEngine.ts). The config value must be injected by the application layer (`runImpactChain.ts`) as a new optional parameter, not read directly from infrastructure inside the domain function.

### FR-6: Inject `marketWideCascadeMinImpact` via `runImpactChain.ts`

- **Description**: `buildCausalChain()` is a pure domain function with no I/O. The config value `alerts.marketWideCascadeMinImpact` must be loaded by the application layer and passed in.
- **Change to `buildCausalChain` signature**: add optional parameter `broadcastMinImpact?: number` (default `6` if omitted — matches the config default, preserving backward compatibility).
- **Change to `runImpactChain.ts`**: load `mcp.config.json` via `loadMcpConfig()`, read `alerts.marketWideCascadeMinImpact`, pass it as `broadcastMinImpact` to `buildCausalChain`.
- **Change to `pollNews.ts`**: same — load config and pass `broadcastMinImpact` when calling `buildCausalChain`.
- **Backward compatibility**: both callers are in the application layer. No MCP tool signature changes. No Telegram format changes.
- **DDD layer**: application/usecases (runImpactChain.ts, pollNews.ts).

### FR-7: `mcp.config.json` new key

- **Key**: `alerts.marketWideCascadeMinImpact`
- **Type**: integer
- **Default**: `6`
- **Semantics**: minimum `impactScore` on the seed article for the market-wide broadcast to fire. Impact scores 1-5 are informational/low-relevance; 6-10 are sector-to-market-moving events.
- **DDD layer**: infrastructure configuration.

## Non-Functional Requirements

- **Performance**: `detectStocksInText` is called in the inner loop of `buildCausalChain` and `pollNews`. It must complete in < 1 ms per invocation for a text of up to 500 characters and a watchlist of up to 20 stocks. The static alias map is a pre-built object — no I/O, no regex compilation at call time.
- **Test coverage**: minimum 30 test cases for `stockAliases.ts` as specified in the PO spec. At least 10 test cases for the broadcast path in `cascadeEngine.ts`.
- **No type breakage**: `CausalChainEntry`, `WatchlistImpact`, `Signal`, and `Alert` type shapes are unchanged. `buildCausalChain` gains one optional parameter at the end of its argument list — backward compatible.
- **Language**: alias entries must include both Vietnamese and English forms where applicable. Reasoning annotations in the cascade output are Vietnamese (consistent with existing entries).
- **Data freshness**: alias dictionary is static. Updates require a code change and redeploy. This is acceptable at the current watchlist scale (4-20 stocks).

## Edge Cases and Data Quality

- **Partial alias match**: "vinamilk" appears in an unrelated headline about a competitor ("cạnh tranh với vinamilk"). `detectStocksInText` will still return `["VNM"]` — this is intentional and consistent with how the current ticker scan works (any mention is a mention). The task 152 noise filter will suppress alerts if sentiment is neutral.
- **Alias collision**: two stocks sharing an alias substring (e.g. if "FPT" appears in a headline about "FPT Retail" which is actually MWG's competitor). The alias map must avoid mapping common English words ("oil", "gas") as aliases for specific tickers; aliases must be trade-name specific.
- **Accent normalisation edge case**: some news sources omit diacritics entirely (e.g. "Hoa Phat" instead of "Hòa Phát"). The NFD normalisation strips combining marks, so "Hoa Phat" and "hoa phat" must both be entries in HPG's alias list — NFD normalisation alone does not convert fully unaccented strings.
- **Empty text input**: `detectStocksInText("", [...])` must return `[]` without throwing.
- **Empty watchlist**: `detectStocksInText(text, [])` must return `[]` without throwing.
- **Unknown ticker**: `getAliasesForCode("ZZZZ")` must return `[]` without throwing.
- **Market-wide broadcast with empty watchlist**: if `watchlist` is empty, broadcast produces zero entries — no crash.
- **Market-wide + alias overlap**: an article may be both market-wide and contain a trade-name alias. The regular cascade path (alias detection FR-2) should fire first; broadcast must not create a duplicate entry for a stock that already received a regular action entry.
- **`marketWideCascadeMinImpact` not in config**: fall back to default value 6; do not throw.
- **Vietnamese number/punctuation in alias comparison**: source text may contain quotes or punctuation adjacent to trade names ("Vinamilk," or "\"Vinamilk\""). Use word-boundary-aware matching where possible, or strip punctuation before comparison.

## Key design contracts for the Architect

### `stockAliases.ts` exported API (domain layer)

```
getAliasesForCode(code: string): string[]
detectStocksInText(text: string, watchlistCodes: string[]): string[]
```

Both functions are synchronous, pure, and side-effect-free.

### `buildCausalChain` signature extension

```
buildCausalChain(
  seedEntry: AnalysisEntry,
  watchlist: WatchlistEntry[],
  ragResults?: SearchResult[],
  macroContext?: MacroContext | null,
  macroStats?: MacroStats[],
  broadcastMinImpact?: number,   // NEW — optional, default 6
): CausalChain
```

This is backward compatible: all existing callers that omit the 6th argument will use the default of 6.

### `mcp.config.json` addition

Under the `alerts` section (alongside existing `newsMention` sub-object):
```json
"marketWideCascadeMinImpact": 6
```
