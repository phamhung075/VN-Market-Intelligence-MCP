# REQ-122: ohlcvDailyAggregatorJob — Aggregate Intraday Ticks into daily_ohlcv

status: READY_FOR_ARCHITECT
sprint: 122
po_vision: Add ohlcvDailyAggregatorJob — scheduled cron that aggregates intraday market_prices_history ticks into daily_ohlcv rows after market close, so taSummary accumulates without manual VPS backfill.

## User Story

As a Vietnamese stock investor using Claude,
I want the system to automatically build daily OHLCV candles from intraday price ticks every trading day after market close,
So that TA signals (RSI, MA, BB) accumulate in daily_ohlcv without requiring manual VPS backfill scripts.

---

## Root Cause Context

| Symptom | Root cause |
|---------|-----------|
| `taSummary: []` in every evening report | `daily_ohlcv` rows exist only from one-time backfill; no ongoing job writes new rows |
| `defaultComputeTa` never reaches 8-row threshold | 0 new `daily_ohlcv` rows since backfill aged out (>60 days) |
| `taDiag.tickersBelowThreshold = N` (all tickers) | No job to replenish the table |

The backfill script on VPS is a one-shot tool. This job closes the gap permanently.

## Functional Requirements

### FR-1: Aggregate intraday ticks → one OHLCV row per ticker per trading day

- **Description**: After VN market close, for each watchlist ticker, aggregate all `market_prices_history` ticks whose `fetched_at` falls within today (VN timezone, UTC+7) into one `daily_ohlcv` row.
- **Input**:
  - `watchlist` table: `code TEXT`
  - `market_prices_history` table: `code TEXT`, `price REAL`, `fetched_at TEXT` (ISO datetime string stored in UTC)
  - `nowMs`: current epoch millisecond (injectable for tests)
- **Output**: Upserted row in `daily_ohlcv(code, date, open, high, low, close, volume, updated_at)`
- **Business rules**:
  - `date` = today in VN timezone (`YYYY-MM-DD`, UTC+7 = UTC + 7h offset)
  - `open` = `price` of the tick with the earliest `fetched_at` in the day window
  - `close` = `price` of the tick with the latest `fetched_at` in the day window
  - `high` = `MAX(price)` across all ticks in the window
  - `low` = `MIN(price)` across all ticks in the window
  - `volume` = `COUNT(*)` ticks (tick-count proxy — no actual trade volume in intraday data)
  - `updated_at` = ISO datetime of job run
  - Skip ticker with 0 ticks (market holiday or data gap) — no row inserted/updated
- **DDD layer**: scheduler

### FR-2: Idempotent upsert — re-runs on same day do not create duplicates

- **Description**: If the job runs multiple times on the same trading day (server restart, manual trigger), the `daily_ohlcv` row for that day is updated, not duplicated.
- **Business rule**: Use `INSERT OR REPLACE INTO daily_ohlcv` (or `ON CONFLICT(code, date) DO UPDATE`) so `close`, `high`, `low`, `volume` reflect the latest aggregation.
- **DDD layer**: scheduler

### FR-3: Day boundary computed in VN timezone (UTC+7)

- **Description**: "Today" must be computed in Asia/Ho_Chi_Minh (UTC+7), not UTC, to match how `daily_ohlcv.date` is used by `defaultComputeTa` and `taDiag`.
- **Business rule**:
  - VN midnight (start of day) in UTC = `today 00:00 VN` = `today - 7h UTC` (i.e., previous day 17:00 UTC)
  - Query window: `fetched_at >= <VN_midnight_UTC_ISO> AND fetched_at < <now_UTC_ISO>`
  - `date` field value: `YYYY-MM-DD` in VN local date, not UTC date
- **DDD layer**: scheduler

### FR-4: Cron registered at 16:00 UTC Mon-Fri (= 23:00 VN)

- **Description**: Job fires daily after VN market close (15:30 VN = 08:30 UTC). 16:00 UTC provides a 30-minute buffer after the latest VPS price push.
- **Cron expression**: `0 16 * * 1-5`
- **No day-of-week guard inside the aggregator**: the cron expression already restricts to M-F; the job itself does not check `isVnMarketHours()` — it aggregates whatever ticks exist.
- **DDD layer**: scheduler

### FR-5: Injectable dependencies — `dbFn`, `nowMsFn`, `sendWorkFn`

- **Description**: All external dependencies injected for testability. Production defaults resolved via dynamic `import()` (same pattern as `ohlcvStartupProbe.ts`).
- **Inputs (injectable)**:
  - `dbFn?: () => Database` — returns the SQLite DB instance
  - `nowMsFn?: () => number` — returns current epoch ms (default: `Date.now()`)
  - `sendWorkFn?: (msg: string) => Promise<boolean>` — sends to WORK channel
- **DDD layer**: scheduler

### FR-6: Register in `jobs.ts` + update `cron-registry.json`

- **Description**: Wire `ohlcvDailyAggregatorJob` into `src/scheduler/jobs.ts` using `recordJobRun` wrapper. Add entry to `docs/data/cron-registry.json`. Update `schedulerFileCount` in `cron-registry.json` and `docs/data/project-stats.json` to 33.
- **DDD layer**: scheduler / interface

## Non-Functional Requirements

- **Performance**: Single-pass per ticker — 3 SQL queries max per ticker (open tick, close tick, MIN/MAX/COUNT aggregate). For 30-ticker watchlist, total DB work per run is ~90 parameterized queries (fast on local SQLite).
- **Idempotency**: Multiple runs same day produce identical result — deterministic by design (INSERT OR REPLACE / ON CONFLICT).
- **Error isolation**: Per-ticker try/catch — one bad ticker does not abort the others. Log warning to WORK channel.
- **Data freshness**: Job runs at 16:00 UTC; VPS price-push service (`vn-price-fetch.service`) runs every 60s, so 30+ minutes of ticks available after market close.
- **Language**: Log messages in English (WORK channel).
- **No Telegram to MARKET channel**: This job is infrastructure — it sends a brief WORK summary only (tickers processed, rows written, any skipped).

## SQL Contract

### Query A — OHLCV aggregate for the day window (parameterized)

```sql
SELECT
  MIN(price) AS low,
  MAX(price) AS high,
  COUNT(*)   AS ticks
FROM market_prices_history
WHERE code = ?
  AND fetched_at >= ?   -- VN midnight as UTC ISO string: e.g. '2026-04-17 17:00:00'
  AND fetched_at <  ?   -- now as UTC ISO string:         e.g. '2026-04-18 09:00:00'
```

### Query B — Open price (earliest tick)

```sql
SELECT price
FROM market_prices_history
WHERE code = ?
  AND fetched_at >= ?
  AND fetched_at <  ?
ORDER BY fetched_at ASC
LIMIT 1
```

### Query C — Close price (latest tick)

```sql
SELECT price
FROM market_prices_history
WHERE code = ?
  AND fetched_at >= ?
  AND fetched_at <  ?
ORDER BY fetched_at DESC
LIMIT 1
```

### Upsert

```sql
INSERT OR REPLACE INTO daily_ohlcv
  (code, date, open, high, low, close, volume, updated_at)
VALUES (?, ?, ?, ?, ?, ?, ?, ?)
```

Note: `daily_ohlcv` PRIMARY KEY is `(code, date)` — `INSERT OR REPLACE` triggers implicit delete+insert. Alternatively, use explicit `ON CONFLICT(code, date) DO UPDATE SET close=excluded.close, high=MAX(daily_ohlcv.high, excluded.high), low=MIN(daily_ohlcv.low, excluded.low), volume=excluded.volume, updated_at=excluded.updated_at`. Both are acceptable; Architect chooses.

## Data Contracts

### Input: `market_prices_history` schema (actual columns)

| Column | Type | Notes |
|--------|------|-------|
| `code` | TEXT | ticker, e.g. `VCB` |
| `price` | REAL | last traded price |
| `volume` | REAL | raw volume from VPS (not used — we use tick count proxy) |

| `exchange` | TEXT | `HOSE` / `HNX` / `UPCOM` |

### Output: `daily_ohlcv` schema (existing table)

| Column | Type | Notes |
|--------|------|-------|
| `code` | TEXT | ticker |
| `date` | TEXT | `YYYY-MM-DD` in VN timezone (UTC+7) |
| `open` | REAL | first price of day |
| `high` | REAL | max price |
| `low` | REAL | min price |
| `close` | REAL | last price of day |
| `volume` | REAL | tick count proxy |
| `updated_at` | TEXT | ISO datetime of job run |

PRIMARY KEY: `(code, date)`

### Return type: `OhlcvAggregatorResult`

```typescript
interface OhlcvAggregatorResult {
  tickersProcessed: number;   // watchlist tickers attempted
  rowsWritten: number;        // daily_ohlcv rows upserted
  tickersSkipped: number;     // tickers with 0 ticks (holiday / data gap)
  sent: boolean;              // WORK channel notify sent
}
```

## Edge Cases & Data Quality

- [ ] Watchlist empty → return `{ tickersProcessed: 0, rowsWritten: 0, tickersSkipped: 0, sent: false }` — no error
- [ ] Ticker with 0 ticks today → skip, increment `tickersSkipped` — no row upserted
- [ ] Job runs on weekend (manual trigger) → cron guard prevents it, but if invoked directly, aggregates whatever ticks exist (no guard inside job)
- [ ] `fetched_at` stored in local VN timezone by VPS (risk) → Architect must verify VPS time format. If `fetched_at` is in local VN time, the midnight boundary calculation changes. Check `src/infrastructure/fetchers/` for how VPS pushes prices.
- [ ] Market holiday (no ticks) → all tickers skipped → `rowsWritten = 0` → WORK message notes holiday-like result
- [ ] Single tick in window → open = close = that price, high = low = that price, volume = 1
- [ ] DB write failure on one ticker → catch per ticker, log warning, continue others
- [ ] `INSERT OR REPLACE` deletes then inserts — if another process reads mid-write, it sees 0 rows briefly. Acceptable for single-process server.
- [ ] VN midnight boundary crosses UTC date: e.g., VN date `2026-04-17` = UTC window `2026-04-16 17:00:00` to `2026-04-17 09:00:00`. Must use UTC-ISO boundary strings, not DATE() SQLite function, to avoid ±1 day errors.

## Acceptance Criteria

### AC-1: Tickers with intraday ticks → correct OHLCV row inserted

**Given** 2 watchlist tickers (e.g., `VCB`, `FPT`) each with 3 ticks in today's VN-day window in `market_prices_history`
**When** `runOhlcvDailyAggregator()` is called with injected in-memory DB and a fixed `nowMs`
**Then**

- 2 rows exist in `daily_ohlcv`
- `open` = price of tick with earliest `fetched_at`
- `close` = price of tick with latest `fetched_at`
- `high` = max price across all 3 ticks
- `low` = min price across all 3 ticks
- `volume` = 3
- `date` = VN local date string (`YYYY-MM-DD`)
- Result: `{ tickersProcessed: 2, rowsWritten: 2, tickersSkipped: 0 }`

### AC-2: Ticker with no ticks → no row inserted, no error

**Given** 1 watchlist ticker with 0 ticks in `market_prices_history` for today's window
**When** `runOhlcvDailyAggregator()` is called
**Then**

- 0 rows exist in `daily_ohlcv`
- No exception thrown
- Result: `{ tickersProcessed: 1, rowsWritten: 0, tickersSkipped: 1 }`

### AC-3: Re-run same day → idempotent upsert, no UNIQUE constraint error

**Given** `daily_ohlcv` already has 1 row for `VCB` on today's date with `close = 80000`
**And** `market_prices_history` now has an additional tick at `price = 82000` (later `fetched_at`)
**When** `runOhlcvDailyAggregator()` is called a second time
**Then**

- Still exactly 1 row in `daily_ohlcv` for `(VCB, today)`
- `close` updated to `82000`
- No UNIQUE constraint error thrown
- `volume` incremented to reflect new tick count

### AC-4: Ticks from yesterday but not today → no row inserted for today

**Given** `market_prices_history` has ticks for `VCB` with `fetched_at` in yesterday's VN-day window only
**When** `runOhlcvDailyAggregator()` is called with `nowMs` set to today's VN date
**Then**

- 0 rows inserted in `daily_ohlcv` for today's date
- Yesterday's window ticks are not aggregated (date boundary is correct)
- Result: `{ tickersProcessed: 1, rowsWritten: 0, tickersSkipped: 1 }`
