# REQ-119: ohlcv-startup-probe

status: READY_FOR_ARCHITECT
sprint: 119
po_vision: Send one WORK alert on server boot when any watchlist ticker has fewer than 8 daily_ohlcv rows — prevents silent taSummary:[] after redeployments.

## User Story

As a VN Market dev team member,
I want the MCP server to check daily_ohlcv row counts for every watchlist ticker at boot and alert WORK channel if any ticker is sparse,
So that I can run fetch-ohlcv-backfill.sh on the VPS before the user notices empty TA signals in their evening report.

## Functional Requirements

### FR-1: Query daily_ohlcv row counts per watchlist ticker on startup

- Description: On server boot, query `SELECT code, COUNT(*) as cnt FROM daily_ohlcv WHERE code = ? GROUP BY code` for each ticker in the `watchlist` table.
- Input: `Database` instance (injectable), list of tickers from `SELECT code FROM watchlist`.
- Output: Map of `code → rowCount` (missing entry = 0 rows).
- Business rule: Threshold is 8 rows. Tickers with `cnt < 8` (including absent tickers = 0 rows) are "sparse".
- DDD layer: scheduler

### FR-2: Send single WORK alert listing sparse tickers

- Description: If any sparse ticker exists, call `sendTelegramWork` once with a structured message listing all sparse tickers and instructing the dev to run `fetch-ohlcv-backfill.sh`.
- Input: Array of `{ code, count }` objects where `count < 8`.
- Output: One WORK channel message. Format:

  ```
  [ohlcv-probe] daily_ohlcv sparse on boot — taSummary will be empty for: VNM(3), FPT(0), VCB(5)
  Run on VPS: ./fetch-ohlcv-backfill.sh
  ```

- Business rule: Message is sent once per server boot. No cron. No dedup guard needed — startup runs exactly once per process lifetime.
- Business rule: If zero sparse tickers, send NO message (silent ok path).
- Business rule: If watchlist is empty, send NO message.
- DDD layer: scheduler (calls infrastructure/notifiers/telegram.ts)

### FR-3: Error isolation — DB failure does not throw

- Description: Any exception from the DB query (schema missing, locked, corrupt) is caught. The probe logs a warn and returns without sending any Telegram message and without re-throwing.
- Input: DB error of any kind.
- Output: `{ sparseTickers: [], sent: false }` — no throw, no crash.
- Business rule: Server startup must complete even if probe fails. Probe failure is non-fatal.
- DDD layer: scheduler

### FR-4: Wire into startScheduler() as a one-shot startup call

- Description: `startScheduler()` in `src/scheduler/jobs.ts` calls `runOhlcvStartupProbe()` once via `void` (fire-and-forget) immediately after the idempotency guard, similar to the existing `runDailyAuditIfStale` and `runBctcReparseJob` startup patterns.
- Input: No arguments needed for production call (uses `getDb()` default).
- Output: Probe fires once at boot, result logged by probe itself.
- Business rule: NOT wrapped in `setTimeout` — fires immediately (no delay needed, DB is ready before `startScheduler()` is called).
- DDD layer: scheduler/jobs.ts

## Non-Functional Requirements

- Performance: One SQL query per watchlist ticker (N queries, N <= 30). Acceptable at startup — not on hot path.
- Atomicity: All queries in a single synchronous pass. No transactions required.
- Language: WORK channel message in English (dev-facing, not user-facing).
- Telegram channel: WORK only (`sendTelegramWork`). Never MARKET.
- No new DB tables, no schema changes.

## Edge Cases & Data Quality

- [ ] Ticker in watchlist but zero rows in daily_ohlcv → count = 0, included in sparse list
- [ ] Watchlist table empty → return early, no alert
- [ ] daily_ohlcv table missing (schema not yet initialised) → DB error caught by FR-3, no throw
- [ ] DB locked during startup → caught, warn logged, no throw
- [ ] sendTelegramWork failure (bot token missing, network down) → sendTelegramWork never throws (per telegram.ts contract), probe returns normally
- [ ] All watchlist tickers >= 8 rows → no message sent (silent ok)
- [ ] Exactly 8 rows → not sparse (threshold is strictly < 8)

## Blockers

None — spec is self-contained.

## Acceptance Criteria

### AC-1: Sparse DB triggers exactly one WORK alert

**Given** watchlist has tickers [VNM, FPT] and daily_ohlcv has 3 rows for VNM and 0 rows for FPT
**When** `runOhlcvStartupProbe()` is called
**Then**

- `sendTelegramWork` called exactly once
- Message contains "VNM(3)" and "FPT(0)"
- Message contains "fetch-ohlcv-backfill.sh"
- Return value has `sparseTickers.length === 2` and `sent === true`

### AC-2: Populated DB sends no alert

**Given** watchlist has tickers [VNM, FPT] and daily_ohlcv has 20 rows for VNM and 15 rows for FPT
**When** `runOhlcvStartupProbe()` is called
**Then**

- `sendTelegramWork` never called
- Return value has `sparseTickers.length === 0` and `sent === false`

### AC-3: Empty watchlist sends no alert

**Given** watchlist table has zero rows
**When** `runOhlcvStartupProbe()` is called
**Then**

- `sendTelegramWork` never called
- Return value has `sparseTickers.length === 0` and `sent === false`

### AC-4: DB error is caught, does not throw

**Given** DB query throws an exception (e.g., `SQLITE_ERROR: no such table`)
**When** `runOhlcvStartupProbe()` is called
**Then**

- No exception propagates to caller
- `sendTelegramWork` never called
- Return value has `sent === false`

### AC-5: Threshold boundary — exactly 8 rows is not sparse

**Given** watchlist has ticker [HPG] and daily_ohlcv has exactly 8 rows for HPG
**When** `runOhlcvStartupProbe()` is called
**Then**

- `sendTelegramWork` never called
- `sparseTickers` is empty

### AC-6: Mixed tickers — only sparse subset listed

**Given** watchlist has [VNM(20 rows), FPT(5 rows), VCB(0 rows)]
**When** `runOhlcvStartupProbe()` is called
**Then**

- `sendTelegramWork` called once
- Message lists FPT(5) and VCB(0), not VNM
- `sparseTickers.length === 2`

### AC-7: jobs.ts integration — startScheduler calls probe once

**Given** `startScheduler()` is called
**When** the function body runs past the idempotency guard
**Then** `runOhlcvStartupProbe()` is called (fire-and-forget `void`) without delay

## Implementation Notes

### Function signature

```typescript
// src/scheduler/ohlcvStartupProbe.ts

export interface OhlcvStartupProbeDeps {
  db?: Database;
  sendWorkFn?: (msg: string) => Promise<boolean>;
}

export interface OhlcvStartupProbeResult {
  sparseTickers: Array<{ code: string; count: number }>;
  sent: boolean;
}

export async function runOhlcvStartupProbe(
  deps?: OhlcvStartupProbeDeps
): Promise<OhlcvStartupProbeResult>
```

### Query pattern (per ticker)

```sql
SELECT COUNT(*) as cnt FROM daily_ohlcv WHERE code = ?
```

Single-row result. If ticker absent from table, returns `cnt = 0`.

### jobs.ts wiring position

Insert immediately after the `g.__vnMarketSchedulerStarted = true` line (before any `cron.schedule` calls), following the same `void fn().then(…)` pattern used by `runDailyAuditIfStale`:

```typescript
void runOhlcvStartupProbe().then((r) => {
  if (r.sent) log(`[ohlcv-probe] sparse tickers: ${r.sparseTickers.map(t => t.code).join(', ')}`)
})
```
