# TECH-1004: VN Government Stabilization + Systemic Stress Cascade Rules

status: APPROVED_BY_ARCHITECT
req_ref: TASKS.md#1004 (Report 1001)

---

## Problem Statement

The cascade engine (`src/domain/services/cascadeEngine.ts`) scores news articles
through `SECTOR_RULES` → `POLICY_RULES` → market-wide broadcast. However, three
specific classes of Vietnamese macro news are mislabelled or underscored:

1. **Government stabilization actions** — SBV rate cuts, Treasury bond buybacks,
   official credit room expansions, market support packages — fire the generic
   market-wide broadcast at `confidence = impactScore / 10` (typically 0.6–0.7)
   because no dedicated SECTOR_RULE covers the full vocabulary. The existing
   "stabilization fund" block (lines 530–600) handles `quỹ bình ổn` and
   `gói hỗ trợ` but misses the direct SBV rate-cut pathway and fiscal stimulus
   injections.

2. **Systemic stress indicators** — bank-run signals, interbank rate spikes,
   NPL crises — are partially covered by `overnightRatePct > 5` in
   `MACRO_ADJUSTMENTS` but have no SECTOR_RULE entry, so they fire only when the
   `MacroContext` is injected. Pure-text news about banking stress (e.g.
   "nợ xấu hệ thống vượt 5%") produces no domain entry at all.

3. **Policy-intervention combinations** — simultaneous SBV rate cut + fiscal
   stimulus + credit room expansion — receive three separate rules that each fire
   independently but are never combined into a higher-confidence composite signal.

The net effect: an article headlined "NHNN hạ lãi suất điều hành 50bp + Bộ Tài
chính bơm 50.000 tỷ đồng vào thị trường" scores the same confidence as an
article about a routine trade policy update, failing to surface a systemic
bullish reversal to the user.

## Architecture Decision

All new logic lives inside `SECTOR_RULES` (the existing keyword-to-domain array
in `cascadeEngine.ts`) and a new exported helper `detectPolicyInterventionCombo`.
No new files, no new interfaces, no infrastructure imports. The cascade engine is
already purely synchronous domain code; extending its rule tables is the correct
extension point.

The approach deliberately avoids restructuring `MacroContext` or adding new
optional parameters to `buildCausalChain`. Instead:

- **Keyword rules** handle the text-matching path (news article contains "hạ lãi
  suất điều hành").
- **MACRO_ADJUSTMENTS** already handle the numeric-threshold path (SBV
  `refinancingRatePct < 4`); these remain unchanged.
- A new `detectPolicyInterventionCombo` pure function counts how many distinct
  policy-intervention categories matched the seed text, then returns a confidence
  multiplier that `buildCausalChain` applies only when ≥ 2 categories fire
  simultaneously. This avoids touching action entry logic.

Placement in `SECTOR_RULES`: new rules for SBV stabilization must be inserted
**before** the existing generic "lãi suất giảm" rules (line 638) so that
the more-specific rule wins under the first-match-wins policy.

### 3. `detectPolicyInterventionCombo` — new exported pure function

Add below the `POLICY_RULES` const and above the `isMarketWide` helper:

```typescript
/**
 * Policy intervention category definitions for combo detection.
 * Each category is independent; a single article can trigger multiple.
 */
const POLICY_INTERVENTION_CATEGORIES: Array<{ key: string; keywords: string[] }> = [
  {
    key: "sbv_rate",
    keywords: [
      "nhnn hạ lãi suất", "hạ lãi suất điều hành", "giảm lãi suất điều hành",
      "sbv rate cut", "cắt giảm lãi suất điều hành",
    ],
  },
  {
    key: "fiscal_stimulus",
    keywords: [
      "gói kích thích tài khóa", "bộ tài chính bơm tiền", "gói phục hồi kinh tế",
      "giải ngân đầu tư công khẩn cấp", "fiscal stimulus vietnam",
    ],
  },
  {
    key: "credit_room_expansion",
    keywords: [
      "nới room tín dụng", "tăng room tín dụng cho ngân hàng",
      "tín dụng ngân hàng tăng trưởng", "room tín dụng tăng",
    ],
  },
  {
    key: "market_stabilization",
    keywords: [
      "quỹ bình ổn", "bình ổn thị trường", "scic mua vào cổ phiếu",
      "stabilization fund", "nhnn mua trái phiếu chính phủ",
      "nghiệp vụ thị trường mở", "chính phủ hỗ trợ thị trường",
    ],
  },
  {
    key: "forex_intervention",
    keywords: [
      "nhnn bán ngoại tệ", "sbv fx intervention", "bán ngoại tệ bình ổn tỷ giá",
      "can thiệp tỷ giá",
    ],
  },
];

/**
 * Count how many distinct policy-intervention categories are present in the
 * seed text. Returns a confidence boost multiplier:
 *
 *   0–1 category  → 1.00 (no combo boost)
 *   2 categories  → 1.10 (+10% confidence on domain entries for banking/securities)
 *   3+ categories → 1.18 (+18% — systemic policy response, rare event)
 *
 * Pure function: no I/O, no side effects.
 *
 * @param textLower - Lowercased seed title + summary
 * @returns         - Object with matchedCategories list and multiplier
 */
export function detectPolicyInterventionCombo(textLower: string): {
  matchedCategories: string[];
  multiplier: number;
} {
  const matched: string[] = [];

  for (const cat of POLICY_INTERVENTION_CATEGORIES) {
    if (cat.keywords.some((kw) => textLower.includes(kw))) {
      matched.push(cat.key);
    }
  }

  let multiplier = 1.0;
  if (matched.length >= 3) multiplier = 1.18;
  else if (matched.length === 2) multiplier = 1.10;

  return { matchedCategories: matched, multiplier };
}
```

Wire into `buildCausalChain` at Step 2 (domain entry construction), immediately
after the SECTOR_RULES loop builds `domainEntryMap`. Apply the multiplier only
to `banking` and `securities` domain entries (the two domains most directly
responsive to simultaneous policy actions):

```typescript
// ── Step 2d: Policy-intervention combo boost ──────────────────────────────
// Only applies when ≥ 2 independent government policy categories co-occur.
// Targets banking + securities (most direct beneficiaries of VN policy combos).
const comboResult = detectPolicyInterventionCombo(summaryLower);
if (comboResult.multiplier > 1.0) {
  const comboTargets: DomainType[] = ["banking", "securities"];
  for (const [domain, domainEntry] of domainEntryMap) {
    if (!comboTargets.includes(domain)) continue;
    const boosted = Math.min(0.99, domainEntry.confidence * comboResult.multiplier);
    domainEntry.confidence = boosted;
    domainEntry.reasoning +=
      ` [PolicyCombo: ${comboResult.matchedCategories.join("+")} → ×${comboResult.multiplier.toFixed(2)} ${domain}]`;
  }
}
```

This block slots in after Step 2c (`applyDynamicMacroAdjustments`) and before
Step 3 (action entry construction).
