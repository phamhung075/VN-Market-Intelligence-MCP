# REQ-133: Test isolation via preload + structural registry contract

status: READY_FOR_ARCHITECT
sprint: 133
po_vision: Eliminate production-DB bleed and stale fixture rot permanently — preload enforces :memory: isolation; 8 duplicate DDL helpers deleted; tool-registry count made structural.

## User Story

As the dev team running `bun test`,
I want every test file to receive a fresh in-memory DB automatically — with no manual `process.env["DB_PATH"] = ":memory:"` guard and no duplicated DDL helper files,
So that production-DB bleed never causes UNIQUE constraint failures or silent dedup skips, and adding a new MCP tool never breaks `308-tool-registry.test.ts`.

## Functional Requirements

### FR-1: Bun preload file `src/__tests__/setup.ts`

- Description: A Bun test preload module that runs before any test file is evaluated. It sets `DB_PATH=:memory:` at the process level and registers a global `beforeEach` that calls `closeDb()` so each test starts with a fresh singleton DB handle.
- Input: Process environment at test startup.
- Output: `process.env["DB_PATH"]` equals `":memory:"` for all test modules. Each `beforeEach` callback silently calls `closeDb()` — errors swallowed (handle may already be null).
- Business rule: Must be the first code to run — before any production module is imported. Bun preload guarantees this execution order.
- DDD layer: test infrastructure (no production layer touch)

Exact content:

```ts
import { beforeEach } from "bun:test";
process.env["DB_PATH"] = ":memory:";
import { closeDb } from "../infrastructure/db/index.js";
beforeEach(() => { try { closeDb(); } catch (_) {} });
```

### FR-2: Wire preload into `bunfig.toml`

- Description: Add `preload` key to the `[test]` section so Bun auto-loads `setup.ts` before every test file.
- Input: `bunfig.toml` `[test]` section.
- Output: `[test]` section contains `preload = ["src/__tests__/setup.ts"]`. All other keys (`coverage`, `timeout`) remain unchanged.
- Business rule: No other `bunfig.toml` sections are modified.
- DDD layer: test infrastructure

### FR-3: Delete 8 DDL helper files

- Output: `src/__tests__/helpers/` directory is empty.
- Business rule: Deletion is permanent. No replacement helper files.
- DDD layer: test infrastructure

### FR-4: Replace helper call-sites with `initDatabase()`

- Description: In each of the 12 test files that import from `helpers/`, remove the helper import and replace the `ensureXxxTable(db)` / `initPharmaStore(db)` call with `closeDb(); await initDatabase()`. Then replace the local `db` variable with `getDb()` for subsequent store calls.
- Input: 12 call-site files (see table below).
- Output: Zero imports from `src/__tests__/helpers/` across the entire test suite.
- Business rule:
  - `initDatabase()` uses the singleton via `getDb()` — it does NOT accept a `db` parameter.
  - The pattern to replace `makeTestDb()` is: `closeDb(); await initDatabase(); const db = getDb();`
  - If a test already sets `process.env["DB_PATH"] = ":memory:"` at line 1, remove that line — the preload now handles it.
  - Each affected test file imports `{ initDatabase, getDb, closeDb }` from `"../infrastructure/db/index.js"`.

## Edge Cases & Data Quality

- [ ] `closeDb()` called when `_db` is already null — must not throw (already handled by `if (_db)` guard in schema.ts).
- [ ] Test file that already has `process.env["DB_PATH"] = ":memory:"` at line 1 — that line is now redundant; remove it during call-site migration to keep files clean.
- [ ] `initDatabase()` is async — call-sites in `beforeEach` must use `await` or return the promise.
- [ ] Tests that pass a local `db` handle to store functions (e.g. `upsertBond(db, ...)`) — after migration the `db` variable becomes `getDb()`, which is the same singleton that `initDatabase()` initialized.
- [ ] `vnstockTestDdl.ts` — grep shows no current call-sites; delete unconditionally.
- [ ] `reputationScoresTestDdl.ts` — used by 3 files (`265`, `266`, `267`); all 3 must be migrated before deletion.
- [ ] Bun preload import order: `process.env["DB_PATH"] = ":memory:"` must be set BEFORE `import { closeDb }` — dynamic import in the preload body is not needed because Bun evaluates the `process.env` assignment synchronously before the static import is resolved.
