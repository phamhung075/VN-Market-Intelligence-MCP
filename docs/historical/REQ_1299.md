# REQ-1299: MCP Tool Context Optimization

**Status:** APPROVED
**Created:** 2026-04-23
**Sprint:** 1299
**BA:** BA Agent
**Target Completion:** 2026-04-28

---

## Executive Summary

Current MCP tool loading wastes ~40k tokens (32.4% of context budget) by injecting ALL 106 tools into every agent session, even if only 10–15 tools per agent are used. Solution: implement skill-aware tool filtering + session-scoped caching to reduce default context from 65k → <30k tokens.

**Impact:** Frees 40k tokens for agent reasoning depth, multi-turn message history, and analysis complexity — essential for market intelligence quality.

---

## Business Requirements

### BR-1: Context Budget Pressure
- **Current state:** 65k tokens consumed by tool context (32.4% of typical 200k budget)
- **Problem:** Agents forced to truncate reasoning, drop message history, ignore complex chains
- **Goal:** Reduce to <30k (≤15% of budget), restoring 40k+ tokens for intelligence work

### BR-2: No Feature Regression
- **Current capability:** All 106 tools discoverable by all agents
- **Requirement:** Maintain capability (all tools remain accessible), but defer loading
- **Strategy:** Load tools per skill declaration + skill-union computation

### BR-3: Session-Aware Optimization
- **Insight:** Tool usage varies by session (user workflow, market conditions, agent context)
- **Requirement:** Cache must be session-scoped, not global (avoid over-generalization)
- **Benefit:** Enables future optimization via usage analytics

## Functional Requirements

### FR-1: Tool Index Documentation
**Requirement:** Create searchable reference mapping all 106 tools to 1-line summaries.
**Why:** Enable BA/Architect/Dev to quickly identify tool purpose without reading full context.

| Sub-Req | Description | Output |
|---------|-------------|--------|
| FR-1a | Extract tool list from mcp-tools.md + tool-registry.json | docs/TOOL_INDEX.md |
| FR-1b | Write 1-liner per tool (name, input signature, output type) | <10k tokens, alphabetical |
| FR-1c | Group tools by category (watchlist, alerts, market, macro, etc.) | TOOL_INDEX.md + category index |
| FR-1d | Map per-skill tool requirements | docs/SKILL_MANIFEST.md |

### FR-2: Skill-Gated Bootstrap Loading
**Requirement:** Bootstrap accepts skill list, returns filtered tool context.
**Why:** Agents declare skills → system loads only skills' tools + always-on tools.

| Sub-Req | Description | Input | Output |
|---------|-------------|-------|--------|
| FR-2a | Refactor agentBootstrap.ts to accept skill array | sessionId, skillIds[] | tool list |
| FR-2b | Compute tool union from SKILL_MANIFEST | skillIds + "always-on" category | string[] of 10–25 tools |
| FR-2c | Return filtered agent context | skills: ["financial-analyst"] | ~15k tool tokens (not 65k) |
| FR-2d | Backwards compatibility: no skills → all tools (old behavior) | sessionId (no skills param) | all 106 tools |
| FR-2e | Performance: bootstrap completes <100ms (session cache hit) | cached bootstrap + 3 skills | ≤100ms |

### FR-3: Session Memory Cache
**Requirement:** LRU cache tracks tools loaded per session for analytics.
**Why:** Enable future optimization via usage frequency, identify dead tools.

| Sub-Req | Description | Interface | SLA |
|---------|-------------|-----------|-----|
| FR-3a | Create sessionToolCache: sessionId → {tools, timestamp} | get(), set(), clear() | <5ms |
| FR-3b | LRU eviction: max 100 sessions, TTL 8h | session map | O(1) lookup |
| FR-3c | Cron: trackSessionToolUsageJob every 8h | aggregate + histogram | <1min batch |
| FR-3d | Output: tool usage stats JSON (tool → usage count last 7d) | docs/agent-memory/modules/tool-usage-stats.json | updated every 8h |

## Non-Functional Requirements

### NFR-1: Performance
- **Tool loading:** <100ms per bootstrap (cold: read manifest, warm: cache hit)
- **Session cache:** <5ms lookup, <10ms insert
- **Cron job:** Aggregate 100 sessions in <1 minute
- **Memory:** Cache footprint <1MB (100 sessions × ~10KB per session)

### NFR-2: Backwards Compatibility
- **Old code:** Agents without skill params still work (load all 106 tools)
- **No breaking:** Existing tool calls unchanged
- **Deprecation:** Mark full-load path as "legacy" in comments, target removal in Sprint 1302+

### NFR-3: Maintainability
- **SKILL_MANIFEST:** Single source of truth (manual maintenance via code review)
- **Tool changes:** Whenever tool added/removed, manifest updated (enforce via checklist)
- **Agent memory:** Usage stats inform future decisions (archived in docs/agent-memory/)
