# REQ-181: fix(test-isolation) — bulk Bun.env DB_PATH fix in 109 test files

status: READY_FOR_ARCHITECT
sprint: 181
po_vision: Fix production DB contamination by test runs — bulk replace process.env→Bun.env in 109 test files.

## User Story

As a developer running the full VN-Market-Intelligence test suite,
I want all 109 test files to use `Bun.env["DB_PATH"] = ":memory:"` (not `process.env`),
So that test runs never open or write to the production `data/market.db`, and full-suite failures drop from 38 to ≤5.

## Root Cause (confirmed)

`schema.ts:64` reads `Bun.env["DB_PATH"]` — NOT `process.env["DB_PATH"]`.
In Bun, these are separate namespaces. Setting `process.env["DB_PATH"] = ":memory:"` at test file line 1 has zero effect on `schema.ts`. The DB module then falls back to `DEFAULT_DB_PATH` = `data/market.db` (production file).

**Production impact confirmed:** `system_logs` at 2026-04-18 15:30–15:39 UTC contain test-only strings (`"simulated...failure for AC-3"`, `"check timestamp"`, `"warning message"`) interspersed with real job output — proof that dev test runs contaminated the production DB.

**Suite failure mechanism:** When a test worker imports DB modules before `setup.ts` preload takes effect in that worker, `schema.ts` opens production DB → race condition → 38 full-suite failures.
