# REQ-232: Cowork Resilience — Self-Healing Agent Recovery from VPS Pipeline Failures

status: DRAFT
sprint: 232
po_vision: Guarantee zero silent failures when VPS services become unavailable. Implement agent-level retry orchestration with exponential backoff, multi-source fallback chains (primary→secondary→tertiary), and fail-loud escalation to user if all fallbacks exhausted. Improves system uptime 30-50% during VPS incidents.

---

## User Story

**As a** Vietnamese market analyst using Claude,
**I want** the cowork agents (News Scout, Financial Analyst, Market Watcher) to automatically recover from VPS pipeline failures without silent data gaps,
**So that** I receive continuous market intelligence even when Vinahost VPS (prices, BCTC, news, FX rates, foreign flow) becomes unavailable for extended periods.

---

## Executive Summary

**Problem**: VPS Singapore (Vinahost) is the single point of failure for five critical geo-blocked services:
- `vn-price-fetch.service` (HOSE/HNX/UPCOM prices, 60s interval)
- `vn-bctc-fetch.service` (BCTC financial reports, 6h interval)
- `vn-news-fetch.service` (Vietnamese news, 15min interval)
- `vn-sbv-fetch.service` (SBV FX rates, 30min interval)
- `vn-foreign-flow.service` (foreign buy/sell flow, 60s interval)

**Impact**: When any VPS service fails, agents silently continue with stale cached data for 6h+ before watchdog alerts trigger. During 2026-03-15 VPS outage, News Scout did not detect availability of **6 market-moving news items** until 8h later.

**Solution**: Implement agent-level resilient fetcher orchestration with intelligent fallback chains:
- **Step 0c (Agent init)**: Check if VPS services are in circuit breaker "open" state
- **Fallback chain**: Primary (VPS) → Secondary (cached) → Tertiary (domestic alternative if available) → Escalate
- **Retry orchestration**: Exponential backoff (1s → 2s → 4s → 8s) within 15min window
- **Fail-loud escalation**: If all retries exhausted, agent POSTS fail-loud alert to Telegram WORK channel + updates agent log

**Success metric**: System uptime during VPS failures increases 30-50% (measured by agent signal freshness during simulated outages).

## Functional Requirements

### FR-1: Resilient Fetcher Orchestration Engine

**Description**: Domain service that orchestrates retries + fallback routing for any fetcher call.

**Input**:
```typescript
{
  fetcher: async () => Promise<T>,                    // primary fetcher (VPS)
  fallbacks: [async () => Promise<T>, ...],           // secondary, tertiary fallbacks
  maxRetries: number,                                 // attempt limit (default: 3)
  initialBackoffMs: number,                           // starting wait (default: 1000)
  maxBackoffMs: number,                               // cap on exponential growth (default: 8000)
  timeoutMs: number,                                  // per-call timeout (default: 30000)
  context: {
    serviceName: string,                              // "prices" | "news" | "bctc" | "sbv_rates" | "foreign_flow"
    agentName: string,                                // "01-news-scout" | "02-financial-analyst" | "04-market-watcher"
  }
}
```

**Output**:
```typescript
{
  success: boolean,
  data: T | null,
  source: "primary" | "fallback_1" | "fallback_2" | "exhausted",
  retriesUsed: number,
  totalDurationMs: number,
  errorLog: Array<{ attempt: number; source: string; error: string; durationMs: number }>,
}
```

**Business rule**:
- Try primary (VPS) with exponential backoff up to `maxRetries` times
- If all retries fail, immediately try fallback_1 (no backoff, one attempt)
- If fallback_1 fails, try fallback_2 (no backoff, one attempt)
- If all chains exhausted, set `source: "exhausted"` and return null
- Total operation must complete within 15min (180s timeout for entire chain)
- Circuit breaker state ("open"/"half-open"/"closed") does NOT skip fetching; only logs it

**DDD layer**: domain/services

**File**: `src/domain/services/resilientFetcher.ts`

### FR-2: News Source Router with Fallback Chain

**Description**: Intelligent selector for news sources during VPS outages. Maintains fallback decision tree.

**Input**:
- VPS news service health status (circuit breaker state + last success timestamp)
- Current time

**Output**:
```typescript
{
  primary: {
    type: "vps",
    endpoint: "http://$VINAHOST_IP:3001/fetch-news",
    timeout: 30000,
    description: "Real-time VPS proxy (10 sources, 226 items/15min)"
  },
  fallbacks: [
    {
      type: "cache",
      endpoint: "db:select from news where source IN (cafef, vnexpress, reuters, ...)",
      timeout: 5000,
      description: "Cached news from last 7 days (immediate, no freshness)"
    },
    {
      type: "domestic_rss",
      endpoint: "cafef.vn, vnexpress.net, vneconomy.vn (direct, no VPS proxy)",
      timeout: 30000,
      description: "Direct RSS from Vietnamese sources (5-15min stale, bot-risk moderate)"
    }
  ],
  shouldUseFallback: boolean,  // true if VPS was last_failure < 15min ago
  lastVpsHealthCheck: { state: "open" | "half-open" | "closed", failureCount: number }
}
```

**Business rule**:
- Use primary (VPS) if circuit breaker is "closed" AND last success was <15min ago
- Switch to cache fallback if circuit breaker is "open" OR last success >15min ago
- Switch to domestic RSS fallback only if:
  - Cache has <10 articles from last 6h, AND
  - User has explicitly enabled "domestic fallback" in config (opt-in due to bot-risk)
- All fallback decisions logged with timestamp + reason code

**DDD layer**: infrastructure/fetchers

**File**: `src/infrastructure/fetchers/newsSourceRouter.ts`

### FR-5: Fail-Loud Escalation Protocol

**Description**: When all retries + fallbacks exhausted, agent escalates gracefully to user.

**Trigger conditions** (any of):
1. News fetch exhausted after 3 retries + cache + domestic fallback (15min total)
2. Price for critical ticker (VNM/FPT/VCB/HPG) unavailable after retries + cache + Yahoo
3. BCTC quarterly report missing after retries + cache + Công Báo fallback
4. FX rates (SBV) unavailable after 2 retries + cache (FX less critical than prices)

**Escalation action**:
```typescript
// Agent calls:
await resilientFetcher({
  serviceName: "news",
  agentName: "01-news-scout",
  onExhausted: async (context) => {
    // Fail-loud escalation
    await notifyUser({
      channel: "work",
      severity: "alert",
      message: `[01-NEWS-SCOUT] VPS news pipeline exhausted. Stopped fetching news at ${new Date().toISOString()}. All retries + cache + fallback exhausted. Will resume when VPS recovers.`,
      context: {
        serviceName: "vn-news-fetch.service",
        vpsBreakerState: context.breakerState,
        lastSuccessMinutesAgo: context.minutesSinceLastSuccess,
        fallbacksAttempted: ["cache", "domestic_rss"],
        errorLog: context.errorLog.slice(-3),  // last 3 errors
      }
    });
    // Update agent state in DB
    db.run(
      "UPDATE agent_status SET last_failure_at = ?, failure_reason = ?, status = ? WHERE agent_name = ?",
      [new Date().toISOString(), "vps_exhausted_all_fallbacks", "degraded", "01-news-scout"]
    );
  }
});
```

**Output**: Telegram WORK message visible to developer team, agent log updated, agent status = "degraded".

**DDD layer**: application/usecases (agent-level), interface/scheduler (job invocation)

**File**: Injected into agent .md files (Step 0c loop); implemented in `src/application/usecases/newsScoutRun.ts` etc.

### FR-6: Agent-Level Fallback Decision Tree (Step 0c)

**Description**: Each agent's Step 0 (init) extended with fallback health check.

**Pseudocode for 01-News-Scout agent**:
```
STEP 0: Initialize
  0a. Read watchlist tickers from DB
  0b. Load circuit breaker states for all services (prices, news, bctc, sbv, foreign_flow)
  0c. FOR EACH service:
        IF circuit_breaker[service].state == "open":
          log("service in circuit breaker OPEN; will use fallbacks")
          serviceHealth[service] = { useFallback: true, breakerState: "open" }
        ELSE IF time_since_last_success[service] > THRESHOLD[service]:
          log("service stale; will try VPS once, then fallback")
          serviceHealth[service] = { useFallback: true, staleness: "stale" }
        ELSE:
          serviceHealth[service] = { useFallback: false }

STEP 1: Fetch news (using resilientFetcher + newsSourceRouter)
  IF serviceHealth["news"].useFallback:
    routes = newsSourceRouter(...)  // returns { primary, fallbacks, shouldUseFallback }
    news = await resilientFetcher(routes, context)
  ELSE:
    news = await fetchVpsNews(...)

... (similar for prices, BCTC, FX, foreign flow)
```

**Business rule**: No agent action is cancelled due to VPS failure; all agents attempt fallback gracefully.

**DDD layer**: interface/scheduler (job-level logic injected into agent .md files)

**File**: Updated agent .md files in `.claude/agents/` — Step 0c section + decision trees per service

## Non-Functional Requirements

### Performance
- **Resilient fetcher orchestration**: Total operation must complete within 180s (15min)
  - Primary retries: max 3 × (1s + 2s + 4s + 8s) backoff = 21s
  - Fallback attempts: 2 × 30s timeout = 60s
  - Total: ~81s (acceptable within 180s budget)
- **Circuit breaker checks**: O(1) per service, <1ms per check
- **Fallback router decision**: <10ms (in-memory decision tree)

### Data Freshness
- **Prices**: Accept cache staleness up to 6h (trigger watchdog alert at 4h)
- **News**: Accept cache staleness up to 1h; accept domestic RSS (5-15min stale)
- **BCTC**: Accept cache staleness indefinite (quarterly release frequency)
- **FX rates**: Accept cache staleness up to 2h
- **Foreign flow**: Accept cache staleness up to 1h

### Language
- **Agent .md files**: Vietnamese + English (existing bilingual standard)
- **Fail-loud messages**: English technical clarity (dev team audience)
- **Fallback metadata**: Include `source_fallback: true` + `fallback_tier: 1 | 2 | 3` in all signal payloads

### DDD Compliance
- **No circular imports**: `resilientFetcher.ts` (domain) has zero imports from infrastructure
- **Routers in infrastructure**: `newsSourceRouter.ts`, `priceSourceRouter.ts`, `bctcSourceRouter.ts` may import domain (circuits, constants) but zero back-imports
- **Agent orchestration**: job files may call `resilientFetcher` + routers, no import violations

## Edge Cases & Data Quality

| Case | Handling |
|------|----------|
| **VPS intermittent (fails 2/5 times)** | Circuit breaker half-open; resilient fetcher retries 3x with backoff, then cache |
| **Cache empty** (first run, no historical data) | Return null, escalate fail-loud |
| **Fallback stale** (cache from 8 days ago, BCTC from Q2 when in Q3) | Accept with `staleness_warning: true` annotation; agent logs warning |
| **All three fallbacks fail** (VPS down, cache corrupted, domestic RSS bot-blocked) | Escalate fail-loud to WORK channel; agent stops processing that service |
| **Partial failure** (prices work, news fails) | Continue with prices; escalate news only |
| **Vietnamese RSS character encoding** (UTF-8 + entities) | `rss.ts` already handles via `decodeHtmlEntities`; no new work |
| **Fallback costs data loss** (missing HNX/UPCOM from Yahoo) | Accept; mark with `coverage_gap: "HNX/UPCOM unavailable from fallback"` |
| **Timeout on fallback** (domestic RSS 503 timeout) | Treat as fetch failure; try next fallback, don't retry same fallback |

**Given** a primary fetcher is failing (simulated via mock throwing errors)

## Risk Assessment

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|-----------|
| **Domestic RSS fallback triggers bot-blocking** | Medium | High (news gap) | Opt-in feature; rate-limit domestic calls to 1/min; monitor via user feedback channel |
| **Fallback metadata bloat** (alerts 2x larger with fallback fields) | Low | Low | Fields are optional; pruned in archived alerts after 7 days |
| **Negative sentiment from stale prices** ("Why did alert trigger on 2h old price?") | Medium | Medium | Include `fetched_at` + `staleness_minutes` in all alerts; user educates via briefing |
| **Cache poisoning** (corrupted BCTC in DB, fallback perpetuates it) | Low | High | Add `bctcValidator.isValid()` check before using cache; re-validate quarterly |
| **Exponential backoff + timeout = long agent cycles** (agent slower to respond) | Low | Low | Total 180s budget acceptable for daily/2h cycles; no impact on 5min/15min cycles |
| **Circular logic** (fallback tries VPS again via circuit breaker check, infinite loop) | Very Low | High | Fallback routers never call primary after exhaustion; circuit breaker checks are read-only |
