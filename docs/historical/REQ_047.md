# REQ-047: BCTC Extraction Repair

status: READY_FOR_ARCHITECT
sprint: 047
po_vision: Repair the three broken layers of the BCTC extraction pipeline so that VNM, FPT, VCB, and VEA yield correct financial data.

---

## User Story

As a Vietnamese stock investor using Claude,
I want BCTC financial numbers (total assets, net revenue, net profit, EPS) for watchlist
stocks to be correct and non-zero after SSC PDF extraction,
So that conviction scoring, ratio computation (ROE, ROA, margins), and fundamental
analysis tools produce reliable investment signals.

---

## Background & Root Cause Summary

Three independent bugs block all fundamental analysis:

**Bug 287 — Wrong row match in balanceSheetExtractor**
`findValue()` scans lines top-to-bottom and returns the first line matching a pattern.
For "Tổng cộng tài sản", the regex `P_TOTAL_ASSETS` can match a section-header row or
sub-total row before reaching the grand-total line. Real VNM PDFs (via pdf-parse) produce
multi-column layouts where each data row ends with two numbers (e.g. current-year and
prior-year columns). `extractNumber()` grabs the last token on the line which is correct
when a single number exists, but section headers that have a number in the label (e.g.
"Mã số 270") can pollute the scan.

Additionally, the PDF header "Đơn vị tính: Triệu đồng" vs "Đơn vị tính: Tỷ đồng" is
currently ignored. If a report uses tỷ đồng, all stored values are off by 1000×.
The schema stores values as triệu đồng by convention (scaleUnit: 1000 in bctc-schema.ts).

**Bug 288 — Diacritic loss in pdf-parse output for incomeStatementExtractor**
pdf-parse often drops or corrupts Vietnamese diacritics during text extraction from
SSC-sourced PDFs. Current regex patterns in `incomeStatementExtractor.ts` require
diacritic-precise strings (e.g. "thuần", "hoạt động"). Without diacritics the text
becomes "thuan", "hoat dong" and zero-matches every pattern, returning 0 for all fields.
The existing balanceSheetExtractor patterns already use character-class alternations
(e.g. `[àa]`, `[ảa]`) but these are incomplete — they cover only some accents and miss
NFD decomposition artifacts.

**Bug 289/290 — checkSscReports discards discovered URL and re-runs SSC listing**
`checkSscReports` calls `listDocsFn(code)` and receives `doc.url` (the exact PDF URL).
It passes `{ actionCode, pdfUrl: doc.url, publishedAt }` to `pipelineFn`. The default
`pipelineFn` (`defaultPipeline`) ignores `pdfUrl` entirely and calls:

```ts
fetchParseAndStoreBctc({ actionCode, year, quarter: "Q1" })
```

This causes two problems:
1. Re-runs SSC listing from scratch (redundant network call, Puppeteer launch, rate limit).
2. Hard-codes `quarter: "Q1"` regardless of the actual document quarter, corrupting the
   `FiscalPeriod.sortKey` and `FiscalPeriod.quarter` stored in SQLite.

## Functional Requirements

### FR-1: Unit-header detection in balanceSheetExtractor

- **Description**: Before scanning for financial values, parse the PDF header line to detect
  the declared unit. Apply a multiplier so all values are stored in triệu đồng.
- **Input**: `rawText: string` — full PDF text from pdf-parse
- **Output**: `BalanceSheet` with all monetary fields in triệu đồng
- **Business rules**:
  - Scan for a line matching `/đ[oơ]n\s+v[iị]\s+(t[íi]nh|:)\s*:?\s*(tri[eệ]u|trieu)/i`
    → unit is triệu đồng → multiplier = 1 (no conversion needed)
  - Scan for a line matching `/đ[oơ]n\s+v[iị]\s+(t[íi]nh|:)\s*:?\s*t[yỷ]/i`
    → unit is tỷ đồng → multiplier = 1000 (multiply all extracted values by 1000)
  - When no unit header is found → default multiplier = 1, log a warning
  - Apply multiplier to every monetary field except EPS (EPS is in VND/share, not triệu đồng)
- **DDD layer**: domain

### FR-2: Wrong-row guard in balanceSheetExtractor

- **Description**: `findValue()` must skip data-less rows and rows where the trailing
  token is a row-code number (e.g. "270", "100") rather than a financial amount.
- **Input**: individual line string after pattern match
- **Output**: numeric value or null (skip and continue scan)
- **Business rules**:
  - A valid data line must end with a numeric token representing an amount.
  - Row codes are typically 1-3 digit integers that appear as part of the line prefix
    (e.g. "270  Tổng cộng tài sản"). The trailing number on such a line is the amount,
    not the row code.
  - Guard: if `extractNumber(line)` returns a value that is a whole integer in range
    [1, 999] AND the entire line contains no dot-separated or comma-separated larger
    number, treat the match as a row-code artifact and continue scanning.
  - Grand-total lines in real VNM PDFs (total assets ~60,000,000 triệu) will always
    produce values far above the 999 threshold.
  - When a line has two numbers (current-year and prior-year columns), `extractNumber`
    already takes the last token, which is the prior-year column. This is acceptable for
    the smoke test as long as the value is in the correct order of magnitude.
- **DDD layer**: domain

### FR-3: Diacritic-stripped fallback patterns in incomeStatementExtractor

- **Description**: Add ASCII-fallback regex patterns for every income statement line item.
  When the primary diacritic-full pattern fails, the ASCII pattern must match the
  diacritic-stripped equivalent that pdf-parse produces.
- **Input**: `rawText: string` — may contain fully-diacritic, partially-diacritic, or
  fully-stripped Vietnamese text
- **Output**: `IncomeStatement` with all populated fields (non-zero for a real BCTC PDF)
- **Business rules**:
  - Normalization: before splitting into lines, apply Unicode NFC normalization
    (`rawText.normalize("NFC")`) to consolidate decomposed diacritics.
  - For each pattern, provide a companion diacritic-stripped pattern using plain ASCII.
    Example: `P_NET_REVENUE` primary = `/doanh\s+thu\s+thu[ầa]n/i`,
    fallback = `/doanh\s+thu\s+thuan/i`.
  - `findValue()` must try the primary pattern first. Only if no matching line with a
    valid number is found does it try the fallback pattern on the same line array.
  - An alternative implementation is a single preprocessing step: strip all diacritics
    from the entire rawText using Unicode NFD + strip combining characters, then run
    simplified ASCII-only patterns. Either approach is acceptable as long as it passes
    all existing tests and the new real-PDF assertions.
  - The existing diacritic-tolerant character-class patterns in `balanceSheetExtractor`
    (e.g. `[àa]`, `[ảa]`) cover partial cases but are incomplete for all NFD artifacts.
    Apply the same NFC normalization + ASCII fallback strategy to `balanceSheetExtractor`
    as well to keep both extractors consistent.
- **DDD layer**: domain

### FR-4: Optional pdfUrl parameter in fetchParseAndStoreBctc

- **Description**: Add an optional `pdfUrl` field to `FetchParseAndStoreBctcParams`.
  When `pdfUrl` is provided, Step 1 (listSscDocuments) is skipped entirely and the known
  URL is used directly as `doc.url` in Step 2.
- **Input**:
  ```ts
  interface FetchParseAndStoreBctcParams {
    actionCode: string;
    year: number;
    quarter: QuarterString;
    pdfUrl?: string;          // NEW: if set, skip SSC listing
    sscHttpClient?: BrowserFactory;
    pdfHttpClient?: HttpClient;
    pdfTextOverride?: string;
    insertAnalysisFn?: InsertAnalysisFn;
  }
  ```
- **Output**: `FinancialReport | null` — same as before
- **Business rules**:
  - When `pdfUrl` is provided AND non-empty: log "[step 1 SKIPPED — pdfUrl provided]"
    and jump directly to Step 2 using `pdfUrl` as the document URL.
  - The synthetic `SscDocument` used internally should set `publishedAt` to empty string
    when not provided (it will be overwritten later by the caller).
  - When `pdfUrl` is NOT provided or is empty: existing behavior (call `listSscDocuments`)
    is unchanged.
  - `pdfTextOverride` still takes precedence over real PDF download regardless of
    whether `pdfUrl` is set (test shortcut remains functional).
- **DDD layer**: application

### FR-5: Quarter derivation from publishedAt in checkSscReports

- **Description**: `defaultPipeline` in `checkSscReports` must derive the fiscal quarter
  from `params.publishedAt` and pass it along with `params.pdfUrl` to
  `fetchParseAndStoreBctc`, instead of hard-coding `quarter: "Q1"` and ignoring the URL.
- **Input**: `PipelineParams { actionCode, pdfUrl, publishedAt }`
  where `publishedAt` is a date string from the SSC portal (format: "DD/MM/YYYY" or
  ISO 8601 "YYYY-MM-DD", depending on the scraper).
- **Output**: `fetchParseAndStoreBctc` called with correct `{ actionCode, year, quarter, pdfUrl }`
- **Business rules**:
  - Parse `publishedAt` date: try "DD/MM/YYYY" first, then ISO 8601.
  - Derive fiscal quarter from publish month using Vietnamese reporting calendar:
    - Published Jan–Apr → Q4 of prior year (annual/Q4 filing deadline is April)
    - Published May–Jul → Q1 of current year
    - Published Aug–Oct → Q2 of current year
    - Published Nov–Dec → Q3 of current year
  - When `publishedAt` is empty or unparseable: fall back to Q1 of current year
    (existing behavior), log a warning.
  - Pass `pdfUrl: params.pdfUrl` directly to `fetchParseAndStoreBctc`.
  - This derivation does not need to be 100% accurate for all edge cases — it replaces
    the obviously wrong hard-coded "Q1" and handles the common case. Task 290 is P1.
- **DDD layer**: application

### FR-6: Integration smoke test for VNM real PDF

- **Description**: A new test file reads the real VNM consolidated BCTC PDF from
  `data/pdfs/BCTC VNM 31.12.2025 - HOP NHAT - VN.pdf`, extracts text via pdf-parse,
  runs both extractors, and asserts correct magnitudes and non-zero income fields.
- **Input**: Real VNM PDF file at known path
- **Output**: Test assertions (pass/fail)
- **Business rules**:
  - totalAssets: value in range [50,000,000 – 70,000,000] triệu (VNM ~60,000 tỷ)
  - netRevenue: > 0
  - grossProfit: > 0
  - netProfit: > 0
  - eps: > 0
  - totalLiabilitiesAndEquity approximately equals totalAssets (within 1%)
  - The smoke test is tagged `@smoke` and is skipped in CI if the PDF file is absent
    (guards against missing fixture in fresh clone).
  - A second fixture is needed for FPT. If no FPT PDF exists in `data/pdfs/`, the FPT
    assertions are skipped (see Blockers — B1).
- **DDD layer**: infrastructure (file I/O) + domain (extraction logic)

## Non-Functional Requirements

- **Performance**: extractBalanceSheet and extractIncomeStatement must complete in < 200 ms
  for a 200-page PDF (pdf-parse output typically 50,000–200,000 characters). No I/O in
  domain functions.
- **Data freshness**: PDF fixtures used in the smoke test are static files committed to
  `data/pdfs/`. They are not re-downloaded by the test suite.
- **Language**: Log messages in English (existing convention). Vietnamese text appears only
  in extracted content and Telegram alerts.
- **Backward compatibility**: All existing tests in `042-bctc-balance-sheet.test.ts` and
  `043-bctc-income-stmt.test.ts` must continue to pass without modification. The NFC
  normalization step must be transparent for existing synthetic test samples.
- **Zero type errors**: `bun tsc --noEmit` must pass after all changes.

## Edge Cases & Data Quality

- [x] PDF header uses "Đơn vị tính: Triệu đồng" (most common) — multiplier = 1
- [x] PDF header uses "Đơn vị tính: Tỷ đồng" (less common, some banks) — multiplier = 1000
- [x] PDF header absent entirely — default multiplier = 1, log warning
- [x] Diacritics fully present — primary patterns match, no fallback needed
- [x] Diacritics fully stripped (pdf-parse artifact) — ASCII fallback patterns match
- [x] Diacritics partially stripped (NFD decomposition) — NFC normalization resolves
- [x] Multi-column layout (current year + prior year) — `extractNumber` takes last token
- [x] Row codes 1–999 at end of header lines — row-code guard in FR-2
- [x] Vietnamese negative format (1.234.567) — already handled by parseVnNumber
- [x] Parenthesized negatives (100.000) — already handled by parseVnNumber
- [x] Empty PDF / zero-length text — extractors return zeroed objects (existing behavior)
- [x] publishedAt in "DD/MM/YYYY" format from SSC portal scraper — parse in FR-5
- [x] publishedAt in ISO 8601 format — parse in FR-5
- [x] publishedAt empty string — fallback to Q1/current year with warning in FR-5
- [x] pdfUrl is an ssc-adf:// URI — FR-4 passes it through; existing Step 2 branch handles it
- [x] FPT PDF not present in data/pdfs/ — FR-6 smoke test skips FPT assertions gracefully

## Blockers (STOP — user must answer before coding)

- [ ] **B1**: Is there a real FPT BCTC PDF available locally for the smoke test (Task 291)?
  The `data/pdfs/` directory contains only two files:
  - `BCTC VNM 31.12.2025 - HOP NHAT - VN.pdf`
  - `000000015802468_Bao_cao_tai_chinh_Rieng_nam_2025.pdf` (unknown stock — likely VNM rieng le)

  Should the smoke test:
  (a) use only VNM and skip FPT assertions, OR
  (b) also test FPT using the second PDF if it turns out to be FPT, OR
  (c) download a real FPT PDF from SSC during test setup (requires network)?

  **Recommended default if no answer**: use only VNM consolidated PDF for the smoke test;
  FPT is tested via synthetic diacritic-stripped sample. Task 291 scope reduced accordingly.

- [ ] **B2**: For FR-2 (wrong-row guard), the threshold "trailing integer in [1, 999]
  is a row code" is a heuristic. Are there any legitimate financial line items in Vietnamese
  BCTC where the reported value is genuinely ≤ 999 triệu (i.e. less than 1 billion VND)?
  For large-cap stocks (VNM, FPT, VCB) this is extremely unlikely. For small caps it could
  occur. Should the guard apply only when the extracted value is in [1, 999] AND the value
  matches a known row-code range (100–999 in increments of 10), or is the simpler
  magnitude threshold acceptable?

  **Recommended default if no answer**: apply the guard only for values in [1, 999] that
  are also multiples of 10 (row codes are typically 100, 110, 120, ... 270, 300, etc.).
  Non-round numbers < 999 triệu are treated as valid amounts.

## Acceptance Criteria

### AC-1: Unit-header detection (Task 287a)

**Given** a raw PDF text with header "Đơn vị tính: Tỷ đồng"
**When** `extractBalanceSheet(rawText)` is called
**Then**
- All monetary fields are multiplied by 1000
- A unit multiplied text with "Tổng cộng tài sản: 60.000" returns totalAssets = 60,000,000

### AC-2: Wrong-row guard (Task 287b)

**Given** a raw PDF text where the first line matching P_TOTAL_ASSETS ends with "270" (row code)
and a subsequent line ends with "60.000.000" (the actual value)
**When** `extractBalanceSheet(rawText)` is called
**Then**
- totalAssets = 60,000,000 (the second match is used, not the row-code line)

### AC-3: Diacritic fallback — fully stripped (Task 288)

**Given** a raw PDF text where all Vietnamese diacritics have been stripped by pdf-parse
(e.g. "Doanh thu thuan ve ban hang", "Loi nhuan gop")
**When** `extractIncomeStatement(rawText)` is called
**Then**
- netRevenue > 0
- grossProfit > 0
- netProfit > 0
- eps > 0
- All fields that are present in the text are non-zero

### AC-4: Diacritic fallback — NFC normalization (Task 288)

**Given** a raw PDF text with NFD-decomposed diacritics (combining characters separate from base)
**When** `extractIncomeStatement(rawText)` is called with NFC normalization applied internally
**Then**
- All existing test samples in `043-bctc-income-stmt.test.ts` pass without modification

### AC-5: pdfUrl passthrough skips SSC listing (Task 289)

### AC-7: checkSscReports passes doc.url and correct quarter (Task 290)
