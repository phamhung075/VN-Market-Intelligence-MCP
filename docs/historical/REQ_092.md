# REQ-092 — feat(briefing): Integrate TA Signals (RSI/SMA) into Morning Briefing

```
status: READY_FOR_ARCHITECT
sprint: 092
po_vision: Morning briefing shows prices only — adding RSI overbought/oversold and
           price-vs-SMA20 makes it actionable without requiring a separate tool call.
```

---

## User Story

As a Vietnamese stock investor using Claude,
I want the daily morning Telegram briefing to include an RSI and SMA20 status section
for each watchlist ticker that has a non-neutral signal,
So that I can immediately see which stocks are technically extended or trending
without manually calling `get_technical_indicators` for each ticker.

---

## Functional Requirements

### FR-1: New `TaSignal` type and `taSummary` field on `DailyBriefing`

- **Description:** Add a `TaSignal` interface and a `taSummary` optional field to `DailyBriefing` in `assembleBriefing.ts`.
- **Input:** Nothing — type definition only.
- **Output:**
  ```ts
  export interface TaSignal {
    code: string;
    rsi14: number | null;
    rsiStatus: "overbought" | "oversold" | "neutral";
    ma20: number | null;
    priceVsMa20: "above" | "below" | "neutral";
    currentPrice: number | null;
  }
  ```
  `DailyBriefing.taSummary?: TaSignal[]` — optional; absent means no signals computed (pre-1304 briefings remain valid).
- **Business rule:** Only tickers with `rsiStatus !== "neutral" || priceVsMa20 !== "neutral"` are included. Tickers where both signals are neutral are silently skipped.
- **DDD layer:** domain (type) + application (field on `DailyBriefing`)

---

### FR-2: `AssembleBriefingOptions` — inject TA compute function

- **Description:** Add an optional `computeTaFn` injectable to `AssembleBriefingOptions` so tests can stub the TA computation without a real DB.
- **Input:** `computeTaFn?: (code: string, db: Database) => TaSignal | null`
- **Output:** If omitted, `assembleBriefing` uses the default implementation (FR-3).
- **Business rule:** The injected function receives one ticker and the active DB; it returns `null` when data is insufficient (< 20 candles for SMA20, < 15 candles for RSI).
- **DDD layer:** application (`assembleBriefing.ts` — `AssembleBriefingOptions`)

---

### FR-3: Step 17 — TA signals assembly in `assembleBriefing.ts`

- **Description:** Add Step 17 (after Step 16) that iterates `watchlistRows`, calls `computeTaFn` per ticker (or the default impl), filters to non-neutral results, and stores in `taSummary`.
- **Input:** `watchlistRows` (already fetched in Step 5); `db` (already available).
- **Output:** `taSummary: TaSignal[]` — zero or more non-neutral signal entries.
- **Business rule (default impl):**
  1. Query `market_prices_history` for the ticker: `SELECT date(fetched_at) AS day, AVG(price) AS close_price FROM market_prices_history WHERE code = ? AND fetched_at >= datetime('now', '-60 days') GROUP BY day ORDER BY day ASC` — identical SQL to `technicalIndicatorTools.ts`.
  2. Map rows to `DailyCandle[]`.
  3. Call `computeRSI(prices, 14)` and `computeMA(prices, 20)` from `technicalIndicators.ts` (domain service, already built in Task 1302).
  4. Classify:
     - `rsiStatus`: `rsi14 > 70` → `"overbought"` | `rsi14 < 30` → `"oversold"` | otherwise `"neutral"`.
     - `priceVsMa20`: `currentPrice > ma20` → `"above"` | `currentPrice < ma20` → `"below"` | otherwise `"neutral"`.
  5. Return `null` if candles < 15 (RSI minimum). `ma20` will be `null` if candles < 20; `priceVsMa20` defaults to `"neutral"` when `ma20 === null`.
- **Error handling:** Wrapped in `try/catch`; failure does not abort the briefing. `taSummary` defaults to `[]` on error. Log warning with `logger.warn("[assembleBriefing] taSummary step failed")`.
- **DDD layer:** application (`assembleBriefing.ts` — Step 17)

---

### FR-4: `formatBriefingMessage` — new "TA Tín hiệu:" section

- **Description:** Add a "TA Tín hiệu:" section to `formatBriefingMessage` in `morningBriefingJob.ts`. Section is appended after "Tích Lũy Bằng Chứng" and before the final `return`.
- **Input:** `briefing.taSummary: TaSignal[] | undefined`
- **Output format (plain-text, no Markdown):**
  ```
  📡 TA Tín hiệu:
    VCB: RSI=72.3 (quá mua) | giá trên MA20
    HPG: RSI=28.1 (quá bán)
    FPT: giá dưới MA20
  ```
  Rules:
  - Section header: `"📡 TA Tín hiệu:"`.
  - Per-ticker line: `"  {CODE}: {rsi_part} {ma_part}"` where parts are omitted when neutral:
    - `rsi_part`: `"RSI={rsi14.toFixed(1)} (quá mua)"` when overbought, `"RSI={rsi14.toFixed(1)} (quá bán)"` when oversold, empty string when neutral.
    - `ma_part`: `"| giá trên MA20"` when above, `"| giá dưới MA20"` when below, empty string when neutral.
    - When both parts are present, joined with a space.
  - Section is omitted entirely when `taSummary` is absent, undefined, or empty.
- **DDD layer:** interface/scheduler (`morningBriefingJob.ts` — `formatBriefingMessage`)

## Non-Functional Requirements

| Attribute | Requirement |
|-----------|-------------|
| Performance | TA computation per ticker is pure math + one SQLite SELECT. For 30 watchlist tickers the step adds < 50 ms total at briefing assembly time. |
| Data freshness | Uses `market_prices_history` populated by the VPS price proxy every 60 s during market hours. At briefing time (08:00 GMT+7, pre-open), data represents the previous session's close. |
| Language | Mixed: section header and field labels in Vietnamese. RSI value numeric. Status labels ("quá mua", "quá bán", "trên MA20", "dưới MA20") in Vietnamese. |
| Backwards compat | `taSummary` is optional (`?`) on `DailyBriefing` — all existing briefing JSON files and tests remain valid without the field. |
| No new dependencies | Uses `computeRSI` and `computeMA` already exported from `technicalIndicators.ts`. No new imports beyond what assembleBriefing already has. |

## Edge Cases & Data Quality

| Case | Handling |
|------|----------|
| Ticker has 0 rows in `market_prices_history` | `computeTaFn` returns `null`; ticker silently skipped. |
| Ticker has 1–14 candles (< RSI minimum 15) | `computeRSI` returns `null`; `rsiStatus = "neutral"`. `ma20` also null if < 20. Both neutral → ticker excluded from `taSummary`. |
| Ticker has 15–19 candles (RSI computable, SMA20 not) | RSI classified, `ma20 = null`, `priceVsMa20 = "neutral"`. Ticker included if RSI is overbought/oversold. |
| `currentPrice` is null (no market_prices row) | Use last candle's `close` as `currentPrice`. If candles is empty, `currentPrice = null`; `priceVsMa20 = "neutral"`. |
| VPS proxy offline → `market_prices_history` stale | Computation proceeds on available data. Old data may produce stale signals. No special handling required — user already sees stale price in "Giá cổ phiếu" section. |
| RSI exactly 70 or 30 | `> 70` and `< 30` thresholds are strict (not ≥/≤). RSI = 70.0 → neutral. RSI = 70.1 → overbought. |
| All 30 watchlist tickers neutral | `taSummary = []`. Section omitted in formatter. No empty section emitted. |
| `computeTaFn` throws | Wrapped in try/catch per ticker inside Step 17; that ticker is skipped. Outer step-level try/catch ensures `taSummary` defaults to `[]`. |
| Vietnamese number format in `market_prices_history` | Price column is numeric in SQLite (REAL). No parsing needed. AVG() is safe. |
| `market_prices_history` table does not exist | SQLite throws; caught by step-level try/catch. `taSummary = []`. Warning logged. |

## Implementation Notes for Architect

### Data fetch pattern (matches existing tool)

```ts
// Step 17 default impl — mirrors technicalIndicatorTools.ts lines 301–309
interface CandleRow { day: string; close_price: number; }
const rows = db.query<CandleRow, [string, string]>(
  `SELECT date(fetched_at) AS day, AVG(price) AS close_price
     FROM market_prices_history
    WHERE code = ?
      AND fetched_at >= datetime('now', ?)
    GROUP BY date(fetched_at)
    ORDER BY day ASC`,
).all(code, "-60 days");
const prices = rows.map(r => r.close_price);
const currentPrice = prices.at(-1) ?? null;
```

### Signal classification thresholds

| Signal | Condition | Label |
|--------|-----------|-------|
| RSI overbought | `rsi14 > 70` (strict) | `"overbought"` |
| RSI oversold | `rsi14 < 30` (strict) | `"oversold"` |
| RSI neutral | `30 <= rsi14 <= 70` or `rsi14 === null` | `"neutral"` |
| Price above MA20 | `currentPrice > ma20` (both non-null) | `"above"` |
| Price below MA20 | `currentPrice < ma20` (both non-null) | `"below"` |
| Price vs MA20 neutral | either null, or equal | `"neutral"` |

### Filter rule

```ts
taSummary = signals.filter(
  s => s.rsiStatus !== "neutral" || s.priceVsMa20 !== "neutral"
);
```

| oversold | `RSI=${rsi14.toFixed(1)} (quá bán)` |
| above MA20 | `\| giá trên MA20` |
| below MA20 | `\| giá dưới MA20` |
