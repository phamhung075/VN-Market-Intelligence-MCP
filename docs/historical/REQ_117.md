# REQ-117: fix(france-summary-cron) — Widen cron window to survive server restarts

status: READY_FOR_ARCHITECT
sprint: 117
po_vision: franceSummaryJob fires exactly once per market weekday even when the server restarts during the 06:00-09:00 UTC window

## User Story

As a Vietnamese stock investor based in France,
I want the morning digest to arrive reliably every weekday morning (08:00 CET),
So that I always have VN market context before the Paris market opens — even on days when the MCP server was restarted during active development.

## Problem Statement

Production evidence: `france-summary` last sent 2026-04-14. Zero sends on 2026-04-15, 2026-04-16, 2026-04-17 (3 consecutive weekdays missed).

Root cause: `CRONS.franceSummary` default is `'0 7 * * 1-5'` — a single fire-point at 07:00 UTC. When the server is restarted after 07:00 UTC (common during active development sprints), the cron has already passed for the day and the digest is silently skipped. The `alreadySentToday()` dedup guard introduced in Sprint 115 (Task 1345) is correct and sufficient — it just never gets the chance to fire.

Fix strategy: widen the cron window from a single point to a rolling 30-minute interval across the 06:00-08:59 UTC band (`*/30 6-8 * * 1-5`). The existing `alreadySentToday()` guard prevents duplicate sends when the cron fires multiple times in the same day.

## Functional Requirements

### FR-1: Widen cron window

- Description: Change `CRONS.franceSummary` default from single-point `'0 7 * * 1-5'` to `'*/30 6-8 * * 1-5'`
- Input: `Bun.env.CRON_FRANCE_SUMMARY` env var (override path unchanged)
- Output: cron fires at 06:00, 06:30, 07:00, 07:30, 08:00, 08:30 UTC on Mon-Fri
- Business rule: env override `CRON_FRANCE_SUMMARY` takes precedence — the default changes only
- DDD layer: interface/scheduler (`src/scheduler/jobs.ts`, line 121)
- Change: one-line default string replacement in the `CRONS` object

### FR-2: Dedup guard (existing — no change required)

- Description: `alreadySentToday()` in `franceSummaryJob.ts` reads `market_messages WHERE from_agent = 'france-summary' AND sent_at >= date('now')` — blocks duplicate sends when the cron re-fires within the same calendar day
- Status: IMPLEMENTED in Sprint 115 (Task 1345). No modification needed.
- Validation: new TDD tests (Task 1348) must confirm guard still works under the wider cron window

### FR-3: `recordJobRun` wrapper (existing — no change required)

- Description: `franceSummary` cron callback already wraps `runFranceSummary` in `recordJobRun(getDb(), "franceSummaryJob", ...)` — job run history is persisted regardless of dedup outcome
- Status: IMPLEMENTED in `jobs.ts` lines 411-419. No modification needed.

## Non-Functional Requirements

- Performance: no impact — `runFranceSummary` is already idempotent; extra cron wakeups that hit `alreadySentToday()=true` return in < 1 ms (single COUNT query)
- Data freshness: digest sent at the first cron tick after server boot that falls within 06:00-08:59 UTC Mon-Fri, guaranteed at most 30-minute delay
- Language: Vietnamese (digest format unchanged)
- Timezone: cron scheduled with `{ timezone: 'UTC' }` (existing behavior preserved)

## Edge Cases & Data Quality

- [ ] Server restarts at 06:01 UTC — next tick at 06:30, digest sent then (acceptable)
- [ ] Server restarts at 08:45 UTC — no more ticks until next day; digest missed for that day (acceptable — outside the window)
- [ ] Server restarts at 07:15 UTC on a day when digest was already sent at 06:30 — `alreadySentToday()` blocks re-send (correct)
- [ ] `CRON_FRANCE_SUMMARY` env override set — env value takes full precedence, default not used (correct, no change to override path)
- [ ] Weekend / public holiday — `1-5` day-of-week filter unchanged; no sends Saturday/Sunday
