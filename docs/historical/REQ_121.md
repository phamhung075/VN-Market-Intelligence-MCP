# REQ-121: TaDiag Observability Block in Evening Summary

status: READY_FOR_ARCHITECT
sprint: 121
po_vision: Add TaDiag diagnostic block to EveningSummary JSON — expose daily_ohlcv row counts per ticker to diagnose taSummary always empty

## User Story

As a Vietnamese stock investor using Claude,
I want the evening JSON report to include a `taDiag` block showing how many tickers have TA signals and how many OHLCV rows each ticker has,
So that I can diagnose why `taSummary` is empty and confirm whether the VPS OHLCV backfill has run.

## Functional Requirements

### FR-1: TaDiag Interface

- Description: New exported TypeScript interface `TaDiag` in `assembleEveningSummary.ts`
- Input: Computed per-ticker counts collected during the taSummary assembly loop (Step 4)
- Output: `{ tickersWithSignal: number; tickersBelowThreshold: number; ohlcvRowsMin: number; ohlcvRowsMax: number }`
- Business rule:
  - `tickersWithSignal`: count of watchlist tickers for which `computeTaFn` returned a non-null `TaSignal`
  - `tickersBelowThreshold`: count of watchlist tickers where `getOhlcvRowCountFn(code)` returned < 8 (the `defaultComputeTa` guard threshold from Sprint 117)
  - `ohlcvRowsMin`: minimum row count across all watchlist tickers (0 when watchlist is empty or all throws)
  - `ohlcvRowsMax`: maximum row count across all watchlist tickers (0 when watchlist is empty or all throws)
  - When `computeTaFn` throws at the per-ticker level, treat that ticker as: no signal, row count = 0
  - When the outer taSummary block throws entirely, default all four fields to 0 — no crash
- DDD layer: application

### FR-2: taDiag Field on EveningSummary

- Description: Add `taDiag: TaDiag` to the `EveningSummary` interface
- Input: Computed `TaDiag` object from FR-1
- Output: `taDiag` present in the evening JSON file (`reports/YYYY-MM-DD-evening.json`)
- Business rule:
  - JSON report only — NOT passed to Telegram formatter
  - Parallel pattern to `predictionDiag` (Sprint 120): diagnostic-only, JSON-only
  - Telegram formatter (`eveningSummaryJob.ts`) must remain untouched
- DDD layer: application

### FR-3: getOhlcvRowCountFn Injectable Option

- Description: Add optional `getOhlcvRowCountFn?: (code: string, db: Database) => number` to `AssembleEveningSummaryOptions`
- Input: Ticker code + injected DB
- Output: Integer row count
- Business rule:
  - Default implementation: `SELECT COUNT(*) AS cnt FROM daily_ohlcv WHERE code = ?` — single query per ticker, synchronous (Bun SQLite `.get()`)
  - Injectable for tests: avoids real DB, injects deterministic row counts
  - Runs inside the existing taSummary ticker loop (Step 4) — no extra loop, no extra round-trips beyond what `defaultComputeTa` already does
  - Per-ticker errors from `getOhlcvRowCountFn` are swallowed (same guard as `computeTaFn` per-ticker catch)
- DDD layer: application

### FR-4: taSummary Assembly Loop Extension (Step 4)

- Description: Extend the existing taSummary loop in `assembleEveningSummary.ts` to collect `TaDiag` counters alongside TA signal computation
- Input: `watchlistRows` (all tickers from `watchlist` table), `computeTaFn`, `getOhlcvRowCountFn`
- Output: `taSummary: TaSignal[]` (unchanged) + `taDiag: TaDiag` (new)
- Business rule:
  - For each ticker: call `getOhlcvRowCountFn(code, db)`, then call `computeTaFn(code, db)`
  - Track `rowCounts: number[]` — push each ticker's count (0 on error)
  - Increment `tickersWithSignal` when `computeTaFn` returns non-null
  - Increment `tickersBelowThreshold` when row count < 8
  - After loop: `ohlcvRowsMin = Math.min(...rowCounts)` (or 0 if empty), `ohlcvRowsMax = Math.max(...rowCounts)` (or 0 if empty)
  - Outer try/catch defaults `taDiag` to `{ tickersWithSignal: 0, tickersBelowThreshold: 0, ohlcvRowsMin: 0, ohlcvRowsMax: 0 }`
- DDD layer: application

## Non-Functional Requirements

- Performance: One additional `COUNT(*)` query per watchlist ticker per evening run. Watchlist size is ~30 tickers. Total overhead: ~30 synchronous SQLite queries — negligible.
- Data freshness: Diagnostic reflects state of `daily_ohlcv` at the moment the evening job runs (22:00 GMT+7).
- Language: Field names and JSON keys are English. No Telegram output — no language requirement.
- TypeScript: `TaDiag` exported from `assembleEveningSummary.ts`. `bun tsc --noEmit` must pass clean.

## Edge Cases & Data Quality

- [x] Empty watchlist: loop runs 0 iterations — `taDiag` all zeros, no crash
- [x] `computeTaFn` throws per-ticker: caught by inner try/catch — ticker counts as no signal, row count defaults to 0
- [x] `computeTaFn` throws globally (outer try/catch): `taDiag` defaults to all zeros — same guard as current code
- [x] `getOhlcvRowCountFn` throws per-ticker: caught by same inner try/catch — row count defaults to 0
- [x] `daily_ohlcv` table empty for a ticker: COUNT returns 0 — ticker counted in `tickersBelowThreshold`
- [x] Threshold value: 8 rows (matches `defaultComputeTa` guard — Sprint 117 adaptive RSI/MA lowered guard from default to < 8)
- [x] `ohlcvRowsMin`/`ohlcvRowsMax` with single ticker: min === max === that ticker's count
- [x] JSON file write failure: already guarded by outer try/catch in Step 6 — no change needed

## Acceptance Criteria

### AC-1: All tickers have 15+ OHLCV rows — all return signals

**Given** a watchlist with 2 tickers, `getOhlcvRowCountFn` returns 15 for both, `computeTaFn` returns a non-null `TaSignal` for both

**Then**

- `taDiag.tickersWithSignal === 2`
- `taDiag.tickersBelowThreshold === 0`

## Implementation Notes for Architect / Developer

- Threshold constant: use literal `8` (matches `defaultComputeTa` guard, Sprint 117). No new config needed.
- Loop order: call `getOhlcvRowCountFn` first, then `computeTaFn` — both inside the same per-ticker inner try/catch block already present in Step 4.
- Default value for `taDiag` before loop: `{ tickersWithSignal: 0, tickersBelowThreshold: 0, ohlcvRowsMin: 0, ohlcvRowsMax: 0 }` — override with computed values after loop completes.
- Test injection pattern: mirrors `getPredictionSignalsFn` from Sprint 120 (`src/__tests__/1354-prediction-signals-fallback.test.ts`) — no `mock.module`, pure function injection.
- Test DB setup: `setupTestDb()` must include `daily_ohlcv` table (same schema as `schema.ts` lines 152-164) and `watchlist` table. Inject `getOhlcvRowCountFn` to avoid real DB dependency.
