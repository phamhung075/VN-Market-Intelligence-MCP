# REQ-1288: Foreign Flow Fallback Fetcher — Resilience Layer

**status:** READY_FOR_ARCHITECT
**sprint:** 1288
**po_vision:** Implement fetchForeignFlowWithFallback() with degradation chain (primary VPS → cache → SSE → empty) to provide data continuity when vn-foreign-flow.service is unavailable.

---

## User Story

As a Vietnamese stock analyst using Claude market briefings,
I want reliable foreign flow data even when the primary VPS endpoint is temporarily offline,
So that my trading decisions are based on continuous market intelligence rather than intermittent gaps.

---

## Context

**Background:** Sprint 1283 delivered circuit breaker diagnostics for foreign flow data. The primary data source (vn-foreign-flow.service at port 5005 on Vinahost VPS) occasionally experiences outages or network delays. Without a fallback strategy, the entire foreign flow alert subsystem becomes unavailable, creating false negatives in FDI signal detection.

**Solution:** Implement a multi-tier fallback fetcher that gracefully degrades data availability:
1. **Primary (fresh):** VPS endpoint with 5s timeout, circuit breaker protection
2. **Cache (recent):** In-memory cache from last successful fetch (if <2h old)
3. **SSE (broadcast):** Extract data from recent Telegram/SSE messages (if available)
4. **None (warning):** Return empty result with diagnostic logging

**Impact:** Foreign flow alerts continue during VPS recovery, dashboard shows partial data instead of no data, OPS has clear diagnostic trail for troubleshooting.

## Functional Requirements

### FR-1: Primary Endpoint with Circuit Breaker Protection

- **Description:** Fetch foreign flow data from VPS endpoint (port 5005), wrapped in circuit breaker to prevent cascade failures.
- **Input:**
  - VPS endpoint URL (from `Bun.env.VINAHOST_IP` or localhost:5005 fallback)
  - 5-second timeout enforced via AbortController
  - Circuit breaker state (closed/half-open/open)
- **Output:**
  - Array of `WriteForeignFlowItem[]` with schema: `{ code, date, foreignBuyVol, foreignSellVol, putThroughVol }`
  - Validated against `validateForeignFlowFetcherPayload()` (strict schema enforcement)
  - Throws on timeout (>5s), HTTP error (non-200), or schema mismatch
- **Business rule:**
  - Circuit breaker (`breakers.foreignFlow`) opens after 5 consecutive failures, resets after 30s
  - If circuit is OPEN, skip primary endpoint entirely (proceed straight to fallback)
  - If circuit is HALF-OPEN, attempt primary via circuit breaker (may re-open if fails)
  - Log recovery when circuit closes (primary endpoint came back online)
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:113–139`

### FR-2: Cache Fallback with Staleness Guard

- **Description:** Return in-memory cache from last successful primary fetch when primary fails.
- **Input:**
  - `lastSuccessCache` (module-level state) or `overrides.cacheStore.get("foreign_flow_last_fetch")`
  - Current timestamp for age calculation
- **Output:**
  - `{ changes: N, timestamp, source: "cache", warning?: "cache stale: Xmin old" }`
  - Preserved timestamp from cached fetch (not current time)
- **Business rule:**
  - Cache survives circuit breaker state transitions (stored in module state, not DB)
  - If cached data >2h old: include warning field for SLA checker escalation
  - Log staleness level in diagnostic output (used by monitoring)
  - Always return cache if available, even if stale (better than no data)
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:165–193`

### FR-3: Circuit Breaker State Awareness

- **Description:** Check breaker state before attempting primary; conditionally skip based on OPEN state.
- **Input:**
  - `breakers.foreignFlow.stats.state` (open|half-open|closed)
  - Current failure count (`breakers.foreignFlow.stats.failures`)
- **Output:**
  - Decision: attempt primary (if not open) or skip to fallback (if open)
  - Log message with breaker state + failure count if skipped
- **Business rule:**
  - PRIMARY RULE: If `breakers.foreignFlow.stats.state === "open"`, skip primary endpoint
  - HALF-OPEN: Attempt primary via circuit breaker (may re-open if fails)
  - CLOSED: Attempt primary normally
  - Log skip reason with breaker metrics for OPS debugging
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:109–144`

### FR-4: SSE Message Bus Fallback

- **Description:** Extract foreign flow data from recent Telegram/SSE broadcast messages when primary + cache unavailable.
- **Input:**
  - `overrides.sseMessageBus.getRecentMessages("foreign_flow:*", 10)` (up to 10 recent messages)
  - Each message format: `{ event: "signal:foreign_flow", data: WriteForeignFlowItem[] }`
- **Output:**
  - Extracted and deduplicated `WriteForeignFlowItem[]` array
  - `{ changes: M, timestamp, source: "sse" }`
  - Deduplication by (code, date) tuple before write
- **Business rule:**
  - Only activates if `overrides.sseMessageBus` is provided (optional fallback, not always enabled)
  - Extract all valid items from all recent messages, skip invalid items silently
  - Deduplicate by `(code, date)` pair (same stock on same date = same record)
  - Write deduped items to DB via `writeForeignFlowToOhlcv()`
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:199–221`

### FR-5: Validation + Error Handling

- **Description:** Validate VPS payload schema strictly; fail loudly on errors with diagnostic details.
- **Input:**
  - Raw JSON response from VPS endpoint
  - Validation result from `validateForeignFlowFetcherPayload()`
- **Output:**
  - `WriteForeignFlowItem[]` (only valid items) or throw with error details
  - Error message includes item index, field name, validation reason (first 5 errors)
- **Business rule:**
  - Strict schema validation: every field checked (code, date, foreignBuyVol, foreignSellVol, putThroughVol)
  - If validation fails: throw error with "validation failed" marker in message
  - Diagnostic error includes: item index, field name, reason, total error count
  - Log validation errors separately for schema change detection
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:278–293`

### FR-6: Graceful Degradation (All Fallbacks Exhausted)

- **Description:** Return empty result with warning when all sources (primary, cache, SSE) unavailable.
- **Input:** None (previous attempts all failed)
- **Output:**
  - `{ changes: 0, timestamp, source: "none", warning: "all fallbacks unavailable: check VPS endpoint + cache + SSE" }`
- **Business rule:**
  - Never return null or throw; always return result object
  - Warning field guides troubleshooting (list all checked sources)
  - Log level: warn (not error) since fallback mechanism is working as designed
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:227–237`

### FR-7: Diagnostic Logging on Fallback Activation

- **Description:** Log when fallback is activated (primary failed), including reason and metrics.
- **Input:**
  - Failure reason (timeout, validation error, circuit breaker open)
  - Circuit breaker stats (state, failures)
  - Cache metrics (age, row count)
  - SSE message count
- **Output:** Structured log entries with context
- **Business rule:**
  - Log primary failure reason (separate logs for timeout vs. validation vs. circuit open)
  - Log fallback source + metrics (cache age, SSE msg count, rows written)
  - Recovery logging: when primary comes back online, log "[fallback] primary endpoint recovered"
  - All logs use structured format: `{ timestamp, error, hint, metric1, metric2, ... }`
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:145–159, 178–182, 227–229`

### FR-8: Module State Management + Recovery Tracking

- **Description:** Maintain in-memory cache and recovery timestamp across function calls for resilience tracking.
- **Input:**
  - Successful primary fetch result
  - Fallback activation events
- **Output:**
  - `lastSuccessCache` (module variable) updated on successful primary
  - `lastRecoveryAt` timestamp logged when circuit closes
- **Business rule:**
  - `lastSuccessCache` is the SSOT for cache fallback (persists across circuit breaker state changes)
  - Update cache only on successful primary fetch (not on fallback)
  - `lastRecoveryAt` prevents duplicate recovery logs (checked before logging)
  - Reset functions available for testing: `resetFallbackCache()`, `resetCircuitBreaker()`
- **DDD layer:** infrastructure
- **File location:** `src/infrastructure/fetchers/foreignFlowFetcher.ts:69–73, 125–130, 133–136, 383–399`

## Non-Functional Requirements

### Performance

- **Primary fetch timeout:** 5 seconds (abort after 5000ms)
- **Fallback latency:** Cache fallback <1ms (in-memory), SSE fallback <10ms (array scan)
- **Circuit breaker reset timeout:** 30 seconds (aggressive recovery when VPS flickers)
- **Cache staleness threshold:** 2 hours (SLA checker flags ≥120 minutes old)

### Data Freshness & Reliability

- **Data continuity:** Fallback chain ensures data always available (never fully empty except explicit none state)
- **Cache age logging:** Minute-level precision (staleness field rounded to int minutes)
- **Validation strictness:** Schema validation fails loudly (do not silently skip invalid items); see FR-5
- **Deduplication:** SSE fallback dedups by (code, date) to prevent duplicate DB writes

### Language & Logging

- **Language:** English for log messages, code comments; Vietnamese terms in comments only for domain context
- **Structured logging:** All logs include timestamp (ISO 8601), source field (e.g., "[fallback]"), and metrics
- **Diagnostic hints:** Error messages include actionable troubleshooting steps for OPS (e.g., "Check VPS endpoint health")

### Integration Contracts

- **Circuit breaker:** Import `breakers.foreignFlow` from `src/infrastructure/circuitBreakerRegistry.ts`

- **Test injection:** All external dependencies injectable via `overrides` parameter (fetch, cache, SSE, now)

## Edge Cases & Data Quality

### Timeout Scenarios
- [ ] Primary fetch takes >5s → AbortError caught, fallback activates
- [ ] Timeout during SSE message processing → return partial results (continue extracting remaining messages)
- [ ] Cache lookup takes >100ms (unlikely) → continue to next fallback tier

### Schema Mismatches
- [ ] VPS returns `{ results: [...] }` instead of `{ data: [...] }` → throw "Invalid response format"
- [ ] VPS item missing `foreignBuyVol` → fail loudly with item index in error message
- [ ] VPS item has string `"100000"` instead of number `100000` → fail loudly, suggest schema change
- [ ] Empty array from VPS (`{ data: [] }`) → valid response, return 0 changes (proceed to fallback)

### Cache Consistency
- [ ] Circuit breaker open, cached data 8 days old → use cache, log "cache stale" warning
- [ ] Primary succeeds, cache updated while fallback in progress → no race condition (cache is module state, updated only in primary success path)
- [ ] Manual reset of circuit breaker after cache update → cache persists (reset only affects breaker, not cache)

### SSE Fallback Specifics
- [ ] SSE message with malformed event field → skip silently (type guard in `extractForeignFlowFromSseMessages`)
- [ ] SSE message data is null → skip silently, continue to next message
- [ ] SSE message is duplicate (code+date already in results) → deduplicate before write
- [ ] 10 recent SSE messages, only 3 valid → return 3 items (silence invalid ones)

### Vietnamese Market Data Specifics
- [ ] Stock code format: "VNM", "FPT", "BID" (uppercase 1-4 chars) → validated by `validateForeignFlowFetcherPayload`
- [ ] Date format: "2026-04-23" (YYYY-MM-DD) → required ISO string
- [ ] Volume fields: integers only, no decimals (billions of shares) → validated as `number` type
- [ ] Foreign flow on non-trading days (weekends) → VPS should not send, but fallback accepts if present

### Error Recovery & OPS Visibility
- [ ] Breaker HALF-OPEN: probes failing → diagnostic logs every 30s, OPS can call reset tool
- [ ] All fallbacks exhausted, breaker open, no cache, no SSE → warning with "all fallbacks unavailable"
- [ ] Primary validation fails with "schema change" indicator → log hint for OPS to investigate VPS schema

### AC-2: Cache Fallback on Primary Timeout

**Given** primary endpoint times out (>5s)
**When** `fetchForeignFlowWithFallback()` is called and cache has recent data
**Then**

- Primary timeout caught as AbortError
- Cache fetched from `lastSuccessCache` or `overrides.cacheStore`
- Cache age calculated: `(now - cachedAt) / 60_000` minutes
- If age <120min: returned as-is with `source: "cache"`, no warning
- If age ≥120min: returned with `warning: "cache stale: Xmin old"`, log at info level
- Result preserves original cache timestamp (not current time)

### AC-3: Circuit Breaker Respects State

**Given** circuit breaker is open (after 5+ consecutive failures)
**When** `fetchForeignFlowWithFallback()` is called
**Then**

- Primary endpoint is NOT attempted (skipped due to `state === "open"`)
- Log message: "[fallback] circuit breaker open, skipping primary"
- Fallback chain activated immediately (cache → SSE → none)
- Next call (after 30s) transitions circuit to half-open, primary re-attempted

**Test:** Task 1288a test 3, 4

- Deduped array written to DB via `writeForeignFlowToOhlcv()`
- Result returned with `source: "sse"`, `changes` = write count
- Log: "[fallback] using SSE broadcast data, itemCount: N"

## Implementation Notes for Architect

### Dependency Injection Strategy

All external dependencies injectable via `overrides` parameter to enable unit testing without mocks:

- `now()` — control current time (for staleness tests)
- `fetchFn()` — inject mock fetch (timeout/failure scenarios)
- `cacheStore` — in-memory cache (test isolation)
- `sseMessageBus` — mock SSE source (fallback testing)

**Production usage:** Pass no overrides; use defaults (real fetch, module state cache, real logger).

### Circuit Breaker State Machine

```
CLOSED → [5+ failures] → OPEN → [30s timeout] → HALF-OPEN → [1 success] → CLOSED
                                                  ↓ [1 failure] ↓
                                               OPEN (re-open)
```

**Fetcher logic:** If state is OPEN, skip primary entirely. If HALF-OPEN, attempt via breaker (may re-open).

### Logging Strategy

- **Primary success:** info level (normal operation)
- **Primary timeout:** warn level (transient issue, fallback active)
- **Primary validation failure:** warn level (schema mismatch, needs OPS attention)
- **Cache staleness (>2h):** info level (partial data, acceptable degradation)
- **All fallbacks exhausted:** warn level (no data available, needs investigation)
- **Circuit recovery:** info level (operational event, good news)

### Timestamp Handling

- Cache timestamp preserved (not replaced with current time)
- ISO 8601 format normalized: `.000Z` → `Z` for consistency
- Age calculation: `(Date.parse(now) - Date.parse(cached)) / 60_000` minutes
