## Task 065 — Historical Pattern Matcher

### FR-065-1: Query historical precedents from SQLite

- Description: Given a stock code and an event keyword, find past `rag_analyses` rows where `affected_actions` contains the stock code AND `source_title` or `summary` contains the keyword, within a configurable lookback window.
- Input: `stockCode: string`, `eventKeyword: string`, `lookbackHours: number` (default 168 — one week)
- Output: `PatternSummary | null`
- Business rule: Return `null` (not throw) when zero precedents are found. One precedent is sufficient to return a result; the SPRINT_GOAL success metric requires ≥ 3 but the function must still succeed with 1–2.
- Query: `SELECT id, created_at, source_title, impact_score, impact_direction FROM rag_analyses WHERE created_at >= ? AND affected_actions LIKE ? AND (source_title LIKE ? OR summary LIKE ?)` — use `%keyword%` LIKE patterns; `affected_actions` is a JSON string array so use `LIKE '%"STOCKCODE"%'`.
- DDD layer: application

### FR-065-2: Compute aggregate statistics from precedents

- Description: From the set of matching precedents, compute `avgImpactPct` and `dominantDirection`.
- `avgImpactPct`: arithmetic mean of all `impact_score` values (scale 0–10; returned as-is, not converted to %).
- `dominantDirection`: the most frequently occurring `impact_direction` value across precedents. Tie-break: `up` beats `neutral` beats `down` (bullish bias rule).
- Input: array of raw SQLite rows
- Output: `{ avgImpactPct: number, dominantDirection: 'up' | 'down' | 'neutral' }`
- DDD layer: application (pure computation — no I/O)

### FR-065-3: Return PatternSummary type

- Description: Exported TypeScript interface `PatternSummary` and function `getPatternSummary`.

```typescript
export interface Precedent {
  date: string;          // ISO timestamp from created_at
  headline: string;      // source_title
  impactScore: number;   // impact_score 0–10
  impactDirection: 'up' | 'down' | 'neutral';
}

export interface PatternSummary {
  stockCode: string;
  eventKeyword: string;
  precedents: Precedent[];
  avgImpactPct: number;
  dominantDirection: 'up' | 'down' | 'neutral';
  lookbackHours: number;
  generatedAt: string;   // ISO timestamp
}

export async function getPatternSummary(
  stockCode: string,
  eventKeyword: string,
  lookbackHours?: number,
  db?: Database,
): Promise<PatternSummary | null>
```

- `db` parameter is optional — defaults to `getDb()`. Injected in tests for in-memory SQLite.
- DDD layer: application

### Edge Cases — 065

- [ ] Zero precedents found: return `null`, do not throw.
- [ ] `eventKeyword` contains SQL special characters (`%`, `_`, `'`): escape with SQLite `ESCAPE '\''` or use parameterised queries only — never string interpolation.
- [ ] `affected_actions` is stored as JSON array string `["GAS","PVD"]` — LIKE match must use `'%"GAS"%'` (with quotes inside) to avoid partial matches (e.g. `GAS` matching `GASC`).
- [ ] `impact_direction` column contains unexpected values (e.g. `NULL` or empty string): treat as `'neutral'` in aggregation.
- [ ] `lookbackHours = 0`: treat as "no time constraint" — return all matching rows.
- [ ] Very large result set (> 500 rows): add `LIMIT 100` to the query; note in JSDoc that only the 100 most recent precedents are used.

### Acceptance Criteria — 065

**Given** `rag_analyses` contains 3 rows with `affected_actions = '["GAS"]'` and `source_title LIKE '%oil%'`, all within 24 hours
**When** `getPatternSummary('GAS', 'oil', 24)` is called
**Then**
- Returns a non-null `PatternSummary`
- `precedents.length === 3`
- `avgImpactPct` is the arithmetic mean of the three `impact_score` values
- `dominantDirection` matches the most common `impact_direction` in those rows
- `stockCode === 'GAS'`, `eventKeyword === 'oil'`, `lookbackHours === 24`

**Given** `rag_analyses` has no rows matching 'GAS' + 'oil'
**When** `getPatternSummary('GAS', 'oil', 24)` is called
**Then** returns `null`

**Given** `eventKeyword` is `"oil%price"` (contains SQL wildcard)
**When** `getPatternSummary('GAS', "oil%price", 24)` is called
**Then** does not throw; uses parameterised query safely

## Task 066 — AI Summary Generator (Rule-Based BCTC)

### FR-066-1: Signal detection from ratio thresholds

- Description: Inspect `FinancialReport.ratios` and `FinancialReport.periodDeltas` to emit `FinancialSignal` values. No LLM calls — pure threshold logic.
- Input: `FinancialReport` (fully populated with `balanceSheet`, `incomeStatement`, `cashFlow`, `ratios`, `periodDeltas`)
- Output: `FinancialSignal[]`
- DDD layer: application (pure function — no I/O)

Signal threshold table (all thresholds apply to the current period unless noted):

| Signal | Condition |
|--------|-----------|
| `strong_revenue_growth` | `periodDeltas.YoY.netRevenue.changePct >= 20` |
| `revenue_decline` | `periodDeltas.YoY.netRevenue.changePct < 0` |
| `margin_expansion` | `periodDeltas.YoY.grossMarginPP.changePP > 1.5` (percentage points) |
| `margin_compression` | `periodDeltas.YoY.grossMarginPP.changePP < -1.5` |
| `strong_profit_growth` | `periodDeltas.YoY.netProfit.changePct >= 20` |
| `profit_decline` | `periodDeltas.YoY.netProfit.changePct < 0` |
| `high_debt` | `ratios.debtToEquity > 2.0` |
| `debt_reduction` | `periodDeltas.YoY.totalDebt.changePct < -10` |
| `strong_cashflow` | `cashFlow.freeCashFlow > 0 AND periodDeltas.YoY.freeCashFlow.changePct > 0` |
| `negative_cashflow` | `cashFlow.freeCashFlow < 0` |
| `inventory_buildup` | `periodDeltas.YoY.totalAssets.changePct > 0 AND ratios.inventoryDays > 90 AND ratios.inventoryTurnover < (previous period inventoryTurnover * 0.85)` — simplified: use `ratios.inventoryDays > 90` alone if delta is unavailable |
| `receivables_concern` | `ratios.receivablesDays > 60 AND periodDeltas.YoY.netRevenue.changePct < (periodDeltas.QoQ?.netRevenue.changePct ?? 0)` — simplified: `ratios.receivablesDays > 60` |

Priority: if a signal and its opposite would both fire (e.g. both `strong_revenue_growth` and `revenue_decline` — impossible mathematically, but guard anyway), keep only the stronger signal. Deduplicate the output array.

### FR-066-2: Outlook classification

- Description: Derive overall `Outlook` ('positive' | 'neutral' | 'negative' | 'mixed') from the signals array.
- Rules (evaluated in order, first match wins):
  1. Positive signals (`strong_revenue_growth`, `strong_profit_growth`, `margin_expansion`, `strong_cashflow`, `debt_reduction`) count ≥ 2 AND no negative signals: `'positive'`
  2. Negative signals (`revenue_decline`, `profit_decline`, `margin_compression`, `negative_cashflow`, `high_debt`) count ≥ 2 AND no positive signals: `'negative'`
  3. Both positive and negative signals present: `'mixed'`
  4. Default: `'neutral'`
- DDD layer: application (pure)

### FR-066-3: Key strengths and weaknesses text generation

- Description: Convert signals to Vietnamese-language strings for `keyStrengths[]` and `keyWeaknesses[]`.
- Positive signals map to `keyStrengths`; negative signals map to `keyWeaknesses`.
- Each string includes the specific metric value for traceability.

Signal-to-text map (Vietnamese):

| Signal | Category | Text template |
|--------|----------|---------------|
| `strong_revenue_growth` | strength | `"Doanh thu tăng {changePct}% YoY — tăng trưởng mạnh"` |
| `revenue_decline` | weakness | `"Doanh thu giảm {changePct}% YoY — cần theo dõi"` |
| `margin_expansion` | strength | `"Biên lợi nhuận gộp mở rộng +{changePP}pp YoY"` |
| `margin_compression` | weakness | `"Biên lợi nhuận gộp thu hẹp {changePP}pp YoY"` |
| `strong_profit_growth` | strength | `"Lợi nhuận sau thuế tăng {changePct}% YoY"` |
| `profit_decline` | weakness | `"Lợi nhuận sau thuế giảm {changePct}% YoY"` |
| `high_debt` | weakness | `"Nợ/Vốn chủ sở hữu ở mức {debtToEquity:.2f}x — rủi ro đòn bẩy cao"` |
| `debt_reduction` | strength | `"Giảm nợ {changePct}% YoY — cải thiện bảng cân đối"` |
| `strong_cashflow` | strength | `"Dòng tiền tự do dương và tăng trưởng"` |
| `negative_cashflow` | weakness | `"Dòng tiền tự do âm — theo dõi nhu cầu vốn"` |
| `inventory_buildup` | weakness | `"Tồn kho cao — vòng quay hàng tồn kho {inventoryDays} ngày"` |
| `receivables_concern` | weakness | `"Kỳ thu tiền bình quân {receivablesDays} ngày — rủi ro phải thu"` |

### FR-066-4: Generate outlook narrative string

- Description: `AIAnalysis.summary` is a 1–3 sentence Vietnamese-language overview combining `outlook`, top signals, and key metric values. Rule-based template; no randomness.
- Template: `"[Kỳ {period}] {companyCode} ghi nhận {outlook_text}. {top_strength_or_weakness_sentence}. {watch_point_sentence}."`
- If `periodDeltas` is undefined or empty (e.g. first-ever report for a stock): generate a single-sentence summary from current-period ratios only; do not include any delta comparison.
- DDD layer: application

### FR-066-5: Persist AIAnalysis back to SQLite

- Description: After computing `AIAnalysis`, update the `financial_reports` row via `updateFinancialReportAiAnalysis(reportId, aiAnalysis)`.
- Requires: `financial_reports` table must have an `ai_analysis TEXT` column (add via `ALTER TABLE ... ADD COLUMN IF NOT EXIST` pattern using `PRAGMA table_info`).
- The column stores `JSON.stringify(aiAnalysis)`.
- DDD layer: infrastructure (DB write) — called from the application use case.

### FR-066-6: Main exported function

```typescript

  db?: Database;
}

export async function generateAiSummary(
  report: FinancialReport,
  options?: GenerateAiSummaryOptions,
): Promise<AIAnalysis>
```

The function:
1. Calls pure signal detection (FR-066-1).
2. Derives outlook (FR-066-2).
3. Builds keyStrengths / keyWeaknesses (FR-066-3).
4. Generates summary narrative (FR-066-4).
5. Calls `updateFinancialReportAiAnalysis` to persist (FR-066-5).

`db` optional — defaults to `getDb()`. Always injected in tests.

### Edge Cases — 066

- [ ] `periodDeltas` is `null` or empty array: skip all delta-based signals; generate ratios-only summary.
- [ ] `ratios.debtToEquity` is `Infinity` (equity = 0): cap at 99.9, emit `high_debt` signal.
- [ ] `ratios.netMarginPct` is `NaN` (revenue = 0): skip margin signals, do not throw.
- [ ] `changePct` is `null` (previous period value was 0): skip that specific threshold check.
- [ ] `signals` output array is empty: `outlook = 'neutral'`, `keyStrengths = []`, `keyWeaknesses = []`, summary uses current-period ratios only.
- [ ] `financial_reports` table does not have `ai_analysis` column yet: use `PRAGMA table_info(financial_reports)` to check before `ALTER TABLE`.
- [ ] Report `id` not found in DB during persist: log warning but still return `AIAnalysis` — do not throw.

## Task 027 — HNX + UPCOM Market Data Fetcher

### FR-027-1: Fetch HNX prices from HNX JSON API

- Description: Fetch live price and volume for a list of HNX-listed stock codes using the HNX public API.
- Primary endpoint: `https://api.hnx.vn/api/snapshot?code=ACB,NVB&type=stock` (GET, returns JSON array).
- Response shape (per stock):
  ```json
  {
    "code": "ACB",
    "closePrice": 22500,
    "referencePrice": 22000,
    "change": 500,
    "percentChange": 2.27,
    "totalVolume": 2500000
  }
  ```
- Field mapping to `MarketPrice`:
  - `code` → `code`
  - `'HNX'` (hardcoded) → `exchange`
  - `closePrice` → `price`
  - `referencePrice` → `previousPrice`
  - `percentChange` → `changePct`
  - `totalVolume` → `volume`
  - `0` → `avgVolume` (populated lazily via `getAvgVolume()`)
  - `new Date().toISOString()` → `fetchedAt`
- Returns `[]` (never throws) on network error or parse error; logs warning via `logger.warn`.
- DDD layer: infrastructure

### FR-027-2: Fetch UPCOM prices from HNX JSON API

- Description: UPCOM stocks are also listed on HNX's exchange infrastructure; the API is the same endpoint with a `type=upcom` parameter.

- All other behaviour identical to FR-027-1 except `exchange` is hardcoded as `'UPCOM'`.

## Task 105 — Evening Summary Job (22:00 GMT+7)

### FR-105-1: assembleEveningSummary use case

- Description: Collect end-of-day data from SQLite and return a structured `EveningSummary`.
- Input: `AssembleEveningSummaryOptions` (all optional — injectable for tests)
- Output: `EveningSummary`

```typescript
export interface WatchlistMover {
  code: string;
  changePct: number;   // signed; |changePct| >= 1.0 to appear
  price: number;
  exchange: string;
}

export interface EveningSummary {
  date: string;                     // YYYY-MM-DD in Vietnam timezone
  topAlerts: BriefingAlert[];       // up to 5, last 24h, severity DESC
  topStories: TopStory[];           // up to 5, today since midnight, impact_score DESC
  watchlistMovers: WatchlistMover[]; // |changePct| >= 1.0, sorted by |changePct| DESC
  generatedAt: string;              // ISO timestamp
}
```

Reuse `BriefingAlert` and `TopStory` types from `assembleBriefing.ts` — import them directly to avoid duplication.

### FR-105-2: Data queries

- `topAlerts`: `SELECT id, severity, message, affected_actions_json FROM alerts WHERE triggered_at >= ? ORDER BY severity DESC, triggered_at DESC LIMIT 5` — severity sort order: `critical > warning > info` (use `CASE` expression or sort client-side after fetch).
- `topStories`: `SELECT source_title, level, sentiment, impact_score FROM rag_analyses WHERE created_at >= ? ORDER BY impact_score DESC LIMIT 5` — use same `midnightVietnamAsUtc()` helper as `assembleBriefing`.
- `watchlistMovers`: `SELECT w.code, w.exchange, mp.price, mp.change_pct FROM watchlist w LEFT JOIN market_prices mp ON mp.code = w.code WHERE ABS(mp.change_pct) >= 1.0 ORDER BY ABS(mp.change_pct) DESC` — `exchange` joins from `market_prices` if present, else falls back to `w.exchange`.
- Severity sort client-side: map `critical=3, warning=2, info=1`, sort descending.

### FR-105-3: File persistence

- Output path: `reports/YYYY-MM-DD-evening.json` (relative to project root; configurable via `options.reportsDir`).
- Create directory if absent using `mkdirSync(reportsDir, { recursive: true })`.
- Overwrite on re-run — `writeFileSync` (same pattern as `assembleBriefing`).
- On file write failure: log warning, still return `EveningSummary` — do not throw.

### FR-105-4: Cron job

- File: `src/scheduler/eveningSummaryJob.ts`
- Cron expression: `0 22 * * 1-5` (22:00 GMT+7, Monday–Friday only)
- Timezone: `Asia/Ho_Chi_Minh` (same as existing jobs)
- Concurrency guard: module-level `let _running = false` flag; if `_running === true` when cron fires, log warning and skip invocation.
- On error: catch, log with `logger.error`, set `_running = false` in `finally`.

### FR-105-5: Wire into jobs.ts

- Import `scheduleEveningSummaryJob` from `eveningSummaryJob.ts`.
- Call it inside `scheduleJobs()` after the existing morning briefing job registration.
- The cron job does not need a DB injection point for production — it calls `assembleEveningSummary()` which resolves `getDb()` lazily.

### Edge Cases — 105

- [ ] No alerts in last 24 hours: `topAlerts = []` — valid, not an error.
- [ ] No rag_analyses today: `topStories = []` — valid.
- [ ] Watchlist is empty: `watchlistMovers = []` — valid.
- [ ] All watchlist stocks have `|changePct| < 1.0`: `watchlistMovers = []` — valid.
- [ ] `market_prices` has no row for a watchlist stock (price not yet fetched): that stock is excluded from `watchlistMovers` (LEFT JOIN returns NULL for change_pct; `ABS(NULL) >= 1.0` is false in SQLite).
- [ ] Cron fires at 22:00 but previous run still executing (e.g. slow network): concurrency guard skips the overlapping invocation.
- [ ] `reports/` directory does not exist: `mkdirSync` creates it.
- [ ] Job called on weekend manually (not via cron): `runEveningSummary()` runs normally — cron weekday filter only applies to scheduled invocations.

### Acceptance Criteria — 105

**Given** SQLite contains 3 alerts (1 critical, 2 warning), 4 rag_analyses today, 2 watchlist movers with |changePct| >= 1.0
**When** `assembleEveningSummary()` is called
**Then**
- `topAlerts.length === 3`, critical alert is first
- `topStories.length === 4`
- `watchlistMovers.length === 2`, sorted by |changePct| DESC
- File `reports/YYYY-MM-DD-evening.json` exists and contains valid JSON
- `generatedAt` is a valid ISO timestamp

**Given** `runEveningSummary()` is already in progress (`_running === true`)
**When** the cron fires a second time
**Then** second invocation is skipped; first invocation completes normally
