# REQ-137: fix(morning-briefing-filler) — omit filler sections in formatBriefingMessage when data absent

status: READY_FOR_ARCHITECT
sprint: 137
po_vision: Morning briefing emits filler text when data absent — fix by omitting sections silently.

## User Story

As a Vietnamese stock investor using Claude,
I want the morning briefing Telegram message to show only sections with real data,
So that I never see noise lines like "chưa có dữ liệu" or "N/A" when the market has not opened yet.

## Functional Requirements

### FR-1: Omit VN-Index section when vnIndex is null/undefined

- Description: When `briefing.vnIndex` is null or undefined, the entire VN-Index line must be absent from the output. Current code emits `"📈 VN-Index: chưa có dữ liệu"`.
- Input: `DailyBriefing` with `vnIndex = undefined`
- Output: No line containing "VN-Index" in formatted message
- Business rule: Filler = noise. Section with no data = section omitted entirely.
- DDD layer: interface/scheduler

### FR-2: Omit watchlist section header + entries when watchlistSummary is empty

- Description: When `briefing.watchlistSummary.length === 0`, neither the `"📊 Giá cổ phiếu:"` header nor the filler `"Chưa có dữ liệu giá"` must appear.
- Input: `DailyBriefing` with `watchlistSummary = []`
- Output: No "Giá cổ phiếu" header and no "Chưa có dữ liệu giá" line
- Business rule: Empty-section filler = spam. Omit header + body together when source array is empty.
- DDD layer: interface/scheduler

### FR-3: Skip individual watchlist entries where price is null

- Description: When iterating `briefing.watchlistSummary`, skip any entry where `w.price == null` instead of emitting `"N/A"`.
- Input: `WatchlistEntry[]` containing mixed entries — some with `price: number`, some with `price: null`
- Output: Only entries with non-null price appear in message; null-price entries silently absent
- Business rule: Per-stock "N/A" = unknown state shown to user. Unknown = omit.
- DDD layer: interface/scheduler

### FR-4: All-data-present path unchanged

- Description: When `vnIndex` is non-null, `watchlistSummary` is non-empty, and all entries have prices — all sections and all entries must appear as today.
- Input: `DailyBriefing` with full data
- Output: VN-Index line present, all watchlist entries with prices present
- Business rule: Fix must not regress the happy path.
- DDD layer: interface/scheduler

## Non-Functional Requirements
