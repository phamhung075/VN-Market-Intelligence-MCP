# REQ-1400: fix(db-isolation): phantom telegram_reports from broken test DB isolation

status: READY_FOR_ARCHITECT
sprint: 141
po_vision: Stop test fixture rows leaking into production data/market.db — purge 400+ phantom 1970-epoch rows, fix Bun.env namespace mismatch in setup.ts.

## User Story

As a developer running `bun test`,
I want the test runner to use a true in-memory SQLite DB for every test file,
So that production `data/market.db` is never written during the test suite and the BUG channel is free of phantom "First"/"Second" rows from epoch 1970.

## Root Cause (confirmed by code read)

| File | Line | Problem |
|------|------|---------|
| `src/__tests__/setup.ts` | 12 | Sets `process.env["DB_PATH"] = ":memory:"` |
| `src/infrastructure/db/schema.ts` | 64 | Reads `Bun.env["DB_PATH"]` (correct) |

In Bun, `process.env` mutations do NOT propagate to `Bun.env`. These are separate namespaces. Result: `getDb()` always ignores the `:memory:` value set by the preload and opens the production singleton `data/market.db`.

Fixture rows that leak every full test run:

| Source test file | Rows inserted | `created_at` values |
|-----------------|---------------|---------------------|
| `src/__tests__/226-telegram-report-store.test.ts:153-155` | 3 rows ("First", "Second", "Third") | 1000, 2000, 3000 (epoch ~1970-01-01) |
| `src/__tests__/231-claim-telegram-report.test.ts:194-197` | 2 rows ("First", "Second") | 1000, 2000 (epoch ~1970-01-01) |

~45 rows accumulate per full `bun test` run. 400+ phantom rows as of 2026-04-17.

## Functional Requirements

### FR-1: Fix DB_PATH namespace in setup.ts

- Description: Change `process.env["DB_PATH"]` to `Bun.env["DB_PATH"]` in the test preload file.
- Input: Bun test runner loads `src/__tests__/setup.ts` before any test file (via `bunfig.toml` preload).
- Output: `Bun.env["DB_PATH"]` equals `":memory:"` at the time `getDb()` first evaluates `Bun.env["DB_PATH"] ?? DEFAULT_DB_PATH`.
- Business rule: `schema.ts:64` reads `Bun.env` — the fix MUST write to the same namespace.
- DDD layer: infrastructure (test support file)

### FR-2: Purge existing phantom rows

- Description: Delete all `telegram_reports` rows with `created_at < 1000000` from production `data/market.db`.
- Input: Production DB at `data/market.db`.
- Output: Zero rows with `created_at < 1000000` remain in `telegram_reports`.
- Business rule: Epoch `1000000` = 1970-01-12 13:46:40 UTC — safely before any real production timestamp. All real reports have Unix timestamps in the billions (2020s era).
- Delivery: Run as a one-time migration in task 1401 (inline SQL in migration script or direct `bun run` script). NOT a schema.ts migration (avoids running on every boot).
- DDD layer: infrastructure

### FR-3: TDD test asserting isolation (task 1400)

- Description: New test file `src/__tests__/1400-db-isolation.test.ts` that proves `Bun.env["DB_PATH"]` is `":memory:"` during the test run and that the production DB file is never opened.
- Input: Test suite runs with `setup.ts` preload active.
- Output: Assertions pass — `Bun.env["DB_PATH"]` equals `":memory:"` and `DEFAULT_DB_PATH` (the `data/market.db` absolute path) is not the active DB path.
- Business rule: Test must NOT import `getDb()` at module top — import dynamically to avoid singleton caching before the env check.
- DDD layer: infrastructure (test)

## Non-Functional Requirements

- Performance: Purge SQL runs once, < 1ms.
- Data safety: Purge DELETE is scoped by `created_at < 1000000` — cannot delete real production rows (all real rows have `created_at` in Unix seconds, 2020s = ~1.7 billion).
- Language: No user-facing text change.
- Test suite impact: Net zero new failures. Fix eliminates phantom rows — test count unchanged.

## Edge Cases & Data Quality

- [ ] `_db` singleton already open when setup.ts runs: `getDb()` returns cached connection. Fix: test files that call `closeDb()` + `initDatabase()` in `beforeEach` will re-open with correct `Bun.env` value after fix.
- [ ] `bunfig.toml` preload order: `setup.ts` runs before any module import — confirmed by Bun docs. `Bun.env` write at preload time is guaranteed to be visible before `schema.ts` module evaluation.
- [ ] Purge script run on already-clean DB (no rows to delete): `DELETE WHERE created_at < 1000000` returns 0 rows affected — idempotent, no error.
- [ ] Production DB not present (fresh install): script should handle missing `data/market.db` gracefully — skip purge with a warning log.
- [ ] dev-standards.md test template still uses `process.env["DB_PATH"] = ":memory:"` at line 47: this MUST be updated to `Bun.env["DB_PATH"] = ":memory:"` in the same PR to prevent new test files being written with the broken pattern.

## Implementation Notes for Architect

**Change in setup.ts is one line:**

```
- process.env["DB_PATH"] = ":memory:";
+ Bun.env["DB_PATH"] = ":memory:";
```

**Purge SQL:**

```sql
DELETE FROM telegram_reports WHERE created_at < 1000000;
```

**TDD test skeleton (task 1400 — RED phase):**

```typescript
// src/__tests__/1400-db-isolation.test.ts
import { describe, it, expect } from "bun:test";
import { resolve } from "node:path";

describe("Task 1400 — DB isolation: Bun.env namespace", () => {
  it("Bun.env[DB_PATH] is :memory: during test run", () => {
    expect(Bun.env["DB_PATH"]).toBe(":memory:");
  });

  it("production DB path is not the active DB path", async () => {
    const { getDb } = await import("../infrastructure/db/schema.js");
    const db = getDb();
    const PROJECT_ROOT = resolve(import.meta.dir, "..", "..");
    const prodPath = resolve(PROJECT_ROOT, "data", "market.db");
    // db.filename is the path the connection was opened with
    expect((db as unknown as { filename: string }).filename).not.toBe(prodPath);
  });
});
```

Note: `db.filename` (Bun SQLite) returns the path passed to `new Database(path)`. For `:memory:` it returns `":memory:"`.
