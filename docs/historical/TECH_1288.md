## Architecture Decision

### Why This Design

**Problem:** VPS endpoint `vn-foreign-flow.service` (port 5005) occasionally unavailable → foreign flow alerts become unreliable → false negatives in FDI signal detection.

**Solution:** Multi-tier fallback fetcher that gracefully degrades:
1. **Primary:** VPS endpoint (5s timeout, circuit breaker wrapped)
2. **Cache:** In-memory from last successful fetch (survives circuit open state)
3. **SSE:** Extract from Telegram/SSE broadcast messages (optional fallback)
4. **None:** Return empty result with diagnostic warning (never crash)

**Rationale:**
- **Cache in module state (not DB):** Faster (<1ms), survives circuit breaker reset, no transaction cost
- **Optional SSE fallback:** Only activates if `overrides.sseMessageBus` provided (test injection pattern)
- **Circuit breaker state check early:** `if (state !== "open")` at line 112 prevents redundant timeout attempts
- **Structured diagnostics:** Every fallback activation logged with metrics (cache age, SSE count, breaker failures)
- **Recovery logging:** When primary comes back online, log "[fallback] primary endpoint recovered" (prevents duplicate logs via `lastRecoveryAt` check)

## Implementation Contracts

### Main Function Signature

```typescript
export async function fetchForeignFlowWithFallback(
  overrides?: {
    now?: () => Date;
    fetchFn?: (url: string, opts?: any) => Promise<Response>;
    sseMessageBus?: MessageBus;
    cacheStore?: CacheStore;
  },
): Promise<ForeignFlowFetchResult>
```

**Behavior:**
1. Check circuit breaker state (`breakers.foreignFlow.stats.state`)
2. If not open: attempt primary via `fetchPrimaryVpsEndpoint()` (5s timeout, AbortController)
3. If primary succeeds: validate schema, write to DB, cache, return `{ source: "primary", ... }`
4. If primary fails (timeout/validation/error): fall back to cache
5. If cache unavailable: try SSE message bus
6. If all exhausted: return `{ source: "none", warning, ... }`
7. Log all fallback activations with metrics

### Output Type: `ForeignFlowFetchResult`

```typescript
export interface ForeignFlowFetchResult {
  changes: number;                               // rows written/updated in daily_ohlcv
  timestamp: string;                             // ISO 8601, when fetch completed (no .000Z)
  source: "primary" | "cache" | "sse" | "none"; // data source
  warning?: string;                              // optional: "cache stale: Xmin old", "all fallbacks unavailable", etc.
}
```

### Internal: Cache Structure

```typescript
interface ForeignFlowCache {
  timestamp: string;            // ISO 8601, when data was cached (original fetch time)
  changes: number;              // row count from cache fetch
  data: WriteForeignFlowItem[]; // the cached payload
  cachedAt?: string;            // optional: timestamp override for age calc
}
```

Module state: `let lastSuccessCache: ForeignFlowCache | null = null` (updated only on successful primary fetch)

### Internal: Message Bus Type (for SSE fallback)

```typescript
export interface MessageBus {
  getRecentMessages(pattern: string, limit?: number): unknown[];
  // Expected message format: { event: "signal:foreign_flow", data: WriteForeignFlowItem[] }
}
```

### Internal: Cache Store Type (for test injection)

```typescript
export interface CacheStore {
  get(key: string): ForeignFlowCache | null;
  // Key: "foreign_flow_last_fetch"
}
```

## Function Behavior: Step-by-Step

### Path 1: Primary Success

```
1. Check circuit state
   ↓ if not "open"
2. Try fetchPrimaryVpsEndpoint(fetchFn, 5000ms)
   ↓ with AbortController timeout
3. Response ok? → parse JSON
4. Validate schema via validateForeignFlowFetcherPayload()
   ↓ if all valid
5. Write to DB via writeForeignFlowToOhlcv()
6. Update lastSuccessCache = { timestamp, changes, data, cachedAt }
7. Log recovery if breaker was previously down
   ↓
RETURN { changes, timestamp, source: "primary" }
```

**Key details:**
- Line 112: `if (breakers.foreignFlow.stats.state !== "open")` — check state, skip if open
- Line 115: `await breakers.foreignFlow.execute(async () => { ... })` — wrap primary fetch
- Line 269: Check `!response.ok` before parsing JSON
- Line 274: Validate `.data` is array, not `data: undefined`
- Line 279–291: Fail loudly on schema validation errors (include item index + field name)
- Line 125–130: Cache entire result + timestamp for TTL calculation
- Line 133–136: Prevent duplicate recovery logs by checking `lastRecoveryAt !== timestamp`

### Path 2: Primary Timeout → Cache Fallback

```
1. Primary fetch throws AbortError or timeout error
   ↓ caught at line 145
2. Log primary failure reason (separate warn for timeout vs. validation vs. other)
3. Check cache: lastSuccessCache or overrides.cacheStore.get("foreign_flow_last_fetch")
   ↓ if exists
4. Calculate cache age: (now - cachedAt) / 60_000 minutes
   ↓ if age > 120 min
5. Include warning: `"cache stale: ${age|0}min old"`
   ↓
RETURN { changes: cache.changes, timestamp: cache.timestamp, source: "cache", warning? }
```

**Key details:**
- Line 147: Extract error message for diagnostics
- Line 150: Special handling for "validation failed" errors (hint about schema change)
- Line 174: Use `cachedAt` field for age calculation (preserves original fetch timestamp)
- Line 176: Age computation: `(Date.parse(now) - Date.parse(cachedAt)) / 60_000`
- Line 189–191: Add warning if age ≥120 minutes (triggers SLA freshness checker)

### Path 3: Cache Miss → SSE Fallback

```
1. Cache unavailable or empty
2. Check overrides.sseMessageBus exists
   ↓ if yes
3. Get recent messages: sseMessageBus.getRecentMessages("foreign_flow:*", 10)
4. Extract WriteForeignFlowItem[] via extractForeignFlowFromSseMessages()
   ↓ for each message with event="signal:foreign_flow"
5. Validate each item via isValidForeignFlowItem()
6. Deduplicate by (code, date) tuple
7. Write to DB via writeForeignFlowToOhlcv()
   ↓
RETURN { changes, timestamp, source: "sse" }
```

**Key details:**
- Line 199: Guard on `overrides?.sseMessageBus` (optional fallback)
- Line 200: Request last 10 messages with pattern match
- Line 318–341: Extract handler filters message type + validates items silently (skip invalid)
- Line 347–360: Dedup function uses Set<string> with `code|date` key
- Line 210: Write deduped results; log count before return

### Path 4: All Exhausted → Empty Result

```
1. Primary failed, cache empty, SSE unavailable
   ↓
2. Log warning: "[fallback] all fallback sources exhausted, returning empty"
   ↓
RETURN { changes: 0, timestamp, source: "none", warning: "all fallbacks unavailable: check VPS endpoint + cache + SSE" }
```

**Key details:**
- Line 227–236: Never throw; always return result object
- Warning guides troubleshooting (list all checked sources)
- Log level: warn (fallback mechanism is working as designed, not an error)

if (breakers.foreignFlow.stats.state !== "open") {

### Line 113: Wrap primary in breaker

```typescript

  return await fetchPrimaryVpsEndpoint(overrides?.fetchFn ?? fetch, 5000);
});
```

**Behavior:**
- If breaker is CLOSED: execute function normally; record success/failure
- If breaker is HALF-OPEN: attempt function; may re-open on failure
- If breaker is OPEN: line 112 prevents execution (never reached)

### Line 133: Log recovery event

```typescript
if (breakers.foreignFlow.stats.state === "closed" && lastRecoveryAt !== timestamp) {
  lastRecoveryAt = timestamp;
  logger.info("[fallback] primary endpoint recovered", { timestamp });
}
```

**Deduplication:** `lastRecoveryAt` prevents duplicate logs if multiple successful fetches occur in same second.

## Validation & Error Handling

### Schema Validation (lines 278–293)

```typescript
const { validateForeignFlowFetcherPayload } = await import(
  "../../domain/services/market-data/foreignFlowValidator.js"
);
const validationResult = validateForeignFlowFetcherPayload(json.data);

if (validationResult.errors.length > 0) {
  const errorSummary = validationResult.errors
    .slice(0, 5)
    .map((e) => `Item ${e.itemIndex}: ${e.field} — ${e.reason}`)
    .join("; ");
  throw new Error(
    `VPS payload validation failed: ${errorSummary}. Total errors: ${validationResult.errors.length}`,
  );
}
```

**Strategy:** Fail loudly (throw error with first 5 errors + total count).

### Timeout Handling (lines 257–308)

```typescript
const controller = new AbortController();
let timeoutHandle: ReturnType<typeof setTimeout> | null = null;

try {
  timeoutHandle = setTimeout(() => controller.abort(), timeoutMs);
  const response = await fetchFn(url, {
    signal: controller.signal,
    timeout: timeoutMs,
  });
  // ... handle response
} catch (err) {
  if (err instanceof Error && err.name === "AbortError") {
    throw new Error(`VPS endpoint timeout (>${timeoutMs}ms)`);
  }
  throw err;
} finally {
  if (timeoutHandle) {
    clearTimeout(timeoutHandle);
  }
}
```

**Strategy:** AbortController ensures cleanup; detects abort vs. other errors; re-throws as diagnostic error message.

## Logging Strategy

### Recovery Logging (successful primary after downtime)

**When:** Primary succeeds, circuit was previously down (state now closed)
**Log:** `logger.info("[fallback] primary endpoint recovered", { timestamp })`
**Dedup:** Via `lastRecoveryAt` tracking (prevent duplicate logs in same second)

### Fallback Activation Logging

**Primary timeout/validation failure:**
```typescript
logger.warn("[fallback] primary endpoint failed", { error: errMsg });
```

**Primary validation error (special case):**
```typescript
logger.warn("[fallback] VPS payload schema validation failed", {
  error: errMsg,
  timestamp,
  hint: "Check VPS API response format — schema may have changed",
});
```

**Cache usage:**
```typescript
logger.info("[fallback] using cached foreign flow", {
  cachedAt: cacheTimestamp,
  changes: cache.changes,
  staleness, // e.g., " (180min old)" or ""
});
```

**SSE usage:**
```typescript
logger.info("[fallback] using SSE broadcast data", {
  itemCount: extracted.length,
});
```

**All exhausted:**
```typescript
logger.warn("[fallback] all fallback sources exhausted, returning empty", {
  timestamp,
});
```

**Circuit breaker open (skip primary):**
```typescript
logger.warn("[fallback] circuit breaker open, skipping primary", {
  failures: breakers.foreignFlow.stats.failures,
});
```

## Risk Assessment

| Risk | Probability | Severity | Mitigation |
|------|-------------|----------|-----------|
| Cache becomes stale (>8h) during prolonged VPS outage | MEDIUM | MEDIUM | SLA freshness checker alerts OPS; manual breaker reset tool available |
| SSE message bus not initialized in production | LOW | MEDIUM | Guard on `overrides?.sseMessageBus` (optional); fallback to empty if unavailable |
| Validation schema change on VPS side (breaking format) | LOW | MEDIUM | Diagnostic error logs include schema mismatch hint; OPS investigates |
| Race condition: concurrent `fetchForeignFlowWithFallback()` calls | NONE | — | Function is stateless; module state (`lastSuccessCache`) only updated on primary success (no async concurrency) |
| Cache TTL insufficient (2h too short) | LOW | LOW | Configurable via staleness threshold; SLA checker alerts on breach |
| Test injection parameters conflict with prod usage | LOW | LOW | Overrides only used in tests; prod ignores all defaults (fetch, now, logger) |
| Circuit breaker oscillation resumes after fix | LOW | MEDIUM | Monitor via new logging; alert if oscillation pattern detected; see `docs/agent-memory/patterns/circuit-breaker.md` |
