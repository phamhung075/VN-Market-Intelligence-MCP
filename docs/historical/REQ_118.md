# REQ-118: OHLCV Backfill — populate daily_ohlcv with 60-day history

status: READY_FOR_ARCHITECT
sprint: 118
po_vision: Backfill daily_ohlcv so taSummary is non-empty immediately — no 3-week wait

## User Story

As a Vietnamese stock investor using Claude,
I want the evening report taSummary to show RSI and MA20 signals immediately after server deploy,
So that I receive TA context at market close without waiting 3 weeks for daily_ohlcv to accumulate 15 rows.

## Context & Root Cause

Since sprint 097, `taSummary` was wired to `defaultComputeTa()` which requires 15+ rows in
`daily_ohlcv`. The table accumulates only 1 row per trading day via the VPS price push.
Server was last deployed fewer than 15 trading days ago → taSummary always empty.
Sprint 116 lowered the guard to 8 rows with adaptive periods, but with 0–3 rows currently
in production, the fallback to `market_prices_history` (intraday aggregation) also fails
because the table only covers a few days. The root fix is a one-time backfill.

## Functional Requirements

### FR-1: POST /api/push-ohlcv-history endpoint

- Description: France MCP server receives pre-fetched historical OHLCV bars from VPS and
  upserts them into `daily_ohlcv`. This mirrors the pattern used by `/api/push-prices`,
  `/api/push-news`, and `/api/push-foreign-flow`.
- Input: `POST /api/push-ohlcv-history` with body:
  ```json
  {
    "code": "VNM",
    "bars": [
      { "date": "2025-01-15", "open": 73.5, "high": 75.0, "low": 72.8, "close": 74.2, "volume": 1234567 }
    ]
  }
  ```
  - `code`: string, uppercase ticker (e.g. "VNM")
  - `bars`: array of daily candle objects
  - `date`: ISO date string "YYYY-MM-DD" (Vietnam local date)
  - `open`, `high`, `low`, `close`: positive REAL (VND thousands, same unit as existing rows)
  - `volume`: non-negative REAL (lot units, same as existing rows)
- Output: `200 { "ok": true, "inserted": N, "code": "VNM" }` on success
- Auth: `X-API-Key: $VPS_PUSH_API_KEY` header — same key as all other push endpoints
- Business rules:
  - Upsert strategy: `INSERT INTO daily_ohlcv ... ON CONFLICT(code, date) DO UPDATE SET ...`
    — duplicate date overwrites existing row (idempotent, safe to run twice)
  - Empty `bars` array: respond `200 { "ok": true, "inserted": 0 }` — no-op, not an error
  - Missing `code` field or non-string: respond `400 { "error": "..." }`
  - `bars` items with any null/missing OHLCV field: skip that bar, log warning, continue
  - `updated_at` set to current UTC ISO timestamp on every upserted row
- DDD layer: interface (`src/interface/mcp/server.ts` — add handler alongside existing push-* routes)

### FR-2: vps-scripts/fetch-ohlcv-backfill.sh one-time script

- Description: Bash script that runs manually on the VPS (not a systemd loop), fetches 60
  trading days of OHLCV from TCBS chart API for each watchlist ticker, and pushes them to
  the France MCP server via FR-1.
- Source API: `https://api.tcbs.com.vn/stock-insight/v1/stock/bars`
  - Query params: `ticker=VNM&type=stock&resolution=D&from=<unix_epoch>&to=<unix_epoch>`
  - `from`: Unix timestamp for 90 calendar days ago (generous window to cover 60 trading days)
  - `to`: Unix timestamp for now
  - Returns JSON: `{ "data": [ { "tradingDate": "...", "open": ..., "high": ..., "low": ..., "close": ..., "volume": ... } ] }`
  - `tradingDate` format: ISO datetime or date string — extract date portion "YYYY-MM-DD"
- Script logic:
  1. Read `MCP_BASE` and `API_KEY` from env vars (same pattern as `fetch-prices.sh`)
  2. Query `$MCP_BASE/api/watchlist` to get current ticker list dynamically (not hardcoded)
  3. For each ticker: call TCBS API, transform response, POST to `/api/push-ohlcv-history`
  4. Log success/failure per ticker to stdout + `/var/log/vn-ohlcv-backfill.log`
  5. Exit 0 on completion (even if some tickers failed — partial backfill is better than abort)
- Guard: if `$MCP_BASE` or `$API_KEY` not set, print usage and exit 1
- No systemd unit — one-time manual run: `bash vps-scripts/fetch-ohlcv-backfill.sh`
- DDD layer: infrastructure (VPS script, not part of Bun server source)

### FR-3: TDD test coverage (task 1350)

- Test file: `src/__tests__/1350-ohlcv-backfill-endpoint.test.ts`
- Must set `process.env["DB_PATH"] = ":memory:"` at line 1 (before imports)
- Five required test cases:
  1. Valid bars array → inserts N rows into daily_ohlcv, returns `{ ok: true, inserted: N }`
  2. Duplicate date → upserts (no duplicate rows in DB, row count stays N not 2N)
  3. Missing/wrong API key → 401 Unauthorized
  4. Empty bars array → 200 `{ ok: true, inserted: 0 }`, no DB writes
  5. Malformed payload (missing `code`, non-array `bars`) → 400 Bad Request

## Non-Functional Requirements

- Performance: endpoint must handle 60-bar payload per ticker in < 100 ms (single SQLite
  transaction with prepared statement; 60 rows is trivial for SQLite)
- Idempotency: running the VPS script twice must not create duplicate rows or corrupt data
- Security: same `VPS_PUSH_API_KEY` auth as all other push endpoints — no new secrets
- Logging: endpoint logs `[push-ohlcv-history] code=VNM inserted=60` at INFO level
- TypeScript: `bun tsc --noEmit` must remain clean — no `any` escapes on bar fields
- Test isolation: in-memory SQLite, `process.env["DB_PATH"] = ":memory:"` at file line 1

## Edge Cases & Data Quality

- [ ] TCBS API returns `tradingDate` as full ISO datetime "2025-01-15T00:00:00" — script must
      extract "YYYY-MM-DD" substring (first 10 chars)
- [ ] TCBS API may return weekends/holidays with zero volume — include them (TA lib handles gaps)
- [ ] TCBS API rate limit: add 0.2s sleep between tickers in shell script to avoid 429
- [ ] Some tickers (UPCOM: VEA) may return fewer than 60 bars — acceptable, insert what exists
- [ ] Bars with `open=0` or `close=0`: log warning and skip (corrupt data guard)
- [ ] `bars` items missing `volume` field: default to 0 (volume is NOT NULL DEFAULT 0 in schema)
- [ ] VPS network timeout: curl `--connect-timeout 10 --max-time 20` per TCBS call; skip ticker on failure
- [ ] France server `updated_at` collision: upsert always overwrites — safe because backfill data
      is authoritative historical data (TCBS is the price source of record)
- [ ] Large payload size: 30 tickers × 60 bars × ~100 bytes = ~180 KB per full run — well within
      HTTP limits; no chunking needed

**When** the server processes the request
**Then**
- HTTP 401 is returned with body `{ "error": "Unauthorized" }`
- No rows are written to `daily_ohlcv`

### AC-2: Valid bars are inserted

**Given** a POST to `/api/push-ohlcv-history` with valid `X-API-Key`,
  `code: "VNM"`, and `bars` array of 60 candles
**When** the server processes the request
**Then**
- HTTP 200 is returned with `{ "ok": true, "inserted": 60, "code": "VNM" }`
- `daily_ohlcv` contains exactly 60 rows with `code = "VNM"`
- Each row has correct `open`, `high`, `low`, `close`, `volume`, `date`

### AC-3: Duplicate dates upsert without row explosion

**Given** 60 bars for "VNM" already inserted
**When** the same 60 bars are pushed again (e.g. script run twice)
**Then**
- `daily_ohlcv` still has exactly 60 rows for "VNM" (no duplicates)
- Close prices reflect the second push's values

### AC-4: Empty bars is a no-op

**Given** a POST with `code: "VNM"` and `bars: []`
**When** the server processes the request
**Then**
- HTTP 200 returned with `{ "ok": true, "inserted": 0 }`
- No rows written to `daily_ohlcv`

### AC-5: Malformed payload returns 400

**Given** a POST with missing `code` field or `bars` not an array
**When** the server processes the request
**Then**
- HTTP 400 returned with a descriptive `{ "error": "..." }` message
- No rows written to `daily_ohlcv`

### AC-6: Post-backfill taSummary is non-empty

**Given** the VPS script has run successfully for all 30 watchlist tickers
**When** the evening report assembles taSummary via `defaultComputeTa()`
**Then**
- `daily_ohlcv` has 50+ rows per ticker (enough for RSI + MA20 computation)
- `taSummary` in the evening report contains at least 1 non-neutral `TaSignal`

### AC-7: VPS script exits cleanly on partial failure

**Given** 2 of 30 tickers return a TCBS 404 or timeout
**When** the script completes
**Then**
- Script exits 0
- Successful tickers are inserted; failed tickers are logged with WARN
- No global abort on single-ticker failure

## Implementation Notes for Architect / Developer

### Endpoint handler skeleton

```
POST /api/push-ohlcv-history
  1. Auth check: X-API-Key vs Bun.env.VPS_PUSH_API_KEY → 401 if mismatch
  2. Read + JSON.parse body → 400 if parse fails
  3. Validate: typeof payload.code === "string" → 400 if missing
  4. Validate: Array.isArray(payload.bars) → 400 if not array
  5. If bars.length === 0 → return 200 { ok: true, inserted: 0 }
  6. Prepare upsert:
       INSERT INTO daily_ohlcv (code, date, open, high, low, close, volume, updated_at)
       VALUES (?, ?, ?, ?, ?, ?, ?, ?)
       ON CONFLICT(code, date) DO UPDATE SET
         open=excluded.open, high=excluded.high, low=excluded.low,
         close=excluded.close, volume=excluded.volume, updated_at=excluded.updated_at
  7. Run in transaction: for each bar, skip if open<=0 or close<=0, else run upsert
  8. Return 200 { ok: true, inserted: count, code: payload.code }
  9. Log: [push-ohlcv-history] code=VNM inserted=60
```

### TCBS API response shape (reference)

```json
{
  "data": [
    {
      "tradingDate": "2025-01-15T00:00:00",
      "open": 73500,
      "high": 75000,
      "low": 72800,
      "close": 74200,
      "volume": 1234567
    }
  ]
}
```

Note: TCBS prices are in VND (full, not thousands). Existing `daily_ohlcv` rows from the
price-push path (`/api/push-prices`) store prices in the raw unit from `bgapidatafeed.vps.com.vn`
(lastPrice field). Architect must verify unit alignment before implementing the VPS script.
If units differ, the script must apply a conversion factor.

### VPS script skeleton

```bash
#!/bin/bash
# fetch-ohlcv-backfill.sh — ONE-TIME manual run, not a systemd loop
# Usage: MCP_BASE=https://... API_KEY=... bash vps-scripts/fetch-ohlcv-backfill.sh

MCP_BASE="${MCP_BASE:?MCP_BASE not set}"
API_KEY="${API_KEY:?API_KEY not set}"
LOG="/var/log/vn-ohlcv-backfill.log"

FROM=$(date -d "90 days ago" +%s)   # generous window for 60 trading days
TO=$(date +%s)

# Get watchlist from server
CODES=$(curl -s "$MCP_BASE/api/watchlist" -H "X-API-Key: $API_KEY" | jq -r '.codes[]')

for CODE in $CODES; do
  DATA=$(curl -s --connect-timeout 10 --max-time 20 \
    "https://api.tcbs.com.vn/stock-insight/v1/stock/bars?ticker=$CODE&type=stock&resolution=D&from=$FROM&to=$TO")
  BARS=$(echo "$DATA" | jq '[.data[]? | {
    date: (.tradingDate[0:10]),
    open: .open, high: .high, low: .low, close: .close,
    volume: (.volume // 0)
  }]' 2>/dev/null)
  COUNT=$(echo "$BARS" | jq 'length')
  PAYLOAD=$(jq -n --arg code "$CODE" --argjson bars "$BARS" '{"code": $code, "bars": $bars}')
  RESP=$(curl -s -X POST "$MCP_BASE/api/push-ohlcv-history" \
    -H "Content-Type: application/json" -H "X-API-Key: $API_KEY" -d "$PAYLOAD")
  echo "$(date -u) $CODE: $COUNT bars → $RESP" | tee -a "$LOG"
  sleep 0.2
done
```
