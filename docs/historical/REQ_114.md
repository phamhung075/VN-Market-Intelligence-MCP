# REQ-114: TA Fallback — Intraday History When Daily OHLCV Insufficient

status: READY_FOR_ARCHITECT
sprint: 114
po_vision: Evening summary shows taSummary:[] because daily_ohlcv never reaches 15 rows within the first 3 calendar weeks after VPS writes begin; fix by falling back to synthetic daily closes aggregated from market_prices_history intraday ticks.

## User Story

As a Vietnamese stock investor using Claude,
I want TA signals (RSI, MA20) in the evening summary from day 1 of market data collection,
So that I receive actionable technical analysis immediately rather than waiting 3 calendar weeks for enough daily_ohlcv rows to accumulate.

## Problem Statement

Sprint 107 fixed `defaultComputeTa()` to read from `daily_ohlcv` instead of raw intraday ticks. This was correct — daily OHLCV is the right source for TA. However a new gap was exposed: the VPS writes exactly one row per trading day into `daily_ohlcv`. The RSI(14) minimum is 15 candles. At 5 trading days per week, 15 candles require 3 calendar weeks from first VPS push. Until then, `defaultComputeTa()` returns `null` for every ticker and `taSummary: []` appears in every evening report.

`market_prices_history` already contains intraday price ticks (code, price, volume, fetched_at) pushed every 60 seconds by the VPS. A GROUP BY DATE aggregation over this table yields synthetic daily closes equivalent to the last traded price of each calendar day — usable as a daily candle close for TA purposes.

## Functional Requirements

### FR-1: Synthetic Daily Close Aggregation from Intraday Ticks

- Description: When `daily_ohlcv` has fewer than 15 rows for a ticker, query `market_prices_history` and aggregate ticks into synthetic daily closes using `MAX(price)` as the close proxy, grouped by calendar date in Vietnam timezone.
- Input: `code: string`, `db: Database`
- Output: Array of `{ day: string, close_price: number }` sorted ASC by day — same shape as the `CandleRow` interface already used by `defaultComputeTa()`.
- Business rule: Use `DATE(fetched_at)` for grouping (SQLite DATE() extracts YYYY-MM-DD from ISO text). Use `MAX(price)` as the close proxy — this represents the highest intraday price, which for a VPS polling at 60s is the last-traded-price approximation. Do NOT use AVG (misrepresents the close level for TA).
- Business rule: Only use fallback rows when the `daily_ohlcv` count for the ticker is strictly less than 15 (`< 15`). Once `daily_ohlcv` reaches 15 rows, the fallback is never invoked regardless of how many intraday ticks exist.
- DDD layer: application — `src/application/usecases/assembleBriefing.ts`

### FR-2: Modified defaultComputeTa() with Fallback Branch

- Description: Extend `defaultComputeTa(code, db)` to implement the two-path logic: primary path (daily_ohlcv >= 15 rows) unchanged; fallback path (daily_ohlcv < 15 rows, market_prices_history >= 15 distinct dates) computes TA from synthetic closes.
- Input: `code: string`, `db: Database` — signature unchanged.
- Output: `TaSignal | null` — return type unchanged.
- Business rule: If `daily_ohlcv` row count < 15 AND synthetic close count (distinct dates in `market_prices_history`) < 15 → return `null`. No partial signals.
- Business rule: RSI(14) and MA(20) computations use the same `computeRSI` and `computeMA` helpers already in scope — no new math functions.
- Business rule: The `currentPrice` field of the returned `TaSignal` is set to the last close in the chosen price series (primary or fallback).
- DDD layer: application — `src/application/usecases/assembleBriefing.ts`

### FR-3: TDD Test File — task 1342 (written FIRST)

- Test cases (minimum 4):

  | TC | daily_ohlcv rows | market_prices_history days | Expected result |

- DDD layer: test — `src/__tests__/1342-ta-fallback-intraday.test.ts`

## Non-Functional Requirements

- Performance: The fallback GROUP BY query on `market_prices_history` is bounded to a single ticker at a time; `idx_mph_code_fetched` index (code, fetched_at DESC) already exists — query stays O(log N) per ticker.
- Data freshness: No change to write paths. Read-only addition.
- Language: No user-facing text changes. Internal logic only.

## Edge Cases & Data Quality

- [ ] `market_prices_history.fetched_at` is stored as ISO 8601 UTC text (e.g. `"2026-04-16T08:30:00Z"`). `DATE(fetched_at)` in SQLite returns the UTC calendar date, not Vietnam local date. This is acceptable — VN trading hours are 09:00–14:30 ICT (02:00–07:30 UTC), so all ticks for one trading day share the same UTC date. No timezone correction needed.
- [ ] If `market_prices_history` has ticks for fewer than 15 distinct dates but > 0 ticks — return `null` (FR-2 business rule). Do not compute partial RSI.
- [ ] If `daily_ohlcv` has exactly 15 rows, the primary path is used and the fallback is never queried. This preserves the Sprint 107 behaviour unchanged.
- [ ] The `market_prices_history` PRIMARY KEY is `(code, fetched_at)`. Duplicate ticks at the same timestamp are rejected by the DB. The GROUP BY aggregation is safe.
- [ ] A ticker on the watchlist with zero rows in both tables returns `null` — no crash, no signal. Same as pre-Sprint-107 behaviour.

## Implementation Notes for Architect

The change is confined to a single function `defaultComputeTa()` in `assembleBriefing.ts`. The existing `CandleRow` interface (`{ day: string, close_price: number }`) is reused — the fallback SELECT aliases `DATE(fetched_at)` as `day` and `MAX(price)` as `close_price` to match this shape without introducing a new type.

Fallback SQL sketch (parameterized):
```sql
SELECT DATE(fetched_at) AS day,
       MAX(price)       AS close_price
  FROM market_prices_history
 WHERE code = ?
 GROUP BY DATE(fetched_at)
 ORDER BY day ASC
 LIMIT 60
```
