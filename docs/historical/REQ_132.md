# REQ-132: VPS Auto-Deploy on Merge

status: READY_FOR_ARCHITECT
sprint: 132
po_vision: Eliminate the manual VPS deploy step — the full automation loop is truly autonomous after any merge that touches vps-scripts/ or deploy-vinahost.sh.

## User Story

As a developer agent merging a task branch that modifies VPS proxy scripts,
I want `./scripts/maybe-deploy-vps.sh` to run automatically during branch hygiene,
So that the Vinahost VPS always runs the latest scripts without any manual intervention.

---

## Functional Requirements

### FR-1: maybe-deploy-vps.sh — change detection

- Description: Shell script that inspects the last merged commit for changes to VPS-related files and conditionally triggers deploy.
- Input: `git diff HEAD~1 --name-only` output (list of changed file paths); optional `--dry-run` flag
- Output: Prints "VPS deploy triggered" and runs `./deploy-vinahost.sh`, OR prints "VPS deploy skipped"; exits 0 in both paths
- Business rule: Trigger condition — any changed path that starts with `vps-scripts/` OR equals `deploy-vinahost.sh`. All other paths (e.g. `src/`, `docs/`, `.claude/`) are ignored.
- DDD layer: infrastructure (shell-layer, outside TypeScript source tree)

### FR-2: maybe-deploy-vps.sh — dry-run mode

- Description: `--dry-run` flag prints the intended action without executing `./deploy-vinahost.sh`.
- Input: `--dry-run` as first argument
- Output: Prints "VPS deploy triggered (dry-run)" or "VPS deploy skipped (dry-run)" without SSH side effects
- Business rule: Dry-run MUST NOT call `./deploy-vinahost.sh` under any circumstances. Used in TDD test isolation.
- DDD layer: infrastructure (shell)

### FR-3: maybe-deploy-vps.sh — WORK-channel Telegram notification

- Description: After a real (non-dry-run) deploy, posts a short message to the WORK channel via curl.
- Input: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_INFO_WORK_CHANNEL_ID` from `.env` (sourced if present)
- Output: HTTP POST to Telegram Bot API with message "VPS deploy complete: vps-scripts/ or deploy-vinahost.sh changed in last merge."
- Business rule: If `.env` is absent or env vars are unset, skip the notification silently — do not abort the script.
- DDD layer: infrastructure (shell)

### FR-4: dev-standards.md — branch hygiene step 4a

- Description: Insert a new step 4a into the Branch Hygiene checklist in `.claude/knowledge/dev-standards.md`.
- Input: n/a (documentation update)
- Output: Step 4a reads: "If changed files include `vps-scripts/**` or `deploy-vinahost.sh`, run `./scripts/maybe-deploy-vps.sh` before deleting the task branch."
- Business rule: Step 4a must appear between the existing step 4 (worktree removal) and step 5 (stash drop) — i.e. after the merge is confirmed on main, before cleanup.
- DDD layer: documentation

### FR-5: TDD test — detection logic validation

- Description: TypeScript/Bun test that validates the shell script exists, is executable, and produces correct output in both trigger and skip paths using `--dry-run`.
- Input: Bun `Bun.spawnSync` (or `execa`) calling `scripts/maybe-deploy-vps.sh --dry-run`; test passes a fake diff via env var `FAKE_DIFF` (path list, newline-separated)
- Output: asserts stdout contains expected string; asserts exit code = 0
- Business rule: Test must be RED before the script exists (file-exists assertion fails). GREEN after both FR-1 and FR-2 are implemented.
- DDD layer: test

## Non-Functional Requirements

- Performance: Script must complete in under 2 seconds in dry-run mode (no network calls).
- Idempotency: Running the script twice on the same commit is safe — `./deploy-vinahost.sh` is idempotent (restarts existing systemd services).
- Portability: Script uses `#!/bin/bash`, POSIX-compatible diff parsing, no `gawk`/`perl` dependency.
- Language: Output messages in English (dev-team tooling, not user-facing).

---

## Edge Cases & Data Quality

- [ ] Empty diff (initial commit or no files changed) → script prints "VPS deploy skipped", exits 0
- [ ] `HEAD~1` unavailable (shallow clone, first commit) → `git diff HEAD~1` fails; script catches error, falls back to "VPS deploy skipped" with a warning to stderr
- [ ] `deploy-vinahost.sh` itself not found at repo root → script prints error to stderr, exits 1 (hard failure — must be loud)
- [ ] `.env` absent or `VINAHOST_IP` unset → deploy-vinahost.sh already exits 1 with "ERROR: VAR not set in .env"; maybe-deploy-vps.sh propagates the exit code
- [ ] `--dry-run` combined with missing env vars → no error, dry-run never calls deploy
- [ ] Changed file path contains `vps-scripts` as substring of a different directory (e.g. `src/test-vps-scripts/`) → must NOT trigger; match must be prefix `vps-scripts/` (slash required)

## Implementation Notes for Architect

### FAKE_DIFF injection pattern for test isolation

The test cannot control the live git history of the repo. Recommended pattern:

```bash
# maybe-deploy-vps.sh — detection block
if [ -n "$FAKE_DIFF" ]; then
  DIFF_OUTPUT="$FAKE_DIFF"
else
  DIFF_OUTPUT=$(git diff HEAD~1 --name-only 2>/dev/null || echo "")
fi
```

The test sets `FAKE_DIFF` via env and calls the script with `--dry-run`. No git history manipulation needed. This is the only cross-cutting design decision the Architect must preserve.

### Trigger patterns (grep-compatible)

```
^vps-scripts/
^deploy-vinahost\.sh$
```

Both anchored to line start and end to prevent substring false-positives.

### Script location

`scripts/maybe-deploy-vps.sh` — alongside existing `scripts/test-all.sh`. The `scripts/` directory already exists.

### Telegram notification (non-dry-run only)

```bash
if [ -n "$TELEGRAM_BOT_TOKEN" ] && [ -n "$TELEGRAM_INFO_WORK_CHANNEL_ID" ]; then
  curl -s -X POST "https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage" \
    -d chat_id="${TELEGRAM_INFO_WORK_CHANNEL_ID}" \
    -d text="VPS deploy complete: vps-scripts/ or deploy-vinahost.sh changed in last merge." \
    > /dev/null
fi
```

No failure on missing vars — silent skip.
