# REQ-097: TA Close-of-Day Signals in Evening Recap

status: READY_FOR_ARCHITECT
sprint: 097
po_vision: Add RSI and MA20 close-of-day signals to the evening summary so users can plan overnight positions with the same TA context they receive each morning.

## User Story

As a Vietnamese stock investor using Claude,
I want the evening summary to include RSI(14) and MA20 status for each watchlist ticker at market close,
So that I can identify overbought/oversold conditions and price-vs-MA position before planning the next session.

---

## Functional Requirements

### FR-1: Extend EveningSummary type with taSummary field

- Description: Add `taSummary: TaSignal[]` to the `EveningSummary` interface in `assembleEveningSummary.ts`. Import the `TaSignal` type from `assembleBriefing.ts` (already exported as `export interface TaSignal`).
- Input: n/a (type change only)
- Output: `EveningSummary` object now carries `taSummary: TaSignal[]`
- Business rule: Field is always present; empty array when watchlist is empty or all signals are neutral.
- DDD layer: application

### FR-2: Export defaultComputeTa from assembleBriefing.ts

- Description: `defaultComputeTa` is currently a module-private function (line 504, no `export` keyword). It must be exported so `assembleEveningSummary.ts` can import it without duplicating logic.
- Input: n/a (export keyword addition only)
- Output: `export function defaultComputeTa(code: string, db: Database): TaSignal | null` visible to importers.
- Business rule: Do not move or alter the function body. Only add the `export` keyword.
- DDD layer: application

### FR-3: Add computeTaFn injectable dependency to AssembleEveningSummaryOptions

- Description: Extend `AssembleEveningSummaryOptions` with `computeTaFn?: (code: string, db: Database) => TaSignal | null`. Default value = `defaultComputeTa` (imported from `assembleBriefing.ts`).
- Input: Optional function passed at call site (tests inject a mock; production omits it).
- Output: The use-case uses the injected function when provided.
- Business rule: Mirrors the morning briefing pattern (`options.computeTaFn ?? defaultComputeTa`).
- DDD layer: application

### FR-4: Populate taSummary in assembleEveningSummary

- Description: After the watchlist movers step (Step 3), add a TA step. Iterate all watchlist ticker rows, call `computeTaFn(code, db)` per ticker, collect non-null results. Null results (fewer than 15 candles) are silently skipped — ticker is omitted from `taSummary`. Wrap the entire step in try/catch; per-ticker errors are also caught independently so one bad ticker cannot abort the rest.
- Input: `watchlist` table rows (already queried for movers), injected `db`.
- Output: `taSummary: TaSignal[]` — contains only tickers for which `computeTaFn` returned non-null. May include neutral signals (all signals collected, no neutral filter at the use-case level — see FR-6 for display filter).
- Business rule: Collect all non-null signals. The display filter (non-neutral only) is applied in `eveningSummaryJob.ts` for the Telegram section, not here — this keeps the JSON report complete.
- DDD layer: application

### FR-5: Include taSummary in persisted JSON report

- Description: The `EveningSummary` object (which now includes `taSummary`) is serialized to `reports/YYYY-MM-DD-evening.json` via the existing `writeFileSync` call. No additional change needed beyond FR-1 and FR-4 — the field is included automatically.
- Input: `summary` object with `taSummary` populated.
- Output: `reports/2026-04-15-evening.json` has a `taSummary` key containing the array.
- Business rule: Overwrites on re-run (same as existing behavior).
- DDD layer: application

### FR-6: Append TA section to evening Telegram message in eveningSummaryJob.ts

- Description: In `runEveningSummary`, after the "Tín hiệu dự đoán" block, append a "TA tín hiệu đóng cửa" section when `summary.taSummary` contains at least one ticker with `rsiStatus !== "neutral"` OR `priceVsMa20 !== "neutral"`. When all signals are neutral (or `taSummary` is empty), the section is entirely omitted.
- Input: `summary.taSummary: TaSignal[]`
- Output: Telegram message string appended with:
  ```
  TA tín hiệu đóng cửa:
    VCB: RSI=74.2 (quá mua), giá trên MA20
    HPG: RSI=27.8 (quá bán)
  ```
- Business rule:
  - Only render tickers where `rsiStatus !== "neutral"` OR `priceVsMa20 !== "neutral"`.
  - RSI label: `rsiStatus === "overbought"` → `(quá mua)`; `rsiStatus === "oversold"` → `(quá bán)`; `rsiStatus === "neutral"` → omit RSI note.
  - MA20 label: `priceVsMa20 === "above"` → `, giá trên MA20`; `priceVsMa20 === "below"` → `, giá dưới MA20`; `"neutral"` → omit MA20 note.
  - RSI value: include only when `rsi14 !== null`. Format: `RSI={rsi14.toFixed(1)}`.
  - Cap at 5 tickers in the Telegram section.
- DDD layer: interface (scheduler)

## Non-Functional Requirements

- Performance: TA computation per ticker is a pure in-process function (no network). 30 watchlist tickers at close adds < 5ms to the job.
- Data freshness: Uses `market_prices_history` — same table as morning briefing. Data freshness depends on the VPS proxy feed; no change to fetch cadence.
- Language: Vietnamese labels for Telegram (`quá mua`, `quá bán`, `giá trên MA20`, `giá dưới MA20`). Ticker codes uppercase ASCII.
- Type safety: `bun tsc --noEmit` must pass with 0 errors after changes.

---

## Edge Cases & Data Quality

- [ ] Ticker has fewer than 15 candles in `market_prices_history` → `defaultComputeTa` returns null → ticker is silently omitted from `taSummary` (not an error).
- [ ] Ticker has 15–19 candles → RSI computable, MA20 not → `ma20: null`, `priceVsMa20: "neutral"` — signal may still be non-neutral on RSI side.
- [ ] Watchlist is empty → `taSummary: []` → TA section omitted from Telegram.
- [ ] All tickers neutral → `taSummary` populated but no non-neutral entries → TA section omitted from Telegram (message unchanged).
- [ ] `computeTaFn` throws for one ticker → per-ticker catch swallows error, continues with remaining tickers.
- [ ] `market_prices_history` table missing → outer try/catch logs warning, `taSummary` defaults to `[]`.
- [ ] `rsi14 === null` (returned in TaSignal when history exists but < 15 days) → display omits `RSI=...` from line.
- [ ] Evening job re-runs on same day (server restart) → existing dedup guard (`alreadySentToday`) suppresses duplicate Telegram; JSON is overwritten with updated taSummary.
