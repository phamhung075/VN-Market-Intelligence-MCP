# REQ-1303h: BCTC PDF Parser — Impossible Figures Guard

status: READY_FOR_ARCHITECT
sprint: 1303
po_vision: Prevent garbage BCTC values (revenue > GDP, negative equity > assets) from reaching DB and alerts.

---

## User Story

As a Vietnamese stock investor using Claude,
I want the BCTC parser to reject physically impossible financial values,
So that alerts and ratios are never computed from OCR garbage.

---

## Current Behaviour (no bounds)

Both `extractNumber()` functions (income + balance sheet) return any parsed number verbatim:

| File | Line | Current behaviour |
|------|------|-------------------|
| `src/domain/services/financial-reports/incomeStatementExtractor.ts` | 40–63 | Returns first large token; no ceiling/floor |
| `src/domain/services/financial-reports/balanceSheetExtractor.ts` | 45–66 | Same pattern; same gap |

Downstream effects when OCR mis-parses a line:

- `netRevenue = 9_999_999_999` triệu → stored → ratio engine divides by it → P/E ≈ 0
- `equity.total = -50_000_000_000` triệu → stored → solvency alert fires false positive
- No audit trail: raw OCR line is discarded, impossible value silently written to DB

---

## Proposed Bounds

All monetary fields are denominated in **triệu đồng** (million VND) after unit conversion.

Vietnam 2024 GDP ≈ 477 tỷ USD ≈ 11,800,000,000 triệu VND.
Largest listed company (VCB) total assets ≈ 2,700,000 tỷ VND ≈ 2,700,000,000 triệu.

| Bound | Value (triệu đồng) | Rationale |
|-------|--------------------|-----------|
| `GUARD_MIN` | −10,000,000,000,000 (−10T) | Deepest plausible negative equity/loss |
| `GUARD_MAX` | 500,000,000,000,000 (500T) | ~43× VCB assets; physically impossible ceiling |

**EPS is exempt** — it is in VND/share, not triệu. Both extractors already skip EPS from multiplier scaling; guard must also skip EPS fields.

## Functional Requirements

### FR-1: Shared guard function in new file

- **File**: `src/domain/services/financial-reports/extractorGuards.ts` (new)
- **Export**: `guardExtractedValue(value: number, rawLine: string, fieldHint: string): number | null`
- **Logic**:
  1. If `value < GUARD_MIN` or `value > GUARD_MAX` → log raw line + fieldHint → return `null`
  2. Otherwise → return `value` unchanged
- **No I/O**: pure function; logging via `console.warn` only (domain layer)
- **DDD layer**: domain

### FR-2: Wire guard into `incomeStatementExtractor.ts`

- **File**: `src/domain/services/financial-reports/incomeStatementExtractor.ts`
- **Location**: `extractNumber()` at line 40, after `parseVnNumber()` returns a non-null value
- **Change**: wrap return value with `guardExtractedValue(val, line, "income")`
- **Return type change**: `extractNumber()` already returns `number | null`; guard preserves that contract
- **EPS exemption**: `extractNumber()` is called for all fields including EPS. Guard applies — EPS values in the valid [−10T, 500T] triệu range map to absurd VND/share, but EPS is in raw VND not triệu, so EPS can legitimately be a small number (e.g. 2,500 VND/share). Guard GUARD_MIN = −10T triệu = −10,000,000,000,000,000,000 VND — EPS will never hit this. Guard GUARD_MAX = 500T triệu = extremely large. EPS safe: no special handling needed at guard level.
- **DDD layer**: domain

### FR-3: Wire guard into `balanceSheetExtractor.ts`

- **File**: `src/domain/services/financial-reports/balanceSheetExtractor.ts`
- **Location**: `extractNumber()` at line 45, same pattern as FR-2
- **Change**: same `guardExtractedValue` call
- **Caller handling**: `findValue()` returns `0` when `extractNumber()` returns `null`. Guard returning `null` → `extractNumber()` returns `null` → `findValue()` treats as "not found" → defaults to `0`. This is correct: a field that parses to an impossible value is treated as missing (zero), not as the impossible value.
- **DDD layer**: domain

### FR-4: Audit log

- When guard fires: `console.warn("[extractorGuards] Impossible value rejected: field=<fieldHint> value=<value> raw='<rawLine>'")`
- Format must include raw OCR line for post-mortem debugging
- No DB write, no Telegram alert (domain layer only)

## Edge Cases & Data Quality

- [ ] OCR garbles a number into `999.999.999.999` (9.9 quadrillion triệu) → rejected, field → 0
- [ ] Negative equity legitimately −500,000 triệu (loss company) → within bounds, passes
- [ ] Revenue = 0 after guard → downstream ratio engine receives 0 → division guard elsewhere (not in scope here)
- [ ] `null` returned by guard → `extractNumber()` propagates `null` → `findValue()` tries look-ahead lines → eventual default 0
- [ ] Split-block path (`parseSplitBlockIncomeStatement`, `parseSplitBlockBalanceSheet`) uses `extractColumnNumber()` not `extractNumber()` — `extractColumnNumber()` must also call guard (same pattern at its return point)
- [ ] Vietnamese number `(1.234.567)` = negative in BCTC → `parseVnNumber` already handles parentheses as negative; guard MIN covers legitimate negatives
- [ ] Unit multiplier applied AFTER extraction: guard must fire on **pre-multiplier** raw value OR post-multiplier final value. **Decision: guard fires post-multiplier** (in `extractIncomeStatement` / `extractBalanceSheet` final return, not inside `extractNumber`). This is cleaner — see FR-5.

### FR-5 (revised approach): Post-multiplier guard in extractor functions

After code review: `extractNumber()` returns a raw token value; the multiplier (1, 1000, or 0.000001) is applied later. A raw token of `999.999.999` with multiplier=1 = 999,999,999 triệu → impossible. But with multiplier=0.000001 → ≈1 triệu → valid.

**Correct guard placement: post-multiplier, in the final return statement of each extractor function.**

Revised approach:

- `extractorGuards.ts` exports `guardFinancialField(value: number, fieldName: string, rawValue: number): number`
- Takes post-multiplier `value`, field name, and pre-multiplier `rawValue` (for audit log)
- Returns `0` (not `null`) when impossible — callers already default to 0 for missing fields
- Applied per-field in `extractIncomeStatement()` and `extractBalanceSheet()` return objects
- `extractNumber()` itself unchanged — no return type change needed

| Approach | Guard location | Return type change | Multiplier-aware |
|----------|---------------|-------------------|-----------------|
| FR-2/3 original | Inside `extractNumber()` | None needed | No — fires on raw token |
| FR-5 revised | In extractor return | None needed | Yes — fires post-multiplier |

**FR-5 is the correct approach.** Update FR-2 and FR-3 accordingly.

## Acceptance Criteria

### AC-1: Guard function exists and rejects impossible values

**Given** `guardFinancialField(600_000_000_000_000, "netRevenue", 600_000_000_000)` (600T triệu = above cap)
**When** called
**Then**

- Returns `0`
- `console.warn` called with string containing `"netRevenue"` and raw value

### AC-2: Guard passes valid values unchanged

**Given** `guardFinancialField(9_500_000, "netRevenue", 9_500_000)` (9.5T triệu = VNM scale)
**When** called
**Then**

- Returns `9_500_000` exactly

### AC-3: Guard passes valid negative values

**Given** `guardFinancialField(-800_000, "retainedEarnings", -800_000)` (loss company)
**When** called
**Then**

- Returns `−800_000` exactly

### AC-4: Guard rejects values below floor

**Given** `guardFinancialField(-20_000_000_000_000, "equity", -20_000_000_000)` (−20T triệu)
**When** called
**Then**

- Returns `0`
- `console.warn` called

### AC-5: `extractIncomeStatement` rejects impossible revenue

**Given** raw BCTC text with OCR-corrupted line `"Doanh thu thuần  999.999.999.999.999"`
**When** `extractIncomeStatement(rawText)` called
**Then**

- `result.netRevenue` equals `0` (not `999_999_999_999_999`)
- No exception thrown

### AC-6: `extractBalanceSheet` rejects impossible total assets

**Given** raw BCTC text with line `"TỔNG CỘNG TÀI SẢN  888.888.888.888.888"`
**When** `extractBalanceSheet(rawText)` called
**Then**

- `result.totalAssets` equals `0`

### AC-7: Valid real-world scale values pass unmodified

**Given** VNM-scale income statement (netRevenue ≈ 14,000,000 triệu)
**When** `extractIncomeStatement(rawText)` called
**Then**

- All fields within `[−10T, 500T]` range pass unchanged
- No `console.warn` fired
