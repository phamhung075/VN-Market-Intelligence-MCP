## Architecture Decision

All 13 target strings are embedded inside MCP server `tool()` handler callbacks (`registerKinhDichTools`, `registerAlertMuteTools`, `registerWatchlistTools`, `registerCompareTools`) or inside an exported helper (`buildSupplyChainExposureOutput`). Handler-internal strings are not reachable via normal function calls. The test for those 4 files uses **source-file scanning**: `readFileSync` on the `.ts` source, asserting the accented form is present and the unaccented form is absent. `buildSupplyChainExposureOutput` is already exported — called directly. This is consistent with the wave 1-3 precedent of not adding new exports for handler-internal strings.

No new exports, no extracted helpers, no DDD layer changes — interface layer string fixes only.
