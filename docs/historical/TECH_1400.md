## Architecture Decision

`setup.ts` wrote to `process.env` but `schema.ts:64` reads `Bun.env` — separate namespaces in Bun runtime. The singleton `_db` is opened on first `getDb()` call using the stale `DEFAULT_DB_PATH`, bypassing `:memory:` entirely. Fix: write to `Bun.env` in setup.ts — one character-level change, zero architectural change. Purge is a one-shot script (not a schema migration) to avoid running DELETE on every server boot.

### setup.ts (MODIFY — one line)

```typescript
// BEFORE (broken):
process.env["DB_PATH"] = ":memory:";

// AFTER (correct):

```

**Why this works:** `schema.ts:64` evaluates `Bun.env["DB_PATH"] ?? DEFAULT_DB_PATH` at first `getDb()` call. Bun test preload runs before any module import, so `Bun.env` is already set when the singleton opens. `process.env` mutations never propagate to `Bun.env` in Bun runtime — confirmed by Bun docs.

### scripts/purge-phantom-reports.ts (NEW)

```typescript
// Standalone script — run once: bun scripts/purge-phantom-reports.ts
import { Database } from "bun:sqlite";
import { resolve } from "node:path";
import { existsSync } from "node:fs";

const PROJECT_ROOT = resolve(import.meta.dir, "..");
const DB_PATH = resolve(PROJECT_ROOT, "data", "market.db");

if (!existsSync(DB_PATH)) {
  console.warn(`[purge] data/market.db not found — skip`);
  process.exit(0);
}

const db = new Database(DB_PATH);
const result = db
  .prepare("DELETE FROM telegram_reports WHERE created_at < 1000000")
  .run();
console.log(`[purge] deleted ${result.changes} phantom rows (created_at < 1000000)`);
db.close();
```

Safety bound: `created_at < 1000000` = epoch before 1970-01-12. All real production rows have Unix timestamps ~1,700,000,000 (2020s era). Cannot delete valid data.

### src/__tests__/1400-db-isolation.test.ts (NEW)

```typescript
import { describe, it, expect } from "bun:test";
import { resolve } from "node:path";

describe("Task 1400 — DB isolation: Bun.env namespace", () => {
  it("Bun.env[DB_PATH] is :memory: during test run", () => {
    expect(Bun.env["DB_PATH"]).toBe(":memory:");
  });

  it("production DB path is not the active DB path", async () => {
    const { getDb } = await import("../infrastructure/db/schema.js");
    const db = getDb();
    const PROJECT_ROOT = resolve(import.meta.dir, "..", "..");
    const prodPath = resolve(PROJECT_ROOT, "data", "market.db");
    expect((db as unknown as { filename: string }).filename).not.toBe(prodPath);
  });
});
```

Note: dynamic `import()` avoids singleton caching before the env check. `db.filename` is a Bun SQLite property returning the path passed to `new Database(path)` — `":memory:"` for in-memory DBs.
