# REQ-043: Radar Khủng Hoảng — Velocity-based Crisis Detection

status: APPROVED
sprint: 043
po_vision: Phát hiện khủng hoảng sản phẩm, sự cố môi trường, scandal doanh nghiệp qua velocity detection (tốc độ mention + sentiment drop + multi-source). Phát hiện trong 15 phút, giá phản ứng trong 1-2 giờ. Bảo vệ vốn + short-term trading edge.

---

## User Stories

### US-1: Crisis velocity detection
As a Vietnamese stock investor,
I want the system to detect crisis events by measuring the VELOCITY of negative mentions (not just sentiment),
So that I am alerted within 15 minutes of a crisis breaking — before the full price impact.

### US-2: Crisis pattern classification
As a Vietnamese stock investor,
I want the system to classify crisis types (product recall, environmental incident, executive scandal, data breach),
So that I can assess the severity and likely duration based on historical patterns.

### US-3: Reputation score tracking
As a Vietnamese stock investor,
I want the system to maintain a rolling reputation score per watchlist stock,
So that I can see gradual reputation deterioration before a crisis fully materializes.

## Functional Requirements

### FR-1: Crisis Pattern Detector (`src/domain/services/crisisPatternDetector.ts`)

- **Description**: Pure domain service. Detect crisis events from news stream using velocity + pattern matching.
- **Vietnamese crisis patterns**:
  ```
  thu hồi sản phẩm, ngộ độc thực phẩm, sản phẩm lỗi, product recall,
  xả thải, ô nhiễm môi trường, vi phạm môi trường, environmental violation,
  tai nạn lao động, sập công trình, cháy nhà máy, factory fire,
  lộ dữ liệu, data breach, hack, tấn công mạng, cyber attack,
  scandal, bê bối, tố cáo, whistleblower, lừa đảo, gian lận
  ```
- **Crisis types**: `product_recall` | `environmental` | `workplace_accident` | `cyber_breach` | `fraud_scandal` | `executive_scandal` | `regulatory_action`
- **Velocity-based detection**:
  ```typescript
  interface CrisisIndicator {
    stock: string;
    mentionVelocity: number;     // mentions/hour vs 7-day baseline
    negativeSentimentRatio: number; // % negative in last 2 hours
    uniqueSources: number;       // distinct news sources reporting
    crisisScore: number;         // composite: velocity × sentiment × sources
  }
  // CRITICAL: velocity > 5× baseline + sentiment < -0.6 + sources ≥ 2
  // HIGH: velocity > 3× baseline + sentiment < -0.4 + sources ≥ 2
  // MEDIUM: velocity > 2× baseline + sentiment < -0.3
  ```
- **Output**: `CrisisSignal { type, severity, stock, crisisScore, mentionVelocity, topHeadlines, confidence }`
- **Pure function**: No I/O (receives pre-computed mention counts and sentiment).

### FR-2: Reputation Scorer (`src/domain/services/reputationScorer.ts`)

- **Description**: Pure domain service. Compute rolling 30-day reputation score per stock.
- **Input**: Array of `{ date, sentimentScore, mentionCount, crisisEvents }` for past 30 days.
- **Computation**:
  - Base score: exponentially weighted moving average of daily sentiment (recent days weighted more).
  - Crisis penalty: -20 points per CRITICAL crisis, -10 per HIGH, -5 per MEDIUM.
  - Recovery rate: +2 points/day if no new crisis events.
  - Score range: 0–100 (100 = excellent reputation, 0 = severe crisis).
- **Output**: `ReputationScore { stock, score, trend: 'improving'|'deteriorating'|'stable', recentCrises, daysSinceLastCrisis }`
- **Pure function**: No I/O.

### FR-3: Mention Velocity Tracker (`src/infrastructure/db/mentionVelocityStore.ts`)

- **Description**: SQLite store for hourly mention counts per stock.
- **Table**: `mention_velocity (id, code, hour TEXT, mention_count INTEGER, negative_count INTEGER, source_count INTEGER)`
- **Methods**: `recordMention(code, source)`, `getVelocity(code, hours)`, `getBaseline(code, days)`
- **Cleanup**: Auto-delete entries older than 30 days.

### FR-4: Signal Integration

- **Extend `SignalType`**: Add `"crisis_event"` to union.
- **Wire into `pollNews.ts`**: After sentiment classification, update mention velocity store. Check crisis thresholds.
- **Crisis signal always → CRITICAL or HIGH**: Crisis events bypass normal cooldown (shortened to 30 min).

### FR-5: MCP Tools

- `get_crisis_early_warning(stock?: string)` → Active crisis indicators + reputation scores
- Reputation score integrated into morning briefing if any stock drops below 50.

## Edge Cases

1. **Flash mob mentions**: Viral meme about stock (not crisis) → requires `negativeSentimentRatio` filter.
2. **Old news reshared**: Article from 6 months ago goes viral → RAG temporal decay handles this.
3. **Competitor crisis**: Crisis at competitor → may be bullish for watchlist stock → classify separately.
4. **Weekend/off-hours crisis**: Crisis breaks Saturday → generate alert but note market closed.
