## Bug 1 — volume-spike-multiplier (tasks 1402, 1403)

### FR-1: Extend ATC guard window to cover post-close flush

- **Description:** ATC guard in `signalDetector.ts:247` blocks `07:30–08:05 UTC`. Post-ATC volume flush fires at `08:30 UTC` (= 15:30 VN, after session close). Guard must extend to `08:35 UTC` to suppress these false positives.
- **Current code:** `const isAtcWindow = (utcH === 7 && utcM >= 30) || (utcH === 8 && utcM <= 5);`
- **Required code:** `const isAtcWindow = (utcH === 7 && utcM >= 30) || (utcH === 8 && utcM <= 35);`
- **Input:** `utcNow` (Date), `utcH`, `utcM`
- **Output:** `isAtcWindow = true` for all minutes 07:30–08:35 UTC inclusive
- **Business rule:** No volume spike alert fires during VN ATC window OR post-close flush window
- **DDD layer:** domain
- **File:** `src/domain/services/signalDetector.ts:247`

### FR-2: Per-ticker avgVolume debug logging

- **Description:** Add a `console.debug` / `console.log` line after the `avgVolMap` is populated in `server.ts:517-534` that dumps each ticker's computed `avgVolume`. Confirms per-ticker isolation and aids post-deploy verification.
- **Input:** Populated `avgVolMap: Map<string, number>` after the SQL loop
- **Output:** Log line: `[volume-spike] avgVol map: { VCB: 12345678, FPT: 3456789, ... }` (Object.fromEntries)
- **Business rule:** Log at debug level — no user-visible side effect. Must not throw.
- **DDD layer:** interface
- **File:** `src/interface/mcp/server.ts:534` (after avgVolMap loop)

### FR-3: TDD RED test — two tickers produce different multipliers

- **Description:** Test file `src/__tests__/1402-volume-spike-multiplier.test.ts`. Assert that `detectSignals()` called with two tickers having different `avgVolume` values produces different `volume/avgVolume` multipliers in their respective `volume_spike` signals.
- **Input:** Two `SignalInput` objects — ticker A: `volume=10_000_000, avgVolume=1_000_000`; ticker B: `volume=10_000_000, avgVolume=5_000_000`. Both outside ATC window (`_now` = 10:00 UTC).
- **Output:** Signal A multiplier = 10.0×; Signal B multiplier = 2.0×. Both `volume_spike` signals present. Neither suppressed.
- **Business rule:** Multipliers must differ when avgVolumes differ. Uniform output is a regression.
- **DDD layer:** domain (test)
- **File:** `src/__tests__/1402-volume-spike-multiplier.test.ts`
