## Functional Requirements

### FR-1: Diagnose and fix VPS push-prices not persisting (Task 1193)

- **Description:** The VPS Singapore service (`vn-price-fetch.service`) sends price arrays to `POST /api/push-prices` every minute during trading hours (09:00–15:30 GMT+7). The `market_prices` table is empty or stale despite VPS logs showing successful HTTP 200 responses. The evening report therefore finds zero watchlist movers.
- **Root cause hypothesis (from code audit):** The `INSERT OR REPLACE INTO market_prices` statement at `server.ts:376` uses five columns `(code, price, change_pct, volume, updated_at)`. The `market_prices` DDL in `schema.ts:122` defines the PRIMARY KEY as `code TEXT PRIMARY KEY`. `INSERT OR REPLACE` on a PRIMARY KEY conflict silently deletes the old row and inserts the new one — this is correct. The most likely root causes are:
  1. **Auth failure:** `VPS_PUSH_API_KEY` env var missing or mismatched on the server side — the handler returns 401 and `logVpsPush` is called with `status:"error"`. The VPS service logs only HTTP status, not response body, so the error is invisible to the VPS operator.
  2. **Empty body or JSON parse failure:** The VPS service sends a malformed or chunked body. The handler returns 400 and exits before any upsert.
  3. **DB singleton stale after restart:** `getDb()` returns a cached `_db` instance that was opened before the WAL checkpoint; the singleton holds an old file descriptor and all writes silently succeed at the SQLite level but target the pre-checkpoint state. This is the hardest failure to detect.
  4. **price == null guard:** The per-row guard `if (!p.code || p.price == null) continue` may be skipping all rows if the VPS sends `price: 0` for stocks at circuit-breaker limit (VN market ceiling/floor). `0 == null` is false in JS but `price == null` matches only `null`/`undefined`, not `0` — this is actually correct, so price=0 rows are processed. This path is safe.
- **Input:** `POST /api/push-prices` with `x-api-key` header and JSON body `Array<{code, price, type?, ref_price?, volume?, change_pct?, fetched_at?}>`.
- **Output:** `{ok: true, updated: N}` where N equals the number of watchlist stocks in the push batch. Rows visible in `market_prices` immediately after the response.
- **Business rule:** Any push carrying watchlist tickers must persist within 500 ms of the HTTP response being sent. The async signal-detection block (lines 472+) must not block or rollback the synchronous upsert.
- **DDD layer:** infrastructure (server.ts HTTP handler + schema.ts DDL)
- **Diagnostic steps for Dev:**
  1. Query `vps_push_log` to confirm pushes are reaching the server: `SELECT * FROM vps_push_log WHERE service='prices' ORDER BY pushed_at DESC LIMIT 20`.
  2. If `vps_push_log` has no recent rows: auth failure — check `VPS_PUSH_API_KEY` env var on both VPS and server.
  3. If `vps_push_log` shows `status='ok'` but `market_prices` is empty: DB write path issue — add explicit `SELECT COUNT(*)` query immediately after `upsert.run()` loop inside the handler, log the result.
  4. If `market_prices` shows rows but with stale `updated_at`: the VPS service may be running but not sending the correct tickers — cross-check `vps_push_log.items_count` vs `watchlist` count.

### FR-2: Trigger VPS BCTC fetcher for banking Q4-2025 (Tasks 1201 + 1202)

- **Description:** Six watchlist tickers are missing Q4-2025 BCTC data: BID, EIB, SHB, VCB (banking sector), FPT (technology), HPG (steel). The SSC portal (`congbothongtin.ssc.gov.vn`) is an Oracle ADF SPA that returns a JS-bootstrap shell to direct HTTP requests — the Bun server cannot scrape it. The VPS Singapore service (`vn-bctc-fetch.service`) runs a headless browser capable of reaching the portal.
- **Root cause:** The `GET /api/bctc-fetch-queue` handler (server.ts:874) computes the target quarter using the **current calendar month**. In April 2026 (month 4, which is <= 6 but > 3), the logic sets `targetQuarter = "Q1"`. The code is:
  ```
  if (currentMonth <= 3)  { targetYear = currentYear - 1; targetQuarter = "Q4"; }
  else if (currentMonth <= 6) { targetQuarter = "Q1"; }
  ```
  This means the queue endpoint advertises Q1-2026, not Q4-2025. The VPS fetcher finds no pending PDFs to fetch for Q4-2025 because the queue never received those entries. BID/EIB/SHB/VCB/FPT/HPG Q4-2025 rows were never inserted into `bctc_vps_queue`.
- **Fix:** The queue endpoint must distinguish between "what quarter are companies filing right now" (Q4-2025, deadline 30/03 per SSC rules for listed companies) and "what does the calendar say is the previous quarter." The correct target for April 2026 is Q4-2025. The logic must look back one additional quarter when we are in the early months of a quarter (January–April = still collecting Q4 of previous year).
- **Correct target quarter logic:**
  - Month 1–3: target = Q3 of previous year (companies file Q3 in Oct–Jan)
  - Month 4–6: target = Q4 of previous year (companies file Q4 by 30 March — but filings arrive through April)
  - Month 7–9: target = Q1 of current year
  - Month 10–12: target = Q2 of current year
- **Manual backfill:** Even after fixing the logic, the six tickers already missing from `bctc_vps_queue` for Q4-2025 need to be inserted manually or by a one-shot migration in the fix.
- **Input:** `GET /api/bctc-fetch-queue` returns `{queue: [{action_code, period_year, period_quarter, source_hints}]}`. VPS calls this to know what to fetch.
- **Output:** Queue contains entries for BID, EIB, SHB, VCB, FPT, HPG with `period_year=2025, period_quarter="Q4"`.
- **Business rule:** Banking sector (BID/EIB/SHB/VCB) uses the consolidated BCTC (Hop Nhat) format. Filename must include the ticker and end in `.pdf`. The SSC portal URL for banking BCTC differs from regular companies — VPS source_hint must include the HOSE and HNX fallback URLs.
- **DDD layer:** infrastructure (server.ts `/api/bctc-fetch-queue` handler)

### FR-3: Fix BCTC extraction pipeline dropping PDFs (Task 1196)

- **Description:** PDFs for VNM, VEA, and potentially other tickers are present in `data/pdfs/` but no corresponding rows exist in `financial_reports`. The `bctcReparseJob` (`scheduler/bctcReparseJob.ts`) is the recovery mechanism but relies on `agent_feedback` rows with `title LIKE '[AUDIT] stranded_bctc_pdf%'` being present. If `dataAuditJob` did not generate those feedback rows (D-7c check), or if `bctcReparseJob` consistently fails the pipeline step, PDFs remain permanently stranded.
- **Root cause hypotheses:**
  1. **parseBctcReport silently returns default-zero objects:** The domain extractors (`extractBalanceSheet`, `extractIncomeStatement`, `extractCashFlow`) return zeroed structs when the regex patterns do not match Vietnamese number formats. The `storeReport()` call still runs — it inserts a row with `extraction_confidence = 0.0` and all financial fields at 0. This means `financial_reports` is not empty for these tickers; instead, it contains corrupted zero-value records that look valid to the audit job.
  2. **fetchParseAndStoreBctc fails before storeReport:** If `listSscDocuments` returns empty (JS-shell response from ADF portal), the function returns `null` before any parse. The PDF is never downloaded via the live path. However, if the VPS already pushed the PDF to disk, `bctcReparseJob` should pick it up — unless `agent_feedback` stranded entries were never created.
  3. **dataAuditJob D-7c not running:** The check that creates `stranded_bctc_pdf` feedback entries requires `readdirSync("data/pdfs/")` to find PDF files and cross-reference with `financial_reports`. If the audit job's D-7c branch has a bug (e.g., incorrect path, wrong WHERE clause), no feedback is generated and bctcReparseJob has nothing to process.
- **Fix scope:**
  1. Add a guard in `storeReport()` (or in `fetchParseAndStoreBctc`) that checks `extraction_confidence < 0.2` and logs a WORK-channel warning before inserting, flagging the record as `validation_status = 'low_confidence'`. Do not suppress the insert — a low-confidence record is better than no record.
  2. Verify that `dataAuditJob` D-7c correctly computes the cross-reference: scan `data/pdfs/`, for each PDF that has no `financial_reports` row with matching `action_code` and the year/quarter parsed from the filename, insert a `stranded_bctc_pdf` feedback entry.
  3. Add an explicit log statement at the start and end of `runBctcReparseJob()` listing the count of stranded feedback rows found, the count processed, and the count that succeeded.
- **Input:** PDFs present at `data/pdfs/*.pdf` with parseable filename pattern (ticker + date or quarter token).
- **Output:** Every PDF with a parseable filename and sufficient text content (>= 100 chars) produces a `financial_reports` row within one `bctcReparseJob` cycle (runs at 09:30 GMT+7 daily).
- **Business rule:** Vietnamese BCTC PDFs for banking sector use a two-column table layout with Vietnamese labels (e.g., "Tiền và các khoản tương đương tiền", "Doanh thu thuần"). Regex patterns in `balanceSheetExtractor`, `incomeStatementExtractor`, and `cashFlowExtractor` must handle:
  - Number format: `1.234.567` (thousands separator dots) and `(1.234.567)` for negatives.
  - Banking income statement uses "Thu nhập lãi thuần" instead of "Doanh thu thuần" — the extractor must map this to `netRevenue`.
- **DDD layer:** application (`parseBctcReport.ts`, `fetchParseAndStoreBctc.ts`), scheduler (`dataAuditJob.ts`, `bctcReparseJob.ts`)

### FR-4: Delete and re-parse VCB Q1-2025 zero-value record (Task 1204)

- **Description:** The `financial_reports` table contains a row for VCB Q1-2025 where all financial values (net_revenue, gross_profit, net_profit, total_assets, equity_total, etc.) are 0. This is a corrupted record produced by a failed extraction. It blocks YoY delta computation for VCB Q1-2026 (which needs a valid Q1-2025 baseline). The record has `extraction_confidence` close to 0.0.
- **Root cause:** The VCB Q1-2025 PDF was likely a scanned (image) PDF. The pdf-parse library returned < 100 chars of text. At the time of parsing, either (a) OCR was not available (`isOcrAvailable()` returned false) or (b) the OCR cache had no entry for this filename. The pipeline fell through to store a default-zero report rather than returning `null` and leaving no record. The zero record was then accepted as valid by the audit job (D-7c only checks for missing rows, not zero-value rows).
- **Fix:**
  1. Delete the corrupted VCB Q1-2025 record: `DELETE FROM financial_reports WHERE action_code = 'VCB' AND period_year = 2025 AND period_quarter = 'Q1'`.
  2. Trigger a re-parse via `bctcReparseJob` or by manually calling `fetchParseAndStoreBctc` with the VCB Q1-2025 PDF path (if on disk) or by queuing a fresh VPS fetch.
  3. Add a migration/guard to `storeReport()`: if all 16 key confidence fields are 0, skip the insert and return early with a WORK-channel warning. This prevents future zero-value records from being inserted silently.
- **Input:** Existing `financial_reports` row for VCB Q1-2025 with `extraction_confidence ~= 0`, or the PDF file at `data/pdfs/VCB_2025_Q1.pdf` (or equivalent filename).
- **Output:** VCB Q1-2025 row in `financial_reports` has `net_revenue > 0`, `total_assets > 0`, `extraction_confidence >= 0.5`.
- **Business rule:** VCB is a state-owned commercial bank. Its BCTC uses the banking-sector income statement format (see FR-3 note on "Thu nhập lãi thuần"). If VCB Q1-2025 PDF is not on disk, a fresh VPS fetch must be triggered targeting `period_year=2025, period_quarter="Q1"`.
- **DDD layer:** application (`parseBctcReport.ts` storeReport guard), infrastructure (one-time SQL migration)

## Non-Functional Requirements

- **Performance:** The push-prices handler must commit all upserts within 500 ms for a 30-ticker batch. SQLite WAL mode is already enabled; no additional locking is required.
- **Data freshness:** After the 1193 fix, `market_prices.updated_at` for all watchlist tickers must be within 2 minutes of the current time during trading hours.
- **Data quality:** After the 1196 fix, all financial_reports rows for watchlist tickers Q4-2025 must have `extraction_confidence >= 0.3`. Rows below 0.2 must be flagged `validation_status = 'low_confidence'` and a WORK-channel alert sent.
- **Language:** Log messages in English. Telegram WORK-channel alerts in English. User-facing Telegram MARKET alerts in Vietnamese.
- **Idempotency:** All fixes must be safe to run multiple times. SQL migrations use `IF NOT EXISTS` or `ALTER TABLE ... ADD COLUMN IF NOT EXISTS`. The zero-value record deletion must be conditional on the record having `extraction_confidence < 0.1`.

## Edge Cases & Data Quality

- [ ] Banking BCTC PDF uses two-column layout: left = Vietnamese label, right = current quarter, third column = previous quarter. The income statement extractor may pick up the previous-quarter column instead of the current one.
- [ ] VCB BCTC: "Thu nhập lãi thuần" (net interest income) must map to `incomeStatement.netRevenue` for banking sector, not the manufacturing sector label "Doanh thu thuần về bán hàng".
- [ ] VN number format: `1.234.567` uses dots as thousand separators (not decimal). The regex must not confuse `1.234` as the number one-point-two-three-four.
- [ ] Negative values in BCTC: `(1.234.567)` = minus 1,234,567. Parentheses = negative, not brackets or minus sign.
- [ ] EIB (Eximbank) and SHB trade on HOSE and HNX respectively — the VPS source_hints must include the correct exchange URL for each.
- [ ] VEA (Vietnam Engine and Agricultural Machinery) trades on UPCOM. The `bctc-fetch-queue` source_hints already include `upcom.hnx.vn` — verify the VPS fetcher can reach it.
- [ ] Concurrent push-prices calls: Two VPS pushes arriving within the same second with the same ticker code will race on `INSERT OR REPLACE`. This is safe because SQLite serialises writes in WAL mode; the second write simply overwrites the first.
- [ ] `bctc_vps_queue` may have stale `status='failed'` rows (attempts >= 5) for the six missing tickers if previous fetch attempts failed silently. The backfill migration must reset `attempts = 0, status = 'pending'` for these rows, not insert new duplicate rows.

## Acceptance Criteria

### AC-1: Prices persisting (Task 1193)

**Given** the VPS Singapore service sends a valid `POST /api/push-prices` payload with 30 watchlist tickers during trading hours

**When** the response returns `{ok: true, updated: 30}`

**Then**
- `SELECT COUNT(*) FROM market_prices WHERE updated_at > datetime('now', '-2 minutes')` returns 30
- `SELECT * FROM vps_push_log WHERE service='prices' ORDER BY pushed_at DESC LIMIT 1` shows `status='ok', items_count=30`
- Evening report assembled after this push contains at least 5 watchlist movers with non-zero `change_pct`

### AC-2: Banking BCTC Q4-2025 in queue (Tasks 1201 + 1202)

**Given** the fix to the quarter-detection logic is deployed and the server is restarted

**When** the VPS calls `GET /api/bctc-fetch-queue`

**Then**
- Response contains entries for BID, EIB, SHB, VCB, FPT, HPG with `period_year=2025, period_quarter="Q4"`
- `bctc_vps_queue` table shows these six tickers with `status='pending'` and `attempts < 5`
- No Q1-2026 entries appear in the queue while we are still in Q1-2026 filing period

### AC-3: PDFs on disk produce financial_reports rows (Task 1196)

**Given** PDF files exist in `data/pdfs/` for at least one watchlist ticker with a parseable filename

**When** `runBctcReparseJob()` completes one cycle

**Then**
- `result.examined > 0` — stranded feedback entries exist
- `result.resolved >= 1` — at least one PDF successfully parsed
- `SELECT COUNT(*) FROM financial_reports WHERE extraction_confidence > 0` increases by the number of resolved PDFs
- A low-confidence extraction (`extraction_confidence < 0.2`) sends a WORK-channel alert and marks `validation_status = 'low_confidence'`

### AC-4: VCB Q1-2025 has non-zero values (Task 1204)

**Given** the corrupted VCB Q1-2025 row is deleted and a re-parse is triggered

**When** `fetchParseAndStoreBctc` or `bctcReparseJob` completes for VCB Q1-2025

**Then**
- `SELECT net_revenue, total_assets, extraction_confidence FROM financial_reports WHERE action_code='VCB' AND period_year=2025 AND period_quarter='Q1'` returns a single row with `net_revenue > 0`, `total_assets > 0`, `extraction_confidence >= 0.3`
- `get_financial_summary('VCB')` MCP tool no longer shows "0 tỷ" for Q1-2025 revenue

### AC-5: No future zero-value silent inserts

**Given** the `storeReport()` guard is added

**When** `parseBctcReport` receives raw text that produces all-zero financial fields

**Then**
- `storeReport()` does not insert the row
- A WORK-channel message is sent: `[BCTC] Zero-confidence extraction — skipped insert for {CODE} {YEAR}-{Q}`
- `financial_reports` has no new row for the ticker/period
