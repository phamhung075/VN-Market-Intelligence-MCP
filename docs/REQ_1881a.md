# REQ-1881a — source_tier Retrofit for Macro & News Tools

**Sprint:** 1881a
**Track:** A — METHODOLOGY-INFRA
**Status:** READY FOR ARCHITECT
**Author:** BA (2026-05-13)
**Methodology reference:** TNB Layer 9 — Source Hierarchy (`docs/standards/tnb-methodology-layers.md`)

---

## TLDR

Retrofit `source_tier: 1 | 2 | 3` to the JSON output of 16 MCP tools that emit data without exposing source authority. Consumers (financial-analyst, unified-agent, news-scout) need this field to weight signals correctly per the Trần Ngọc Báu (TNB) methodology. No existing consumer contract breaks — the field is additive.

---

## Methodology Context

TNB Layer 9 establishes a mandatory source-authority ranking for every data point used in the analysis pipeline. The ranking is:

| Tier | Label | Examples |
|------|-------|---------|
| 1 | Primary / Official | SBV (State Bank of Vietnam), SSC portal (`congbothongtin.ssc.gov.vn`), HOSE/HNX exchanges (via VnDirect API), FRED (Federal Reserve), IMF DataMapper, GSO (Vietnam General Statistics Office) |
| 2 | Aggregator | TradingEconomics, Yahoo Finance, VnDirect aggregator API (price data re-aggregated), Google News RSS, CafeF, VnExpress, VnEconomy, Reuters RSS |
| 3 | Derived / Computed | Any value computed from primary or aggregator data (RSI, MACD, carry-trade spread, yield-spread signal, investment-clock phase, sentiment trend, evidence scores) |

**Conservative assignment rule (from task brief):** when uncertain, assign the lower-authority tier. A source that re-packages official data without direct API access = tier 2.

**SBV nuance:** The `sbv.ts` fetcher has the SBV web portal down as of the current codebase and reads rates from Vietcombank's XML feed (`portal.vietcombank.com.vn`) + env-var fallbacks. Rates data therefore arrives through Vietcombank (a commercial bank aggregating SBV rates), not directly from `sbv.gov.vn`. Conservative assignment = **tier 2** for the commodity/rates snapshot in `macroTools.ts`. The SBV env-var fallback path is tier 2 as well (static estimate). If and when a direct SBV REST API is implemented, upgrade to tier 1.

**Foreign flow nuance:** Data originates from HOSE/HNX via the Vinahost VPS proxy (which scrapes or receives push from the exchanges). The VPS is an intermediary. Conservative assignment = **tier 2**.

## Schema Delta

### FR-1 — Per-response envelope field (all 16 tools)

Every affected tool must add a top-level `source_tier` field to its JSON response object:

```typescript
{
  source_tier: 1 | 2 | 3;   // Required. Never null.
  // ... existing fields unchanged ...
}
```

**Placement rule:** at the envelope root, not inside nested records. This is the primary addition.

**DDD layer:** interface — the field is set in the tool handler, not in domain or infrastructure.

### FR-2 — Per-record source field for multi-source tools

For tools that return arrays of records from mixed sources, each record must also carry a `source_tier` field when the per-record tier can differ from the envelope tier.

| Tool | Condition | Per-record field location |
|------|-----------|--------------------------|
| `get_imf_signals` | Each indicator has `source` already in response; the DB row carries `ind.source`. Add `source_tier: 1` to each indicator object. | `response.indicators[].source_tier` |
| `fetch_and_analyze` | 4 sources, all tier 2; uniform. Per-record tier same as envelope. Per-record field not required; envelope is sufficient. | N/A |
| `get_ticker_intelligence` | Sections are mixed-tier; document in envelope comment only. Per-record breakdown deferred (out of scope for 1881a). | Deferred |

### FR-3 — Multi-source fallback documentation

For tools with primary + fallback source paths that cross tier boundaries:

| Tool | Primary tier | Fallback tier | Required behavior |
|------|-------------|---------------|------------------|
| `get_macro_snapshot` | 2 (Yahoo + VCB XML) | 2 (env-var fallback for rates) | Envelope `source_tier: 2` in all paths. No tier change on fallback. |
| `get_foreign_flow` | 2 (VPS primary) | 2 (cache / SSE fallback) | Envelope `source_tier: 2` in all paths. Add `source_note: "fallback:cache"` or `"fallback:sse"` when not on primary path. |

### FR-4 — Text-output tools (string response, not JSON)

Some tools return formatted text strings, not JSON. These require a JSON wrapper or a header line:

| Tool | Current output | 1881a output |
|------|---------------|-------------|
| `get_macro_snapshot` | Plain text string | Wrap in `{ source_tier, text, fetchedAt }` JSON envelope **OR** prepend `[source_tier:2]` header line |
| `get_market_snapshot` | Plain text string | Same choice |
| `get_sentiment_trend` | Plain text string | Same choice |
| `get_policy_signals` | Plain text string | Same choice |

**Architect decision required (BLK-1):** For text-output tools, choose between (a) JSON wrapper breaking the string format, or (b) a `[source_tier:N]` header line preserving the string format. Option (b) is backward-compatible with consumers that parse the text; option (a) is cleaner for JSON consumers. BA recommends option (b) as conservative default, but Architect must decide based on consumer contracts.

## Acceptance Criteria

All criteria must pass before the impl cycle is considered done.

### AC-1 — Static value, no runtime error
- Each of the 16 tools returns `source_tier` in its response on every call, including error paths.
- `source_tier` value matches the tier table in this spec (not configurable, not computed).

### AC-2 — JSON shape tests (per tool)
For each tool that returns JSON (`get_carry_trade_signal`, `get_yield_spread_signal`, `get_imf_signals`, `get_fed_liquidity_spread`, `get_investment_clock_phase`, `get_foreign_flow`, `get_insider_transactions`, `get_technical_indicators` — where response is JSON-parseable):
- Test: response includes `source_tier` at root level.
- Test: `source_tier` is a number equal to the tier in the inventory table.
- Test: existing fields are still present at their prior paths (backward-compat check).

### AC-3 — Text-output tools (post-Architect BLK-1 decision)
- If option (b) header line: every call returns a string whose first line matches `/^\[source_tier:[123]\]/`.
- If option (a) JSON wrapper: response is valid JSON with `source_tier` and `text` fields.

### AC-4 — Multi-source tool (get_imf_signals)
- Each object in `response.indicators[]` has `source_tier: 1`.
- Test: filter by `indicator_code` — returned subset still has `source_tier` on each record.

### AC-5 — Fallback path (get_foreign_flow)
- When primary VPS is unavailable and cache fallback activates: response includes `source_tier: 2` AND `source_note: "fallback:cache"`.
- When SSE fallback activates: `source_note: "fallback:sse"`.
- When primary path is used: `source_note` is absent or `"primary"`.

### AC-6 — Description string updated
- `server.tool(name, description, ...)` description for each of the 16 tools includes the phrase `"Source tier: N"` or `"source_tier: N"`.
- Test: string assertion on the description parameter (grep or snapshot test).

### AC-7 — TypeScript types
- Each tool's response interface (where a named interface exists) is updated to include `source_tier: 1 | 2 | 3`.
- `tsc --noEmit` passes with zero new errors after the retrofit.

### AC-8 — Error path
- When a tool handler hits its catch block and returns `{ error: "..." }`, `source_tier` is still present in that error envelope.

## Edge Cases

| Scenario | Handling |
|----------|---------|
| Tool returns partial data (one section unavailable) | `source_tier` reflects the tool's canonical data source, not the completeness of the response. Present even when sections show "unavailable". |
| `get_imf_signals` returns empty indicators array | `source_tier: 1` on the envelope; empty `indicators: []`; `source_tier` not needed in empty array. |
| `get_foreign_flow` circuit breaker is open | Returns error or `source: "none"` from fetcher. Tool response still includes `source_tier: 2` and `source_note: "fallback:none"`. |
| Vietnamese locale formatting — no impact | `source_tier` is an integer; locale formatting rules do not apply. |
| Missing BCTC data or low-confidence OCR | Out of scope for 1881a; BCTC tools (`get_financial_summary`, `compare_financials`) are not in the 16-tool list because they have a dedicated confidence field already. |
