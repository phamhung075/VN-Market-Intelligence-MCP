# REQ-048: OCR + PDF Pipeline Fix

status: READY_FOR_ARCHITECT
sprint: 048
po_vision: "Make the BCTC data flow work end-to-end for Vietnamese scanned PDFs"

## User Story

As a Vietnamese stock investor using Claude,
I want the system to reliably extract financial data from image-based BCTC PDFs
(VNM, VCB, VEA, FPT quarterly filings),
So that balance sheet, income statement, and ratio tools produce correct numbers
rather than zeros or nulls for all four watchlist stocks.

---

## Background: Current State

Three independent failure modes block the pipeline today.

### Failure 1 — Scanned PDF, no usable text (blocks Tasks 292 + 293)

`src/infrastructure/fetchers/pdf.ts → extractPdfText()` calls pdf-parse and then falls
through to `ocrPdfBuffer()` (the inline OCR in `pdf.ts`) if fewer than 200 chars are
returned. However there is also a separate, better-structured OCR worker at
`src/infrastructure/fetchers/pdfOcrWorker.ts` that:

- stores text page-by-page in SQLite table `pdf_extracted_text`
- is called at startup via `src/index.ts:77` for PDFs in `data/pdfs/`
- is **never read** by `fetchParseAndStoreBctc` — the pipeline calls
  `downloadAndExtractPdf()` which goes through `pdf.ts`, not `pdfOcrWorker.ts`

Additionally, both `pdf.ts:ocrPdfBuffer` and `pdfOcrWorker.ts:ocrOnePage` run
`pdftoppm -r 150`. At 150 DPI, dense Vietnamese number tables are borderline — the
number columns frequently OCR as garbled characters.

The confidence threshold in `pdfOcrWorker.ts:extractAndStorePdfPages` stores pages
with `confidence = 0.1` (fewer than 10 chars) as empty rows. These rows fool the
"already extracted" guard (`existing.c > 0`) so a subsequent call returns early and
reports the PDF as done when in fact it has mostly empty rows.

Finally, `pdf_extracted_text` table has no CREATE TABLE statement in either
`src/infrastructure/db/schema.ts` or `bctc-schema.ts`. `pdfOcrWorker.ts` uses it
directly without ever creating it — the table only exists on machines that have run
the worker successfully at least once. On a fresh install the table is absent and the
first call to `getCachedPdfText` throws `no such table: pdf_extracted_text`.

### Failure 2 — OCR-to-extractor gap (blocks Task 293)

`fetchParseAndStoreBctc` in `src/application/usecases/fetchParseAndStoreBctc.ts`
currently only calls `downloadAndExtractPdf(doc.url)` in Step 2. The function
signature already has a `pdfTextOverride` escape hatch but no production code path
reads from the `pdf_extracted_text` SQLite table. If pdf-parse returns fewer than
100 chars and OCR is available, the fallback should call `getCachedPdfText(filename)`
and, if that returns null (not yet extracted), trigger `extractAndStorePdfPages`
synchronously before proceeding.

### Failure 3 — Chrome crash loop (blocks Task 294)

`listSscDocuments` in `src/infrastructure/fetchers/ssc.ts` launches a full Puppeteer
Chrome process per call. The intelligence cycle (`intelligenceCycleJob.ts`) checks all
four watchlist stocks every 15 minutes. If two cycle ticks overlap, or if the scraper
is called concurrently for multiple stocks, multiple Chrome instances start in parallel.
On memory-constrained servers (VPS with 1-2 GB RAM) a single Chrome with `--single-process`
can consume 300-500 MB. Two simultaneous instances kill the server.

There is currently no mutex or semaphore. `_activeBrowsers` tracks instances for
shutdown cleanup but does not prevent concurrent launches.

### Failure 4 — SSC selector drift (blocks Task 295)

The SSC portal is an Oracle ADF application. The search input uses
`input[id$="it8112::content"]` and result rows use `tr[_afrRK]`. ADF generates
component IDs that can change after portal upgrades. The selectors were written
against the portal as it existed in Sprint 009 and have not been verified since.
A selector mismatch causes `listSscDocuments` to return an empty array silently,
making every stock appear to have no filings.

## Functional Requirements

### FR-1: pdf_extracted_text SQLite table DDL in schema.ts

- Description: The `pdf_extracted_text` table must be created as part of `initDatabase()`
  so the table exists on any fresh install before `pdfOcrWorker.ts` is called.
- Input: `initDatabase()` call at server startup.
- Output: Table `pdf_extracted_text` exists with correct schema.
- Schema:
  ```sql
  CREATE TABLE IF NOT EXISTS pdf_extracted_text (
    id           INTEGER PRIMARY KEY AUTOINCREMENT,
    filename     TEXT    NOT NULL,
    page_number  INTEGER NOT NULL,
    text_content TEXT    NOT NULL DEFAULT '',
    confidence   REAL    NOT NULL DEFAULT 0,
    extracted_at TEXT    NOT NULL DEFAULT (datetime('now')),
    UNIQUE(filename, page_number)
  );
  CREATE INDEX IF NOT EXISTS idx_pet_filename ON pdf_extracted_text(filename, page_number);
  ```
- Business rule: `UNIQUE(filename, page_number)` enforces idempotent `INSERT OR REPLACE`.
- DDD layer: infrastructure (`src/infrastructure/db/schema.ts`)

### FR-2: Raise OCR DPI from 150 to 200

- Description: Both `pdfOcrWorker.ts:ocrOnePage` and `pdf.ts:ocrPdfBuffer` pass `-r 150`
  to pdftoppm. Both must be updated to `-r 200`.
- Input: PDF page buffer.
- Output: Higher-resolution raster image fed to Tesseract, producing more accurate OCR
  of Vietnamese number tables.
- Business rule: DPI 200 is the minimum recommended for Tesseract on small-font tables.
  DPI > 300 is unnecessary and degrades throughput. 200 is the correct target.
- DDD layer: infrastructure (`src/infrastructure/fetchers/pdfOcrWorker.ts`,
  `src/infrastructure/fetchers/pdf.ts`)

### FR-3: Fix confidence threshold — skip empty pages, avoid poisoning the guard

- Description: `extractAndStorePdfPages` currently inserts rows with `confidence = 0.1`
  for pages that produce fewer than 10 chars. The "already extracted" guard checks
  `COUNT(*) > 0` and treats any non-zero row count as complete extraction.
- Current broken behaviour:
  - Page produces 0 chars → `insert.run(filename, page, "", 0)` is called in both
    the success and the catch branch — two inserts per page on failure.
  - Empty rows are counted by the guard as extracted pages.
  - A 30-page PDF with all empty pages shows `c = 30` and the guard returns early.
- Fix:
  - Do NOT insert a row for pages that produce fewer than 10 chars.
  - The completeness threshold for the "already extracted" guard becomes meaningful:
    `existing.c >= Math.max(expectedPages * 0.5, 3)` (at least 50 % of pages
    extracted with real text, or at least 3 pages minimum).
  - Remove the duplicate `insert.run(filename, page, "", 0)` in the catch block.
- Input: Page OCR result string.
- Output: Only rows with `length >= 10` are stored. Empty or near-empty pages are
  silently skipped.
- DDD layer: infrastructure (`src/infrastructure/fetchers/pdfOcrWorker.ts`)

### FR-4: isOcrAvailable() — async check with caching

- Description: `isOcrAvailable()` currently calls `execSync("which pdftoppm")` and
  `execSync("which tesseract")` synchronously. This is acceptable at startup but it
  runs inside `extractAndStorePdfPages` which is called in the hot path.
- Fix: cache the result in a module-level variable after the first call. Subsequent
  calls return the cached boolean without re-running `execSync`.
- Input: First call triggers `execSync`; subsequent calls return cached value.
- Output: Correct availability flag, single synchronous probe per process lifetime.
- DDD layer: infrastructure (`src/infrastructure/fetchers/pdfOcrWorker.ts`)

### FR-5: OCR fallback in fetchParseAndStoreBctc (closes the gap)

- Description: `fetchParseAndStoreBctc` Step 2 calls `downloadAndExtractPdf(doc.url)`.
  When the returned `text` is fewer than 100 chars, the pipeline must attempt OCR
  text retrieval before aborting.
- Fallback sequence:
  1. `downloadAndExtractPdf(doc.url)` → `extraction.text`.
  2. If `extraction.text.trim().length >= 100`: proceed to Step 3 as now.
  3. If `extraction.text.trim().length < 100`:
     a. Derive `filename` from the URL path (last path segment) or from the
        `pdfFilename` field on the `SscDocument` if present.
     b. Call `getCachedPdfText(filename)` from `pdfOcrWorker.ts`.
     c. If `cached !== null && cached.confidence >= 0.5`: use `cached.text` as `rawText`.
     d. If `cached === null` and `isOcrAvailable()`: download the PDF to
        `data/pdfs/<filename>`, call `extractAndStorePdfPages(pdfPath, filename)`,
        then call `getCachedPdfText(filename)` again.
     e. If still no text after the above: log `warn` and return `null`.
- Input: `FetchParseAndStoreBctcParams` (no new fields required).
- Output: `FinancialReport | null` — same as current. Behaviour change: scanned PDFs
  that have been OCR'd now produce a report instead of returning null.
- Logging: Log `[fetchParseAndStoreBctc] using OCR cache for <filename>` at `info`
  level when the fallback path is taken.
- DDD layer: application (`src/application/usecases/fetchParseAndStoreBctc.ts`)

### FR-6: SSC Puppeteer global browser semaphore (mutex, capacity = 1)

- Description: `listSscDocuments` and `downloadSscDocument` in `ssc.ts` each call
  `defaultBrowserFactory()` directly. There is no gate preventing concurrent launches.
- Fix: Add a module-level Promise-based semaphore with capacity 1. Both
  `listSscDocuments` and `downloadSscDocument` must acquire the semaphore before
  calling the factory and release it in a `finally` block after `browser.close()`.
- Semaphore contract:
  - If the semaphore is free: acquire immediately, launch browser.
  - If the semaphore is held: queue the call; it waits until the current holder
    releases (no timeout at the semaphore level — the caller's own timeout governs).
  - Semaphore capacity: exactly 1 (not configurable at this stage).
- Implementation pattern (no external library):
  ```typescript
  let _browserLock: Promise<void> = Promise.resolve();
  async function withBrowserLock<T>(fn: () => Promise<T>): Promise<T> {
    let release!: () => void;
    const next = new Promise<void>(r => { release = r; });
    const prev = _browserLock;
    _browserLock = next;
    await prev;
    try { return await fn(); } finally { release(); }
  }
  ```
- Input: Concurrent calls to `listSscDocuments` or `downloadSscDocument`.
- Output: Sequential browser launches — at most one Chrome process at any time.
- DDD layer: infrastructure (`src/infrastructure/fetchers/ssc.ts`)

### FR-7: SSC selector probe and update

- Description: Verify the two ADF selectors used in `listSscDocuments` and
  `downloadSscDocument` against the live SSC portal DOM. Update if drifted.
- Selectors under test:
  - `input[id$="it8112::content"]` — stock code search input
  - `tr[_afrRK]` — result table rows
  - Button click via `span.textContent.includes("Tìm ki")` — search button
- Probe approach: Use `page.evaluate(() => document.documentElement.outerHTML)` to
  capture a snapshot of the portal DOM. Confirm whether these selectors match.
  If drifted, identify the replacement selectors from the DOM snapshot and update
  the constants in `ssc.ts`.
- Input: Live `https://congbothongtin.ssc.gov.vn/faces/NewsSearch` page.
- Output: Selector constants in `ssc.ts` match the live portal, or a documented
  blocker if the portal is unreachable.
- DDD layer: infrastructure (`src/infrastructure/fetchers/ssc.ts`)

### FR-8: End-to-end smoke test (Task 296)

- Description: A deterministic integration test that takes a real VNM BCTC PDF from
  `data/pdfs/`, runs OCR via `pdfOcrWorker.ts`, feeds the resulting text through
  `balanceSheetExtractor` and `incomeStatementExtractor`, and asserts correct ranges.
- Test file: `src/__tests__/296-ocr-pipeline-e2e.test.ts`
- Test guard: Skip automatically if `isOcrAvailable()` returns false (CI without
  tesseract) using `if (!isOcrAvailable()) { console.log("skip: OCR not available"); return; }`.
- Test steps:
  1. Create a fresh in-memory SQLite DB (`DB_PATH=:memory:`).
  2. Call `initDatabase()` to ensure `pdf_extracted_text` table exists.
  3. Locate `data/pdfs/` and find the first `.pdf` file whose name contains `VNM`
     (case-insensitive). If none found, skip test.
  4. Call `extractAndStorePdfPages(pdfPath, filename)`.
  5. Assert `result.totalChars >= 5000` (OCR produced substantial text).
  6. Call `getCachedPdfText(filename)`.
  7. Assert `cached !== null && cached.confidence >= 0.5`.
  8. Run `extractBalanceSheet(cached.text)` — assert `totalAssets` in range
     [50,000,000, 100,000,000] triệu đồng.
  9. Run `extractIncomeStatement(cached.text)` — assert `netRevenue > 0`.
- DDD layer: test (`src/__tests__/296-ocr-pipeline-e2e.test.ts`)

## Non-Functional Requirements

- Performance: OCR per page must complete within 45 seconds (existing timeout is correct).
  The 2-second yield between pages must be preserved to keep the server responsive.
- Concurrency: After FR-6, at most 1 Chrome process runs at any time.
- Data freshness: `pdf_extracted_text` rows include `extracted_at` timestamp.
  No TTL/expiry for Sprint 048 — OCR is triggered once per filename.
- Language: Vietnamese (`-l vie+eng` tesseract flag) is already correct and must not
  be changed.
- Idempotency: `extractAndStorePdfPages` called twice for the same filename produces
  the same rows (INSERT OR REPLACE + completeness guard).
- Error handling: Every function returns gracefully (never throws to caller).
  All errors are logged at `warn` or `error` level with structured fields.

## Edge Cases & Data Quality

- [ ] `pdf_extracted_text` table does not exist on a fresh install (no `initDatabase`
  has run) — FR-1 closes this; the worker must not crash before schema is ready.
- [ ] VNM PDF is in `data/pdfs/` but `pdftoppm` fails for a page because the page is
  blank (cover page, back page) — FR-3 skips pages producing fewer than 10 chars.
- [ ] `pdfinfo` is not installed — `totalPages` defaults to 30 (existing fallback is
  correct, no change needed).
- [ ] Two intelligence cycle ticks overlap and both call `listSscDocuments("VCB")`
  simultaneously — FR-6 semaphore serialises them.
- [ ] SSC portal is down or returns a 500 during selector probe — FR-7 logs the error,
  returns empty array, does not crash the server.
- [ ] `filename` derived from URL contains URL-encoded characters (e.g. `%20`) —
  FR-5 must `decodeURIComponent()` before using as SQLite key.
- [ ] OCR text contains Vietnamese number artefacts: `O` misread as `0`, `l` misread
  as `1`, dots used as thousands separators (`1.234.567`) confused with decimal
  notation — the existing `parseVnNumber` in the domain already handles dot-separated
  thousands; no new logic needed here, but test assertions must not assume clean digits.
- [ ] `data/pdfs/` directory does not exist — bootstrap OCR block in `src/index.ts`
  already wraps in try/catch; no change needed.
- [ ] `getCachedPdfText` called before `extractAndStorePdfPages` has finished (race) —
  FR-5 calls them sequentially with `await`; no race.

## Acceptance Criteria

### AC-1: pdf_extracted_text table always exists

**Given** a fresh database (`:memory:` or new file)
**When** `initDatabase()` is called
**Then**
- `SELECT COUNT(*) FROM pdf_extracted_text` executes without error and returns 0.
- The table has columns: `id`, `filename`, `page_number`, `text_content`,
  `confidence`, `extracted_at`.

### AC-2: DPI raised to 200 in both OCR code paths

**Given** any call to `ocrOnePage(tmpPdf, page)` in `pdfOcrWorker.ts`
**When** the pdftoppm subprocess is spawned
**Then**
- The arguments array contains `"-r", "200"`, not `"-r", "150"`.

**Given** any call to `ocrPdfBuffer(buffer, totalPages)` in `pdf.ts`
**When** the pdftoppm subprocess is spawned
**Then**
- The arguments array contains `"-r", "200"`, not `"-r", "150"`.

### AC-3: Empty pages not stored; guard is not fooled

**Given** a PDF where every page produces fewer than 10 chars from tesseract
**When** `extractAndStorePdfPages(pdfPath, filename)` completes
**Then**
- `SELECT COUNT(*) FROM pdf_extracted_text WHERE filename = ?` returns 0.
- A second call to `extractAndStorePdfPages` does NOT return early (guard threshold
  not triggered with 0 rows).

### AC-4: fetchParseAndStoreBctc uses OCR text when pdf-parse returns empty

**Given** `fetchParseAndStoreBctc` is called with a PDF URL pointing to an image-based PDF
**AND** `getCachedPdfText(filename)` returns a result with `confidence >= 0.5`
**When** `downloadAndExtractPdf` returns fewer than 100 chars
**Then**
- The pipeline uses the OCR cached text as `rawText` (logged at info level).
- The function does NOT return null at the empty-text guard.
- `parseBctcReport` is called with the OCR text.

### AC-5: Browser semaphore prevents concurrent Chrome launches

**Given** two concurrent calls to `listSscDocuments("VCB")` using the real browser factory
**When** both are awaited in parallel (`Promise.all([...])`)
**Then**
- The second call waits until the first browser is closed before launching its own.
- No more than one Chrome process is running at any point (verifiable via `ps aux | grep chrome`
  count during the test or via a spy on the browser factory call count).

**Given** the browser factory spy is called
**Then** it is called at most once at a time (calls are serialised, not concurrent).

### AC-6: listSscDocuments returns at least 1 document for VNM (live selector test)

**Given** the SSC portal is reachable
**When** `listSscDocuments("VNM", "quarterly")` is called
**Then**
- Returns an array with length >= 1.
- Each document has a non-empty `title` and `publishedAt`.

### AC-7: End-to-end OCR → extractor pipeline (Task 296 smoke test)

**Given** `data/pdfs/` contains a VNM BCTC PDF
**AND** tesseract + pdftoppm are installed
**When** the smoke test in `src/__tests__/296-ocr-pipeline-e2e.test.ts` runs
**Then**
- `extractAndStorePdfPages` returns `totalChars >= 5000`.
- `getCachedPdfText(filename)` returns `confidence >= 0.5`.
- `extractBalanceSheet(text).totalAssets` is in range [50,000,000 – 100,000,000] triệu.
- `extractIncomeStatement(text).netRevenue > 0`.

## Data Contract: pdf_extracted_text

| Column        | Type    | Constraint              | Notes                          |
|---------------|---------|-------------------------|--------------------------------|
| id            | INTEGER | PRIMARY KEY AUTOINCREMENT | —                             |
| filename      | TEXT    | NOT NULL                | PDF base filename (no path)    |
| page_number   | INTEGER | NOT NULL                | 1-based page index             |
| text_content  | TEXT    | NOT NULL DEFAULT ''     | OCR text for this page         |
| confidence    | REAL    | NOT NULL DEFAULT 0      | 0.0 – 1.0; only rows >= 0.5   |
|               |         |                         | are considered reliable        |
| extracted_at  | TEXT    | DEFAULT (datetime('now'))| ISO 8601 UTC                  |
| UNIQUE        | —       | (filename, page_number) | Enforces idempotent upsert     |

`getCachedPdfText` aggregates `text_content` ordered by `page_number`.
Average `confidence` across all rows is returned as the document-level confidence score.

## Data Contract: getCachedPdfText output

```typescript
interface CachedPdfTextResult {
  text: string;       // all pages joined with "\n\n"
  pages: number;      // number of rows returned
  confidence: number; // average confidence across all rows (0.0 – 1.0)
}
```

`fetchParseAndStoreBctc` treats `confidence >= 0.5` as "good enough to parse".
Confidence 0.3 – 0.49 triggers a warn log but still attempts parsing.
Confidence below 0.3 logs a warn and returns null.
