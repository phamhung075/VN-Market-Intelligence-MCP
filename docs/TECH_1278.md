## Architecture Decision

Sprint 1272 classified insider dump keywords (xả hàng, bán sạch, thoái sạch) as BEARISH sentiment. This sprint bridges the gap: **detect insider dumps at one banking stock, then cascade alerts to peer banks**, capturing the systemic contagion effect. The approach mirrors the existing LEGAL_RISK_RULES (lines 2110–2121) — keyword-driven rule matching + sector-based peer alert generation.

**Key principle:** Insider dumps signal leadership loss of confidence. In a tightly-correlated banking sector (VN's systemic hub), one bank's CEO exit cascades confidence losses to peers. This is distinct from policy/legal risks: it's **company-specific exit sentiment**, not macro-level policy change.

 * Insider dump cascade rules: CEO/leadership exit selling (xả hàng, bán sạch, thoái sạch)
 * signals systemic banking sector distress.
 *

 *   1. News contains insider dump keyword (already classified as BEARISH in sentimentClassifier.ts)
 *   2. Original stock is banking sector

export const INSIDER_DUMP_RULES: CascadeKeywordRule[] = [
  { key: "insider_dump_banking_peers", keyword: "xả hàng", sector: "banking" },
  { key: "insider_dump_banking_peers", keyword: "bán sạch", sector: "banking" },
  { key: "insider_dump_banking_peers", keyword: "thoái sạch", sector: "banking" },
];

**Pattern notes:**
- Mirrors LEGAL_RISK_RULES structure (key + keyword + sector)
- All three keywords map to same rule key (insider_dump_banking_peers) for peer filtering logic
- Sector = "banking" ensures non-banking insider dumps don't cascade (per AC-4)
- No confidence field in CascadeKeywordRule interface; confidence handling happens in downstream alertGenerator

### Step 3: Create Cascade Executor Helper (application layer)

New file: `src/application/cascadeExecutor.ts` (lightweight orchestrator)

```typescript
import { INSIDER_DUMP_RULES } from "../domain/services/cascadeEngine.js";
import { classifySentiment } from "../domain/services/sentimentClassifier.js";
import type { WatchlistEntry } from "../domain/services/cascadeEngine.js";

/**
 * Post-processes a causal chain to apply insider-dump peer cascade rules.
 *
 * Pure function — no I/O, no side effects.
 *
 * @param causalChain - Built chain from buildCausalChain()
 * @param seedSummary - Original news summary (for sentiment re-check)
 * @param watchlist - Watchlist to find peer banking stocks
 * @returns List of peer stock codes that should receive alerts
 */
export function detectInsiderDumpPeers(
  causalChain: CausalChain,
  seedSummary: string,
  watchlist: WatchlistEntry[],
): string[] {
  const summaryLower = seedSummary.toLowerCase();

  // Check if any insider dump keyword matched
  const matchedRule = INSIDER_DUMP_RULES.find(rule =>
    summaryLower.includes(rule.keyword)
  );

  if (!matchedRule) return []; // No insider dump keywords found

  // Must be banking sector
  if (matchedRule.sector !== "banking") return [];

  // Verify sentiment is bearish + confidence > 0.6
  const sentiment = classifySentiment(seedSummary);
  if (sentiment.direction !== "bearish" || sentiment.confidence <= 0.6) {
    return [];
  }

  // Find the original stock (most-specific entry in chain)
  const actionEntries = causalChain.entries.filter(e => e.level === "action");
  if (actionEntries.length === 0) return [];

  const originalStocks = new Set<string>();
  for (const entry of actionEntries) {
    entry.affectedActions.forEach(code => originalStocks.add(code));
  }

  // Get all banking peers EXCEPT original stock
  const bankingPeers = watchlist
    .filter(w => w.domain === "banking" && !originalStocks.has(w.actionCode))
    .map(w => w.actionCode);

  return bankingPeers;
}
```

**Design rationale:**
- Keeps domain layer (sentimentClassifier) pure
- Application layer handles orchestration
- Function is testable in isolation

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|-------------|--------|-----------|
| **False positives: xả hàng misclassification** (e.g., "xả hàng lao động" = layoff, not insider dump) | Medium (3–5%) | Low (affects 1-2 stocks, non-fatal) | Keyword weight 3 + confidence >0.6 threshold filter false positives; monitor alert volume weekly |
| **Non-banking insider dumps cascade to unintended sectors** | Low (rule explicitly checks sector="banking") | Medium (noisy alerts, alert fatigue) | Unit tests TC-6 validates sector filtering; code review enforces rule definition |
| **Peer list staleness (TCB/MBB not in watchlist, newer banks added)** | Low (watchlist updates quarterly) | Low (missed opportunities, not false positives) | stock-classification.json is SSOT; PM updates quarterly via sprint; test uses hardcoded watchlist |
| **Circular cascade (A→B→A)** | Very low (rule excludes original stock from peer filtering) | High (infinite alert loop) | TC-5 + code review: peer loop explicitly excludes original stock |
| **Integration timeout (cascade adds latency to pollNews)** | Low (pure functions, <50ms per article) | Medium (cycle timeout, missed news) | Pure functions guarantee <50ms; perf test in GREEN phase validates <10% cycle overhead |
