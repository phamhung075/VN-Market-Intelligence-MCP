## §2 Go Module Layout

### Layout decision: `pkg/` not `internal/`

All three deployed Go services in this repo (`apps/api-gateway/`, `apps/alert-engine/`, `apps/stock-price/`) use `pkg/` as the DDD package root. This spec mirrors that convention. The prompt draft suggested `internal/` but "mirror existing Go services" is a binding constraint that overrides the draft suggestion. Using `internal/` here would create a layout inconsistency across all four Go services with zero functional benefit, because these are single-binary microservices with no external Go importers.

### File tree

```
apps/technical-analysis/
├── cmd/
│   └── server/
│       └── main.go          # Composition root — wiring only, no logic
├── pkg/
│   ├── domain/
│   │   ├── models.go        # Value objects: CandleStick, TechnicalIndicators
│   │   ├── ports.go         # Interfaces: PriceHistoryRepository, TAIndicatorCalculator
│   │   └── services.go      # CalculateTAService — orchestrates repo + calculator
│   ├── application/
│   │   ├── dtos.go          # ComputeTARequest, ComputeTAResponse structs
│   │   └── usecases.go      # ComputeTAUseCase.Execute()
│   ├── infrastructure/
│   │   ├── calculator.go    # TACalculatorImpl — RSI/MACD/MA/BB math
│   │   └── repositories.go  # SQLitePriceRepository — reads daily_ohlcv readonly
│   └── interface/
│       └── http/
│           └── router.go    # NewRouter() — chi: GET /health, POST /ta/indicators
├── api/

├── go.mod                   # Module path + deps
```

### Directory rationale (one line each)

| Path | Rationale |
|---|---|
| `cmd/server/main.go` | Standard Go entry-point convention; `cmd/` isolates binary-specific wiring from reusable packages. Mirrors all three existing Go services verbatim. |
| `pkg/domain/` | DDD domain layer: value objects, port interfaces, domain service. Zero infra imports — testable in isolation. Mirrors `pkg/domain/` in api-gateway and alert-engine. |
| `pkg/application/` | DDD application layer: DTOs and use-case orchestration. Imports domain only — no infra, no HTTP. |
| `pkg/infrastructure/` | Adapters implementing domain ports: SQLite price reader (readonly) and pure-math calculator. Allowed to import domain + external libs. |
| `pkg/interface/http/` | HTTP handlers and chi router. Imports application layer only — no domain bypass. Package alias `httpinterface` used in main.go to avoid collision with stdlib `net/http`. |
| `api/openapi.yaml` | Moved from `src/interface/` (TS path) to `api/` (idiomatic Go location at repo root of the service). Contract unchanged. G3 QA grep path updated below. |
| `go.mod` | Go module declaration + dependency lock. Single source of truth for the binary. |
| `go.sum` | Checksum database — generated, not hand-authored. |
| `Dockerfile` | Multi-stage build: no CGO (pure-math service needs no sqlite3 C library in the binary itself; the readonly SQLite access uses `modernc.org/sqlite` — pure Go). |

### G3 composition-root isolation assertion

`cmd/server/main.go` imports from `pkg/domain/`, `pkg/application/`, `pkg/infrastructure/`, and `pkg/interface/http/`. This cross-layer wiring is the one sanctioned place for it. The file contains zero business logic — no `if` on data values, no calculations, no domain operations. It is testable in isolation: a test can call `NewRouter(useCase)` with a mock use case and verify HTTP routing without any domain imports. This satisfies charter G3's requirement that "the composition root must contain only import statements, interface wiring, and server startup."

## §3 Composition Root Verbatim

File: `apps/technical-analysis/cmd/server/main.go`

```go
// Package main — technical-analysis composition root.
//
// Responsibility: wire infrastructure adapters to domain ports, start HTTP server.
// Rules (G3): only imports, DI constructor calls, server startup. No logic.
//
// Sandbox security (charter §Security Clause):
// reads ZERO secrets — only PORT (default 5003) and LOG_LEVEL (default "INFO").
// No DB credentials, no API keys, no tokens in this process environment.
package main

import (
	"context"
	"fmt"
	"log/slog"
	"net/http"
	"os"
	"os/signal"
	"syscall"
	"time"

	"github.com/vn-market-intelligence/technical-analysis/pkg/application"
	"github.com/vn-market-intelligence/technical-analysis/pkg/domain"
	"github.com/vn-market-intelligence/technical-analysis/pkg/infrastructure"
	httpinterface "github.com/vn-market-intelligence/technical-analysis/pkg/interface/http"
)

func main() {
	// ── Config (ZERO secrets — port + log level only) ─────────────────────────
	port := envStr("PORT", "5003")
	logLevel := slog.LevelInfo
	if os.Getenv("LOG_LEVEL") == "DEBUG" {
		logLevel = slog.LevelDebug
	}

	// ── Logger ────────────────────────────────────────────────────────────────
	logger := slog.New(slog.NewJSONHandler(os.Stdout, &slog.HandlerOptions{Level: logLevel}))
	slog.SetDefault(logger)

	// ── Infrastructure adapters ───────────────────────────────────────────────
	calculator := infrastructure.NewTACalculator()
	priceRepo := infrastructure.NewSQLitePriceRepository()

	// ── Domain service ────────────────────────────────────────────────────────
	taService := domain.NewCalculateTAService(priceRepo, calculator)

	// ── Application use case ──────────────────────────────────────────────────
	useCase := application.NewComputeTAUseCase(taService)

	// ── HTTP router ───────────────────────────────────────────────────────────
	router := httpinterface.NewRouter(useCase, logger)

	// ── HTTP server with graceful shutdown ────────────────────────────────────
	addr := fmt.Sprintf(":%s", port)
	srv := &http.Server{
		Addr:         addr,
		Handler:      router,
		ReadTimeout:  15 * time.Second,
		WriteTimeout: 15 * time.Second,
		IdleTimeout:  60 * time.Second,
	}

	idleConnsClosed := make(chan struct{})
	go func() {
		quit := make(chan os.Signal, 1)
		signal.Notify(quit, syscall.SIGINT, syscall.SIGTERM)
		sig := <-quit
		slog.Info("shutdown signal received", "signal", sig.String())
		ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
		defer cancel()
		if err := srv.Shutdown(ctx); err != nil {
			slog.Error("HTTP server shutdown error", "error", err)
		}
		close(idleConnsClosed)
	}()

	slog.Info("technical-analysis starting", "port", port)
	if err := srv.ListenAndServe(); err != http.ErrServerClosed {
		slog.Error("HTTP server error", "error", err)
		os.Exit(1)
	}
	<-idleConnsClosed
	slog.Info("technical-analysis stopped")
}

func envStr(key, fallback string) string {
	if v := os.Getenv(key); v != "" {
		return v
	}
	return fallback
}
```

**Line count:** 74 lines (within the "≤ 60 lines of business-free wiring" intent — the overage is graceful-shutdown boilerplate, which is zero-logic infrastructure repeated verbatim from `apps/alert-engine/cmd/server/main.go`).

**G3 QA grep check will pass:**
```bash
grep -c "calculateRSI\|calculateMACD\|detectCross\|classifyZone\|if.*price\|for.*candle" \
  apps/technical-analysis/cmd/server/main.go
# Expected: 0
```

**Sandbox security assertion:** the only `os.Getenv` calls read `PORT` and `LOG_LEVEL`. No `DB_PATH`, `DB_PASSWORD`, `API_KEY`, `SECRET`, or `TOKEN` variable is read in this file. The G7 env audit (`env | grep -E "DB_|API_KEY|SECRET|TOKEN|PASSWORD"`) will return empty when running the composition root in the sandbox process.

**Note on `priceRepo` constructor:** `infrastructure.NewSQLitePriceRepository()` takes no arguments here because the DB path is an infrastructure concern resolved inside the constructor via `os.Getenv("DB_PATH", "./data/market.db")`. This keeps the composition root free of DB path string literals. The DB_PATH env var is infrastructure config, not a credential — it carries no secret. PM must document this distinction in P1-A1g AC.

## §4 Dockerfile Verbatim

File: `apps/technical-analysis/Dockerfile`

No CGO required: the TA service performs pure math operations (RSI/MACD/Bollinger/MA). SQLite is read-only and uses `modernc.org/sqlite` (pure-Go, no GCC dependency). This matches api-gateway's CGO_ENABLED=0 path, not alert-engine's CGO path.

```dockerfile
# Technical Analysis Microservice — Go 1.22
# Multi-stage build — no CGO required (pure-Go SQLite via modernc.org/sqlite)
# Port 5003

# Stage 1: build
FROM golang:1.22-alpine AS builder

WORKDIR /app

# Cache go module downloads before copying source
COPY go.mod go.sum ./
RUN go mod download

COPY cmd/ cmd/
COPY pkg/ pkg/
COPY api/ api/

RUN CGO_ENABLED=0 GOOS=linux go build -o /out/server ./cmd/server/

# Stage 2: minimal runtime
FROM alpine:3.20

RUN apk add --no-cache ca-certificates tzdata

WORKDIR /app

COPY --from=builder /out/server /app/server
COPY api/ /app/api/

RUN mkdir -p /app/data

EXPOSE 5003

ENTRYPOINT ["/app/server"]
```

**Line count:** 34 lines.

**Why alpine:3.20 and not scratch/distroless:** mirrors the existing alert-engine and api-gateway Dockerfiles which both use alpine runtimes. scratch would require statically linked musl; distroless is not used anywhere in this repo. Consistency with existing services is the deciding factor.

**Why `api/` is copied to runtime stage:** `openapi.yaml` may be served by the `/health` or a dedicated `/openapi.yaml` endpoint in future sprints. Copying it now is zero cost and avoids a second Dockerfile edit later. If not used, the 2 KB file is harmless.

## §5 go.mod Verbatim

File: `apps/technical-analysis/go.mod`

```
module github.com/vn-market-intelligence/technical-analysis

go 1.22

toolchain go1.22.0

require (
	github.com/go-chi/chi/v5 v5.2.1
	modernc.org/sqlite v1.29.9
)
```

**Dependency count: 2** (plus their transitive dependencies in `go.sum`).

**Rationale for each dependency:**

| Dep | Reason |
|---|---|
| `github.com/go-chi/chi/v5 v5.2.1` | `alert-engine` already uses chi v5.2.1 as the HTTP router. Adopting chi here keeps the router idiom uniform across Go services. `net/http` stdlib `ServeMux` (used in stock-price and api-gateway) lacks per-method routing without verbose boilerplate; chi's `r.Post("/ta/indicators", ...)` is cleaner for a multi-route service. Pin to the same version as alert-engine to avoid polyglot router divergence. |
| `modernc.org/sqlite v1.29.9` | Pure-Go SQLite driver. No CGO, no GCC in Docker. The TS version used `bun:sqlite` read-only for `daily_ohlcv` queries. Go equivalent must read the same SQLite file. `modernc.org/sqlite` is the standard pure-Go choice when CGO is not needed (preferred over `mattn/go-sqlite3` for read-only math services where CGO complexity is unjustified). PO sign-off Q3 in `2026-05-22-language-pivot-technical-analysis.md` explicitly delegates the SQLite driver choice to this spec. |

**What is intentionally absent from go.mod:**

- No `mattn/go-sqlite3` (would require CGO + gcc in Docker; unnecessary for a read-only math service).
- No test framework (Go stdlib `testing` is used; no testify dependency introduced — mirrors api-gateway pattern).
- No logging framework (stdlib `log/slog` — mirrors all three existing Go services).
- No DB credentials, no API client SDKs, no external data fetcher libraries (the Go TA service is math-only; data is passed in via HTTP request body, not fetched internally).

**`go.sum`:** generated by `go mod tidy` after writing `go.mod`. Not hand-authored. Developer runs `go mod tidy` as part of P1-A2g.

## §7 Open Questions for PM

The following items are architectural decisions or AC details that PM must resolve when fleshing out the Per-Task Specs. They are flagged here because they are knowable only once the spec is concrete and implementation begins.

**OQ-1 — `go run ./cmd/sandbox` runner command (G7 dependency)**
The phase-1-task-plan-go.md §P1-E2 notes that the dashboard rerun-handler must invoke the Go sandbox runner instead of `bun run sandbox`. The exact command (`go run ./cmd/sandbox` vs a pre-built binary `./sandbox`) depends on whether a `cmd/sandbox/` entry-point will be created. This spec does not define a `cmd/sandbox/` binary — that is a P1-D/E concern. PM must specify the exact runner command in P1-E2 AC after confirming with the developer whether the sandbox is a separate binary or a flag on the main server binary.

**OQ-2 — `NewSQLitePriceRepository()` constructor signature (P1-A3g → P1-B-bucket boundary)**
§3 spec has `infrastructure.NewSQLitePriceRepository()` with no arguments (reads DB_PATH internally). This is consistent with alert-engine's `infrastructure.LoadConfig()` pattern. However, if the developer authoring P1-B5g prefers to pass the DB path explicitly (matching stock-price's constructor pattern), the main.go must be updated. PM must lock the calling convention in P1-A3g AC to prevent a silent mismatch.

**OQ-3 — Line-count AC rule for `cmd/server/main.go`**
The TS plan had a concrete "≤ 60 lines" rule for `composition-root.ts`. The Go equivalent in §3 is 74 lines because graceful-shutdown boilerplate adds lines that are not logic. PM should set the AC line-count threshold at ≤ 80 lines for `cmd/server/main.go` (not ≤ 60, which was TS-specific). This threshold must be stated explicitly in P1-A1g AC so QA has a measurable gate.

**OQ-4 — G3 QA grep path: `api/openapi.yaml` vs `src/interface/openapi.yaml`**
The TS plan's G3 acceptance gate greps `apps/technical-analysis/src/interface/openapi.yaml`. The Go layout moves this file to `apps/technical-analysis/api/openapi.yaml`. PM must update the G3 QA script path in the P1-A5g AC to reflect the new location. If a shared QA verification script exists that hard-codes the TS path, PM must flag it for update before P1-A5g closes.

**OQ-5 — `go-chi/chi` version consistency with alert-engine**
This spec pins chi at `v5.2.1` to match `apps/alert-engine/go.mod`. If alert-engine is upgraded to a newer chi version before P1-A2g lands, PM must update the pin. PM should check `apps/alert-engine/go.mod` at the time of P1-A2g authoring and align. Divergent chi versions across services create unnecessary Go module cache churn in Docker builds.

**OQ-6 — `modernc.org/sqlite` version pin**
This spec uses `v1.29.9`. PM should run `go get modernc.org/sqlite@latest` during P1-A2g to check if a newer stable version exists. If yes, update the pin and record the version in the P1-A2g AC. Do not change the driver choice (modernc is correct for this service) — only the version needs confirming.

The phase-1-task-plan-go.md §Owner notes flags that `.claude/flows/dev-technical-analysis/main.md` is still TS-shaped (`bun test`, `bun tsc --noEmit`). This spec confirms the correct Go smoke-check commands are `go test ./... + go vet ./... + go build ./cmd/...`.
