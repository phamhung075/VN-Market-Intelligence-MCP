## 2. Guardrail design — zero-tolerance, NOT baseline/ratchet (deviation from the sibling, evidence-backed)

The size-lint sibling used baseline/ratchet because its live debt was 733 files — grandfathering was the only option. Here live debt is **4 lines in 2 files**, small enough to fix in the same child task that ships the gate. Design: fix the 4 real masks + annotate the 1 legitimate default BEFORE the CI job goes live, so the gate opens at zero offenders and can be true zero-tolerance (fail on ANY match, no baseline manifest, no per-file tolerance drift to track).

**Mechanism — single cross-language regex script** (not 3 separate native-linter integrations as the ticket literally suggests): the pattern is lexically detectable (`??`/`||`/Python `or`/destructuring-or-param default with a non-zero numeric literal, on an identifier matching `/confidence|score|impact|magnitude|probability/i`) and current debt is empirically small — this grep-based sweep itself found the 4 true positives and correctly separated the 1 false-candidate. A single `scripts/audits/metric-mask-lint.sh` scanning `*.ts`/`*.py`/`*.go` mirrors the size-lint sibling's cheap-CI-job pattern (bash/grep only, no bun/go/python toolchain) rather than building 3 language-native plugins for near-zero live debt. Escape hatch matches the ticket's own text: an inline `metric-mask-allow: <reason>` comment on the same/preceding line suppresses a match (mirrors `size-justification:`'s convention). **Always-allowed literals:** `0`, `0.0`, `null` — the honest-absence idiom already established by the 5 fixes; only non-zero literals are fabrication candidates. If false-positive rate proves too high after real use, migrating to per-language native rules (ESLint `no-restricted-syntax` selector, ruff custom AST, golangci `forbidigo`) is the documented enhancement path — deferred, not needed at current debt scale.

**CI wiring:** new `metric-mask-lint` job in `.github/workflows/ci.yml`, `ubuntu-latest` + checkout only (same cheap-job shape as `size-lint`).
