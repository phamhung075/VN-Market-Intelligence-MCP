## 3. Guardrail design — baseline/ratchet, NOT zero-tolerance (different axis than size-lint, same conclusion)

**Sizing call:** unlike the dead-code/metric-mask/no-hardcode siblings (small, *mechanically and safely* fixable in the same child task with zero domain-judgment risk) this debt's fix is gated on a **domain decision already owned by a separate, larger, in-flight-eligible task** (`FACTORY-SHARED-wire-or-prune-shared-packages`). Forcing that decision inside a CI-tooling child task would either (a) preempt/duplicate work already tracked there, or (b) force a rushed keep-or-cut call without the field-superset reconciliation care that task's own DoD demands (its own caution note: "Alert/Signal/ServiceHealth shapes are structurally different across apps... ComputeTAResponse in the app is a SUPERSET — reconcile FIRST or you erase served fields"). Size-lint went baseline/ratchet because the debt was *too voluminous* to fix in one sitting; this goes baseline/ratchet because the debt is *not this task's decision to make* — same mechanism, different justifying axis.

**Mechanism — `scripts/audits/shared-package-import-check.sh` (bash/grep, no toolchain), package-level granularity:**
1. **Orphan-importer check (blocking, baseline/ratchet):** for every `packages/*/package.json` with a `@vn-market/`-scoped name, grep the repo (excluding the package's own files) for an import specifier or `package.json` dependency entry naming it. Zero hits + package listed in `docs/data/shared-package-import-baseline.json` (seeded `--update` run: `shared-types`, `shared-config`, `shared-db`) → PASS (prints `BASELINE: <pkg> — tracked by FACTORY-SHARED-wire-or-prune-shared-packages`). Zero hits + **not** in baseline → **FAIL** — this is the actual regression-prevention value: blocks a NEW `packages/primitives`-shaped phantom package from ever landing again. A package gaining ≥1 real importer always passes (baseline membership becomes stale — `--update` shrinks it; not auto-enforced, mirrors size-lint's manual-regen idiom).
2. **Structural-drift check (advisory only, non-blocking):** scan exported top-level symbol names (`export interface/type/const/function <Name>`) in each `packages/shared-*/index.ts`; grep for the same identifier name exported anywhere under `apps/**/*.ts` (excl. tests/vendor). Any hit prints an `ADVISORY:` line (never fails `--check`) — e.g. today's `Alert`/`Signal`/`McpConfig` collisions from §2.

**Deferred, NOT built now (documented enhancement, same reasoning as the dead-code-gate/no-hardcode siblings' deferrals):** field-by-field AST structural diffing to make check 2 blocking. Rejected for MVP — no TS AST tool is wired into any existing bash-only audit script in this repo (unlike the depguard-Go check, which could reuse `go/ast` because every `go-lint` job already has the Go toolchain); a regex-based field-set diff would false-positive constantly on reordered fields, JSDoc-only differences, and optional-marker churn. Per-symbol (vs package-level) importer granularity is also deferred — same "fundamentally larger-scope, higher-false-positive-risk" class of tool (knip/ts-prune) the dead-code-gate sibling already declined to build; today's debt is 100% package-level (0/3 packages have ANY importer), so package granularity fully captures it.

**CI wiring:** new `shared-package-import-check` job in `.github/workflows/ci.yml`, `ubuntu-latest` + checkout only — same cheap-job shape as every sibling.
