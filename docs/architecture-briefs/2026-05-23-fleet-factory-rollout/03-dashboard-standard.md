# Dashboard Standard — "Reveals the Functions of Its Microservice Server"

## What "Dashboard Working" Means Concretely

A service dashboard is working when a non-technical user can open `apps/<svc>/dashboard/index.html` in a browser
and immediately see:

1. **What this service does** — its name, port, language, and one-sentence purpose.
2. **What primitive functions it contains** — each primitive as a card with name, description, and pass/fail status.
3. **What scenarios were run** — each sandbox scenario with input, output, duration, and green/red result.
4. **What module(s) compose the primitives** — the module-level composition trace showing which primitives were called and in what order.
5. **The service's HTTP endpoints** — the actual routes the microservice server exposes (derived from the router).
6. **Overall health** — a green/yellow/red badge derived from scenario pass rate and coverage %.

This is derived by generalizing the existing TA (`1729L`) and macro (`1876L`) dashboards plus the spec in `08-sandbox-dashboards.md`.

## Data Sources for the Dashboard

| Section | Data Source |
|---|---|
| Service name/port/language | Hardcoded at build time from service manifest or `go.mod` / `package.json` |
| Endpoint list | Parsed from router source file (`router.go`, `router.ts`, `main.py routes`) at dashboard build time |
| Primitive cards | Trace JSON files in `pkg/primitive/<name>/testdata/` or sandbox output |
| Scenario pass/fail | Generated by `cmd/sandbox` (Go) / Bun sandbox runner (TS) / pytest sandbox (Python) |
| Coverage % | `go test -coverprofile` (Go) / `bun test --coverage` (TS) / `pytest --cov` (Python) |
| Duration | Captured in trace JSON `durationMs` field |
| Overall badge | Green if all scenarios pass AND coverage ≥ 80%; Yellow if any scenario warning; Red if any scenario fail OR coverage < 60% |

## Stack-Specific Rendering

### Go services (TA/macro reference implementation)

- Dashboard rendered by `dashboard/app.ts` (compiled to `app.js` via `build.sh`)
- Trace JSON format: `{"id","tier","subject","story","steps","input","output","passed","durationMs"}`
- Coverage: `go test -coverprofile=coverage.out ./... && go tool cover -func=coverage.out`
- Endpoint extraction: `grep -E 'r\.(Get|Post|Put|Delete)' pkg/interface/http/router.go`
- Rerun handler: `dashboard/rerun-handler.ts` calls `cmd/sandbox` binary with new input JSON

### TypeScript/Bun services (kinh-dich, news-fetch)

- Dashboard rendered by same pattern as Go (app.ts + build.sh, Tailwind CDN)
- Trace JSON: same schema as Go — narrator.ts (from `packages/primitives/sandbox-kit/`) produces identical format
- Coverage: `bun test --coverage --coverage-reporter=json`
- Endpoint extraction: `grep -E 'app\.(get|post|put|delete)' src/interface/handlers.ts`
- Sandbox runner: Bun process — `bun run src/sandbox/index.ts` (writes trace JSON, then render.ts produces HTML)

### Python services (pdf-extractor, rag-service)

- Dashboard rendered by same HTML/Tailwind pattern — Python generates trace JSON; a small TS/JS script or inline Python renders the HTML
- Trace JSON: same schema — Python sandbox produces identical `{"id","tier","subject","story","steps","input","output","passed","durationMs"}` via a Python narrator module (to be authored in SI-4 spike)
- Coverage: `pytest --cov=. --cov-report=json`
- Endpoint extraction: `grep -E '@app\.(get|post)' interface/handlers.py`
- Sandbox runner: pytest with monkeypatching for zero-creds; trace JSON written to `testdata/traces/`

## Endpoints Section — "Reveals Functions of the Server"

The endpoint section is what makes the dashboard a live function-revealing document, not just a test report.

**How to extract endpoints at dashboard build time:**

```bash
# Go (chi router pattern)
grep -E '\.(Get|Post|Put|Delete)\(' apps/<svc>/pkg/interface/http/router.go \
  | sed 's/.*\.\(Get\|Post\|Put\|Delete\)("\([^"]*\)".*/\1 \2/'

# TypeScript (Hono pattern)
grep -E '\.(get|post|put|delete)\(' apps/<svc>/src/interface/handlers.ts \
  | sed "s/.*\.\(get\|post\)('\([^']*\)'.*/\1 \2/"

# Python (FastAPI pattern)
grep -E '@(router|app)\.(get|post|put|delete)' apps/<svc>/interface/handlers.py
```

The extracted routes are embedded as a static JSON array in the dashboard at build time.
Each route shows: method, path, description (from docstring/comment if available), example response shape.

## Build Scripts (Per-Service)

Each service must have these entries in its `package.json` (TS) or `Makefile` (Go):

```json
// TypeScript services (package.json)
"scripts": {
  "sandbox:run":   "bun run src/sandbox/index.ts",
  "dashboard:build": "bun run src/sandbox/index.ts && bun run dashboard/app.ts && node dashboard/build.sh",
  "dashboard":     "npm run dashboard:build && open dashboard/index.html"
}
```

```makefile
# Go services (Makefile)
.PHONY: sandbox dashboard
sandbox:
	go test ./cmd/sandbox/...

dashboard:
	go test ./cmd/sandbox/... -v 2>&1 | tee /tmp/sandbox-trace.txt
	cd dashboard && bun run build.sh
	open dashboard/index.html
```

```bash
# Python services (Makefile or pyproject.toml scripts)
make sandbox:   pytest __tests__/sandbox/ --json-report --json-report-file=dashboard/trace.json
make dashboard: make sandbox && python dashboard/render.py && open dashboard/index.html
```

## Acceptance Test for "Dashboard Working" (per G6/G8/G9)

A dashboard is working when ALL of the following are verifiable by the QA agent:

| Check | Method |
|---|---|
| File exists | `ls apps/<svc>/dashboard/index.html` returns file |
| File non-trivial | `wc -l apps/<svc>/dashboard/index.html` > 200 lines |
| Opens in browser | Browser opens without JS errors (Playwright screenshot or manual check) |
| Shows endpoints section | `grep -c "SERVICE ENDPOINTS\|<endpoint" dashboard/index.html` > 0 |
| Shows at least N primitive cards | `grep -c "primitive-card\|data-tier=\"primitive\"" dashboard/index.html` >= N_primitives |
| Shows pass/fail | `grep -c "PASS\|FAIL\|passed" dashboard/index.html` > 0 |
| Coverage banner if < 80% | `grep "WARNING: This dashboard shows" dashboard/index.html` absent (implies coverage ≥ 80%) |
| G8: all scenarios green | Sandbox exit code 0; dashboard has zero RED badges |
| G9: user readable | Non-technical description present per primitive (from contract.md §description field) |
