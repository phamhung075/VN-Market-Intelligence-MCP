## 2. Pass Criteria

The audit window is `2026-05-10T00:00:00Z` → `2026-05-17T00:00:00Z` (7 calendar days from Phase A ship).

### C1 — Header format conformance

**Threshold: ≥ 90% of commits match the header regex.**

```
^(feat|fix|chore|test|docs|refactor)\([^)]+\): .+
```

Rationale: 90% allows a small number of merge commits and agent-memory commits whose scope pattern differs (`memory/<id>`), while guaranteeing that the overwhelming majority of developer/qa/pm work lands in structured form. Below 90% means the convention has not been operationally absorbed.

Exclusion from denominator: bare `Merge branch '...'` commits generated by git itself (not by agents). These carry no subject line and are not agent-authored.

### C2 — Task trailer presence (sprint commits only)

**Threshold: ≥ 85% of sprint-scoped commits carry a `Task:` trailer.**

A "sprint commit" is any commit whose scope contains a digit (e.g. `feat(1872a/db):`, `chore(1872a/architecture):`). Notebook commits (`chore(memory/<id>):`) are explicitly excluded — they follow the no-trailer rule in the convention.

Rationale: 85% not 90% because merge commits (`chore(NNN/area): merge task/...`) legitimately omit `Task:` when bundling multi-task branches. The 5-point gap covers that class.

### C3 — AC trailer presence (task-completing commits only)

**Threshold: ≥ 80% of commits that carry a `Task:` trailer also carry an `AC:` trailer.**

Rationale: AC trailers are the highest-effort field and agents may legitimately omit them on chore/infra commits even when scoped to a sprint task. 80% is the minimum that makes git-log auditable as a review surface; below 80% the log cannot substitute for manual Done-column review.

### C4 — Scope vocabulary compliance

**Threshold: ≥ 95% of non-notebook commit scopes use a recognized area token.**

Recognized area tokens (from `docs/policies/commit-convention.md § Scope Rules`; historical note 2026-07-23: the `.claude/knowledge/` path never existed in this repo, path corrected to the actual SSOT location):
`scheduler`, `mcp`, `knowledge`, `agents`, `infra`, `docker`, `qa`, `rag`, `db`, `alerts`, `telegram`, `vps`, `architecture`, `tree-map`, `memory`, `state`, `merge`, `tasks`, `audit`, `cycle`

Rationale: 95% because vocabulary drift is the leading indicator of convention abandonment. One or two novel area tokens in 7 days is acceptable; more signals agents are working outside the SSOT.

### Overall PASS rule

All four thresholds must be met independently. A single failing threshold = FAIL verdict. No averaging across criteria.

## 3. Audit Script Spec

**File to create:** `scripts/audits/commit-convention-audit.sh`

No `scripts/audits/` directory exists yet — developer must create it. Existing audit precedent: `scripts/audit-bctc-confidence-1345b.ts` (TypeScript). The convention audit should be a shell script for zero-dependency portability (no Bun/Node required).

### Inputs

```
SINCE_DATE="2026-05-10T00:00:00Z"   # hardcoded for Day-7 audit; parameterisable via $1
UNTIL_DATE="$(date -u +%Y-%m-%dT%H:%M:%SZ)"
REPORT_DIR="docs/signals/processed"
```

### Algorithm

1. `git log --since="$SINCE_DATE" --until="$UNTIL_DATE" --pretty="format:%H %s%n%(trailers:key=Sprint,valueonly)%n%(trailers:key=Task,valueonly)%n%(trailers:key=AC,valueonly)%n---"` → parse into per-commit records.
2. Filter out bare git-generated merge commits (subject matches `^Merge branch`).
3. For each remaining commit apply:
   - C1: subject regex match → `header_ok` boolean
   - C2: if sprint-scoped (scope digit present) and not notebook commit → `task_trailer_ok` boolean
   - C3: if `Task:` present → `ac_trailer_ok` boolean
   - C4: extract area token → check against vocabulary set
4. Compute pass rates for each criterion.
5. Emit JSON report to `docs/signals/processed/commit-convention-audit-<YYYYMMDD>.json`:

```json
{
  "generated_at": "<UTC>",
  "window": {"since": "...", "until": "..."},
  "total_commits": 0,
  "excluded_bare_merges": 0,
  "audited_commits": 0,
  "criteria": {
    "C1_header_format":   {"threshold": 0.90, "actual": 0.0, "pass": false, "violations": []},
    "C2_task_trailer":    {"threshold": 0.85, "actual": 0.0, "pass": false, "violations": []},
    "C3_ac_trailer":      {"threshold": 0.80, "actual": 0.0, "pass": false, "violations": []},
    "C4_scope_vocab":     {"threshold": 0.95, "actual": 0.0, "pass": false, "violations": []}
  },
  "verdict": "PASS|FAIL",
  "greenlight_action": "C1+C2|none"
}
```

Each `violations` array: list of `{sha, subject, reason}` objects, capped at 20 entries.

### Idempotency

Output filename includes run date (`-YYYYMMDD`). Running twice on same day overwrites same file. Safe to re-run; no side effects outside `docs/signals/processed/`.

### Verdict output

Script exits 0 on PASS, 1 on FAIL. Prints verdict to stdout for agent consumption.

## 4. Greenlight Action

### If PASS

1. Script creates `docs/signals/processed/commit-convention-audit-<date>.json` (done as part of audit — see §3).
2. Script drops greenlight signal: `docs/signals/agents-architect-<ts>-phase-b-c1-c2.json`

```json
{
  "from": "agents-architect",
  "to": "agent-father",
  "type": "phase_b_greenlight",
  "tasks": ["C1", "C2"],
  "audit_report": "docs/signals/processed/commit-convention-audit-<date>.json",
  "verdict": "PASS",
  "generated_at": "<UTC>"
}
```

3. agent-father reads signal and executes C1+C2 collapse per the Phase B plan below.

### C1 Execution Steps (agent-father)

C1 = retire the Done section from `docs/TASKS.md`.

- Read current `docs/TASKS.md`.
- Verify Done section exists and contains rows.
- Delete the `## Done` heading and all rows under it.
- Commit: `chore(tasks): phase-b-C1 retire TASKS.md Done section — git log is canonical`
- Trailer: no Sprint/Task/AC (no-sprint rule applies — this is repo maintenance).

### C2 Execution Steps (agent-father)

C2 = collapse TASKS.md/Todo into BACKLOG.md.

- Read current `docs/TASKS.md` (Todo section) and `docs/BACKLOG.md`.
- Append all Todo rows from TASKS.md to the bottom of BACKLOG.md under a `## Backlog — migrated <date>` heading.
- Delete the `## Todo` heading and all rows from `docs/TASKS.md`.
- Commit both files atomically: `chore(tasks): phase-b-C2 collapse TASKS.md Todo into BACKLOG.md`
- Trailer: no Sprint/Task/AC (no-sprint rule).

Sequencing: C1 must commit before C2 begins (both touch TASKS.md — sequential writes, no conflict).

### If FAIL

Script drops failure signal: `docs/signals/agents-architect-<ts>-phase-b-c1-c2-fail.json`

```json
{
  "from": "agents-architect",
  "to": "user",
  "type": "phase_b_fail",
  "tasks": ["C1", "C2"],
  "verdict": "FAIL",
  "failing_criteria": ["<list of failing C-ids>"],
  "audit_report": "docs/signals/processed/commit-convention-audit-<date>.json",
  "remediation": "See violations list in audit report. Extend window by 7 days (re-run 2026-05-24). Fix agent flows that produced violations.",
  "generated_at": "<UTC>"
}
```

agents-architect sends Telegram WORK notification: `[agents-architect] Phase B C1+C2 FAIL — window extended. See audit report.`

## 6. Risk and Rollback

### Risk: C1 collapse loses Done rows

TASKS.md is tracked in git. Any row deleted in C1 is recoverable via:

```bash
git show HEAD~1:docs/TASKS.md          # Done rows before collapse
git diff HEAD~1 HEAD -- docs/TASKS.md  # Exact lines removed
```

Restore: `git revert <C1-commit-sha>` — creates a new commit restoring the Done section. No force-push required.

### Risk: C2 migration loses Todo rows or corrupts BACKLOG.md

Same recovery pattern:

```bash
git show HEAD~1:docs/TASKS.md    # Todo rows before collapse
git show HEAD~1:docs/BACKLOG.md  # BACKLOG before append
git revert <C2-commit-sha>       # Restore both files
```

BACKLOG.md append uses a dated heading (`## Backlog — migrated <date>`) so the migrated block is trivially identifiable and removable without reverting the entire file.

### Risk: PASS verdict on a window that was not truly conforming

Threshold selection (§2) is conservative enough that a false PASS would require both high overall compliance and selective non-compliance on lower-visibility commits. If a false PASS is suspected post-collapse: restore via revert, re-audit manually with `git log --since="2026-05-10" --pretty=format:"%H %s"`, and raise window to 14 days.

### Risk: audit script bugs produce wrong pass rates

The JSON report includes per-criterion violation lists. pm/developer can spot-check 3–5 violations against `git log --oneline` to verify parse correctness before acting on the verdict. Script is read-only until the signal-drop step; no destructive action until PASS is confirmed.
