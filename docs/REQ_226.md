# REQ-226: Cowork Performance — Agent Merge, Bootstrap Tool, Direct MCP Access

status: READY_FOR_ARCHITECT
sprint: 226
po_vision: Three-track improvement: reduce agent count, eliminate 3-call opening overhead, grant all agents live data access

---

## User Story

As a Vietnamese stock investor using Claude,
I want the Cowork analysis team to run faster and validate data live before posting signals,
So that alerts arrive sooner and hallucinated prices never reach the MARKET channel.

---

## Problem Statement

| Problem | Root Cause | Impact |
|---------|-----------|--------|
| BCTC Collector posts signal → Report Analyzer waits 60 min to analyze | Two separate agents on staggered schedules | Fundamental signals arrive 1–2h after PDF ingestion |
| Every agent opens with 3 serial MCP calls | `get_agent_signals` + `get_market_context` + `get_system_status` = 3 round-trips before real work | Wasted latency each cycle |
| 6 of 9 agents draft output without backend access | Unified Coordinator is last-mile gatekeeper | Hallucinations reach output; coordinator is a bottleneck |
| Monday digest + prediction are separate agents at different times | 08 fires at 07:30, 06 fires at 22:30 — no shared context | Predictions not woven into digest narrative |

## Functional Requirements

### FR-1: Merge BCTC Collector + Report Analyzer → Financial Analyst

- **Description**: Delete `02-bctc-collector.md` and `03-report-analyzer.md`. Create `02-financial-analyst.md` combining both roles in a single agent that collects BCTC status then immediately analyzes in the same cycle.
- **Input**: Scheduled trigger at 08:00 VN and 20:00 VN (former 02 schedule — absorbs 03's 09:00/21:00 slots).
- **Output**: `fundamental_validation` signal posted directly to `alert-commander` after analysis. No intermediate `cross_validate` hop via signal bus.
- **Tool set**: Union of 02 + 03 tool lists. See Pre-Confirmed Tool Lists below.
- **Business rule**: Signal flow `BCTC Collector → Report Analyzer → Alert Commander` collapses to `Financial Analyst → Alert Commander`. Signal type stays `fundamental_validation` (unchanged — downstream agents need no update).
- **Business rule**: `get_system_status` call from old 02-Step-2-6 removed. Step 0 bootstrap covers it.
- **DDD layer**: interface (agent .md file only — no TypeScript change)

### FR-2: Merge Digest Writer + Prediction Synthesizer → Digest & Predict

- **Description**: Delete `08-prediction-synthesizer.md`. Merge logic into `06-digest-predict.md` replacing `06-digest-writer.md`.
- **Schedule**: Daily 22:30 VN (unchanged). Monday 07:30 VN: run prediction synthesis FIRST, then full digest. Other days: digest only (prediction block skipped).
- **Monday sequence**: Step P (prediction) runs before Step 2 (compile digest). Prediction output feeds into digest narrative under a `Du bao tuan moi` section.
- **Tool set**: Union of 06 + 08 tool lists. See Pre-Confirmed Tool Lists below.
- **Business rule**: Prediction signals (WORK channel only) and digest (MARKET channel) routing rules unchanged. Max 5 claims cap unchanged. Dampening logic (10% confidence reduction when calibration degrading) unchanged.
- **DDD layer**: interface (agent .md file only — no TypeScript change)

### FR-3: New MCP Tool — `get_cycle_bootstrap`

- **Description**: Single compound tool replacing the 3-call opening sequence used by all agents.
- **Input**: `{ agent_name: string }`
- **Output**:
  ```typescript
  {
    agent_signals: AgentSignal[],      // result of get_agent_signals(agent_name)
    market_context: MarketContext,     // result of get_market_context(hours_back=24)
    system_status: SystemStatus        // result of get_system_status()
  }
  ```
- **Internal behavior**: calls `get_agent_signals`, `get_market_context(hours_back=24)`, `get_system_status` in parallel (Promise.all). Returns combined payload.
- **Business rule**: If any sub-call fails → return partial payload with `error` field per failed key. Agent applies fail-loud protocol on error field presence.
- **Business rule**: `agent_name` must match known agent identifiers (see validation table). Unknown name → return 400 with list of valid names.
- **Performance target**: Must complete in ≤ 3s at p95 (vs ~6–9s for 3 serial calls).
- **DDD layer**: application (use case: `src/application/useCases/getCycleBootstrap.ts`) + interface (MCP tool registration)

### FR-4: All 7 Cowork Agents Use `get_cycle_bootstrap`

- **Description**: Update Step 0 + Step 1 of all 7 Cowork agent .md files to call `get_cycle_bootstrap(agent_name="{agent-name}")` instead of 3 separate calls.
- **Agents updated**: `01-news-scout.md`, `02-financial-analyst.md` (new), `04-market-watcher.md`, `05-alert-commander.md`, `06-digest-predict.md` (new), `07-qa-responder.md`, `unified-agent.md`.
- **Pattern after update**:
  ```
  Step 0: get_cycle_bootstrap(agent_name="<name>")
    → bootstrap.agent_signals: process signals as before
    → bootstrap.market_context: use as market context
    → bootstrap.system_status: check health
    → any bootstrap.error.<key>: apply fail-loud protocol
  ```
- **Agent-specific overrides** (preserve existing logic):
  - News Scout: still calls `get_market_context()` separately if `BASE_CONTEXT_FRESH=true` is needed — bootstrap already includes it; NEWS_CONTEXT can be extracted from `bootstrap.market_context`.
  - Digest Writer: always needs 24h context for digest compilation — bootstrap already provides it.
  - BCTC Collector (now Financial Analyst): skip the separate `get_system_status` in old Step 2-6 — bootstrap covers it.
- **Business rule**: `BASE_CONTEXT_FRESH` detection logic preserved. If `bootstrap.agent_signals` contains `chain_catalyst` with `payload.title = "BASE_CONTEXT"` from `unified-agent`, age < 20 min → set `BASE_CONTEXT_FRESH=true` and use `watchlist_tickers` from that signal payload.
- **DDD layer**: interface (agent .md files only)

### FR-5: Direct MCP Access for All 7 Cowork Agents

- **Description**: Add MCP server URL `https://zenmidi.com/mcp` to the system prompt header of all 7 Cowork agent .md files.
- **Currently**: Only `unified-agent.md` has `MCP server: https://zenmidi.com/mcp` in its header. Other agents draft output without live backend access.
- **Change**: Each agent adds a live data validation step before posting signals:
  - After drafting a claim or signal, cross-check key values (price, %, ticker) against `get_market_snapshot()` or relevant MCP tool.
  - Divergence > 5% or unknown ticker → discard draft, re-fetch, re-draft.
- **Unified Coordinator role change**: Remove "LAST-MILE REVIEWER — ONLY analysis-team agent with backend access" constraint. New role: daily/weekly quality reviewer. Step 4c (LAST-MILE REVIEW) becomes weekly-only (run during WEEKLY_REVIEW mode, not every MARKET cycle).
- **Business rule**: Alert Commander (05) retains sole write access to MARKET channel. Direct MCP access does NOT grant other agents permission to `send_telegram(channel="market")`. Channel routing rules unchanged.
- **DDD layer**: interface (agent .md files + unified-agent.md header change)

## Edge Cases & Data Quality

- [ ] `Promise.all` in bootstrap: if `get_market_context` slow (>5s) → timeout individually, return partial, agent fail-louds
- [ ] `BASE_CONTEXT_FRESH` logic: bootstrap returns `agent_signals` which may contain the `BASE_CONTEXT` chain_catalyst — parsing logic must be in agent .md, not tool
- [ ] Merged Financial Analyst: if PDF ingested at 08:00, analysis runs immediately — race condition if PDF not fully OCR'd. Rule: `list_stored_pdfs` → `get_bctc_full` (uses DB, not raw PDF) → only call `read_bctc_pdf` if `get_bctc_full` returns no data for that ticker
- [ ] Monday prediction + digest: if `get_evidence_summary` returns "No evidence" for all stocks → prediction block exits, digest still runs (no skip of full digest)
- [ ] Track C validation step: agents compare draft price vs `get_market_snapshot()` — define threshold: divergence >5% OR ticker not found in snapshot → discard + re-fetch. Prevent infinite loop: max 2 re-fetch attempts then skip that stock with flag
- [ ] `get_cycle_bootstrap` called with empty `agent_name` string → 400 error (treat same as unknown name)
- [ ] unified-agent LAST-MILE weekly mode: Step 4c moves to WEEKLY_REVIEW only — MARKET mode skips it. Ensure existing Step 4d (message quality audit) remains in MARKET mode

## Acceptance Criteria

### AC-1: Track A — Financial Analyst merge

**Given** a new BCTC PDF is ingested by the server at 20:00 VN
**When** the Financial Analyst runs its 20:00 cycle
**Then**
- BCTC status checked AND full financial analysis (revenue YoY, D/E, insider signals) completed in same cycle
- `fundamental_validation` signal posted to `alert-commander` within that cycle
- No `cross_validate` intermediate signal in signal bus
- Old `03-report-analyzer.md` file deleted; `02-bctc-collector.md` deleted; `02-financial-analyst.md` exists

### AC-2: Track A — Digest & Predict merge

**Given** it is Monday 07:30 VN
**When** the Digest & Predict agent runs
**Then**
- `get_evidence_summary` called per watchlist ticker
- Up to 5 `create_prediction_claim` calls made (or skip if no evidence)
- Digest sent at 22:30 VN includes `Du bao tuan moi` section with those claims
- `08-prediction-synthesizer.md` file deleted; `06-digest-predict.md` exists

**Given** it is any day other than Monday
**When** the Digest & Predict agent runs
**Then**
- No prediction logic executed (no `get_evidence_summary`, no `create_prediction_claim`)
- Digest sent normally at 22:30 VN

### AC-3: Track B — Bootstrap tool

**Given** a Cowork agent calls `get_cycle_bootstrap(agent_name="news-scout")`
**When** the MCP server processes the request
**Then**
- Returns `{ agent_signals: [...], market_context: {...}, system_status: {...} }` in ≤ 3s at p95
- All three sub-calls executed in parallel (verifiable via server logs showing concurrent timing)
- `agent_signals` identical to direct `get_agent_signals(agent="news-scout")` call result

**Given** `agent_name` = `"unknown-bot"`
**When** the tool is called
**Then**
- Returns HTTP 400 with `{ error: "Unknown agent", valid_agents: [...] }`

**Given** `get_system_status` sub-call fails (circuit breaker open)
**When** bootstrap is called
**Then**
- Returns partial: `{ agent_signals: [...], market_context: {...}, system_status: null, error: { system_status: "circuit breaker open" } }`
- Does NOT throw 500; agent receives partial result and applies fail-loud

### AC-4: Track C — Direct MCP access

**Given** agent `04-market-watcher` drafts a price anomaly signal with HPG at 35,000 VND
**When** it calls `get_market_snapshot()` to validate before posting
**Then**
- If backend shows HPG at 33,500 VND (>5% divergence) → signal discarded, price re-fetched, signal re-drafted with 33,500 VND
- Max 2 re-fetch attempts enforced
- If 2nd fetch also diverges → stock flagged, skipped, `submit_feedback` filed

**Given** unified-agent runs in MARKET mode after Track C ships
**When** Step 4c is evaluated
**Then**
- Step 4c (last-mile review) is SKIPPED in MARKET mode
- Step 4c runs only during WEEKLY_REVIEW mode
- Step 4d (message quality audit) still runs in MARKET mode

### AC-5: Registry updates

**Given** all three tracks shipped
**Then**
- `docs/data/tool-registry.json` updated: `get_cycle_bootstrap` listed, tool count incremented
- `.claude/knowledge/agent-roster.md` updated: agent table shows 7 agents (02→Financial Analyst, 06→Digest & Predict, 03+08 removed)
- `.claude/knowledge/mcp-tools.md` "Tools Per Agent" table updated: reflects merged agents + bootstrap in opening sequence
- `unified-agent.md` "YOUR ROLE" section: "LAST-MILE REVIEWER" constraint removed, new text: "Quality Reviewer (daily/weekly)"
