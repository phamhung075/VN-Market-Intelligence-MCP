## Lessons / patterns

- **When :3000 (mcp-server backend) is down, the MUTEX SYSTEM is down too — task_claim/task_release are vn-market tools served by that same backend.** So you cannot mutex-wrap an emergency recovery spawn (chicken-and-egg: the mutex can't return until the backend does, and the backend needs ops to return). Resolution: spawn a SINGLE ops agent WITHOUT mutex for backend recovery (no fleet-concurrency risk from one agent); the mutex requirement is a fleet-panic guard, not applicable to the one spawn that restores the mutex. A failed call_tool returning `connection refused :3000` (vs a structured `{"ok":...}`) is the tell that the backend — not just the tool — is down. Recovery = single-service `docker compose up -d mcp-server` (verify host healthy first: SIGTERM signal=15 + mem-free ≠ OOM = false-positive destructive stop, AUD-ND-1 class), NEVER `up -d` the whole project (host-panic).
- **Verify the DEPLOY TARGET, not just that the code is correct — a guard on the wrong deployer protects nothing.** GUARD-1/2/3 passed every local check (bash -n, deliberate-violation exit-1, clean-render, QA 6/6) but were added to `scripts/deploy-vps-proxy.sh` (`${VULTR_IP}`) while the LIVE host is Vinahost via `scripts/deploy-vinahost.sh` (memory: Vultr decommissioned 2026-04-13). PO's design-phase "canonical=deploy-vps-proxy.sh" + QA's "TE handled by vinahost, non-blocking" were both plausible-but-unchecked; relaying either would have shipped a guard that leaves the live deploy path unguarded + the TE script's `__TE_API_KEY__` un-converted. When a repo has >1 deployer/host, the FIRST raw check is "which one targets the live host" (grep both for target IP/host + which scripts each ships) before trusting any "canonical deployer" claim. Cousin of [[feedback_router_verify_raw_not_badges]].
- **A "compress-to-pointer" move is only safe if the pointer TARGET exists — verify the destination, not just the line count.** pm compressed a sprint block in TASKS.md (90→80L, cap met = LOOKED green) but the "full items in SPRINT_GOAL.md §X" pointer it added resolved to NOTHING (section never written) → 5 backlog item bodies (ACs/triggers/routing) survived only in git history. `wc -l ≤cap` is NOT proof of a lossless compress; `grep` the pointer target for the moved IDs before trusting it. Same false-green family as [[feedback_fence_false_green]] (config reports 0 errors while checking nothing).
- **A recon's INFERRED root cause is a hypothesis, not fact — make the fixer verify-raw before acting on it.** ops-vps-fetch recon read "boot-1/boot-2 08:57Z" log lines and I inferred VPS-reboot-killed-socat; passed that to ops as the working hypothesis. ops verify-raw'd (uptime 48d, socat alive via curl 200) and found the REAL cause (unrendered `__MCP_BASE__`/`__API_KEY__` placeholders). The wrong hypothesis cost nothing because ops re-verified instead of blindly restarting socat. Never relay a recon's suggested root-cause bucket as settled.
- **A deploy that copies a repo template can silently clobber a rendered live config — green code tests don't cover it.** cafef sprint (814088b0) fixed is_blocked() (verified cafef 0→20), but the SAME deploy overwrote /root/fetch-vn-news.sh's rendered API_URL/API_KEY lines with raw `__PLACEHOLDER__` template → ~1h push outage. The code fix was correct; the DEPLOY-RENDER step was skipped. Lesson: any VPS-script deploy needs a pre-deploy placeholder-leak guard (reject `__[A-Z_]+__` in deployed artifacts) + render step; prefer `${VAR:-default}` env-fallback form (foreign-flow has it, fetch-vn-news.sh didn't). Filed VPS-DEPLOY-PLACEHOLDER-GUARD.
- **brief_complete can arrive AFTER its own impl already shipped same-session** — the context-resume-economy brief was fully implemented (b38ac812) before its signal was even drained; PO raw-verified current code state and caught it instead of re-dispatching done work. Always verify the brief's claimed pre-state against live code before scoping.
- **A SKILL/flow file can breach its cap *because* a fresh feature added load-bearing content** — the fix is lazy-load extraction (pointer the bodies to a sibling .md), NEVER a naive prune that would delete a live contract. Route .md cap fixes through architect→agent-father (agent-md-factory), not code CLEAN→qa.
