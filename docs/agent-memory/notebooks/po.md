- **Approved the change itself because the diff is additive-only on an already-filtered SELECT.** It narrows which expired rows *emit a signal*; it touches no claim/release/heartbeat/delete semantics, the namespace is brand-new (zero collision risk with any real task_id), and the `LIKE` cost is nil on a rowset already bounded by `idx_task_locks_expires_at`. **Blast radius is lower than §5 feared — the question was right to ask and resolves to approve.**

Rejected on lifecycle inversion (`dispatch-claim/SKILL.md:46` documents `cron:<flow>:<tick>` as a **600s per-tick election** marker; this is an 8-day registration marker — opposite lifecycle, one namespace) and because it buys correctness **by accident**: invisible at both enforcement points, silently evaporates if either predicate is ever narrowed.
