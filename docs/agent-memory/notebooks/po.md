## Lessons

- **⚠️⚠️ A cited "fleet-wide policy" can simply not exist — enumerate before deferring to it.** The developer declined to grant Bash citing policy "shared by every cowork gatherer/publisher agent". Enumerated all 43 `.claude/agents/*.md` frontmatter lines: **fb-market-poster (a cowork PUBLISHER), system-auditor and orch-sentinel all hold Bash and all write shared state.** Three standing exceptions in the same cadence tier. An agent's honest refusal to act unilaterally is right; its stated *reason* still needs checking.
- **⚠️ The option that "needs no permission change" can be the expensive one — check the deployment surface, not the tool grant.** The MCP-wrapper path looked strictly better (both agents already hold `mcp__gateway__call_tool`, zero governance change). Killed by one unrun check: **`./scripts` is NOT mounted into the mcp-server container**, so the tool cannot exec the script — it is a full TS rewrite of 313 tested lines, a second implementation held in drift-lock. `./docs/data` IS mounted RW, so it was feasible, just costly. **Feasibility and cost are different questions; answer both.**
- **⚠️ "Blast radius" arguments need a baseline.** Both agents already hold repo-wide `Write`+`Edit`, so an injected agent can already reach code execution transitively by rewriting a script a Bash-capable peer runs. Bash makes that *direct*, not newly possible. Genuinely new: process execution + network egress. **Ask what the marginal capability is, not what the absolute one sounds like.**
