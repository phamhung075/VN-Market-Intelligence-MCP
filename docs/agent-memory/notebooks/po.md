## 2026-08-14T09:29Z · The auditor filtered on a status the CHECK constraint forbids — one disjunct was dead by construction

- **Trigger:** router bug report — two DATA-tier auditor spawns 30min apart classified the same static `cron_job_runs` table oppositely (REAL/HIGH → dedup'd, vs NOISE/`signal_id:null` → unrouted). **Output: 1 `orch-apply.sh` pipe, conservation OK (740→741), 1 mint, 0 dedups.**
- **★ THE REPORT, BOTH AUDITOR SPAWNS, AND MY OWN GROUND-TRUTH ALL MISSED THE DECISIVE FACT: THE SCHEMA DECLARES THE ENUM.** `CHECK(status IN ('running','success','error','crashed'))`. The bad query filtered `status='failed' or 'error'` — **`'failed'` is not a legal value**, so that disjunct could never match a row, ever. This reframes the whole fix: the defect is not "the keyword list was too short", it is **"there is a hand-authored keyword list at all when the enum is already declared in the schema."** AC-1 therefore mandates `GROUP BY status` emitting every bucket and **rejects a hardcoded IN-list in review even if today's list is complete**.
- **★ I REJECTED THE REPORTER'S OWN PROPOSED PREDICATE.** The filed root-cause candidate said count `status != 'success'`. That folds `running` — a legal in-flight state — into the failure count, so every sweep landing mid-run manufactures a phantom failure. **It trades one silent false negative for a recurring false positive.** AC-2 pins failure = `IN ('error','crashed')` and makes `running` its own bucket. A root-cause candidate arriving with the bug report is a hypothesis, not a spec.
- **★ ROOT CAUSE WAS LICENSED IN WRITING BY THE SPEC ITSELF.** `cron-db-data-integrity.md:101` specifies cron_job_runs failure detection as prose only ("last run errored"), and the NO HALLUCINATED COUNTS guard at `:162` scopes itself to four counts then says ad-hoc queries are for *discovering* anomalies "not for re-counting **the known four**". Measured instead of assumed: consumers of the `counts` contract = 3 files, `db-integrity-history-append.sh:146` passes `$counts.counts` through generically, a regression test file already exists, and the remedy pattern is already shipped in that same script for 4 siblings. **No design left to buy.** Rationale + an explicit escalate-back escape hatch written into `po_rescope_note` so it is auditable, not a silent downgrade.
