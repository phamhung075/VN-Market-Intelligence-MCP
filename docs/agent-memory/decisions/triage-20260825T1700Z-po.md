## RULING 1 — `OCR_TEXT_BACKEND` default flips to `auto`, behind four gates

task_id: `DECISION-PDFX-OCR-TEXT-BACKEND-DEFAULT-FLIP-TO-AUTO`

**what-considered:** three options. (a) Leave it unset forever — rejected: it makes a measured,
ratified quality fix permanently dead code and abandons the user's standing directive with no
replacement path. (b) Flip the code default in `apps/pdf-extractor/main.py` — rejected: reverting it
then needs a rebuild, and the running behaviour becomes unreadable from outside the container.
(c) Set `OCR_TEXT_BACKEND=auto` in `docker-compose.yml` for the `pdf-extractor` service only, keeping
`main.py`'s unset-default at `tesseract-vie` — CHOSEN. One line to revert, visible in
`docker inspect`, and every ephemeral `docker compose run --rm` container plus every test keeps the
conservative baseline unless told otherwise.

**why-change:** the wholesale swap stays REJECTED and is not re-litigated — paddleocr 2.10.0 maps
`lang="vi"` into a shared 30+-language `latin` rec bucket (library limitation, not config), ran 2.4x
slower, and pinned at cgroup `memory.max` with 1444 hard-limit hits vs tesseract-vie's 0. `auto` is a
different proposition and clears both bars the swap failed: +3.8% table-phase wall clock
(117.26s vs 112.97s, same session) and `memory.peak` 1274.9 MiB = 49.8% of the 2,684,354,560 B cap,
0 hard-limit hits, 0 oom — better headroom than tesseract-vie's own corrected 63.7% baseline. The
negative control holds on two independent bases: the rescue fired 1x in 51 regions, and per-unit
sha256 left 29 of 30 table units byte-identical to a pure tesseract run. The second basis is the one
that matters, because it also catches a rescue that fires and then silently loses. Upside is not
marginal: page 9 went 122 → 452 chars with 9/9 income-statement figures recovered. A page that loses
100% of the revenue and profit figures while self-reporting 0.92 confidence is a data-integrity
failure, and those figures are the BCTC product.

**gates (all four, in order):**
- **G1 QA-green, stated not assumed.** `FIX-PDFX-TESSERACT-CONFIDENCE-MEAN-OVER-NONEMPTY-MASKS-TOTAL-PAGE-MISS`
  must reach DONE_VERIFIED on its own AC-1..AC-4. QA is verifying `e9144ea75` concurrently; a failed AC
  sends this row back to BACKLOG.
- **G2 second-document margin.** `PROBE-PDFX-OCR-CONFIDENCE-SECOND-DOCUMENT-MARGIN` must pass. The
  developer flagged the n=1 caveat; I promoted it from suggestion to hard gate. Two of the three
  rejected discriminators *inverted* on the only document measured — a bad discriminator breaks the
  negative control first, which is the expensive direction.
- **G3 the image must carry the fix.** `OPS-PDFX-REDEPLOY-DEBT-LANG-VI-FIX-INERT-IN-PRODUCTION` first.
  Live container `e2801b67406c` was Created 2026-08-24T13:35:05Z and cannot contain `e9144ea75`.
- **G4 market-hours guard**, inherited: no rebuild/exercise during VN market open 02:00–08:59 UTC weekdays.

**rollback:** 7-day window. Revert (unset the env var, no rebuild) on any of — rescue fire rate above
10% of table regions on any document (baseline 1/51 = 2.0%); any cgroup hard-limit hit or oom
(baseline 0); table-phase wall clock more than 15% over the tesseract-vie baseline (measured +3.8%).
