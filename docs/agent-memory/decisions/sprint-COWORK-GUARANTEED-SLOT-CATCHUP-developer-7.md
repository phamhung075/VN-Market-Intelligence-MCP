**what-done:** Root-caused + fixed `nso_ts_key()` (`scripts/agents-flow/lib/notebook-section-direction.sh`): old single-pattern `grep -oE <date-regex> | tail -1` treated the T..Z time suffix as OPTIONAL, so an all-digit commit-SHA run anywhere later in a `## cycle-N · <ISO ts> · ... commit \`<sha>\`` heading matched the same pattern as the real timestamp, and `tail -1` preferred whichever match landed LAST — the SHA, not the ts. **what-considered:**
- single-pattern tweak (just swap tail→head) — rejected, still vulnerable to a SHA colliding earlier than the real ts, or a T-less SHA of exactly 8 digits with clean boundaries

**why-decision:** Tier-1 requiring literal T/Z is collision-proof by construction against hex SHAs (root_cause note's own 2nd suggested option); Tier-2 boundary-guard covers the qa.md date-only convention symmetrically, same root cause.
