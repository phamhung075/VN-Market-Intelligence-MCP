## 2. RULING — `DECISION-PDFX-OCR-TEXT-BACKEND-DEFAULT-FLIP-TO-AUTO`

**REJECTED. CANCELLED. Auto-mode does not become the production default.**
The 17:00Z ruling ("YES, FLIP TO auto") is WITHDRAWN. Reasons, strongest first.

### (a) My own rollback trigger is already breached, pre-deployment, on document #2
The 17:00Z ruling set: roll back on "(a) rescue fire rate above 10% of table regions on
any single document" and "(b) any cgroup hard-limit hit or oom (baseline 0 of each)".
Measured on DBC: **46% fire rate** and **494 `memory.max` events**. A change that its own
criteria would roll back on day one must not be deployed. This alone is dispositive.

### (b) The premise is falsified STRUCTURALLY, not by calibration
`_ink_coverage` = (ink pixels inside boxes the engine emitted text for) / (**all** Otsu
foreground pixels in the crop). The denominator includes every dark pixel the engine was
*correct* to ignore: table rule lines, shaded header bands, company seals and signature
blocks, scan speckle, page-edge shadow. The metric therefore conflates two things:

    text the engine MISSED   (the intended signal — recall)
  + non-text ink the engine correctly SKIPPED   (a function of the issuer's table styling)

The second term is orthogonal to read quality. That is precisely why FPT (lowest-legit
0.674) and DBC (lowest-legit 0.329) disagree by ~2x on documents that were BOTH read
correctly. **No threshold can repair a metric whose value depends on a variable
orthogonal to what it claims to measure.**

And the retune is arithmetically dead, which is worth stating because it will be
proposed: lowering 0.5 to ~0.30 clears DBC's legitimate regions but stops rescuing FPT
page 9 (0.174) only barely, and the bands now **overlap** — on FPT alone there was a 3.9x
gap with no overlap (broken 0.174 vs legit 0.674); across the two documents together
there is no separating constant at all. n=2 already destroys the design.

### (c) The code's own comment states the failing behaviour as deliberate intent
`_recall_adjusted_confidence`'s docstring justifies `min()` over an F1 thus:

> "under an F1 a region read perfectly but only 34% covered still scores 0.507 and
> escapes a 0.5 gate. Under min() it scores 0.34 and is rescued."

DBC page 14 is verbatim that region: read perfectly, 0.329 covered, rescued. The design
consciously chose the semantics that produce qa's failure. This is not an implementation
that missed a case — **the specification is wrong**, and that is why the fix is not "try
harder at the same thing."

### (d) A structural defect NOBODY has named: the winner-pick cannot protect the negative control
`AutoFallbackOcrBackend.recognize_text()` picks `paddle_conf >= tesseract_conf`, and both
sides are `min(precision, ink_coverage)` over **the same ink denominator**. But:
- Tesseract's boxes are **word-level** (`image_to_data` level-5, filtered to conf>0 and
  non-empty text).
- PaddleOCR's boxes are **line-level** polygons (`_polygon_to_box(item[0])` — one per
  detected text line), and PaddleOCR routinely detects rule lines as text lines, whose
  non-empty `.strip()` output adds a box.

So PaddleOCR's coverage is biased upward by **box granularity and detector behaviour**,
independent of read accuracy — and the bias is largest exactly in the low-coverage regime
where the rescue fires. The tie also goes to PaddleOCR (`>=`, not `>`). The guard that was
supposed to stop a worse rescue from winning is systematically tilted toward letting it
win, precisely when it matters most. **Whether this actually fired on DBC is the
unanswered AC-3 digest diff from §1** — which is why that number is now mandatory rather
than nice-to-have. Also note `coverage = _ink_coverage(image_arr, boxes) if boxes else 1.0`:
a PaddleOCR run that emits boxes but few of them is scored generously.

### (e) The memory regression is SUPERLINEAR in fire count — so it is not bounded by the discriminator at all
From qa's paired A/B (same harness, same ephemeral container class, cgroup counters only):

| doc | tesseract-vie peak | auto peak | fires | delta |
|---|---|---|---|---|
| FPT Q4 2025 | 1,235,070,976 B | 1,346,867,200 B | 1 | +111.8 MiB, 0 events |
| DBC Q4 2025 | 1,118,744,576 B | 2,684,354,560 B (**= memory.max exactly**) | 6 | +1,493 MiB, 494 events |

6x the fires produced ~13x the delta. This is NOT one-time model residency: `PaddleOCR(...)`
is constructed unconditionally in `_load_pek_models()` (`pek_engine_adapter.py:408`) in
**both** arms, so residency is already in the tesseract-vie baseline and cancels out. A
delta that scales with *invocation count* is retention across calls.

**If that holds, no fire rate is safe.** A document with enough genuinely-broken pages
OOMs even under a perfect discriminator. This is the finding that makes auto-mode unsafe
*independent of how the discriminator question resolves*, and it is the cheapest decisive
experiment available: `AUTO_FALLBACK_CONFIDENCE_THRESHOLD` reads
`os.environ.get("OCR_FALLBACK_THRESHOLD", "0.5")`, so fire count can be swept 0→13 on one
document **with no code change and no rebuild**. Plot `memory.peak` against N. Flat ⇒
residency, safe. Rising ⇒ retention, hard blocker.

Separately and not to be conflated: `FIX-PDFX-PARENT-PROCESS-MEMORY-BURST-HEADROOM`
(review[], BLOCKED, next_agent=po) records the LONG-RUNNING container reaching
`memory.peak == memory.max` with 1.5-3.7 MiB free **under tesseract-vie alone**. The live
container reads 3.9% right now only because it is 25 minutes old. So the headroom auto
would need is available in a fresh container and demonstrably decays toward zero over a
container's life. These are two different phenomena that compound.

### (f) The +3.8% table-phase figure is STRUCK from the record
Ruling on the explicitly-flagged discrepancy (dev: +3.8%, 117.26s vs 112.97s; qa: +54.9%,
168.45s vs 108.78s):

1. **Unreproduced.** Same script (`scripts/audits/ocr_bench_inner.py`, unmodified since
   16:22Z — before both runs), same commit, independent attempt.
2. **Ambient load does not explain it.** qa's *tesseract-vie* arm was FASTER than dev's
   (108.78 vs 112.97) while qa's *auto* arm was 44% slower (168.45 vs 117.26). Host
   contention slows both arms; this asymmetry is auto-specific and therefore real signal,
   not noise.
3. **Mechanically implausible.** The valid lang=vi wholesale benchmark puts PaddleOCR at
   414.5s vs tesseract's 174.5s over the same 51 regions ≈ **8s per region for PaddleOCR**.
   dev's number says one PaddleOCR page cost 4.3 seconds in total — less than a single
   region's inference.

**Verdict: dev's +3.8% is not usable. qa's +54.9% is better supported. I certify
neither.** And the deeper point: **criterion #3 as I wrote it ("table-phase wall >15% over
baseline") is UNMEASURABLE on either dataset** — both are single-fire measurements, and
auto's cost is fire-count-dependent. A percentage-over-baseline measured at n=1 fire
predicts nothing about a document with 6. Criterion #3 is WITHDRAWN and replaced by a
marginal-cost-per-fire bound (§3 Phase 3).

### (g) The code stays. Do NOT revert `e9144ea75`.
Verified inert: `OCR_TEXT_BACKEND` is absent from the live container's env, so
`AutoFallbackOcrBackend` is never instantiated. The confidence value's only escape path

strict improvement to the confidence *signal* (a near-total page miss no longer
self-reports 0.92 — true on both documents) and costs nothing while parked.

## 3. RULING — the bar for `dev-pdf-extractor`'s next cycle

The overfit risk is real: the discriminator was tuned on 1 document and broke on the 2nd;
tuning on 2 would repeat the mistake at n=2. **The next cycle is MEASUREMENT ONLY. Do NOT
modify `apps/pdf-extractor/infrastructure/ocr_backends.py`.**

### Phase 1 — re-analyze signals ALREADY instrumented but never evaluated (cheapest, do first)
`scripts/audits/ocr_confidence_probe_inner.py` emits SEVEN candidate signals per region.
The AC-1 evaluation reported on FOUR. Untested:

- **`line_ink_cov`** — ink covered by word boxes, restricted to the interior of level-4
  line boxes. This is a **different quantity** from `line_cov_ratio` (= 1.0000 on every
  region, correctly rejected as structurally inert), and it is the natural fix for the
  confound in §2b: it excludes rule lines, seals and shading that fall outside any
  detected text line.
- **`min_conf`** — computed, never reported.
- **`n_lvl5_conf_le0` / `n_lvl5_empty_text`** — counts of word slots where Tesseract
  emitted a box and FAILED to read it. A **direct, layout-independent recall signal**: the
  engine itself saying "something is here and I could not read it." Cannot be confounded
  by table styling because it never looks at a pixel outside a box.
- **Numeric-token density** — not yet instrumented; instrument it. **This is the signal a
  human used successfully on BOTH documents**: qa classified all 6 DBC regions correctly
  by reading for parseable VND accounting figures, and FPT page 9's failure signature was
  literally "headers, a stray '178%', zero figures". It is also the thing the BCTC product
  actually cares about.

**Correction to the AC-1 evaluation that reopens a rejected candidate:** AC-1's candidate
"recognised row count vs the row count **the layout detector** found in the same region"
was implemented using Tesseract's OWN level-4 line boxes — self-referential by
construction (Tesseract emits a line box only where it already found words), hence the
1.0000. **That candidate was never tested as specified.** DocLayout-YOLO already runs over
every page in this pipeline and is an INDEPENDENT detector; testing its boxes against
Tesseract's output is not circular. Re-test it properly before calling it dead.

### Phase 2 — reframe: RESCUE-AND-VERIFY (may make a perfect scalar unnecessary)
The current design bets irreversibly on a scalar *before* seeing the alternative, which is
why the discriminator has to be near-perfect. Evaluate instead: fire liberally on a cheap
signal, then **ACCEPT the PaddleOCR result only if it strictly improves an objective,
non-circular content criterion** (e.g. the count of parseable VND figures strictly
increases). Under that shape a false-positive fire costs compute and **never** costs
quality — the diacritic-regression risk that made broad firing dangerous disappears,
because a PaddleOCR result that does not add figures is discarded. The discriminator
degrades from a correctness gate to a cost filter, and the calibration problem stops being
load-bearing. This does NOT dissolve §2e — memory binds harder under liberal firing.
**Settle §2e first.**

### Phase 3 — the sample. What would ACTUALLY close this.
- **n >= 8 documents, DEDUPLICATED BY CONTENT HASH.** Measured: `data/pdfs/` holds 324
  files but only **188 unique by md5** (~42% duplication — `DBC_2025_Q4.pdf`,
  `DBC_2024_Q4.pdf` and `DBC_2023_Q4.pdf` are byte-identical, 3,413,297 B each). A sample
  that does not dedupe has a fake n. The corpus is more than large enough.
- **Stratified, and FROZEN BEFORE MEASUREMENT.** >=2 banks (VCB / ACB / SHB / CTG —
  grid-heavy, different table geometry), >=2 industrials (HPG / DGC / BSR), >=2
  consumer-retail (SAB / FRT / KDC), >=1 real estate (DIG / KDH / DXG). **FPT is HELD OUT
  and does not count toward n** — a discriminator tuned on it cannot be validated on it.
  Publish the chosen ids and their hashes BEFORE running, so the sample cannot be revised
  after seeing results.
- **The bar is SEPARATION, not a threshold.** Per signal, per document, report the full
  per-region distribution plus `max(score over genuinely-broken regions)` and
  `min(score over legitimate regions)`. **Ground truth by reading extracted cell content —
  NEVER by the score under test.** PASS requires `min(legit) > max(broken)` on EVERY
  document with margin, AND **one single fixed constant** sitting inside that gap on ALL of
  them simultaneously. A per-document threshold is not a discriminator, it is a lookup
  table.
- **Report failures as findings.** If nothing separates at n=8, that is a valid and
  valuable result — say so and hand back to PO. **Do NOT tune a constant to make it pass.**
  That prohibition already cost one cycle; restating it.
- **Carried from §1's unanswered probe ACs:** per-unit sha256 diff (tesseract-vie vs auto)
  on DBC and on every sampled document — the number that says whether false-positive fires
  CHANGE output or merely waste compute; and table-phase wall clock **with fire count
  reported alongside**, so cost is expressed as marginal-cost-per-fire, never as a bare
  percentage (§2f).
- **Run the §2e memory sweep FIRST** — it is the cheapest and it can moot everything else.
- **Market-hours guard remains binding:** never exercise pdf-extractor 02:00-08:59 UTC on
  weekdays.
