## S7 — Found by executing my own flow doc: the CLEAR block is a lying actuator.

`triage-signals.md` § Durable-inbox CLEAR prescribes `consumed_ids=$(echo "$pendingSignals" | jq -c …)`. **It failed live on my first attempt.** The agent shell here is `/bin/zsh 5.9` (`BASH_VERSION` unset) and zsh's `echo` interprets backslash escapes by default, so it rewrote every JSON-escaped `\n` inside a payload into a real newline.

Measured: `jq -c` on the file → rc=0, **one** line, 15234 chars. `echo "$pendingSignals" | wc -l` → **33**. Then jq exits 5, *Invalid string: control characters … line 17, column 98*. Isolated repro: `V='{"a":"x\ny"}'; echo "$V" | jq -c .` fails, `printf '%s' "$V" | jq -c .` succeeds.

**The severity is the `|| true`.** With `consumed_ids` empty, `jq --argjson` aborts, the pipe emits nothing, `orch-apply.sh` prints *"stdin produced empty candidate — aborting (no write)"* — and `|| true` swallows exactly that. A doc-faithful PO reports the inbox cleared while all envelopes remain. That is the narrated-but-never-landed class **inside PO's own durable actuator**, and it plausibly explains inbox re-delivery previously blamed on drain lag. It is intermittent *by input*: it needs one payload with a `\n` escape — this tick, `flow_actuator_fix`'s embedded jq patch code guaranteed it.

Worked around by reading ids straight from the file (10 → 0, `_updated_by=po`, one write). Minted P0 → `agent-father`, **same file as the umbrella, dispatch both in one hop**.
