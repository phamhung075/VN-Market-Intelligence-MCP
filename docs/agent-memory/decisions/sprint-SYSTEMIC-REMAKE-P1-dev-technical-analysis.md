**what-considered (trend-port-or-drop decision):**
- Investigated every candidate live caller of the TS `determineTrend`/scalar+trend shape repo-wide (mcp-server, frontend, alert-engine, packages/shared-types):
  1. `apps/technical-analysis/Dockerfile` copies only `cmd/ pkg/ api/` and builds `./cmd/server` — the TS `src/` tree is never started in the deployed image; `docker-compose.yml` only wires the Go binary.   2. `packages/shared-types/index.ts` has a byte-identical `{code,days}->...,trend` twin of the TS DTO, but grep confirms zero importers of its `ComputeTARequest`/`ComputeTAResponse` anywhere in the repo — a second orphaned copy of the same dead shape.
  3. `apps/mcp-server/src/infrastructure/microservices/clients.ts:134-186` (`computeTAIndicators`) calls the *Go* array-shape endpoint (`{symbol,closes}`) and maps it into a **separate, mcp-server-local** `ComputeTAResponse` type that happens to also carry a `trend` field — but that field is hardcoded `'NEUTRAL'` unconditionally (`// TA service does not return trend; default for now`), never derived from Wilder RSI/MACD/determineTrend semantics. The one downstream reader (`mapGoTrend()` in `technicalIndicatorTools.ts:408`) only feeds a cosmetic Vietnamese report line, not a decision/alert-scan path (`grep -rn '\.trend\b'` across every scheduler job returned zero hits on TA's `ComputeTAResponse`). This is a pre-existing, independent mcp-server gap, not a dependency on the TS `determineTrend` function or its 70/30 thresholds.
  4. `apps/frontend/app/lib/api/client.ts:307-322` (`fetchTASnapshot`) does construct a request shaped like the TS contract (`{code,date}` → `TASnapshot` with `movingAverages/bollingerBands/trend`) and is wired live from `dashboard.analysis.tsx` (`Promise.allSettled`, "TA non-fatal — null on failure"). But tracing the actual wire path: api-gateway registers `ta` with `PreservePath=true` (`apps/api-gateway/pkg/infrastructure/registry.go:35`), so `ResolveProxyPath` (`preservePath=true` branch) forwards the frontend's full `/ta/ta/indicators` request path **verbatim** to `http://technical-analysis:5003/ta/ta/indicators` — a route chi never registers (only `/ta/indicators`, singular `/ta`). Confirmed this is a pre-existing, orthogonal frontend URL-construction bug (double `/ta` segment), out of `apps/technical-analysis/` zone — not fixed here, only documented as a discovered signal.
  5. Cross-checked against the source audit itself: `docs/architecture-briefs/2026-06-15-maintainability-factory-audit.md:374` independently labels this "the determineTrend 70/30 hardcode finding (latent in dead code)" and states deleting `src/` (the sibling task `FACTORY-TECHANALYSIS-delete-orphaned-ts-service`, gated on this task) "auto-resolves" it — i.e. the audit's own authors already concluded no live dependency exists.
- Considered porting `determineTrend` into the Go module tier anyway (named `RSI_BULLISH_THRESHOLD=70`/`RSI_BEARISH_THRESHOLD=30` etc. constants) as a defensive/complete gesture. Rejected: DoD explicitly says port only "if trend is ported" conditional on finding a live caller; fabricating a Go trend endpoint nobody calls would violate the no-fake-data / no-speculative-feature standing policy and add an unused surface for the sibling deletion task to reconcile against.
