# Session Logs — Retention Policy

## preflight-lsof-*.log (HEAD.lock diagnostics)

**Retention:** Last 7 days
**Rotation:** Automated via cron / janitor sweep (cleanup-lsof-logs job)
**Purpose:** Diagnostic logs for git HEAD.lock contention on concurrent agent worktree operations

**Rotation trigger:**
- Manual: `docs/agent-memory/sessions/ | find . -name "preflight-lsof-*.log" -mtime +7 -delete`
- Scheduled: janitor agent, every 3 hours after scan cycle

**Rationale:**
- Each cycle may generate 1–3 logs (one per agent worktree)
- Logs are diagnostic only — not source of truth
- 7-day retention covers ~150–200 logs before disk overhead becomes meaningful
- Older logs rarely needed for root-cause analysis

**Added:** 2026-05-13 (Bucket C cleanup, CLEAN-c79-stale-artifacts)

## docs/agent-memory/sessions/*.md (session stubs, notes, WORK.md trims)

**Retention:** Last 14 days, then archived (not deleted) to `docs/agent-memory/sessions/archive/`
**Rotation:** `scripts/agents-flow/memory-prune-sweep.sh`, wired into code-janitor's sweep cadence
**Scope:** `*.md` only — `*.log` writers (preflight-lsof, cowork-guaranteed-slot-firer, fleet-push, fb-daily-firer, ...) and other non-`.md` artifacts in `sessions/` root are left untouched by this rule; `archive/` itself is excluded from re-sweeping.
**Rationale:** sessions/ only ever grows (test stubs, one-off notes, WORK.md 14-day trims land here) with no downstream pruner; agents-architect reads "last 3 days" so unbounded growth costs linear listing time forever.
