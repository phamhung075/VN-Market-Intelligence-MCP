### CRITICAL-1: post_agent_signal schema validation — ALL signals rejected

Root cause identified from code review (not a guess):

1. `cycle.md` flow instructs news-scout to post `type="news_impact"` and `type="crisis_velocity"`.
2. Neither type exists in `SignalTypeEnum` (`agentSignalTools.ts` line 42–51).
3. Zod rejects the call at the `signal_type` field level — before reaching `finding_data`.
4. The "root: Required" error in reports is Zod's collapse output when the discriminated union fails at root level.
5. Additionally: for valid types (`chain_catalyst`, `urgent_news`), the flow provides no `finding_data` field templates — the agent must guess required fields, leading to schema rejections.

Fix scope: `cycle.md` must map `news_impact` → `chain_catalyst` (or `urgent_news`) with explicit `finding_data` field templates matching `ChainCatalystFindingDataSchema` and `UrgentNewsFindingDataSchema`. No schema code change needed — the code is correct, the agent instruction is wrong.

Prior working signals #1714–1716 used a different code path (direct DB insert, not through the validator added in task 1293b).

Root pattern: the CB design assumes VPS is always reachable during market hours — it has no understanding that VPS itself can have intermittent periods where probe responses are non-2xx (not network failures, but application-level responses the CB counts as failures). Each fix adds more backoff but doesn't resolve the probe-failure feedback loop. Architect must review before any new code is written.
