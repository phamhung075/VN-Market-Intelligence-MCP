# TECH-1112: BCTC VPS Proxy — Route PDF Fetching Through Singapore VPS

status: APPROVED_BY_ARCHITECT
req_ref: (inline — no separate REQ doc; requirements captured in this design)

---

## Problem Statement

The MCP server runs in France. The Vietnamese Securities Commission portal
(`congbothongtin.ssc.gov.vn`) and exchange disclosure sites (`hsx.vn`,
`hnx.vn`, `upcom.hnx.vn`) are either geo-blocked or TLS-broken from France.
The current fallback in `ssc.ts` uses a permissive TLS agent
(`rejectUnauthorized: false`) and a non-browser User-Agent to obtain SSR HTML,
but the SSC portal now returns a JavaScript-only Oracle ADF shell regardless
of User-Agent — so `listSscDocuments` reliably returns zero results in
production. The OCR fallback path in `fetchParseAndStoreBctc.ts` never runs
because the upstream PDF URL is never resolved.

A Vultr VPS in Singapore (`139.180.185.18`) already bridges the geo-block for
VN stock prices using a proven push pattern. This design extends the same
pattern to BCTC PDF fetching.

## Architecture Decision

This design copies the push-pattern architecture that already works for stock
prices (VPS pulls config, VPS fetches remote data, VPS pushes results to MCP)
because it satisfies all geo-block and security invariants without any new
infrastructure complexity. The MCP server never initiates outbound calls to the
VPS at runtime; it remains a passive receiver. The only MCP-side changes are:
(1) a new queue endpoint that tells the VPS what to fetch, and (2) a new
receive endpoint that accepts raw PDF bytes and hands them to the existing
`fetchParseAndStoreBctc` pipeline via `pdfTextOverride` or the existing
`pdfUrl` bypass. A new `bctc_vps_queue` table provides deduplication so the
VPS cannot push the same ticker-period combination twice.

## Interface Contracts

### New SQLite table — `bctc_vps_queue`

```sql
CREATE TABLE IF NOT EXISTS bctc_vps_queue (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  action_code  TEXT    NOT NULL,
  period_year  INTEGER NOT NULL,
  period_quarter TEXT  NOT NULL,   -- 'Q1' | 'Q2' | 'Q3' | 'Q4'
  status       TEXT    NOT NULL DEFAULT 'pending',
                                   -- 'pending' | 'fetching' | 'done' | 'failed'
  source_url   TEXT,               -- filled by VPS on push
  attempts     INTEGER NOT NULL DEFAULT 0,
  last_attempt TEXT,               -- ISO-8601
  created_at   TEXT    NOT NULL DEFAULT (datetime('now')),
  UNIQUE(action_code, period_year, period_quarter)
);
CREATE INDEX IF NOT EXISTS idx_bvq_status ON bctc_vps_queue(status);
CREATE INDEX IF NOT EXISTS idx_bvq_code   ON bctc_vps_queue(action_code);
```

Queue population: the `GET /api/bctc-fetch-queue` handler populates this table
lazily on first call. It queries watchlist codes, computes which
(ticker, year, quarter) combinations are missing from `financial_reports`, and
inserts `status = 'pending'` rows for the gaps. This is the same
gap-detection logic already used by `bctcOverdueCheckJob.ts` — reuse
`getCurrentDeadline` / `classifyFilingStatus` from
`src/domain/services/earningsCalendar.ts`.

### `GET /api/bctc-fetch-queue` — MCP endpoint

**Auth**: `X-API-Key` header must equal `process.env.VPS_PUSH_API_KEY`.

**Response** `200 application/json`:

```jsonc
{
  "queue": [
    {
      "action_code": "VCB",
      "period_year": 2025,
      "period_quarter": "Q4",
      "source_hints": [
        "https://congbothongtin.ssc.gov.vn/faces/NewsSearch?...",
        "https://www.hsx.vn/Modules/Listed/Web/StockDisclosure?...",
        "https://hnx.vn/vi-VN/cong-bo-thong-tin.html"
      ]
    }
  ],
  "total": 1
}
```

`source_hints` are pre-built URL templates for each exchange, giving the VPS
a starting list to try in order. The VPS tries each and stops at first
successful PDF download. No hints are mandatory — the VPS may have its own
discovery logic.

Max items returned per call: 10 (to avoid oversized responses and to allow the
VPS to process a bounded batch per cycle).

### `POST /api/push-bctc-pdf` — MCP endpoint

**Auth**: `X-API-Key` header must equal `process.env.VPS_PUSH_API_KEY`.

**Content-Type**: `multipart/form-data` with the following fields:

| Field | Type | Required | Notes |
|-------|------|----------|-------|
| `action_code` | text | yes | Ticker e.g. `VCB` |
| `period_year` | text | yes | Four-digit year e.g. `2025` |
| `period_quarter` | text | yes | `Q1` \| `Q2` \| `Q3` \| `Q4` |
| `source_url` | text | yes | Original URL on SSC/HOSE/HNX/UPCOM |
| `pdf` | file | yes | Raw PDF binary; max 50 MB |

Rationale for multipart over base64 JSON: raw binary transfer is ~33% smaller
than base64 and curl supports `--form` natively in bash without jq encoding.
The `pdf` field carries the file bytes directly.

**Handler logic** (in `server.ts`, same file as the existing push-prices handler):

1. Validate auth — `401` if key mismatch.
2. Parse multipart body using the existing Node `node:http` `IncomingMessage`
   with a minimal multipart parser (no new npm dep required — use boundary
   splitting, same approach used internally by Bun's FormData). Limit read to
   52 MB (50 MB PDF + 2 MB overhead); return `413` if exceeded.
3. Write PDF bytes to `data/pdfs/<normalised_filename>` (call `normaliseFilename`
   from `fetchParseAndStoreBctc.ts` for filename normalisation; this function is
   already exported).
4. Mark queue row `status = 'fetching'`, increment `attempts`.
5. Fire-and-forget (same `setImmediate` pattern as post-push signal detection):
   call `fetchParseAndStoreBctc({ actionCode, year, quarter, pdfUrl: source_url })`
   — the `pdfUrl` bypass skips the SSC listing step and goes directly to PDF
   extraction from the already-written file path, then OCR fallback, then parse.
   On success, update queue row `status = 'done'`. On failure,
   `status = 'failed'`.
6. Return `200 { ok: true }` immediately (before the async pipeline finishes).

**On duplicate push** (same action_code + year + quarter already `done`):
return `200 { ok: true, skipped: true }` without re-running the pipeline.

**Response** `200 application/json`:
```jsonc
{ "ok": true, "queued": "VCB-2025-Q4" }
```

**Error responses**:

| Status | Condition |
|--------|-----------|
| 401 | Missing or wrong `X-API-Key` |
| 400 | Missing required fields |
| 413 | PDF > 52 MB |
| 500 | Server error writing file |

### VPS script — `vps-scripts/fetch-bctc.sh`

```bash
#!/bin/bash
# BCTC PDF Proxy — auto-deployed
# Pulls fetch queue from MCP, downloads PDFs from SSC/HOSE/HNX/UPCOM,
# pushes each to MCP.  Same auth pattern as fetch-prices.sh.

API_URL="__MCP_BASE__/api/push-bctc-pdf"
QUEUE_URL="__MCP_BASE__/api/bctc-fetch-queue"
API_KEY="__API_KEY__"
LOG="/var/log/vn-bctc-fetch.log"
MAX_PDF_BYTES=52428800   # 50 MB

# Log rotation
LOG_SIZE=$(stat -c%s "$LOG" 2>/dev/null || echo 0)
if [ "$LOG_SIZE" -gt 10485760 ]; then mv "$LOG" "$LOG.old"; fi

echo "$(date -u +%Y-%m-%dT%H:%M:%SZ) === BCTC START ===" >> "$LOG"

# Step 1: Pull queue
QUEUE=$(curl -s --connect-timeout 10 --max-time 15 \
  "$QUEUE_URL" \
  -H "X-API-Key: $API_KEY" \
  -H "User-Agent: VN-Market-VPS-Proxy/1.0")

if [ -z "$QUEUE" ]; then
  echo "$(date -u) FAIL: cannot reach MCP server" >> "$LOG"
  exit 1
fi

TOTAL=$(echo "$QUEUE" | jq '.total')
echo "$(date -u) Queue: $TOTAL items pending" >> "$LOG"

if [ "$TOTAL" = "0" ] || [ "$TOTAL" = "null" ]; then
  echo "$(date -u) Nothing to fetch — exit" >> "$LOG"
  exit 0
fi

# Step 2: Process each queue item
echo "$QUEUE" | jq -c '.queue[]' | while read -r ITEM; do
  CODE=$(echo "$ITEM"    | jq -r '.action_code')
  YEAR=$(echo "$ITEM"    | jq -r '.period_year')
  QTR=$(echo "$ITEM"     | jq -r '.period_quarter')
  HINTS=$(echo "$ITEM"   | jq -r '.source_hints[]' 2>/dev/null)

  TMP_PDF=$(mktemp /tmp/bctc_XXXXXX.pdf)
  FETCHED=0
  FETCH_URL=""

  # Try each hint URL in order
  for HINT_URL in $HINTS; do
    HTTP_CODE=$(curl -s -o "$TMP_PDF" -w "%{http_code}" \
      --connect-timeout 15 --max-time 120 \
      --max-filesize "$MAX_PDF_BYTES" \
      -L \
      -H "User-Agent: VN-Market-Intelligence/1.0" \
      "$HINT_URL")

    if [ "$HTTP_CODE" = "200" ]; then
      FSIZE=$(stat -c%s "$TMP_PDF" 2>/dev/null || echo 0)
      MIME=$(file --mime-type -b "$TMP_PDF" 2>/dev/null || echo "")
      if [ "$FSIZE" -gt 1024 ] && echo "$MIME" | grep -q "pdf"; then
        FETCHED=1
        FETCH_URL="$HINT_URL"
        echo "$(date -u) $CODE $YEAR-$QTR: downloaded ${FSIZE}B from $HINT_URL" >> "$LOG"
        break
      fi
    fi
    echo "$(date -u) $CODE $YEAR-$QTR: hint failed HTTP=$HTTP_CODE url=$HINT_URL" >> "$LOG"
  done

  if [ "$FETCHED" = "0" ]; then
    echo "$(date -u) $CODE $YEAR-$QTR: all hints exhausted — skip" >> "$LOG"
    rm -f "$TMP_PDF"
    continue
  fi

  # Step 3: Push PDF to MCP
  RESP=$(curl -s --connect-timeout 10 --max-time 30 \
    -X POST "$API_URL" \
    -H "X-API-Key: $API_KEY" \
    -H "User-Agent: VN-Market-VPS-Proxy/1.0" \
    -F "action_code=$CODE" \
    -F "period_year=$YEAR" \
    -F "period_quarter=$QTR" \
    -F "source_url=$FETCH_URL" \
    -F "pdf=@$TMP_PDF;type=application/pdf")

  echo "$(date -u) $CODE $YEAR-$QTR: push → $RESP" >> "$LOG"
  rm -f "$TMP_PDF"
done
```

### VPS loop driver — `vps-scripts/fetch-bctc-loop.sh`

```bash
#!/bin/bash
# BCTC PDF Proxy — forever loop for systemd
# Runs every 6 hours. No market-hours window — BCTC filings are published
# any time; a 6-hour polling cadence balances freshness vs. server load.

set -u

while true; do
  /root/fetch-bctc.sh
  sleep 21600   # 6 hours
done
```

### Systemd unit — `vps-scripts/vn-bctc-fetch.service`

```ini
[Unit]
Description=VN Market BCTC PDF proxy — push BCTC PDFs to zenmidi MCP
Documentation=https://github.com/phamhung075/VN-Market-Intelligence-MCP
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
ExecStart=/root/fetch-bctc.sh
# Run once, let systemd timer or cron replace the loop approach; alternatively
# use the fetch-bctc-loop.sh driver instead for continuous systemd management.
ExecStart=/root/fetch-bctc-loop.sh
Restart=always
RestartSec=10
StandardOutput=append:/var/log/vn-bctc-fetch.log
StandardError=append:/var/log/vn-bctc-fetch.log
MemoryMax=256M
TasksMax=32

[Install]
WantedBy=multi-user.target
```

Note: `MemoryMax=256M` (vs. 128M for prices) to accommodate large PDF
buffering on disk. PDF bytes are written to `/tmp` then uploaded; the process
itself never holds the full PDF in memory.

## Acceptance Criteria

1. **Auth guard** — `GET /api/bctc-fetch-queue` and `POST /api/push-bctc-pdf`
   return `401` when called without `X-API-Key` or with wrong key.

2. **Queue returns pending gaps** — after inserting a watchlist row (`VNM`)
   without a matching `financial_reports` row for the current quarter, calling
   `GET /api/bctc-fetch-queue` returns at least one item for `VNM` with
   correct `period_year` and `period_quarter`.

3. **Queue deduplicates** — once `financial_reports` contains a row for
   `VNM 2025-Q4`, calling the queue endpoint returns no entry for that
   combination.

4. **Push stores PDF and triggers pipeline** — sending a valid multipart POST
   with a synthetic 1-page PDF (the test `pdfTextOverride` shortcut covers
   this via unit test injection) results in:
   - PDF file written to `data/pdfs/VNM_2025_Q4.pdf` with correct bytes.
   - `bctc_vps_queue` row updated to `status = 'done'`.
   - `financial_reports` row inserted for `VNM 2025-Q4`.

5. **Duplicate push is idempotent** — pushing the same `action_code +
   period_year + period_quarter` a second time returns `200 { ok: true,
   skipped: true }` without inserting a duplicate `financial_reports` row.

6. **Oversized PDF rejected** — a POST with a 53 MB body returns `413`.

7. **VPS script smoke** — `fetch-bctc.sh` with a stubbed MCP server (mock
   `QUEUE_URL` returning a 1-item queue, mock `API_URL` recording the push)
   completes without error and produces a push call with the correct
   `action_code`, `period_year`, `period_quarter`, and a non-empty `pdf` field.

8. **No MCP-to-VPS call** — grep the entire `src/` tree confirms zero
   references to `139.180.185.18`, `sshpass`, or `VULTR_PASSWORD` in any
   TypeScript file.

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| SSC PDF URL structure changes (portal migrated to Oracle ADF PPR links) | High | High | `source_hints` are optional starting points; VPS script logs each failed attempt. When all hints fail, the queue item remains `pending` and is retried on the next 6-hour cycle. Operator can manually supply a direct URL by setting `source_url` directly in the `bctc_vps_queue` table. |
| PDF size exceeds 50 MB (rare, scanned annual reports) | Low | Medium | The 52 MB cap on the MCP push handler returns `413`. The VPS `curl --max-filesize` also prevents download. Operator can raise `MAX_PDF_BYTES` on VPS and the `52428800` limit in the handler independently. |
| Multipart parser adds complexity to `server.ts` (already 650 lines) | Medium | Low | Node's `IncomingMessage` exposes the raw boundary-delimited body. A 50-line helper function handles splitting. No new npm dep is needed. If parsing complexity grows, extract to `src/infrastructure/http/multipartParser.ts` in a follow-up. |
| VPS disk exhaustion from accumulated PDFs | Low | High | `fetch-bctc.sh` writes to `/tmp` (tmpfs), not to permanent disk. Permanent storage is on the MCP server under `data/pdfs/`. VPS temp files are deleted after each push regardless of success (`rm -f "$TMP_PDF"`). |
| Concurrent VPS pushes race on the same queue row | Low | Low | SQLite `UNIQUE(action_code, period_year, period_quarter)` on `bctc_vps_queue` prevents duplicate rows. `INSERT OR IGNORE` on the queue insert side; `UPDATE ... WHERE status = 'pending'` on the handler side provides soft exclusion. Full race safety is not required for a single-VPS setup. |
| `fetchParseAndStoreBctc` called with `pdfUrl` pointing to already-written local file | Medium | Low | The `pdfUrl` parameter routes through `downloadAndExtractPdf`, which calls `axios.get` on the URL. If the URL is the original SSC URL (which we pass), the VPS has already proven the URL is reachable. Alternatively, the handler can invoke `extractAndStorePdfPages` directly on the local file path (a refactor tracked as optional follow-up in 1112-C). |
| VN government sites serve HTML error pages with HTTP 200 | Medium | Medium | VPS script checks MIME type via `file --mime-type` on the downloaded bytes and validates `$FSIZE > 1024` before treating the download as successful. HTML error pages are small and non-PDF — both checks catch them. |

## Security Review

- [ ] SQL parameterized? Yes — all `bctc_vps_queue` reads and writes use
      parameterized `db.prepare` statements. The queue handler does not
      interpolate user input into SQL.
- [ ] File paths validated (no `../`)? Yes — `normaliseFilename` produces
      `{TICKER}_{YEAR}_{QTR}.pdf` (uppercase ticker + digits only). The
      handler must additionally strip any directory separators from
      `action_code`, `period_year`, and `period_quarter` before calling
      `normaliseFilename`. Validation: `action_code` must match
      `/^[A-Z0-9]{2,10}$/`; year must be a 4-digit integer 2000–2099;
      quarter must be one of `Q1|Q2|Q3|Q4`.
- [ ] External HTTP rate-limited? N/A — MCP server does not make outbound HTTP
      in this design. The VPS-side script uses sequential processing (one PDF
      at a time) with a 6-hour outer cycle, which is inherently rate-limited.
- [ ] Secrets via `Bun.env` only? Yes — `VPS_PUSH_API_KEY` is read via
      `process.env.VPS_PUSH_API_KEY` (same as the existing price-proxy auth
      handler). The VPS receives the key only at deploy time via
      `deploy-vps-proxy.sh` `sed` substitution into the script; it is not
      stored in the systemd unit file.
- [ ] PDF content not executed? Yes — the PDF bytes are written to disk and
      passed to `pdf-parse` / `pdfOcrWorker`. Neither evaluates PDF JavaScript.
      The permissive TLS agent (`rejectUnauthorized: false`) is already
      accepted for VN government sites; the VPS sidesteps this entirely by
      fetching from Singapore where the TLS chains validate correctly.
