## Problem Statement

The current signal pipeline has three specific weaknesses that degrade alert quality and conviction accuracy:

1. **Alert storms on correlated events.** When a Fed rate decision hits, the system fires 3 separate alerts for FPT, VCB, and VNM as if each were independent. They share the same causal root. No mechanism exists to group them.

2. **Shallow conviction math.** The chain synthesizer averages all signal scores. A one-time catalyst ("FPT wins a government contract") overrides a structural factor ("FPT P/E = 28x, above sector median") when it should not. Signal class is undifferentiated.

3. **Stale RAG context.** `search_similar_context()` returns FPT analysis from 6 months ago at VND 80k alongside current analysis at VND 140k, with no recency weighting. Old context pollutes current reasoning.

These are the real problems the "Deep Thinking Tree" concept was meant to solve. Each is a targeted schema change — not a full architecture rewrite.

---

## Business Goal

Each fix improves signal-to-noise ratio for the end investor. Fewer redundant alerts. More accurate conviction scores. Fresher analysis context. All three can be shipped independently as separate tasks.

## Fix A — Causal Root Tagging

### Motivation

One macro event causes multiple stock-level signals. Currently they fire as separate alerts. Grouping by causal root produces one consolidated alert: "Fed rate cut: positive for FPT (+bank exposure), VCB (cost of funds down), VNM (USD cost input)."

### Schema Change

```sql
ALTER TABLE agent_signals ADD COLUMN causal_root_id TEXT;
ALTER TABLE agent_signals ADD COLUMN causal_root_label TEXT;
CREATE INDEX IF NOT EXISTS idx_agent_signals_causal_root
  ON agent_signals(causal_root_id, created_at DESC);
```

`causal_root_id` format: `"{EVENT_TYPE}_{YYYY-MM-DD}"` e.g. `"FED_RATE_2026-04-10"`, `"OIL_SPIKE_2026-04-09"`.

`causal_root_label`: human-readable label e.g. "Fed rate cut 2026-04-10".

Both fields are NULL for stock-specific signals with no macro root.

### Behaviour Change

News Scout: when posting a `post_agent_signal()` call that originates from a macro/global event, includes `causal_root_id` and `causal_root_label` in payload.

Alert Commander: before firing MARKET alerts, groups pending signals by `causal_root_id`. Signals sharing a non-null `causal_root_id` fire as one consolidated message instead of N separate messages.

Consolidated message format:
```
[MACRO CATALYST] {causal_root_label}
- FPT: {signal_summary}
- VCB: {signal_summary}
- VNM: {signal_summary}
```

### Acceptance Criteria

| # | Scenario | Expected |
|---|----------|----------|
| AC-A1 | `post_agent_signal({..., payload: { causal_root_id: 'FED_2026-04-10', ... }})` | Row inserted, `causal_root_id` column populated |
| AC-A2 | 3 signals with same `causal_root_id` pending for Alert Commander | Alert Commander fires 1 MARKET message (not 3) |
| AC-A3 | 2 signals with `causal_root_id=NULL`, 2 with same causal root | 3 MARKET messages fired (2 individual + 1 consolidated) |

## Fix B — Signal Class Field

### Motivation

A single conviction score derived by averaging structural factors with one-time catalysts is misleading. A structural factor ("FPT P/E exceeds sector by 40%") should act as a ceiling on enthusiasm from one-time catalysts ("FPT wins a contract"). Signal class allows the chain synthesizer to apply appropriate weights.

### Schema Change

```sql
ALTER TABLE agent_signals ADD COLUMN signal_class TEXT
  CHECK(signal_class IN ('structural_factor','one_time_catalyst','cyclical','sentiment','technical_signal') OR signal_class IS NULL);
```

NULL = unclassified (treated as weight 1.0).

### Weight Map (locked in this REQ — Architect may adjust multipliers in TECH doc)

| Class | Weight Multiplier |
|-------|------------------|
| `structural_factor` | 1.5 |
| `cyclical` | 1.0 |
| `one_time_catalyst` | 0.7 |
| `sentiment` | 0.5 |
| `technical_signal` | 0.8 |
| NULL / unclassified | 1.0 |

### Behaviour Change

News Scout: tags each posted signal with the appropriate `signal_class` when `post_agent_signal()` is called.

Chain synthesizer (wherever conviction score is computed from agent_signals): applies weight multiplier before averaging. Weighted average replaces simple average.

### Acceptance Criteria

| # | Scenario | Expected |
|---|----------|----------|
| AC-B1 | `post_agent_signal({..., signal_class:'structural_factor'})` | Row inserted, `signal_class='structural_factor'` |
| AC-B2 | 2 signals: structural_factor score=0.6, one_time_catalyst score=0.9 | Weighted avg = (0.6*1.5 + 0.9*0.7)/(1.5+0.7) = 1.53/2.2 = 0.695 (not 0.75) |
| AC-B3 | All signals NULL signal_class | Conviction score equals simple average (no regression) |

## Fix C — RAG Recency Weight

### Motivation

`search_similar_context()` returns results by cosine similarity alone. A high-similarity result from 6 months ago at a different price level is less useful than a lower-similarity result from last week. Recency should discount old results.

### Behaviour Change

`search_similar_context(query, limit?, recency_days?)` adds an optional `recency_days` parameter (default: 90).

Results older than `recency_days` have their similarity score multiplied by a recency decay factor:

```
recency_weight = max(0.1, 1.0 - (age_days / recency_days) * 0.9)
```

Final ranking score = `cosine_similarity * recency_weight`.

Results are re-ranked by final score before the `limit` is applied.

The existing `search_similar_context` call signature is backward-compatible (new parameter is optional with default=90).

### Acceptance Criteria

| # | Scenario | Expected |
|---|----------|----------|
| AC-C1 | Two results: A (similarity=0.9, age=200d, recency_days=90), B (similarity=0.7, age=5d, recency_days=90) | B ranks above A after recency weighting |
| AC-C2 | `search_similar_context(query)` called without recency_days | Behaves identically to recency_days=90 (default) |
| AC-C3 | `search_similar_context(query, 5, 30)` | Returns at most 5 results, recency window is 30 days |
| AC-C4 | All results are age=0 | recency_weight=1.0 for all, ranking unchanged from cosine-only |
