## Functional Requirements

### FR-1: Restore SSC path testability for test 1025 cases 7 and 8

- **Description:** `listSscDocuments()` reads `mcpConfig.features.disableSscPolling` at its entry point. In production this flag defaults to `true`, causing the function to always bypass SSC and route to HOSE/HNX. Test 1025 cases 7 and 8 call `listSscDocuments()` directly — they receive the production-default path (`disableSscPolling=true`) regardless of the mock HTTP responses, so the assertions about SSC-vs-HOSE routing never exercise the SSC code path.
- **Input:** Test cases 7 and 8 in `src/__tests__/1025-ssc-adf-pdf-discovery.test.ts`
- **Output:** Both cases exercise the correct path (SSC-first) via `listSscDocumentsWithFlag(..., false, mockClient)`.
- **Business rule:** `listSscDocuments()` production behavior (defaulting to `disableSscPolling=true`) must NOT change. The fix is test-side only. `listSscDocumentsWithFlag` is already exported from `ssc.ts` as the testable entry point.
- **DDD layer:** infrastructure (test fix only — `src/__tests__/1025-ssc-adf-pdf-discovery.test.ts`)

| Case | Current call | Fixed call | Expected assertion |
|------|-------------|------------|-------------------|
| 7 — SSC JS shell triggers HOSE fallback | `listSscDocuments("VCB", "quarterly", 2025, mockClient)` | `listSscDocumentsWithFlag("VCB", "quarterly", 2025, false, mockClient)` | `sscFetched === true`, no error thrown; `hoseFetched` behavior driven by JS-shell detection logic |
| 8 — SSC full HTML skips HOSE fallback | `listSscDocuments("VCB", "quarterly", 2025, mockClient)` | `listSscDocumentsWithFlag("VCB", "quarterly", 2025, false, mockClient)` | `hoseFetched === false`, `docs.length >= 1`, `docs[0].title` contains "quý" |

**Import change required:** Case 7 and 8 must import `listSscDocumentsWithFlag` from `../../infrastructure/fetchers/ssc.js` (already exported). No new exports needed.

### FR-2: Make `direction` and `expected_move_pct` optional in `create_prediction_claim` schema

- **Description:** The `create_prediction_claim` MCP tool in `src/interface/mcp/tools/evidenceTools.ts` added `direction` (enum: bullish/bearish) and `expected_move_pct` (number 0.001–0.5) as required fields after test 1124 was written. Test 1124 has 5 cases that omit both fields. The zod schema now rejects these calls with `-32602 Input validation error`.
- **Input:** MCP tool call to `create_prediction_claim` without `direction` or `expected_move_pct` fields.
- **Output:** Tool call is accepted; claim is inserted with `direction = null` and `target_price = null`.
- **Business rule:**
  - `direction`: change from `z.enum(["bullish", "bearish"])` to `z.enum(["bullish", "bearish"]).optional()`
  - `expected_move_pct`: change from `z.number().min(0.001).max(0.5)` to `z.number().min(0.001).max(0.5).optional()`
  - Handler step 3 (target_price computation): when `direction` or `expected_move_pct` is `undefined`, set `targetPrice = null` (skip the multiplication). `PredictionClaimInput.target_price` already accepts `null`.
  - Handler step 7 (confirmation text): when `direction` is `undefined`, omit or replace with `"(not specified)"`. When `expected_move_pct` is `undefined`, omit the "Expected move" line or replace with `"(not specified)"`. Do NOT call `.toFixed()` on undefined.
  - `PredictionClaimInput.direction` is typed as `ClaimDirection = "bullish" | "bearish" | "neutral"` — passing `undefined` must be coerced to `null` at the `insertPredictionClaim` call site (SQLite column accepts NULL via `params.direction ?? null`).
- **DDD layer:** interface (`src/interface/mcp/tools/evidenceTools.ts`)

**Schema diff (zod):**

| Field | Before | After |
|-------|--------|-------|
| `direction` | `z.enum(["bullish", "bearish"])` | `z.enum(["bullish", "bearish"]).optional()` |
| `expected_move_pct` | `z.number().min(0.001).max(0.5)` | `z.number().min(0.001).max(0.5).optional()` |

**Handler logic diff:**

| Step | Before | After |
|------|--------|-------|
| Step 3: targetPrice | `direction === "bullish" ? round(price * (1 + pct)) : round(price * (1 - pct))` | `direction && expected_move_pct != null ? (direction === "bullish" ? round(price * (1 + expected_move_pct)) : round(price * (1 - expected_move_pct))) : null` |
| Step 5: insertPredictionClaim direction arg | `direction` (ClaimDirection) | `(direction as ClaimDirection | undefined) ?? null` — cast to pass null when absent |
| Step 7: confirmation text direction line | `Direction: ${direction}` | `direction ? \`Direction: ${direction}\n\` : ""` |
| Step 7: confirmation text move line | `Expected move: ${(expected_move_pct * 100).toFixed(1)}%` | `expected_move_pct != null ? \`Expected move: ${(expected_move_pct * 100).toFixed(1)}%\n\` : ""` |

## Edge Cases & Data Quality

- [ ] `direction = undefined`, `expected_move_pct = undefined` — `targetPrice` must be `null`; `insertPredictionClaim` must write `NULL` to DB column, not `NaN` or `0`.
- [ ] `direction = "bullish"`, `expected_move_pct = undefined` — `targetPrice` must be `null` (both fields required together to compute a price); do not attempt partial computation.
- [ ] `direction = undefined`, `expected_move_pct = 0.05` — same as above: `targetPrice = null`.
- [ ] Confirmation text must not throw on `undefined.toFixed()` — guard both optional fields before formatting.
- [ ] `PredictionClaimInput.direction` is typed `ClaimDirection` (non-nullable). The `insertPredictionClaim` call must not pass TypeScript `undefined` — coerce to `null` at the call site and cast as needed, or widen the type. Prefer the cast/null approach to avoid touching the store interface (which has downstream callers in tests 1123, 1154).
- [ ] Test 1025 case 7: after the fix, `sscFetched` is asserted `true` in the current test body. Confirm `listSscDocumentsWithFlag(..., false, ...)` does hit the SSC URL path (it does: `disableSscPolling=false` triggers `_runSscPath`). The `hoseFetched` assertion in case 7 is currently loose (`toBeGreaterThanOrEqual(0)` on docs) — preserve this; do not tighten it.

### Task 1296 — evidenceTools.ts schema fix

The `insertPredictionClaim` store function accepts `direction: ClaimDirection` (non-optional in the interface). To avoid touching the store type, use a cast at the call site:

```typescript
direction: (direction ?? null) as ClaimDirection,
target_price: targetPrice,   // already null when direction/pct absent
```

SQLite will write NULL for both columns. The `prediction_claims` table schema allows NULL on `direction` and `target_price` (confirmed: `target_price?: number | null` in `PredictionClaimInput`).
