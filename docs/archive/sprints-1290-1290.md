### Context

Sprint 1288 delivered fallback logic (primary→cache→SSE→none) for when VPS is down. The VPS endpoint has been unreachable since 2026-04-22 07:36:55. Sprint 1290 activated the fallback by creating a new scheduler job that:
- Fetches foreign flow data every 60 seconds
- Hits fallback on timeout/error
- Uses cache or SSE to keep data flowing when primary is down
- Logs fallback activation and circuit breaker state for observability

**Result:** Outages now mitigated automatically. Alert Commander can analyze with staleness warnings until primary recovers.

### Test Summary

**Assertions:** 8 (all passing with `--timeout 30000`)

1. Primary endpoint success → returns {source:primary, changes, timestamp}
2. Primary timeout (>5s) → cache fallback with metadata
3. Circuit breaker open → skips primary, uses cache
4. All fallbacks exhausted → returns empty result with warning
5. Cache >2h old → includes staleness warning
6. Circuit breaker recovery → closes on primary success
7. Result contract → always includes {source, changes, timestamp, warning?}
8. Error logging → contextual logging (error, source, cbState, timestamp)

### Key Decisions

1. **Timestamp formatting**: Strips `.000Z` when milliseconds are zero for consistent ISO 8601 format
2. **Database initialization**: Tests require `initDatabase()` + `closeDb()` for schema setup on :memory: database
3. **Circuit breaker state**: Made `cbState` required field in result for observability
4. **Fallback detection**: Implemented as `fallbackActivated: (source !== 'primary')`

### Deployment

- No database schema changes (uses existing `daily_ohlcv` table)
- No new environment variables required (optional: `CRON_FOREIGN_FLOW_FETCH` to override schedule)
- VPS service independence: Job fetches every 60s; VPS also pushes on schedule. Both write to same table—dedup by (code, date) automatic
- Circuit breaker shared: Uses same `breakers.foreignFlow` as VPS push endpoint for consistent state
