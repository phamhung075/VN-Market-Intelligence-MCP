## Sprint 1289 — Foreign Flow Parse Errors Root-Cause Fix (M-size, COMPLETE)

**Status:** COMPLETE | **Merged:** 2026-04-22 | **Baseline:** 6275 → 6297 | **Tests:** 4 tasks, 31 tests, 119 assertions

| Task | Title | Status |
|------|-------|--------|
| 1289a | (Design phase — Architect root-cause analysis) | Done |
| 1289b | RED: Validation error handling tests | Done |
| 1289c | GREEN: Fetcher validator integration (replace silent filter) | Done |
| 1289d | GREEN: POST endpoint validator integration (reject HTTP 400) | Done |
| 1289e | QA: Parse errors <5/day verification | Done |

**Root Cause:** `isValidForeignFlowItem()` in `foreignFlowFetcher.ts` line 267 used silent `.filter()` to discard invalid items without logging. When VPS sent 30 items with 3 schema violations: filter dropped 3 invalid items silently, returned 27 valid items with `changes: 27` (success), caller saw "success" and never learned 3 rows were missing. Missing 3 rows accumulated over days (10 days = ~30 missing rows). Prior fixes (Sprint 228 + Sprint 1288) did not address this path.

**Solution:** Unified validators across entry points (POST endpoint + fallback fetcher). Replaced silent `.filter()` with explicit `validateForeignFlowFetcherPayload()` that returns `{ valid: [], errors: [] }`. If errors.length > 0, logs diagnostics (itemIndex, field, reason, originalValue) and fails loudly instead of silently filtering.

**Impact:** Parse error count drops from 784/24h to <5/day. Validation errors logged with full diagnostics for VPS ops team debugging. HTTP 400 on all-invalid payloads (breaking change, acceptable per TECH-1289 pre-deploy audit).
