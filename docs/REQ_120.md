# REQ-120: predictionDiag Block + Medium-Severity Fallback in Evening Summary

status: READY_FOR_ARCHITECT
sprint: 120
po_vision: Fix predictionSignals always empty — add medium-severity fallback + predictionDiag observability block

## User Story

As a Vietnamese stock investor using Claude,
I want the evening report to show at least medium-severity prediction market signals when no high/critical signals exist,
So that I always receive some crowd-sourced risk context at market close, not a silent empty array.

## Functional Requirements

### FR-1: Medium-Severity Fallback in assembleEveningSummary Step 5

- Description: When the high/critical filter yields zero results, include up to 3 medium-severity signals from the last 24h as a fallback. Low-severity signals are never promoted. The fallback is purely additive — it never suppresses high/critical signals.
- Input: `allSignals: BriefingPredictionSignal[]` — full result of `getRecentPredictionSignals(db, 24)`, unfiltered
- Output: `predictionSignals: BriefingPredictionSignal[]` — high+critical if any; else up to 3 medium; else []
- Business rule:
  1. Filter `allSignals` to `highCritical` where `severity === "high" || severity === "critical"`
  2. If `highCritical.length > 0` → `predictionSignals = highCritical` (no change from current behaviour)
  3. Else filter `allSignals` to `medium` where `severity === "medium"` → `predictionSignals = medium.slice(0, 3)`
  4. If neither → `predictionSignals = []`
- DDD layer: application (`src/application/usecases/assembleEveningSummary.ts`, Step 5)

### FR-2: predictionDiag Diagnostic Block in EveningSummary

- Description: Add a `predictionDiag` field to `EveningSummary` carrying observability counts. This block is written to the evening JSON file only; it is NOT included in the Telegram message formatter.
- Input: counts derived from DB queries already performed in Step 5
- Output: `predictionDiag: { stored: number }` where `stored` = total rows in `prediction_signals` with `detected_at >= since24h` (any severity, before any filter)
- Business rule:
  - `stored` counts all prediction_signals rows in last 24h regardless of severity — this is the unfiltered `allSignals.length` value already in memory, so zero extra DB queries required
  - Field is always present (never undefined); value is 0 when table is empty or Step 5 throws
- DDD layer: application (`src/application/usecases/assembleEveningSummary.ts`) + type definition in same file

### FR-3: AssembleEveningSummaryOptions — getPredictionSignalsFn Injection

- Description: Add an injectable `getPredictionSignalsFn` to `AssembleEveningSummaryOptions` so tests can override the prediction store call without `mock.module`.
- Input: `(db: Database, hoursBack: number) => BriefingPredictionSignal[]`
- Output: used in Step 5 replacing the dynamic `import(predictionStore.js)` call
- Business rule: optional field; production default is `getRecentPredictionSignals` from `predictionStore.js` loaded via existing dynamic import
- DDD layer: application (options interface in `assembleEveningSummary.ts`)

## Non-Functional Requirements

- Performance: `stored` count uses `allSignals.length` (already in memory) — zero extra DB queries
- Data freshness: same 24h window as existing predictionSignals query
- Language: field names English; no Telegram message changes
- TypeScript: `bun tsc --noEmit` must pass after changes

## Edge Cases & Data Quality

- [ ] `prediction_signals` table does not exist → `getRecentPredictionSignals` returns [] gracefully; `predictionDiag.stored = 0`; `predictionSignals = []`
- [ ] Only low-severity signals exist → `predictionSignals = []`; `predictionDiag.stored = N` (observability preserved)
- [ ] Mix of medium + high signals → high/critical wins; medium fallback NOT used; `predictionDiag.stored = total count`
- [ ] Exactly 4 medium signals, no high/critical → only first 3 returned (slice(0, 3))
- [ ] `getRecentPredictionSignals` throws → catch block sets `predictionSignals = []`, `predictionDiag = { stored: 0 }`, logger.warn fires

## Acceptance Criteria

### AC-1: High/critical signals pass through unchanged

**Given** the DB has 2 signals with severity "high" and "critical" detected in last 24h
**When** `assembleEveningSummary` runs
**Then**
- `predictionSignals` contains both signals
- No medium signals appear even if medium signals also exist

### AC-2: Medium fallback fires when no high/critical exist

**Given** the DB has 4 signals with severity "medium" and 0 with high/critical in last 24h
**When** `assembleEveningSummary` runs
**Then**
- `predictionSignals.length === 3` (capped at 3)
- All returned signals have `severity === "medium"`

### AC-3: Empty result when only low-severity signals exist

**Given** the DB has signals with severity "low" only
**When** `assembleEveningSummary` runs
**Then**
- `predictionSignals` is `[]`
- `predictionDiag.stored` equals the number of low signals (>0 — observability shows data exists)

### AC-4: predictionDiag.stored reflects actual DB count

**Given** the DB has 5 signals of mixed severity detected in last 24h
**When** `assembleEveningSummary` runs
**Then**
- `predictionDiag.stored === 5`
- The value matches `allSignals.length` before any severity filter

### AC-5: Error resilience — getPredictionSignalsFn throws

**Given** `getPredictionSignalsFn` is injected and throws an error
**When** `assembleEveningSummary` runs
**Then**
- Function does not throw
- `predictionSignals === []`
- `predictionDiag.stored === 0`
- `logger.warn` called with message containing "prediction"

### Step 5 Logic (pseudocode)

```
allSignals = getPredictionSignalsFn(db, 24)   // injected or default
stored = allSignals.length

highCritical = allSignals.filter(s => s.severity === "high" || s.severity === "critical")
if highCritical.length > 0:
  predictionSignals = highCritical
else:
  medium = allSignals.filter(s => s.severity === "medium")
  predictionSignals = medium.slice(0, 3)

predictionDiag = { stored }
```
