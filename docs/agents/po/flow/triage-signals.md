# PO — Step 0-SIG: Triage pendingSignals[]

**Parent flow:** `docs/agents/po/flow/main.md` (Step 0-SIG dispatcher — MANDATORY when dev-team passes signals)

The dev-team Step 0a drain hands `pendingSignals[]` to PO. Each signal has shape `{from, to, type, payload, priority, createdAt}` where `payload` is usually a file path. PO must read each payload and route accordingly — otherwise the signal is silently lost.

For each signal in `pendingSignals[]`:

| Signal `type` | From | Action | Routing in Step 1 BATCH |
|---|---|---|---|
| `audit-handoff` | `tran-ngoc-bau` | Already covered by Step 0-TNB (reads `docs/handoffs/tnb-audit-latest.md`) | findings → FIX / SPRINT-* |
| `brief_complete` | `agents-architect` | Read `payload` (a `docs/architecture-briefs/*.md`). Brief specifies which files/agents change. | If brief targets `.claude/agents/*` or `docs/agents/*` → UNBLOCK with `route_to: agent-father`. If brief targets `apps/flow/*` code → SPRINT-S/M/L depending on scope. Propagate target zone (e.g. `apps/stock-price/`) into the sprint so architect inherits zone hint. |
| `news_impact` / `price_anomaly` / `bctc_signal` / `fundamental_*` | cowork agents | Cowork signals are usually for `alert-commander`, not PO. If `to=po` was set explicitly, read payload and decide: investment-thesis update (skip — not dev work) or data-pipeline bug (FIX task with `zone: apps/<service>/`). | rarely actionable; default skip with notebook log |
| `zone_missing_tier3` | `dev-team` | Open a CHORE task pre-tagged `zone: <suggestedZone>` (BATCH type CLEAN). **Before inserting:** check `docs/data/orch/orch-state.json` `.task_board` for an existing open entry with `taskId` in title or task_id (dedup on `taskId` field — same guard used in drain-signals). If duplicate found → skip, log `"[po] zone_missing_tier3: task {taskId} — duplicate, skipped"`. If new: append to `.task_board.backlog[]` — canonical shape per `docs/standards/task-schema.md`: `{id: "fix-zone-{taskId}", title: "Fix missing zone on task {taskId} ({suggestedZone})", owner: "po", status: "TODO", zone: "{suggestedZone}", created_at: "<ISO-8601 UTC now>"}`, mark signal processed. If `payload.suggestedZone` absent → emit SPIKE to architect for zone inference. Log `"[po] zone_missing_tier3: task {taskId} — CHORE created zone:{suggestedZone}"`. | CHORE/CLEAN with `zone: {suggestedZone}` OR SPIKE to architect |
| `zone_health_report` | `dev-<service>` | Read `payload.findings[]` and `payload.severity`. If `severity=critical` → open FIX task with `zone: {payload.zone}`. If `severity=warn` → add to `pendingObservations[]` for sprint planning. If `severity=ok` → log and skip. Batch all zone_health_report signals from the same week into one sprint review entry. | FIX (critical) OR pendingObservations (warn) OR skip (ok) |
| `implementation_complete` | `agent-father` | Acknowledgment that a brief track shipped. Log `"[po] track {payload.track} of {payload.brief} acknowledged — {N} files changed"`. No task creation. Append to notebook `pendingObservations[]` if `payload.summary` flags a follow-up (e.g. "needs verification"). Signal moved to processed/ by dev-team — no further action. | skip (acknowledgment-only) |
| `improvement_proposal` | `agents-architect` | Read the proposal doc at `payload` path. **MANDATORY PO critique — ALL FIVE fields must be filled before writing a verdict. An empty or placeholder value on any field auto-rejects with reason "critique incomplete".** Write the following into the `## PO Critique` section of the proposal doc: **(1) What could break:** answer required — which live agent/flow/cron is disrupted. **(2) False-green / silent-swallow risk:** answer required — can the Success Signal return green while the weakness persists. **(3) Is the success signal gameable:** answer required — can the proposed verification be manipulated by the fix itself. **(4) Host-load impact:** answer required — RAM/disk/tick estimate; reference Docker 8GB cap + `project_host_memory_panic`. **(5) Lane-C-in-disguise check (C-3):** answer required — explicitly judge whether this proposal, regardless of its labeled lane, actually edits the gate/audit logic, the loop's own success criteria, an irreversible action, or user-facing comprehensibility. If yes on any sub-criterion → auto-reject, reclassify to LANE-C. Cannot be empty or "N/A". Then write verdict + date + rationale. **SHADOW-PILOT BRANCH (brief 2026-06-01-agent-self-critique-detect-source.md §8 — REMOVE at Phase-2 promote decision):** Check the proposal doc's `Created by:` field. IF `Created by` value is an agent-id ∈ {news-scout, dev-team} → this is a shadow-pilot proposal: perform the FULL five-field MANDATORY critique and write verdict into `## PO Critique` AS NORMAL (required to measure "what fraction would have been approved" per §8 promote criteria). Do NOT emit the LANE-A agent-father dispatch signal. Do NOT create the LANE-B SPRINT batch entry. NO dispatch of any kind. Instead append one line to the proposal doc: `[SHADOW] would-have: <APPROVED-LANE-A | APPROVED-LANE-B | REJECTED | LANE-C> — <reason>`. Then `send_telegram(channel="work", message="[shadow-pilot] {id} verdict logged (no dispatch): {would-have}")`. Commit: `git add docs/improvement-proposals/{id}.md docs/agent-memory/notebooks/po.md` (commit-mutex, explicit paths). EXIT this row — do not fall through to routing-by-outcome. ELSE (Created by = agents-architect or any non-pilot author) → fall through to routing-by-outcome unchanged. Routing by outcome: LANE-A + APPROVED → emit signal `type=improvement_approved_md` to agent-father with `payload=proposal-path`; LANE-B + APPROVED → create SPRINT-S or SPRINT-M batch entry for dev-team with signal `type=improvement_proposal_lane_b`; LANE-C or any REJECTED → `send_telegram(channel="work", message="[loop] Lane-C or rejected: {id} — {reason}")`. Commit: `git add docs/improvement-proposals/{id}.md docs/agent-memory/notebooks/po.md` (commit-mutex, explicit paths). | SHADOW-PILOT (Created by ∈ {news-scout, dev-team}): critique+verdict written, no dispatch, shadow-log line + WORK Telegram. ELSE APPROVED→ agent-father signal (lane-a) or BATCH entry (lane-b); REJECTED/C → WORK Telegram |
| `repair_task_request` | `system-auditor` | Read signal JSON at `payload` path. Extract `check_id`, `anomaly_type`, `severity_class`, `zone_owner`, `summary`, `suggested_sprint_class`. **Dedup check:** scan `docs/data/orch/orch-state.json` `.task_board` for any open entry (status ∈ TODO/IN_PROGRESS/REVIEW/BLOCKED) whose title or id contains `check_id`. If found → log `"[po] repair_task_request: {check_id} — duplicate task_board entry, skipped"`, mark signal DONE, skip. If no duplicate: append to `.task_board.backlog[]` — canonical shape per `docs/standards/task-schema.md`: `{id: "{check_id}-FIX", title: "{check_id}-FIX ({zone_owner}) — {summary ≤80 chars}", owner: "po", status: "TODO", zone: "{zone_owner}", created_at: "<ISO-8601 UTC now>", status_note: "AC: {check_id} check passes Tier-N (no signal_queue row, no BUG alert 7d). Priority: {severity_class}."}`. Commit orch-state.json update (commit-mutex, atomic write, path `docs/data/orch/orch-state.json`). Log `"[po] repair_task_request: created BACKLOG task {check_id}-FIX zone:{zone_owner}"`. | `.task_board.backlog[]` entry — normal po→ba→pm→dev chain applies |
| any unknown `type` | any | Log `"[po] Unknown signal type {type} from {from} — payload retained"` and skip. Notify WORK so the type can be added to this table. | skip; signal already moved to processed/ by dev-team |

ACK each processed signal by writing the result into your notebook entry (no file ACK — the signal is already in `signals_processed` DB).

If `pendingSignals[]` is empty, log `"[po] No pending signals"` and proceed to Step 0 Channel Audit.
