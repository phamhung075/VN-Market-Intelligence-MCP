# Task Size Rules

**Owned by:** PO / architect
**Read by:** PO (sprint planning), PM (task scoping), BA (spec sizing)
**Source:** extracted from `docs/agents/po/flow/main.md` L26 (c83 — task 1888-CDG-G)

---

## Size Definitions

| Size | Line budget | File budget | Domain scope | Typical type |
|------|-------------|-------------|--------------|--------------|
| FIX | ≤ 10 lines | ≤ 3 files | single | bug fix, config patch, doc update |
| SPRINT-S | ≤ 30 lines | ≤ 5 files | 1 domain | small feature, refactor, SSOT fix |
| SPRINT-M | > 30 lines or > 5 files | — | multi-domain | cross-service feature, schema change |
| SPRINT-L | large scope | — | arch/new service | new microservice, major refactor, migration |

Priority order when classifying: recurring bugs → UNBLOCK → FIX → CLEAN → SPRINT-S → SPRINT-M/L

---

## Escalation Rules

- **FIX → SPRINT-S:** any fix that touches > 3 files OR > 10 lines must be reclassified as SPRINT-S. PO reclassifies before emitting BATCH.
- **SPRINT-S → SPRINT-M:** if implementation crosses domain boundaries (e.g. mcp-server + alert-engine both modified), reclassify. Architect must assign `zone: multi` and split into sub-tasks.
- **SPRINT-M → SPRINT-L:** if architect requires a new service, new DB schema, or structural refactor affecting ≥ 3 services — reclassify. BA spec required before architect handoff.
- **SPRINT-L:** always goes through full BA → architect → PM planning chain (Step 2, SPRINT-L row in dev-team planning matrix). Post-merge architect review mandatory.

---

## Line-Budget Guidelines

- Line budget = net diff lines changed (additions + deletions), not file size.
- Comments and blank lines count toward the budget.
- Generated files (migrations, fixtures) excluded from budget if generated by a single command.
- Doc-only tasks: line budget applies to `.md` / `.json` changes only (no source code budget).

---

## When to Use SPIKE Instead

Use `SPIKE` (not FIX/SPRINT) when:
- The scope is unclear and exploration is needed before committing to an implementation
- Time-box default: 120 min
- Output: a findings doc only (no code shipped)
- After SPIKE completes, PO re-sizes the follow-up task using the findings
