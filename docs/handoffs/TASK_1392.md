## Root Cause

`fetchForeignFlowWithFallback` (in `foreignFlowFetcher.ts`) wrapped
`fetchPrimaryVpsEndpoint` in `breakers.foreignFlow.execute()`. This caused
every half-open probe to fail:

1. The VPS is **push-only** — `vps-proxy-server.js` has no `/foreign-flow`
   GET route (only `/proxy/ssc-iboard`, `/proxy/bctc-discover`, `/bctc-files`).
2. Every probe hits 404 → throws `Error("VPS returned 404")` → `_onFailure()`
   is called inside `execute()` → CB re-opens immediately from half-open.
3. The 5-minute reset restarts (`_openedAt = new Date()`), so the circuit
   never closes. "11 consecutive failures" = 5 initial + 6 probe failures over
   ~30 min of log observations.

Sprint 1388 (`halfOpenMaxAttempts:1`) was correct in intent — one successful
probe should close the CB. But the probe was **structurally broken** because
the GET endpoint does not exist on the VPS.

---

## Fix

**File changed**: `apps/mcp-server/src/infrastructure/fetchers/foreignFlowFetcher.ts`

Remove `breakers.foreignFlow.execute()` from the GET fetcher path. The
`foreignFlow` CB guards DB writes in the **push handler** only
(`POST /api/push-foreign-flow` in `server.ts`). The GET fetcher attempts
the primary endpoint directly and falls through to cache/SSE/none on failure —
no CB interaction.

Lines removed: ~18 (the `execute()` wrapper, CB state guard, and CB-open log block).

**Test updated**: `1288-foreign-flow-fallback.test.ts` — test 4 "skips primary
when circuit is open" was updated to assert the new contract: GET path always
attempts primary, CB state does not block it.

**New test**: `1392-foreign-flow-cb-probe-regression.test.ts` — 4 tests
confirming CB is not incremented by GET-path failures.
