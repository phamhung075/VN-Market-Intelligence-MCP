# TASK 1790 — Fix: alertDigestJob dedup guard skipped when db not injected

## Status: DONE — awaiting QA

## Root Cause

In `apps/mcp-server/src/scheduler/alerts/alertDigestJob.ts` line 83 (before fix):

```typescript
if (db && alreadySentToday(db)) {   // BUG: when db=undefined, short-circuits to false
```

When `db` is `undefined` (or falsy), the entire `&&` expression evaluates to `false` and the
guard is skipped entirely — `alreadySentToday()` is never called. The digest fires unconditionally.

The production call path in `startScheduler.ts` line 150 passes `getDb()`, but this means
two separate `getDb()` calls exist (one for `recordJobRun`, one passed into `runAlertDigest`).
If either call races during startup before the DB is initialized, db can be undefined and
the guard is bypassed.

No duplicate cron registrations were found — `alertDigest` is scheduled exactly once in
`startScheduler.ts` with no startup catch-up variant.

## Fix

**File changed:** `apps/mcp-server/src/scheduler/alerts/alertDigestJob.ts`

1. Added import: `import { getDb } from "../../infrastructure/db/schema.js"`
2. Replaced the conditional guard pattern:
   ```typescript
   // BEFORE (buggy)
   if (db && alreadySentToday(db)) { ... }

   // AFTER (fixed)
   const effectiveDb = db ?? getDb();
   if (alreadySentToday(effectiveDb)) { ... }
   ```

The guard now always runs. Injected `db` (tests / callers with an existing handle) takes
priority via `??`. When no db is passed, `getDb()` provides the production instance.

## DDD Compliance

`alertDigestJob.ts` is in `interface/scheduler` — importing from `infrastructure/db/schema.js`
is permitted per dev-standards.md (interface → infrastructure is allowed).
