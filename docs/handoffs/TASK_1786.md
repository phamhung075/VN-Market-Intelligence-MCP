# Handoff — Task 1786: Earnings Source Conflict Detection

## Status
DONE — implementation committed on branch `task/1786-earnings-conflict-detection`.

## Problem
Two news messages for VIC Q1/2026 earnings reported contradictory growth figures:
- "lãi quý I tăng 17 lần (1.700%)"
- "lãi quý I/2026 tăng 150%"

The pipeline posted both as `chain_catalyst` signals without any cross-check, so the user saw conflicting data with no indication which was correct.

## Fix

### New domain service
`apps/mcp-server/src/domain/services/earningsConflictDetector.ts`

Two exported functions:
- `extractEarningsGrowthPct(text)` — parses a growth % from Vietnamese free-text using regex (handles parenthesised values like "1.700%", plain "tăng 150%", and decimal values like "25.5%"). Vietnamese thousands separator (dot before 3 trailing digits) is stripped; decimal dot is preserved.
- `detectEarningsConflict(db, stockCode, newDetail)` — queries recent non-expired `chain_catalyst` signals for the same ticker with `event_type = "earnings"`, extracts their growth figure, and returns a warning string if the new figure differs by more than 0.01%.

### Integration point
`apps/mcp-server/src/infrastructure/db/agentSignalStore.ts` — `postSignal()` now calls `detectEarningsConflict()` before insert when:
- `signalType === "chain_catalyst"`
- `findingData.event_type === "earnings"`
- `stockCode` is non-null

If a conflict is found, `payload.detail` is appended with:
```
— [WARNING] Conflict: prior signal shows 1700%, this signal shows 150% — verify source
```

Posting is **never blocked** — the warning is purely informational.
