## Problem

The vnstock Python library (VCI backend) renders a `rich` progress bar to **stdout**
when the API is rate-limited or returns a maintenance page. The output is ANSI escape
sequences (`╭`, box-drawing characters) rather than valid JSON.

`runPython()` in `vnstockBridge.ts` reads raw stdout and calls `JSON.parse(trimmed)`.
The SyntaxError is caught, returning `null`. The caller (`syncVnstockData.ts`) treats
`null` as "empty result — retry in 30 min". No alert is raised.

**Effect:** All 20+ tickers silently get stale financial data during any vnstock
rate-limiting or maintenance window. The user sees no signal that the financial
data layer is entirely down.

---

## Root Cause

1. `runPython()` does not strip ANSI codes before `JSON.parse`.
2. `runPython()` does not distinguish "legitimate null/empty" from "junk output".
3. `syncVnstockData.ts` has no bulk-failure detection or alert.

---

## Fix Specification

### Change 1 — `vnstockBridge.ts`: strip ANSI + detect junk output

In `runPython<T>()`, before `JSON.parse(trimmed)`:

```typescript
// Strip ANSI escape sequences (vnstock rich progress bar pollution)
const ANSI_RE = /\x1b\[[0-9;]*[mGKHF]|[\u2500-\u257F\u2800-\u28FF\u256A-\u2593]/g;
const cleaned = trimmed.replace(ANSI_RE, '').trim();

// Detect junk: if cleaned is empty after stripping, log and return null
if (!cleaned || cleaned === 'null') return null;

// Detect junk: if first non-whitespace char is not '{' or '[', it's not JSON
if (cleaned[0] !== '{' && cleaned[0] !== '[') {
  logger.warn(`[vnstock:${label}] non-JSON stdout — possible rate-limit or ANSI output`, {
    preview: cleaned.slice(0, 120),
  });
  return null;
}

return JSON.parse(cleaned) as T;
```

The ANSI_RE covers ESC sequences AND Unicode box-drawing characters used by `rich`.

### Change 2 — `syncVnstockData.ts`: consecutive-failure circuit breaker

Add module-level state:
```typescript
// Circuit breaker: track consecutive null returns per data type
// Opens after FAIL_THRESHOLD consecutive failures; resets after RESET_MS
const FAIL_THRESHOLD = 3;
const RESET_MS = 2 * 60 * 60 * 1000; // 2 hours
const cbState: Record<string, { failures: number; openedAt: number | null }> = {};
```

In each data-type fetch block (financials, balance_sheet, cash_flow, trading_stats)
within `syncStock()`:
- On null result: increment `cbState[type].failures`; if >= FAIL_THRESHOLD and not
  already open, mark `openedAt = Date.now()`
- On non-null result: reset `cbState[type]`
- Before fetching: if circuit is open AND `Date.now() - openedAt < RESET_MS`, skip
  the fetch entirely (return early for that type)

After `syncVnstockData()` loop completes, count how many codes had ALL financial
types skipped (circuit open). If >= 10 codes: send one Telegram WORK alert:
```
[VNSTOCK] Financial data circuit breaker open — vnstock API may be returning
non-JSON (ANSI/rate-limit). Types affected: financials, balance_sheet, cash_flow.
Will auto-retry in 2h. Check: python3 -c "from vnstock import Vnstock; print('ok')"
```
Use 60-min send cooldown on this alert (module-level `lastVnstockAlertAt`).
