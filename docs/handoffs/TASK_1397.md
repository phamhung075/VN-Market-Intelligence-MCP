# TASK_1397 — vnIndexRefreshJob: VNINDEX Staleness Fix

**Architect:** design complete
**Date:** 2026-04-28
**Baseline:** 7915 pass / 0 fail

---

## Root Cause

`VPS:vn-price-fetch.service` pushes stock prices for watchlist tickers only.
VNINDEX is an index code, not a stock ticker — it never appears in the VPS
push payload. The MCP server's push-prices handler only writes what arrives,
so `market_prices.updated_at` for code `VNINDEX` has not been updated in 10+
days.

`fetchVnIndex()` already exists in
`apps/mcp-server/src/infrastructure/fetchers/hose.ts` and calls the
dedicated `api-finfo.vndirect.com.vn/v4/vnmarket_prices` endpoint directly
from the MCP server (no VPS involved). It returns a `MarketPrice` object.
`storeMarketPrices()` in the same file handles the upsert into both
`market_prices` and `market_prices_history`.

The fix is a thin scheduler job that calls these two functions on a cron and
registers it in `jobs.ts`.

---

## Architecture Decision

### Layer assignment

| File | DDD layer |
|------|-----------|
| `apps/mcp-server/src/scheduler/market-data/vnIndexRefreshJob.ts` | interface/scheduler |
| `apps/mcp-server/src/scheduler/jobs.ts` (modified) | interface/scheduler |

The job is **interface-layer only**: it calls `fetchVnIndex()` and
`storeMarketPrices()` directly from `infrastructure/fetchers/hose.ts`.
No new domain service, no new use case — the infrastructure functions already
cover the full requirement.

### Why not add VNINDEX to the VPS script?

Rejected. `fetch-prices.sh` uses the VnDirect `/v4/stocks` endpoint which
does not return index data. VNINDEX requires the separate
`/v4/vnmarket_prices` endpoint, which the MCP server can reach directly
without a VPS proxy (not geo-blocked). Adding VPS complexity for something
the MCP server can fetch natively is over-engineering.

### Interval: every 5 minutes during VN market hours

Pattern: `*/5 2-8 * * 1-5` (UTC) — same window as `vpsServiceHealth`.
Rationale:
- VNINDEX moves with every trade; 5-min resolution is adequate for analysis.
- Avoids hammering the VnDirect endpoint (watchlist stocks refresh every 60s
  via VPS, index can be coarser).
- Env-overridable via `CRON_VN_INDEX_REFRESH`.

## Files to Create / Modify

### 1. NEW — `apps/mcp-server/src/scheduler/market-data/vnIndexRefreshJob.ts`

```typescript
/**
 * VN-Index Refresh Job (Task 1397)
 *
 * Fetches VNINDEX (and optionally HNX-INDEX / UPCOM-INDEX) from the VnDirect
 * vnmarket_prices API and upserts into market_prices + market_prices_history.
 *
 * Called by the scheduler every 5 min during VN market hours.
 * Does NOT depend on the VPS price-push pipeline — fetches directly.
 *
 * Layer: interface/scheduler
 */

import { fetchVnIndex, storeMarketPrices } from "../../infrastructure/fetchers/hose.js";
import { logger } from "../../infrastructure/logger.js";

/** Index codes to refresh on each cycle. */
const INDEX_CODES = ["VNINDEX"];

export interface VnIndexRefreshResult {
  fetched: number;   // number of index codes successfully fetched
  stored: number;    // number of MarketPrice rows passed to storeMarketPrices
  skipped: number;   // codes that returned null (API unavailable)
}

/**
 * Fetch all INDEX_CODES and upsert into market_prices.
 * Never throws — errors are logged and counted as skipped.
 */
export async function runVnIndexRefreshJob(): Promise<VnIndexRefreshResult> {
  let fetched = 0;
  let skipped = 0;
  const prices = [];

  for (const code of INDEX_CODES) {
    try {
      const price = await fetchVnIndex(code);
      if (price === null) {
        logger.debug("[vn-index-refresh] API returned null", { code });
        skipped++;
      } else {
        prices.push(price);
        fetched++;
      }
    } catch (err) {
      logger.warn("[vn-index-refresh] fetch failed", {
        code,
        error: err instanceof Error ? err.message : String(err),
      });
      skipped++;
    }
  }

  if (prices.length > 0) {
    await storeMarketPrices(prices);
    logger.debug("[vn-index-refresh] stored", { count: prices.length });
  }

  return { fetched, stored: prices.length, skipped };
}
```

Key implementation notes for developer:
- `INDEX_CODES` array is intentionally exported-adjacent — developer can add
  `"HNX-INDEX"` or `"UPCOM-INDEX"` later without touching jobs.ts.
- `storeMarketPrices` handles the `INSERT OR REPLACE` into both
  `market_prices` and `market_prices_history` — no custom SQL needed.
- `fetchVnIndex` already has a 10s `AbortController` timeout and returns
  `null` on any failure, so the try/catch above is a belt-and-suspenders guard.
- No trading-session guard inside the job: the cron expression already
  constrains to market hours. The job itself is stateless.


**Step C — Register the cron inside `startScheduler()`, after the
`vpsServiceHealth` block:**

```typescript
// Every 5 min during VN market hours (02:00-08:59 UTC, Mon-Fri) — VN-Index refresh — task 1397
// Fetches VNINDEX directly from VnDirect vnmarket_prices API (not via VPS).
// Ensures market_prices.VNINDEX stays fresh regardless of VPS push payload.
cron.schedule(CRONS.vnIndexRefresh, async () => {
  await recordJobRun(getDb(), 'vnIndexRefreshJob', async () => {
    const result = await runVnIndexRefreshJob()
    return { rowsWritten: result.stored }
  })
}, { timezone: 'UTC' })
```

**Step D — Update the log line at the bottom of `startScheduler()`:**

The log line currently says `${Object.keys(CRONS).length} cron keys`. Adding
one key to `CRONS` automatically increments the count — no manual edit needed.

## market_prices Schema (confirmed from schema-market-data.ts)

```sql
CREATE TABLE IF NOT EXISTS market_prices (
  code        TEXT PRIMARY KEY,
  price       REAL,
  change_amt  REAL,
  change_pct  REAL,
  volume      REAL,
  updated_at  TEXT,
  exchange    TEXT DEFAULT 'HOSE'
);
```

`storeMarketPrices()` maps `MarketPrice.changePct` → `change_pct` and
`MarketPrice.fetchedAt` → `updated_at`. The `change_amt` column is not
populated by `storeMarketPrices` (it passes NULL via `INSERT OR REPLACE`
omission) — this is the existing behavior for all VPS-pushed prices too, so
no regression.

## Risk Flags

| Risk | Severity | Mitigation |
|------|----------|------------|
| VnDirect vnmarket_prices rate limit | Low | 5-min interval = 12 calls/hour. VnDirect does not publish rate limits but this endpoint is used only for index codes (1 call per cycle). |
| VNINDEX row polluting `priceUpdateWatchdog` staleness check | None | `readLatestPriceTimestamp()` reads `MAX(updated_at) WHERE code NOT IN ('TEST','PROBE')` — VNINDEX is included, which is correct: a fresh VNINDEX row keeps the watchdog happy during market hours even if stock prices are delayed. |
| `change_amt` always NULL for VNINDEX | Acceptable | No existing consumer of `market_prices.change_amt` for VNINDEX. Same NULL behavior as all VPS-pushed rows. |
| Job fires on weekends (misconfig) | Mitigated | Cron expression `*/5 2-8 * * 1-5` is weekday-only. `fetchVnIndex` returns real data even on weekends (API has no guard), but the cron will not fire. |

---

## No Schema Migration Required

`market_prices` already has a row for `VNINDEX` (created by seed or prior
fetch). `INSERT OR REPLACE` will update it. If no row exists yet,
`INSERT OR REPLACE` will create it. No DDL change needed.
