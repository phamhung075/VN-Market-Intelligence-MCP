# TASK 1781 — Fix: Off-by-one in classifyFilingStatus()

## Status: DONE — ready for QA

## What was fixed

`classifyFilingStatus()` in `apps/mcp-server/src/domain/services/financial-reports/earningsCalendar.ts` (lines 203-221) previously computed `daysUntilDeadline` via raw millisecond subtraction:

```
diffMs = deadline.getTime() - today.getTime()
daysUntilDeadline = Math.floor(diffMs / MS_PER_DAY)
```

Because filing deadlines are stored as UTC midnight (`new Date("2026-04-30")` = `2026-04-30T00:00:00Z`), any call after UTC midnight on the deadline day produced `diffMs < 0`, yielding `daysUntilDeadline = -1` and status `QUA_HAN`. Wrong.

### Fix applied

Replaced millisecond subtraction with calendar-date comparison. Both `today` and `deadline` are sliced to `YYYY-MM-DD`, then each component is reconstructed via `Date.UTC()` to produce midnight-aligned epoch values. The difference is then divided by `MS_PER_DAY` and rounded (not floored) — rounding is safe here because both operands are already midnight UTC so the quotient is always an integer.

```typescript
const todayDate = today.toISOString().slice(0, 10);
const deadlineDate = deadline.toISOString().slice(0, 10);
const todayUTC = Date.UTC(parseInt(todayDate.slice(0,4),10), parseInt(todayDate.slice(5,7),10)-1, parseInt(todayDate.slice(8,10),10));
const deadlineUTC = Date.UTC(parseInt(deadlineDate.slice(0,4),10), parseInt(deadlineDate.slice(5,7),10)-1, parseInt(deadlineDate.slice(8,10),10));
const daysUntilDeadline = Math.round((deadlineUTC - todayUTC) / MS_PER_DAY);
```

### Result

- `today = 2026-04-30T07:29Z`, `deadline = 2026-04-30` → `daysUntilDeadline = 0` → `SAP_DEN` (correct)
- `today = 2026-04-30T23:59Z`, `deadline = 2026-04-30` → `daysUntilDeadline = 0` → `SAP_DEN` (correct)
- `today = 2026-05-01T00:00Z`, `deadline = 2026-04-30` → `daysUntilDeadline = -1` → `QUA_HAN` (correct)
