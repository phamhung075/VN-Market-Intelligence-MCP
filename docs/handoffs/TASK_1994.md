- **Technical notes:**
  - Fire-time election: at cron START (Step 0), claim `fire-time:<flow>:<period-key>:<start-timestamp>` atomically
  - Winner gets TTL 1800s (covers typical cron window: cowork */15min = 900s window + 900s margin, dev-team = 7:00-7:05 = 300s window + 1500s margin, etc.)
  - Loser session defers: log "[leader-election] DEFER to live leader <session-id>" and exits cleanly (not error)
  - Stale leader reclaim: if leader claims and then dies (no heartbeat for 600s?), next fire-time attempts re-claim; next successful claim wins
  - No orphan work: all defer cases must have ZERO task assignments (pre-verify in cowork/dev-team before deferral)
  - Period-key collision: two ticks of same cron in <1800s window should NOT collide (e.g., cowork fires */15min, period-key = first timestamp of 15-min window, should be unique per tick)

- **Edge cases to test:**
  - Stale leader not replaced immediately (TTL expires, next tick elects new leader) ✓
  - Two sessions fire same cron in parallel → exactly one claims → other defers cleanly
  - Short dispatch window (dev-team = 5min) + long election: ensure election finishes before dispatch close
  - Cross-session peer detection: router sees winner + loser in presence roster
