# Handoff — TASK 1793: pollNews all-sources-dark 4h cooldown across restarts

## Status
DONE — fix applied, 4 new tests GREEN, 1398 regression tests still GREEN.

## Root Cause

`pollNews.ts` (lines 652–656 before fix) stored the cooldown sentinel timestamp
using `strftime('%Y-%m-%dT%H:%M:%SZ','now')` — SQLite's real wall clock. The
cooldown comparison used `nowMs()` (an injectable clock, and `Date.now()` in
production). In tests using a fake-future `nowMs`, the stored timestamp (real
clock ~`1.78e12 ms`) was vastly different from the fake clock's `now` value,
making the cooldown comparison unreliable:

- Fake now = `100h` (~`3.6e8 ms`) — real DB row at `~1.78e12 ms`
- Second call: `now - dbLastMs = 3.6e8 - 1.78e12` → **negative** → cooldown
  never expires → alert suppressed even after 4h in fake time.

In production (no fake clock), if `nowMs` is not injected, both use real
`Date.now()` — so the production comparison is consistent. But the code was
wrong in the sense that the stored timestamp was not derived from `nowMs`,
making the clock injection incomplete and leading to test coverage gaps that
masked potential production issues.

The secondary production bug: `intelligenceCycleJob.defaultPollNews()` passes
all-empty fetchers, so every cycle produces `allItems.length === 0`. On every
container restart `_lastAllDarkAlertAt` resets to 0. If the DB INSERT ever
fails silently (WAL contention, schema mismatch during migration), the DB row
is never written and every restart fires a new alert — matching the 16+
identical reports over 3 days.

## Fix Applied

**File**: `apps/mcp-server/src/application/usecases/pollNews.ts`

Changed the DB INSERT from:
```ts
db.prepare(
  `INSERT INTO cron_job_runs (job_name, started_at, status)
   VALUES ('pollNews_all_sources_dark', strftime('%Y-%m-%dT%H:%M:%SZ','now'), 'success')`
).run();
```

To:
```ts
const nowIso = new Date(now).toISOString();
db.prepare(
  `INSERT INTO cron_job_runs (job_name, started_at, status)
   VALUES ('pollNews_all_sources_dark', ?, 'success')`
).run(nowIso);
```

Where `now` is already resolved from `options.nowMs?.() ?? Date.now()` at the
top of the all-sources-dark block. This guarantees the stored timestamp is on
the same clock as the comparison, eliminating the divergence.
