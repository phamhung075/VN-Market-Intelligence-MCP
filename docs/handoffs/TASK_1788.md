# Handoff — TASK 1788: HCM Geographic False Positive Fix

## Status
DONE — committed on branch `task/1788-news-alert-ticker-fix`

## Root Cause

`extractStockTickers()` Pattern 2 in `newsNormalizer.ts` uses `\b([A-Za-z]{2,5})\b`.
The dot in "TP.HCM" acts as a `\b` word boundary, so "HCM" is extracted as a standalone
alpha token and matched against `KNOWN_VN_STOCKS` — incorrectly triggering the HCM
(HCM Securities) alert on any article mentioning Ho Chi Minh City.

## Fix

**File:** `apps/mcp-server/src/domain/services/newsNormalizer.ts`

1. Added `GEOGRAPHIC_CONTEXT_MAP` — maps `"HCM"` to geographic prefix tokens:
   `"tp.hcm"`, `"tp hcm"`, `"tphcm"`, `"tp."`, `"tp "`, `"thành phố hcm"`, etc.

2. In Pattern 2 loop of `extractStockTickers()`, added a 10-character look-behind
   window check after the currency-context guard. If the window ending at the match
   contains a geographic prefix, the match is skipped.

3. Pattern 1 (parenthetical `"(HCM)"`) is NOT guarded — always means the ticker.

4. Alias path (Pattern 3 / `detectStocksInText`) is NOT affected — HCM's aliases
   (`"chung khoan ho chi minh"`, `"hcm securities"`) require the securities company
   context and do not fire on bare geographic references.
