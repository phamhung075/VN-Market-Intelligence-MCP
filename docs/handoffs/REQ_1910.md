### 2.5 Tool output schema

```typescript
{
  source_tier: 1,
  new_orders:   number,     // diffusion index, e.g. 52.3
  employment:   number,
  prices_paid:  number,
  backlog:      number,
  fetchedAt:    string,     // ISO-8601 datetime of last fetch
  asOf:         string,     // YYYY-MM-DD of latest data month
  regime_signal: "EXPANDING" | "CONTRACTING" | "MIXED"
}
```

**Fallback on missing series:** if any sub-index unavailable → `null` for that field, `regime_signal: "MIXED"` (cannot classify with incomplete data).

### 2.6 Domain function — `computeIsmRegimeSignal()`

Pure function, zero infra imports. DDD contract identical to `computeFedLiquiditySpread()` pattern from 1879b.

```typescript
export type IsmRegimeSignal = "EXPANDING" | "CONTRACTING" | "MIXED";

export interface IsmSubcomponents {
  new_orders:  number | null;
  employment:  number | null;
  prices_paid: number | null;
  backlog:     number | null;
}

export function computeIsmRegimeSignal(data: IsmSubcomponents): IsmRegimeSignal
```

**Threshold logic:**
- `EXPANDING`: `new_orders > 50 && new_orders > prices_paid` — demand pulling ahead of cost pressure; leading signal positive
- `CONTRACTING`: `new_orders < 50 && employment < 50` — both demand and labour contracting; confirmed contraction
- `MIXED`: all other cases — divergence, incomplete data, or boundary conditions

**Boundary cases (required in tests):**
| Case | Input | Expected |
|------|-------|----------|
| Both expanding cleanly | `new_orders=54, prices_paid=51` | `EXPANDING` |
| Both contracting | `new_orders=47, employment=48` | `CONTRACTING` |
| Divergence: new_orders low, prices high | `new_orders=48, prices_paid=60` | `MIXED` |
| Null data | `new_orders=null` | `MIXED` |

### 2.7 Cron wiring

**Inside `macroIndicatorRefreshJob`** (daily 06:00 UTC, `CRON_MACRO_INDICATOR_REFRESH`). ISM is monthly — fetcher runs daily but inserts 0 new rows on non-release days (`INSERT OR IGNORE` idempotency). No separate monthly cron needed. First business day of each month: FRED publishes the new ISM release → fetcher picks it up within 24h.

PO spec §3.1 suggests "monthly, first business day" — implementation is daily cron with idempotent inserts (same pattern as EFFR/IORB). No new cron entry created. Compliant with PO AC-2.
