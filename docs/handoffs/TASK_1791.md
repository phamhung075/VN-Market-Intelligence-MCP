# Handoff — Task 1791: assembleAlertDigest intra-digest identical message dedup

## What was done

Fixed `assembleAlertDigest.ts` to deduplicate identical alert messages within
each ticker group before rendering the top-3 digest lines.

**Root cause:** `sorted.slice(0, 3)` operated on raw alerts with no dedup.
When a cron fires 24 times for the same condition (e.g. "VRE volume spike 3.3×"),
all 24 rows had identical `message` strings. The top-3 were all duplicates.

**Fix location:**
`apps/mcp-server/src/application/usecases/assembleAlertDigest.ts`
Lines ~291-312 (inside the `.map()` that builds `stockBlocks`)

**Change:**
After the `sorted` array is built (severity DESC, triggered_at DESC), a `Set<string>`
deduplicates by `message` string. Only the first occurrence of each unique message is
kept (= highest-severity / most-recent, because of sort order). `top3` and `overflow`
are then derived from the deduplicated list. The raw `count` (total alerts including
duplicates) is preserved unchanged.

## Invariants maintained

- `count` = raw alert total (no change)
- `overflow` = `uniqueMessages.length - 3` (not raw - 3)
- `topMessages` = up to 3 unique message strings
- Existing price_drop / cumulative prefix logic in `formatAlertDigest` is untouched
- All 23 pre-existing tests still pass
