## 2. What Was Originally Broken

VCB BCTCs use Mẫu B02a/TCTD-HN (banking format). This format has two structural properties that the original extractor did not handle:

**Property 1 — No standard item codes (100-440 scheme).** Banking BCTCs omit the standard Vietnamese BCTC item code scheme. `parseSplitBlockBalanceSheet` found zero codes in the labels block and fell through, returning `null`. This caused `extractBalanceSheet` to use `findValue`, which scanned ~3,900 OCR lines into prose territory and returned wrong sub-item values for `total_liabilities` and `equity_total`.

**Property 2 — No standalone date/unit separator line.** VCB Q4 encodes the date and unit in a merged multi-column OCR header (`"Thuyết 31/12/2025 31/12/2024" / "minh Triệu VND Triệu VND"`). VCB Q1 has no separator at all — labels appear on one physical page, values on the next. The original anchored `DATE_PATTERN = /^\d{1,2}\/\d{1,2}\/20\d\d$/` never matched either format.

**Consequence for total_assets specifically.** The banking-label fallback (added in an earlier task) correctly searched for a `grandTotal + liabilities + equity` accounting triple, but only emitted keys `"300"`, `"400"`, and `"440"` in its return value. Key `"270"` (the canonical total_assets key) was never emitted. As a result, `fv(P_TOTAL_ASSETS, "270")` fell through to `findValue`, which returned a wrong sub-item value (~35 million triệu instead of ~2.1 billion triệu).

## 3. What Each Prior Task Fixed

### Task 1415b — Contains-based separator + page-pair merge

**Fix location:** `parseSplitBlockBalanceSheet` (separator scan) and `extractSplitBlockAll` (page-merge logic)

**Change 1:** Widened the date/unit separator search from anchored patterns to contains-based:
- `DATE_CONTAINS = /\d{1,2}\/\d{1,2}\/20\d\d/` — matches date anywhere in a line, handles VCB Q4 inline header
- `UNIT_CONTAINS = /tri[eệ]u\s+VND|(?<![\/\d])VND(?!\d)/i` — matches unit anywhere in a line

**Change 2:** Added a page-boundary fallback separator (second occurrence of `"Báo cáo tình hình tài chính"`) for VCB Q1 where no date/unit separator exists.

**Change 3:** Added labels-only page detection in `extractSplitBlockAll`. Pages that contain item codes but zero monetary values are concatenated with the following page before parsing (page-pair strategy for VCB Q1).

**Result:** `total_liabilities` and `equity_total` extracted correctly for both Q1 and Q4. `total_assets` was explicitly out-of-scope in the 1415b ADR because the banking-label fallback never emitted key `"270"`.

### Task 1416a — Emit key "270" from banking-label fallback

**Fix location:** `parseSplitBlockBalanceSheet`, banking-label fallback return statement

**Change:** Single-line: changed `return { "300": liab, "400": eq, "440": grandTotal }` to `return { "270": grandTotal, "300": liab, "400": eq, "440": grandTotal }`.

**Rationale:** For Mẫu B02a/TCTD-HN, total assets equals total sources of capital by the balance sheet identity. The `grandTotal` already computed by the triple-search is the correct value for both `"270"` (total assets) and `"440"` (total liabilities + equity). Emitting `"270"` means `fv(P_TOTAL_ASSETS, "270")` resolves from `sbMap` directly and never falls through to `findValue`.

**Result:** `total_assets` extracted correctly. Verification confirmed in live Docker DB as of 2026-04-29.
