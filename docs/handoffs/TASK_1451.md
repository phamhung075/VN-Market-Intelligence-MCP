## Root Cause

The SQL queries compared ISO-formatted timestamps against SQLite datetime expressions. When the database stored `"2026-04-18T09:00:00.000Z"` (TEXT), the comparison:
```sql
WHERE updated_at >= datetime('now', '-3 days')
```
Failed because:
1. `datetime('now', '-3 days')` evaluates to `"2026-04-19 07:00:00"` (SQLite datetime format)
2. `updated_at` is stored as `"2026-04-18T09:00:00.000Z"` (ISO format TEXT)
3. String comparison: `"2026-04-18T09:00:00.000Z" >= "2026-04-19 07:00:00"` evaluates to FALSE
4. Query returns no rows → vnIndex is NULL

## Solution Details

1. **Remove SQLite datetime computation** — move to application layer where it can be mocked for tests
2. **Use date() function for comparison** — `date(updated_at)` extracts YYYY-MM-DD from ISO strings
3. **Pass cutoff as parameter** — `.get(cutoffDateStr)` where `cutoffDateStr = threeDaysAgo.toISOString().split('T')[0]`
4. **Make testable** — franceSummaryJob accepts `nowFn` injection, so cutoff is always relative to mocked time

Result: `date(updated_at) >= '2026-04-15'` (string comparison now works correctly)

## Security

Parameter binding is safe:
- `cutoffDateStr` is derived from `.split('T')[0]` → extracts YYYY-MM-DD only
- Query uses `?` placeholder → SQLite binds parameter safely, no string interpolation
- No SQL injection possible
