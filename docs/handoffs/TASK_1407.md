## Root Cause

1. VPS endpoint `bgapidatafeed.vps.com.vn` was unreachable during trading hours (Apr 28 ~03:23 UTC)
2. CB trips to OPEN after threshold failures
3. Half-open probe fires every 60s against same unreachable URL → immediately fails → CB stays OPEN
4. No market-hours gate: CB calls continue during closed market accumulating failures
5. No manual reset tool available via MCP

---

## Required Developer Fixes

### Fix 1 (Critical — prevents recurrence): Market-hours gate
Gate `foreignFlowFetcherJob` to skip CB calls outside VN trading window `02:00-09:00 UTC Mon-Fri`. This prevents accumulating failures during closed market and stops the OPEN-HALF_OPEN-OPEN loop from persisting overnight.

### Fix 2 (Critical — operational): Manual CB reset tool
Add MCP tool or admin HTTP endpoint to reset a named circuit breaker. Ops cannot recover this incident without a full Docker restart or code change.

### Fix 3 (Important): Half-open probe backoff
Current half-open probe retries every 60s. Should use exponential backoff (start 5 min, max 30 min) to prevent rapid cycling.

### Fix 4 (Minor — separate bug): `idle` status constraint violation
`vps_service_health` CHECK constraint does not allow `idle` as a valid status value (flagged in TASK 1403). VPS service correctly returns `idle` when market is closed but the DB schema rejects it.
