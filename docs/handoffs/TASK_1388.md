# TASK_1388 — foreignFlow CB Auto-Reset Handoff

## What Was Done

Changed `breakers.foreignFlow` in `circuitBreakerRegistry.ts` to use `halfOpenMaxAttempts: 1` (was 2, the default).

### Root Cause Analysis

The `CircuitBreaker` already had OPEN → HALF_OPEN → CLOSED logic via `_checkTimeout()` (fires after `resetTimeoutMs: 300_000` ms = 5 min). The bug was not missing half-open logic — it was the probe count:

- With `halfOpenMaxAttempts: 2`, closing the circuit required **2 consecutive successes** after a half-open transition
- During the Sprint 1346b incident (UNIQUE constraint on `vnstock_trading_stats`), the VPS kept pushing data every minute
- Pattern: 5 failures → OPEN → 5 min → HALF_OPEN → push probe → DB write fails → OPEN (again, resets timer)
- Each re-open reset `_openedAt = new Date()`, starting the 5-min timeout over
- After DB fix: first half-open probe succeeds (halfOpenSuccesses=1), CB stays HALF_OPEN waiting for probe #2
- If the second VPS push arrived with any other transient error, CB re-opened again
- Result: CB accumulated 168 failures and stayed stuck, requiring manual `reset_foreign_flow_circuit_breaker` MCP tool call

### Fix

`halfOpenMaxAttempts: 1` — the **first successful probe after the underlying error is fixed closes the circuit**. After the DB fix, the very next VPS push that succeeds auto-closes the CB without waiting for a second confirmation.

The OPEN→HALF_OPEN transition mechanism (timer-based via `_checkTimeout()`) was already correct and was not modified.
