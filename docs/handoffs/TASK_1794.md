# Task 1794 Handoff — EOD Vol and RSI Fix

## What was done

EOD summaries were showing `Vol: N/A | RSI: N/A` for all tickers because the formatter only had access to `changePct`.

### Root cause
`WatchlistMover` had no `volume` or `rsi14` fields. The SQL query did not SELECT volume. RSI was computed in the TA step but never cross-referenced into movers.

### Changes

**`apps/mcp-server/src/application/usecases/assembleEveningSummary.ts`**
- Added `volume?: number` and `rsi14?: number | null` to `WatchlistMover` interface
- Added `volume` to `WatchlistMoverRow` internal type
- Extended both SQL paths (ohlcv CTE + market_prices fallback) to `SELECT COALESCE(mp.volume, oc.today_volume) AS volume`
- After TA step: builds a `rsiMap` from `taSummary` and patches `mover.rsi14` by code

**`apps/mcp-server/src/scheduler/briefings/eveningSummaryJob.ts`**
- Added `MoverEntry` type with optional `volume` and `rsi14`
- Added `fmtVolume(v)`: `>= 1M → "X.XM"`, `>= 1K → "X.XK"`, else raw
- Added `fmtMoverLine(prefix, m)`: renders `"CODE: +X.XX% | Vol: Y | RSI: Z"` with N/A fallbacks
- Updated `formatMoversSection` to accept `MoverEntry[]` and use `fmtMoverLine` for all ticker lines (sector sub-lines + flat block)

**`apps/mcp-server/src/__tests__/1794-eod-vol-rsi.test.ts`** — 19 new tests (AC-1..AC-10)
