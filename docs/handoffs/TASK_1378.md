# TASK_1378 — VCB duplicate alert handoff

## Branch
`main` (committed directly — fix is 3 files, ≤10 lines changed in domain)

Commit: `aa8cf9a3`

## Problem
VCB fired two separate Telegram alerts in the same digest:
1. Bare `price_drop` alert (deterministic 4h-bucket ID, created cycle N)
2. Composite `price_drop+volume_spike` alert with `severity="critical"` (random ID, created cycle N+1)

The composite was critical because sector-wide decline (step 5a in `scanMarket.ts`) emits a third `price_drop` signal for the same stock, pushing the group to 3 signals → `escalateSeverity` returns `"critical"`.

`shouldSuppressAlert` had an **unconditional early return** for non-MACRO critical alerts (line 69) that skipped the signal-overlap check entirely — so even though `price_drop` was already in recent history, the composite bypassed suppression and fired.

## Root cause
`/apps/mcp-server/src/domain/services/alertCooldown.ts` line 69 (pre-fix):
```typescript
if (alert.severity === "critical" && alert.actionCode !== "MACRO") return false;
```
This ran before the signal-overlap loop, making critical alerts immune to dedup.

## Fix
Moved the critical bypass to AFTER the overlap loop. Now:
- Signal overlap → suppressed regardless of severity (prevents composite duplicates)
- No overlap + critical + not MACRO → skip daily cap, allow firing (genuinely new event)

Changed 8 lines in `alertCooldown.ts`.
