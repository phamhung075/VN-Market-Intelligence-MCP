# TASK_1362 Handoff — FIX-1327 Stale Ticker WORK Spam

## What was done

Fixed Telegram WORK channel spam caused by `[push-prices]` stale ticker warnings firing once **per ticker per push cycle**.

### Changes

**`apps/mcp-server/src/interface/mcp/server.ts`**
- Added module-level `_staleTickers_lastNotifiedDate: string` (exported) — holds the UTC date (`YYYY-MM-DD`) of the last WORK notification.
- Added exported `_resetStaleTickers_lastNotifiedDate()` setter for test isolation.
- Replaced the per-ticker `for` loop (N messages/cycle) with a single aggregated message gated by a daily UTC date key. The message lists all stale tickers in one block. `_staleTickers_lastNotifiedDate` is updated only when a message is actually sent.

**`apps/mcp-server/src/__tests__/1327-push-prices-stale-watchlist-warn.test.ts`**
- Kept original 3 DB-query tests (unchanged behaviour).
- Added 4 new behaviour tests:
  1. One aggregated message for multiple stale tickers (not N individual messages)
  2. No message sent when cooldown date == today
  3. Message sent again next day (different date key)
  4. No message when no stale tickers (cooldown not advanced)
