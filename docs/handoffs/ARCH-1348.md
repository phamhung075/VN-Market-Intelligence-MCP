### Bug 1314 — Root cause

The DSC CEO bearish warning article (impact 8, BEARISH) did **not** pass through the broadcast gate.

The broadcast gate at line 3241–3243 requires EITHER:
- `isMarketWide()` returns true (criteria a–d), AND
- `impactScore >= broadcastMinImpact` (default 6) OR `hasAnalystWarningPattern`

`isMarketWide` criterion (c) fires for any `level === "country"` entry with `impactScore >= 6`. The DSC article scored impact 4 in `run_impact_chain` — below the threshold. The analyst-warning bypass (`hasAnalystWarningPattern`) only matches three NFD patterns hardcoded at lines 3228–3231 (`"đieu chinh sau"`, `"rat sau va đau"`, `"canh bao nha đau tu"`). A brokerage CEO warning that does not use those exact phrases falls through both gates.

There is **no rule** in `SECTOR_RULES` for `catalyst_type = "brokerage_outlook"` or `scope = "market_wide"`. The article never produces a domain-level match, so `run_impact_chain` returns the seed's own low impact score.

### Bug 1315 — Root cause

The Sprint-1335 fix added FR-1/FR-2/FR-3 rules correctly for the VPBankS/OKX **partnership** frame. However, the competitive-threat frame — banks WITHOUT digital-asset strategy facing substitution risk — was not addressed. FR-3 produces a `neutral` entry for `domain: "banking"`, which is correct for generic crypto articles, but it does not differentiate by strategic positioning (which banks have a digital-asset strategy vs. which do not).

The PO brief for 1315 (the current sprint) now specifies a `COMPETITIVE_THREAT` signal. However, reading the 1335 test file shows FR-3 already encodes the neutral/bearish split at domain level — the gap is specifically that banks **without** a digital strategy (VCB, BID, EIB, HDB) should receive a **bearish** action-level entry (competitive pressure), while banks **with** a strategy (VPB, TCB) receive the existing bullish FR-1 entry.

The FR-2 rule (lines 2344–2379) already fires bullish for securities brokers with `affected_actions: [SSI, VCI, VIX, VND]`. The missing piece is an `affected_actions` list on FR-3 (or a new sibling rule) that emits **bearish** action-level entries for the banks exposed to substitution risk.

## Design

### Task 1348c — Implementation (two atomic changes)

#### Change A — Bug 1314: Brokerage outlook broadcast (SECTOR_RULES + isMarketWide)

**Two-part fix, one file:**

**Part A1 — New `SECTOR_RULES` entry** (insert before line 2381, after the FR-2 block ends at ~line 2380)

Add a new rule that matches brokerage-firm bearish/bullish market outlooks and classifies them under the `securities` domain, which is not in `COMMODITY_TRIGGER_DOMAINS`. This makes the article produce a domain-level `securities` entry, which then qualifies for the broadcast pass on step 3b.

```typescript
// ── Brokerage CEO/analyst market outlook (Sprint 1348) ────────────────────
// Brokerage firm CEOs and analysts publishing bearish/bullish market outlooks
// are treated as market-wide signals. The "securities" domain is NOT in
// COMMODITY_TRIGGER_DOMAINS, so step 3b broadcast pass is unrestricted.
// confidence: 0.72 (source reliability: brokerage analyst, not independent data).
{
  keywords: [
    // bearish outlook variants (Vietnamese)
    "giám đốc chứng khoán cảnh báo",
    "lãnh đạo ctck cảnh báo",
    "phân tích viên cảnh báo thị trường",
    "ctck khuyến nghị giảm tỷ trọng",
    "khuyến nghị bán",
    "brokerage bearish outlook",
    "brokerage warns",
    // bullish outlook variants
    "ctck nâng khuyến nghị",
    "brokerage upgrade",
    "brokerage bullish outlook",
    // DSC and peer firm name patterns
    "dsc cảnh báo",
    "chứng khoán dsc",
    "dsc securities",
  ],
  domain: "securities",
  direction: "down",   // bearish outlook default; seed.sentiment overrides in broadcast
  confidence: 0.72,
  title: "Lãnh đạo CTCK phát tín hiệu thị trường — bearish outlook lan rộng toàn thị trường",
},
```

**Part A2 — Extend `isMarketWide` criterion (d)** (lines 2469–2473)

Add brokerage-outlook NFD patterns to `ANALYST_WARNING_PATTERNS` so that a DSC CEO warning at impact score 4 still bypasses the `impactScore >= broadcastMinImpact` gate and reaches the broadcast loop.

Current array (lines 2469–2473):
```typescript
const ANALYST_WARNING_PATTERNS = [
  "đieu chinh sau",
  "rat sau va đau",
  "canh bao nha đau tu",
];
```

Extend to:
```typescript
const ANALYST_WARNING_PATTERNS = [
  "đieu chinh sau",
  "rat sau va đau",
  "canh bao nha đau tu",
  // Sprint 1348: brokerage CEO/analyst outlook patterns
  "giam đoc chung khoan canh bao",   // giám đốc chứng khoán cảnh báo (NFD)
  "lanh đao ctck canh bao",          // lãnh đạo CTCK cảnh báo (NFD)
  "dsc canh bao",                    // DSC cảnh báo (NFD)
  "ctck khuyen nghi ban",            // CTCK khuyến nghị bán (NFD)
];
```

The **same patterns** must be added to `ANALYST_WARNING_PATTERNS_BROADCAST` at lines 3228–3231 — that array is a copy, not a reference to the one in `isMarketWide`. Both must stay in sync.

**Broadcast confidence for brokerage outlook:** The existing broadcast pass uses `Math.min(0.7, seedEntry.impactScore / 10)` at line 3265. For a DSC warning at impact 8 this yields `0.7` — appropriate. No change needed to the broadcast loop itself.

**Result:** A DSC CEO bearish warning with any of the new keywords triggers:
1. A `securities` domain-level entry (from the new SECTOR_RULE)
2. `isMarketWide` criterion (d) fires on the NFD patterns
3. `hasAnalystWarningPattern` is true → bypasses the `impactScore >= 6` gate
4. Broadcast loop emits `bearishEntry` for every watchlist stock not covered by a domain rule
5. `reasoning` contains `"market-wide cascade:"` → 1345d MARKET channel dispatch picks it up

#### Change B — Bug 1315: Competitive threat action-level entries for banks

**One change, same file:**

FR-3 at lines 2328–2343 currently produces a `neutral` domain-level banking entry but no action-level entries. The fix adds `affected_actions` to FR-3 pointing to the banks exposed to substitution risk (no digital-asset strategy):

```typescript
// ── FR-3: banking NEUTRAL for crypto/digital-asset headlines (Sprint 1335) ──
// Sprint 1348: add affected_actions with BEARISH direction for banks without
// digital-asset strategy — VCB/BID/EIB/HDB face substitution/competitive pressure.
// VPB and TCB are excluded here — they are covered by FR-1 (bullish, strategy-aligned).
{
  keywords: [
    "okx",
    "crypto custody",
    "lưu ký tài sản số",
    "tài sản số vietnam",
    "sàn tiền mã hóa",
  ],
  domain: "banking",
  direction: "neutral",
  confidence: 0.65,
  title:
    "Crypto partnership/lưu ký tài sản số — ngân hàng truyền thống không có chiến lược digital-asset: tác động trung lập",
  affected_actions: [
    { code: "VCB", direction: "down" },
    { code: "BID", direction: "down" },
    { code: "EIB", direction: "down" },
    { code: "HDB", direction: "down" },
  ],
},
```

The existing `affected_actions` resolution path at ~line 3150+ already handles `direction: "down"` entries. The `[RuleAffected: <CODE>]` reasoning tag is written by the existing loop — no new logic needed.

**Note on COMPETITIVE_THREAT signal type:** The PO batch doc references a new `COMPETITIVE_THREAT` signal type in `src/types/signals.ts`. After reading the code, this is **not required for the cascade engine itself** — `cascadeEngine.ts` works only with `ImpactDirection` (`"up"/"down"/"neutral"`), not signal types. Signal types live downstream in `signalDetector.ts` / `alertGenerator.ts`. Adding a new `COMPETITIVE_THREAT` signal type is a downstream enhancement that the Developer can choose to add if it improves alert message clarity, but it is not a prerequisite for the cascade fix. The developer should confirm scope before implementing.
