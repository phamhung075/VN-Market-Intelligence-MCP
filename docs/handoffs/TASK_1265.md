## Issue

`batchReviewMarketMessages()` prepared statement created outside transaction scope at line 363, then used inside transaction at line 374. SQLite best practice requires prepared statement to be bound and executed within transaction context to ensure atomicity.

**Bug symptom:** Verdict updates could disappear from DB in some scenarios if statement lifecycle isn't properly managed within transaction scope.

---

## Solution

Moved `db.prepare()` call from outside the transaction (line 363) to inside `db.transaction()` closure (line 368). This ensures:

1. Prepared statement is created within transaction context
2. All `stmt.run()` calls execute atomically within txn scope
3. Updates are guaranteed to persist or rollback as a unit
4. No partial updates possible
