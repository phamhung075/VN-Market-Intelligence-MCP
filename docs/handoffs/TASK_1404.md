# TASK_1404 — VPS: Diagnose and Fix vn-news-fetch (All 6 RSS Sources Return 0 Items)

## Status
Todo

## Priority
HIGH

## Type
ops / infra

## Owner
ops

## Context

`vn-news-fetch.service` on the Vinahost VPS is running but all 6 RSS sources are returning 0 items.
This means the MCP server has received zero news items from the VPS news pipeline, degrading the
News Scout and Alert Commander capabilities.

Possible causes:
- Systemd service failed silently (parsing error, memory issue, feed URL change)
- RSS feed URLs have changed or require authentication headers
- Network connectivity issue from VPS to source domains
- Rate-limiting or IP block from news sources

## Acceptance Criteria

1. SSH to Vinahost VPS and check service status: `systemctl status vn-news-fetch`
2. Review journal for errors: `journalctl -u vn-news-fetch -n 100 --no-pager`
3. Identify which of the 6 RSS sources are returning 0 items and why
4. Fix the root cause (restart / update feed URLs / fix parsing / clear rate limit block)
5. Confirm at least one source returns > 0 items after fix
6. Confirm the MCP server receives pushed news items (check MCP server logs or DB)
7. If all 6 sources are permanently broken (URL changes), update feed config and redeploy service
8. Document root cause + fix per source in task report

## Implementation Notes

- Service config likely at `/etc/systemd/system/vn-news-fetch.service` or `/opt/vn-services/`
- RSS sources for VN news typically include: CafeF, VnExpress, Tuoi Tre, Thanh Nien, NDH, VCSC
- Test individual feed with: `curl -s "<feed-url>" | head -100` from VPS
- After fix: watch MCP server `newsItems` count in next poll cycle
- If service is fundamentally broken beyond a quick fix → escalate to developer with root-cause notes
