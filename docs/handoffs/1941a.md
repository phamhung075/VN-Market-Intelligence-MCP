## Problem Statement

FA cycle 2026-05-17 23:04 UTC reported:
- VCB `earnings_quality_warn=true` (OCF=1.23e15 — absurd extraction anomaly)
- FPT `earnings_quality_warn=true` (OCF/NI raw=503 — unit mismatch)

Despite `OCF_NI_RATIO_PLAUSIBILITY_LIMIT=20` guard added in Task 1930b.

---

## Root Cause Analysis

The guard code at `cashFlowTool.ts:127` is correct and fires correctly. The issue is **which column the guard reads**.

`financial_reports` table has **two OCF columns**:
- `operating_cf` — OCR/PDF extraction. **Corrupted data**: VCB=1.23e15 (raw VND not ÷1M), FPT=10,189,002 (unit mismatch).
- `operating_cash_flow` — vnstock API bridge (Task 1878a, `bridgeOCFToFinancialReports`). **Correct data**: VCB=9,947,260 triệu, FPT=4,108,450 triệu.

`cashFlowTool.ts` was only selecting `operating_cf` — the corrupted column.

The FA flow treats `ocf_ni_suppressed=true` as an anomaly signal and falls back to manual accrual computation using the raw OCF value, which produces absurd accrual ratios, hence `earnings_quality_warn=true`.

---

## Fix Applied

**File:** `apps/mcp-server/src/interface/mcp/tools/financial-reports/cashFlowTool.ts`

1. Added `operating_cash_flow` to SQL SELECT
2. Added `operating_cash_flow: number | null` to `CashFlowRow` interface
3. Computed `effectiveOcf = operating_cash_flow ?? operating_cf`
4. Added `ocf_source: "api_bridge" | "ocr"` field to `CashFlowFound` envelope
5. OCF/NI ratio computed on `effectiveOcf` (not corrupted PDF value)
6. `operating_cf` field in response now returns `effectiveOcf`

**Impact on live data (verified in container):**
- VCB Q4/2025: `operating_cf` 1.23e15 → 9,947,260 triệu | `ocf_ni_ratio` now 1.15 (passes guard, `ocf_ni_suppressed=false`)
- FPT Q4/2025: `operating_cf` 10,189,002 → 4,108,450 triệu | still suppressed (FPT `net_profit=20,225` is a separate NI OCR extraction bug — revenue stored as profit)

## Remaining Issue (Out of Scope for 1941a)

FPT `net_profit=20,225` is wrong — `vnstock_financials.net_profit_bn=2,509.52` shows correct value of 2,509,520 triệu. The `financial_reports.net_profit` field is populated from OCR extraction, not vnstock. This is a separate extraction pipeline bug. Even with correct OCF from API bridge, the NI extraction bug means FPT's ratio remains suppressed. Filing separately.
