## 2. Design Answers

### Q1: Where does EPS live? How to get current prices for P/E computation?

EPS: `vnstock_financials.eps` — latest row per ticker (ORDER BY year_report DESC, quarter DESC LIMIT 1).

Current price: reuse `currentPriceQuery("w.code")` from `priceQueries.ts`.

P/E per ticker: `price / (eps / 1000)` — note EPS is in VND (integer), price is in thousands VND
(VN market convention: price in 1000 VND units on HOSE). Confirm: price in market_prices is
stored in thousands VND (1 unit = 1,000 VND). The formula becomes:
```
pe_ticker = price_in_k_vnd / (eps_vnd / 1000)
          = price_in_k_vnd * 1000 / eps_vnd
```
If P/E is already stored in `vnstock_financials.pe`, use it directly as a sanity check / fallback
to avoid recomputing. Prefer stored `.pe` when available and non-zero; recompute from raw
eps + price only when stored pe is null/0.

### Q2: Where does compute_market_earning_yield logic live?

**Domain pure function** — `apps/mcp-server/src/domain/services/macro/marketEarningYield.ts`

Mirrors the carryTradeSignal.ts pattern exactly:
- Input: `eps[]` array of per-ticker `{ code, pe }` objects, coverage ratio
- Output: `MarketEarningYieldResult` with medianPE, earningYield, coverageRatio, computedAt
- Zero infrastructure imports
- The caller (application use-case OR the cron job) aggregates tickers, calls the pure fn,
  then stores the result

**Aggregation use-case**: `apps/mcp-server/src/application/usecases/computeMarketEarningYield.ts`
- Reads watchlist codes from DB
- Joins vnstock_financials (latest pe per code) + currentPriceQuery for live price
- Filters out null/zero pe rows
- Checks coverage >= 70%
- Calls domain pure function
- Writes result to tracked_indicators

**Scheduler job**: `apps/mcp-server/src/interface/scheduler/macro/marketEarningYieldJob.ts`
- Runs once daily after market close (e.g. 16:30 VN = 09:30 UTC)
- Calls the use-case
- Logs result; no Telegram alert (value stored in DB, surfaced via snapshot)

### Q3: How to store earning_yield in tracked_indicators?

```
indicator = 'market_earning_yield'
value     = earningYield  (e.g. 7.32 = 7.32%)
unit      = '%'
source    = 'bau_phase2'
```

Also store the companion `median_pe`:
```
indicator = 'market_median_pe'
value     = medianPE      (e.g. 13.65)
unit      = 'ratio'
source    = 'bau_phase2'
```

Two rows — keeps tracked_indicators generic (one value per row), consistent with existing
`fed_funds_rate` pattern.

### Q4: Yield spread formula, labels, thresholds?

```
yield_spread = earning_yield - max_deposit_rate_pct
             = (1 / median_PE * 100) - max_deposit_rate_pct
```

Labels (Báu methodology — "Dinh Gia" valuation signal):

| Condition                        | Label           |
|----------------------------------|-----------------|
| earning_yield > deposit_rate + 2 | CHEAP           |
| earning_yield > deposit_rate     | FAIRLY_VALUED   |
| earning_yield <= deposit_rate    | EXPENSIVE       |

Threshold rationale: a 2pp excess earning yield over risk-free deposit = margin of safety
required to compensate equity risk premium in VN market context.

Edge cases:
- Either input is 0 → label = UNKNOWN, reasoning = "Data unavailable"
- coverage < 70% → refuse computation, return `{ refused: true, coverageRatio }` — no label

### Q5: Where does [Dinh Gia] appear in formatMacroSnapshot()?

In `formatMacroSnapshot()`, add a `dinhGia?: DinhGiaInputs` optional parameter alongside
the existing `thienThoi?: ThienThoiInputs`.

Insertion point: **after** `formatThienThoi()` block, before `[Commodity Prices]`.

Format:
```
[Dinh Gia — Asset Valuation]
  Market Earning Yield:  7.32% (median P/E: 13.65, coverage: 28/30)
  Max Deposit Rate:      5.50%
  Yield Spread:          +1.82% — FAIRLY_VALUED
```

When data unavailable:
```
[Dinh Gia — Asset Valuation]
  unavailable
```

The DB read in the tool handler follows the `thienThoi` pattern already in
`get_macro_snapshot`: query `tracked_indicators` for latest `market_earning_yield` and
`market_median_pe` rows, plus `sbv_rates.max_deposit_rate_pct`. All three reads are
already in the DB with no new fetches needed at snapshot time.

## 5. Risk Flags

### RISK-1: EPS unit mismatch (HIGH)
`vnstock_financials.eps` is INTEGER in VND. VN market prices in market_prices/daily_ohlcv
are stored in thousands of VND (1 unit = 1,000 VND). The P/E formula must account for
this unit difference. Prefer using the pre-computed `pe` column from vnstock_financials
when non-null/non-zero; recompute from price/eps only as fallback. Developer must verify
the unit assumption against a known ticker (e.g. VCB) before going live.

### RISK-2: EPS staleness (MEDIUM)
vnstock_financials rows have no TTL. A ticker's latest EPS may be from Q3 last year if
vnstock sync hasn't run. The domain function should include `dataAsOf` (latest year_report,
quarter seen) in its output so the snapshot can show how stale the data is.

### RISK-3: Coverage < 70% is the common startup state (MEDIUM)
On a fresh DB, vnstock_financials may be empty. The job must log a WARN (not ERROR) and
skip the tracked_indicators write silently. The snapshot section shows "unavailable" —
not a crash path.

### RISK-4: No new schema migrations needed (LOW, verified)
tracked_indicators already supports the new key strings via UNIQUE(indicator, source, hour_bucket)
ON CONFLICT REPLACE. No ALTER TABLE required.

### RISK-5: DDD violation guard (LOW)
`computeMarketEarningYield.ts` use-case must NOT import from `domain/` directly for DB
access. DB reads stay in the use-case; the pure domain function receives plain numbers only.
