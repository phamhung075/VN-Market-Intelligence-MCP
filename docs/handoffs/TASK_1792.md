# TASK_1792 — Conviction signal sender debounce

## Problem
`[BCTC-1345b]` low-confidence bug alerts fired on every call to `parseBctcReport`
when the same ticker+quarter was evaluated in a rapid retry loop. Reports 2683–2692
showed "conviction signal skipped for VCB 2025-Q4" repeated 10× within 3 minutes.

## Root cause
`storeReport()` in `parseBctcReport.ts` sent `sendTelegramBug(financialMsg)` via
fire-and-forget `import()` on every call. No memory of prior sends existed.

## Fix applied

### New files
- `apps/mcp-server/src/infrastructure/db/bctcSignalDebounce.ts`
  - `isBctcSignalDebounced(db, actionCode, periodKey, cooldownHours)` — queries `bctc_signal_debounce` for a recent entry within the cooldown window.
  - `recordBctcSignalSent(db, actionCode, periodKey)` — upserts a row (INSERT OR REPLACE, refreshes `sent_at`).
  - `BCTC_SIGNAL_DEBOUNCE_HOURS = 1` — exported constant.

### Modified files
- `apps/mcp-server/src/infrastructure/db/schema-system.ts`
  - Added `bctc_signal_debounce` table with `PRIMARY KEY (action_code, period_key)`.
  - Added supporting index `idx_bctc_signal_debounce_sent`.

- `apps/mcp-server/src/application/usecases/parseBctcReport.ts`
  - Imports `isBctcSignalDebounced`, `recordBctcSignalSent`, `BCTC_SIGNAL_DEBOUNCE_HOURS`.
  - Wraps `sendTelegramBug` in debounce guard: check → record → send (or skip).

### Test file
- `apps/mcp-server/src/__tests__/1792-conviction-debounce.test.ts`
  - 5 tests: 10-rapid-fires→1-message, cross-ticker isolation, expired cooldown (2h old row), DB persistence, isBctcSignalDebounced true/false.
  - All 5 pass. No regressions in adjacent BCTC tests (66+39+67+36 = 208 pass, 0 fail).

## DDD compliance

- `parseBctcReport.ts` (application layer) imports from infrastructure — allowed.
- `financialFiguresValidator.ts` (domain) — untouched.
