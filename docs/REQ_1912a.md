## 2. Endpoint Inventory

Source: `apps/api-gateway/src/interface/handlers.ts` + `src/index.ts` (inspected directly).

| Method | Path | Request | Response shape | HTTP codes |
|--------|------|---------|---------------|------------|
| GET | `/health` | — | `AggregatedHealth` JSON (see below) | 200 (ok/degraded), 503 (down) |
| GET | `/health/:service` | path param `:service` | `ServiceHealthResult` JSON (see below) | 200, 503, 404 `{"error":"Unknown service: <name>"}` |
| GET | `/health-dashboard` | — | self-contained HTML (auto-refresh 60s) | 200 |
| ANY | `/api/*` | passthrough | upstream body verbatim | upstream status |
| ANY | `/:service/*` | path param `:service` | upstream body verbatim | 200-5xx; 404 `{"error":"Unknown service: <name>"}`, 502 `{"error":"Upstream <name> unreachable: <err>"}` |

**AggregatedHealth shape:**
```json
{
  "status": "ok" | "degraded" | "down",
  "services": { "<name>": "ok" | "degraded" | "down", ... },
  "latencies": { "<name>": 42, ... },
  "checkedAt": "2026-05-14T10:00:00.000Z"
}
```

**ServiceHealthResult shape:**
```json
{
  "service": "<name>",
  "status": "ok" | "degraded" | "down",
  "latencyMs": 42,
  "error": "<optional string>"
}
```

**Proxy path rules:**
- `api` service (noProbe=true): full request path forwarded verbatim (`/api/push-news` → `/api/push-news`)
- All other services: strip leading `/:service` segment (`/stock/health` → `/health`)
- Proxy timeout: `svc.timeoutMs * 5` (default 10 000 ms)
- Health probe timeout: 2 000 ms per service

`PORT` (default 4000), `MCP_URL`, `PDF_URL`, `RAG_URL`, `TA_URL`, `MACRO_URL`, `STOCK_URL`, `KINH_DICH_URL`, `ALERT_URL`, `NEWS_URL`

## 3. Acceptance Criteria

**AC-1 (Build):** `golang:1.22-alpine` multi-stage Dockerfile in `apps/api-gateway-go/` builds cleanly — `docker build` exits 0, no CGO required (gateway has no SQLite).

**AC-2 (JSON parity — health):** `GET /health` and `GET /health/:service` return byte-for-byte identical JSON field names, value types, and HTTP status codes as the TS gateway under equivalent upstream mock conditions. `AggregatedHealth` and `ServiceHealthResult` shapes must match exactly.

**AC-3 (Proxy parity):** `ANY /api/*` forwards with full path verbatim (no prefix strip). `ANY /:service/*` strips leading segment. Error envelopes `{"error":"..."}` on 404/502 match TS shape exactly.

**AC-4 (Dashboard):** `GET /health-dashboard` returns HTTP 200 with `content-type: text/html`, contains all 9 service names, renders `status-up` / `status-down` CSS classes, includes `meta http-equiv="refresh" content="60"`, contains no external CDN URLs in `<link>` or `<script>` tags.

**AC-5 (Go test suite):** `go test ./...` passes with equivalent assertions covering all 5 Vitest test files: `aggregate-health-service.test.ts` (domain unit), `static-service-registry.test.ts` (infra unit), `aggregate-health-usecase.test.ts` (integration), `1841a-health-dashboard.test.ts` (handler + HTML), `1892b-api-push-routes.test.ts` (proxy routing). Table-driven tests in Go replace `describe/it` blocks. No real network calls in unit/integration tests.

**AC-6 (MCP-server Vitest unchanged):** mcp-server full Vitest suite 8804/8804 passes unmodified after docker-compose gateway swap — zero consumer-side regression.

**AC-7 (log/slog schema):** Every inbound request produces a structured JSON log line via `log/slog`. Required fields: `time`, `level`, `msg`, `method`, `path`, `status`, `latency_ms`. Schema documented in `apps/api-gateway-go/README-log-schema.md`. At least one sampled log line included in that file.

**AC-8 (Rollback):** docker-compose image-tag rollback validated — reverting `api-gateway` service to previous image tag in `docker-compose.yml` restores prior behaviour in one command (`docker-compose up -d api-gateway`). Zero data state in gateway (no SQLite, no volume mounts) means rollback is stateless.

**AC-9 (DDD package layout):** Go package structure maps to DDD layers per brief § 3.1:
- `pkg/domain/` — models.go, ports.go, services.go (pure logic, no I/O)
- `pkg/application/` — aggregate.go (orchestrates domain via port)
- `pkg/infrastructure/` — healthchecker.go (net/http client, goroutines per service), registry.go (StaticServiceRegistry)
- `pkg/interface/http/` — router.go (net/http or chi router, all handlers)
- `cmd/server/` — main.go (wiring only)

**AC-10 (24h smoke window):** After Go gateway is deployed to production Docker fleet, a 24h monitoring window is observed before Phase 2 (alert-engine) is dispatched. Gate: `GET /health` returns 200 and all 9 services remain enumerated in response at end of window.

**AC-11 (healthz deviation resolved):** `/healthz` referenced in architect brief § 3.1 and TASKS.md does NOT exist in the current TS gateway source. Before implementation begins, architect or PO must confirm whether `/healthz` is (a) a new alias to add in Go only, (b) a typo for `/health`, or (c) to be skipped. See § 5.

## 4. Dev Role Assignment

No `dev-go` or Go-capable agent exists in the current agent roster. Before PM creates the dev branch and sprintifies, **PO and Architect must decide one of:**

**Option A — Extend `dev-api-gateway` agent:** Add a lazy-load Go competency block to `.claude/agents/dev-api-gateway.md`. Trigger: `go_migration`. Loads Go 1.22 patterns, `net/http` handler idioms, table-driven test conventions, `log/slog` usage. Fastest path — no new agent file.

**Option B — Spawn `dev-go-gateway` specialist:** New agent file `.claude/agents/dev-go-gateway.md` with Go-first identity (no TS). Cleaner separation if more Go services follow (P2 alert-engine, P3 stock-price). Higher setup cost (~1 agent-father cycle).

**Recommendation:** Option A for Phase 1 (lowest overhead). Reassess after Phase 1 ships — if P2 alert-engine proceeds, Option B pays off.

**Blocking condition:** PM cannot create task branch or assign sprint until this decision is recorded in TASKS.md or an agent file update is committed.
