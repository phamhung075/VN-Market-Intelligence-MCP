# REQ-1315: Cost-Push Cascade Rules — Logistics / Utilities / Construction Materials

status: READY_FOR_ARCHITECT
sprint: 1315
po_vision: Fill cascade coverage gaps for commodity cost-push events affecting logistics, utilities, and construction materials sectors.

## User Story

As a Vietnamese stock investor using Claude,
I want the cascade engine to fire alerts for GMD, VVN (logistics), POW, HNG (utilities), CTD, HTI (construction materials) when upstream commodity prices move,
So that I receive cost-push impact signals before these stocks react, not after.

---

## Gap Summary (confirmed from codebase)

| Sector | Domain | Tickers | Missing rule |
|---|---|---|---|
| Logistics | `logistics` | GMD, VVN | oil rise → fuel cost (only generic "giá dầu tăng" exists at line 981, but no fuel-cost-specific VN phrases) |
| Utilities | `utilities` | POW, HNG | coal/gas price move → COGS impact (zero rules for `utilities` on commodity input cost) |
| Construction materials | `construction` | CTD, HTI | steel/cement price rise → margin squeeze (zero rules for input-cost squeeze — only capex/infrastructure-demand rules exist) |
| Sentiment | `sentimentClassifier` | n/a | no "cost-push" compound pattern; generic "cost" too broad |

## Functional Requirements

### FR-1: Logistics fuel-cost cascade rules

- **Description**: Extend `SECTOR_RULES` with VN-language fuel-cost keywords for logistics domain. Existing rules at ~981 use only EN/generic terms; VN phrases "chi phí xăng dầu", "cước vận tải tăng do xăng" are unmatched.
- **Input**: news summary containing VN/EN fuel-cost phrases
- **Output**: `CausalChainEntry` for `logistics` domain, direction `down`, confidence 0.72
- **Business rule**: Fuel is ~30-40% of trucking/maritime OPEX. Oil rise → fuel surcharge → GMD margin pressure. Rule must fire BEFORE existing generic logistics oil rule (first-match-wins) — insert above line 979.
- **Keywords to add**:
  - VN: `"chi phí xăng dầu tăng"`, `"cước nhiên liệu tăng"`, `"phí nhiên liệu tăng"`, `"giá xăng tăng"`, `"xăng dầu tăng giá"`
  - EN: `"fuel surcharge"`, `"bunker fuel cost"`, `"trucking fuel cost"`
- **DDD layer**: domain — `src/domain/services/cascadeEngine.ts` ~line 979

### FR-2: Logistics fuel-cost bullish rule (oil fall)

- **Description**: Symmetric inverse rule — oil/fuel fall reduces OPEX, GMD margin expands.
- **Input**: fuel-cost-down phrases
- **Output**: `CausalChainEntry` for `logistics` domain, direction `up`, confidence 0.68
- **Business rule**: Insert paired with FR-1 for symmetry. Existing "giá dầu giảm" rule at ~988 covers generic; this adds VN specifics.
- **Keywords to add**:
  - VN: `"giá xăng giảm"`, `"chi phí nhiên liệu giảm"`, `"xăng dầu giảm giá"`
  - EN: `"fuel cost down"`, `"bunker fuel down"`
- **DDD layer**: domain — `src/domain/services/cascadeEngine.ts` ~line 988

### FR-3: Utilities coal/gas input-cost cascade rules

- **Description**: Add `SECTOR_RULES` entries for `utilities` domain triggered by coal or gas price moves. POW (Petrovietnam Power) and HNG (Hà Nội Gas) have coal/gas as primary fuel input — no rules exist today for this path.
- **Input**: news about coal price rise or gas price rise
- **Output**: `CausalChainEntry` for `utilities` domain
- **Business rules**:
  - Coal price rise → `utilities` bearish (direction `down`, confidence 0.75): thermal power plants (POW) face higher fuel COGS
  - Gas price rise → `utilities` bearish (direction `down`, confidence 0.70): gas-fired plants and city gas distribution (HNG) margin squeeze
  - Coal price fall → `utilities` bullish (direction `up`, confidence 0.68)
  - Gas price fall → `utilities` bullish (direction `up`, confidence 0.65)
- **Keywords — coal rise**:
  - VN: `"giá than tăng"`, `"than đá tăng giá"`, `"chi phí than tăng"`, `"giá than nhiệt điện tăng"`
  - EN: `"coal price rise"`, `"coal price up"`, `"thermal coal surge"`
- **Keywords — gas rise**:
  - VN: `"giá khí đốt tăng"`, `"giá LNG tăng"`, `"giá khí tự nhiên tăng"`, `"chi phí khí đốt tăng"`
  - EN: `"gas price rise"`, `"LNG price rise"`, `"natural gas price up"`, `"gas price surge"`
- **Keywords — coal fall**: `"giá than giảm"`, `"coal price fall"`, `"coal price down"`, `"than đá giảm giá"`
- **Keywords — gas fall**: `"giá khí đốt giảm"`, `"LNG price fall"`, `"gas price fall"`, `"giá LNG giảm"`
- **DDD layer**: domain — `src/domain/services/cascadeEngine.ts` (insert near existing utilities block ~line 1565)

### FR-4: Construction materials input-cost cascade rules

- **Description**: Add `SECTOR_RULES` for `construction` domain triggered by steel/cement price movements as input costs (distinct from existing demand-side rules). CTD and HTI are construction contractors — steel rebar and cement are their two largest input cost lines.
- **Input**: news about steel or cement price moves framed as input costs
- **Output**: `CausalChainEntry` for `construction` domain
- **Business rules**:
  - Steel input rise → `construction` bearish (direction `down`, confidence 0.73): rebar is ~20-25% of project COGS for contractors
  - Cement price rise → `construction` bearish (direction `down`, confidence 0.68)
  - Steel/cement fall → `construction` bullish (direction `up`, confidence 0.65): margin expansion for fixed-price contracts
- **Keywords — steel input rise**:
  - VN: `"giá thép xây dựng tăng"`, `"giá sắt thép tăng"`, `"chi phí thép tăng"`, `"thép xây dựng tăng giá"`, `"vật liệu xây dựng tăng giá"`
  - EN: `"construction steel price rise"`, `"rebar price rise"`, `"steel input cost rise"`
- **Keywords — cement rise**:
  - VN: `"giá xi măng tăng"`, `"xi măng tăng giá"`, `"chi phí xi măng tăng"`
  - EN: `"cement price rise"`, `"cement price up"`
- **Keywords — input cost fall**:
  - VN: `"giá thép xây dựng giảm"`, `"giá xi măng giảm"`, `"vật liệu xây dựng giảm giá"`
  - EN: `"construction material cost fall"`, `"rebar price fall"`, `"cement price fall"`
- **Ordering constraint**: New construction input-cost rules must be inserted AFTER existing demand-side construction rules (lines ~994–1028) to avoid first-match-wins conflict. Construction demand rules target "đầu tư công" (infrastructure spending); input-cost rules target commodity price keywords — no overlap risk, but ordering must be explicit in comments.
- **DDD layer**: domain — `src/domain/services/cascadeEngine.ts` (after line 1028)

### FR-5: SentimentClassifier cost-push pattern

- **Description**: Add compound "cost-push" bearish pattern to `sentimentClassifier.ts` VN_BEARISH list. Current generic `"chi phí tăng"` (weight 2) fires on any cost mention. New compound phrases must be weight 3 to beat bullish "tăng" signals in mixed text.
- **Input**: news text containing cost-push commodity phrases
- **Output**: `classifySentiment()` returns direction `bearish` for cost-push commodity news
- **Business rule**: A text like "giá than tăng mạnh gây áp lực chi phí điện" currently risks neutral/bullish due to "tăng" + "tăng mạnh" weights. Compound cost-push phrase weight 3 guarantees net bearish.
- **New entries for VN_BEARISH** (weight 3):
  - `"giá đầu vào tăng"` — generic input cost rise
  - `"chi phí nguyên liệu tăng"` — raw material cost rise
  - `"giá than tăng gây áp lực"` — coal cost pressure (weight 4 — compound)
  - `"giá khí đốt tăng gây áp lực"` — gas cost pressure (weight 4 — compound)
  - `"giá xăng tăng gây áp lực"` — fuel cost pressure (weight 4 — compound)
  - `"vật liệu xây dựng tăng giá"` — construction material cost rise (weight 3)
- **New entries for EN_BEARISH** (weight 3):
  - `"cost-push"` — direct term
  - `"input cost inflation"` — common EN phrase
  - `"commodity cost pressure"` — broad EN
  - `"margin compression"` — result signal (weight 2)
- **DDD layer**: domain — `src/domain/services/sentimentClassifier.ts` ~line 196 (insert after existing cost-pressure block)

### FR-6: ClimateImpactMapper — commodity cost mapping (new file)

- **Description**: Create `src/domain/services/climateImpactMapper.ts` mapping climate/commodity events to affected sector cost structures. This is a pure lookup table (no I/O) enabling future extension without growing cascadeEngine further.
- **Input**: commodity type string + direction string
- **Output**: `CostImpactMap[]` — array of `{ domain, costDriver, direction, confidence, rationale }`
- **Interface**:
```typescript
export interface CostImpactMap {
  commodity: string;      // 'coal' | 'gas' | 'oil' | 'steel' | 'cement'
  direction: 'up' | 'down';
  domain: DomainType;
  costDriver: string;     // human-readable cost line, e.g. "fuel OPEX ~30-40%"
  confidence: number;
  rationale: string;      // Vietnamese + English
}

export function getCostImpactMaps(commodity: string, direction: 'up' | 'down'): CostImpactMap[];
```
- **Initial data** (10 entries minimum):

| commodity | direction | domain | costDriver | confidence |
|---|---|---|---|---|
| oil | up | logistics | fuel OPEX ~30-40% | 0.72 |
| oil | down | logistics | fuel OPEX ~30-40% | 0.68 |
| coal | up | utilities | fuel COGS ~60-70% thermal | 0.75 |
| coal | down | utilities | fuel COGS ~60-70% thermal | 0.68 |
| gas | up | utilities | fuel COGS ~50% gas-fired | 0.70 |
| gas | down | utilities | fuel COGS ~50% gas-fired | 0.65 |
| steel | up | construction | rebar ~20-25% project COGS | 0.73 |
| steel | down | construction | rebar ~20-25% project COGS | 0.65 |
| cement | up | construction | cement ~10-15% project COGS | 0.68 |
| cement | down | construction | cement ~10-15% project COGS | 0.62 |

- **DDD layer**: domain — `src/domain/services/climateImpactMapper.ts` (new file)
- **Constraint**: Zero imports from infrastructure/ or application/. Only imports: `DomainType` from `bctc-schema`.

- `chain.entries` contains a `logistics` domain entry with `direction: "down"`
- `chain.watchlistImpacts` includes GMD with `impactDirection: "down"`
- `chain.matchedRules` contains a key starting with `"logistics_fuel_cost"`
