# REQ-1315 — VPBankS/OKX Crypto Partnership Cascade Rules

**Sprint:** 1315
**Size:** S
**DDD Layer:** domain (SECTOR_RULES in cascadeEngine.ts)
**Status:** Ready for Architect

---

## Problem Statement

Article: "VPBankS chính thức tăng vốn lên 10.000 tỷ sau cú bắt tay với OKX" (impact 9, BULLISH)

Current cascade output: 4 generic banks (VCB/BID/SHB/EIB) at 50% confidence.

Three gaps:

1. **VPB direct signal missing** — VPBankS is the securities subsidiary of VPB (VPBank). Any capital raise or strategic partnership at VPBankS directly strengthens the parent bank VPB. No rule currently maps this subsidiary relationship.

2. **Securities/fintech sector missing** — OKX partnership signals crypto custody competition pressure on all securities brokers (SSI, VCI, VIX, VND). No rule triggers `domain: "securities"` for crypto/digital-asset headlines.

3. **Wrong sentiment for generic banks** — Banks WITHOUT a digital-asset strategy (VCB, BID, CTG, ACB) should be NEUTRAL (competitive threat, not direct beneficiary), not BULLISH. Banks WITH digital-asset strategy (VPB, TCB) should be BULLISH.

## Functional Requirements

### FR-1 — VPBankS subsidiary direct cascade to VPB (domain: banking)

**Trigger keywords** (any one match):
```
"vpbanks", "vp bank securities", "vpbank securities",
"tăng vốn vpbanks", "vpbanks tăng vốn",
"okx", "vpbanks.*okx", "okx.*vpbanks"
```

**Rule structure:**
- `domain: "banking"`
- `direction: "up"`
- `confidence: 0.88`
- `affected_actions`: `[{ code: "VPB", direction: "up" }, { code: "TCB", direction: "up" }]`
  - VPB: direct parent of VPBankS (subsidiary capital raise = parent P&L improvement)
  - TCB: Techcombank has existing digital-asset / crypto custody strategy (peer beneficiary)
- `requireAnyKeyword`: `["tăng vốn", "vốn", "hợp tác", "partnership", "okx", "crypto", "digital asset", "tài sản số"]`

**Title:** `"VPBankS tăng vốn/hợp tác OKX — VPB (công ty mẹ) và TCB (chiến lược tương đồng) hưởng lợi trực tiếp"`

### FR-2 — Crypto/digital-asset competition signal to securities brokers (domain: securities)

- `confidence: 0.72`
- `affected_actions`: `[{ code: "SSI", direction: "up" }, { code: "VCI", direction: "up" }, { code: "VIX", direction: "up" }, { code: "VND", direction: "up" }]`
- `requireAnyKeyword`: `["chứng khoán", "securities", "vpbanks", "môi giới", "broker", "lưu ký", "custody"]`
- Title: `"Hợp tác crypto/lưu ký tài sản số — tín hiệu cạnh tranh/cơ hội mới cho CTCK (SSI/VCI/VIX/VND)"`

### FR-3 — Generic banking domain rule: NEUTRAL (not BULLISH) for crypto headlines

The existing generic banking rule currently fires BULLISH for any financial-sector news. Crypto partnership news should produce `direction: "neutral"` for banks without digital strategy.

**Implementation approach:** Add `excludeKeywords` to existing broad banking BULLISH rules when crypto/OKX context is present, OR add a new `direction: "neutral"` banking rule with higher specificity for crypto headlines that fires first (first-match-wins per domain).

**Rule structure (new, insert BEFORE generic banking rules):**
- `keywords`: `["okx", "crypto custody", "lưu ký tài sản số", "tài sản số vietnam", "sàn tiền mã hóa"]`
- `domain: "banking"`
- `direction: "neutral"`
- `confidence: 0.65`
- `title`: `"Crypto partnership/lưu ký tài sản số — ngân hàng truyền thống không có chiến lược digital-asset: tác động trung lập"`
- No `affected_actions` — generic banking domain entry, confidence 0.65 propagates to watchlist banking stocks

**Note:** FR-1 sets VPB/TCB to BULLISH via `affected_actions`. FR-3 sets domain-level banking entry to NEUTRAL. The `affected_actions` override in Step 2h (line 2918–2930) fires AFTER domain entries, so VPB/TCB get their own BULLISH action entry while other banking stocks see NEUTRAL from the domain entry. This is the correct separation.

| Case | Handling |
|---|---|
| Article mentions "OKX" in non-VN context (e.g., global OKX news) | `requireAnyKeyword` for FR-1 requires co-occurrence of capital/partnership terms |
| VPB already in watchlist via generic banking domain rule | `affected_actions` in Step 2h creates a separate action-level entry — no conflict, higher specificity wins for VPB display |
| "tài sản số" in BCTC context (balance sheet asset, not crypto) | `requireAnyKeyword` for FR-2 requires co-occurrence of custody/securities context |
| VCI / VIX not in current watchlist | `affected_actions` bypass watchlist check (line 2921: "bypass the watchlist membership check") — confirmed safe |
| TCB already matched by a separate TCB-specific rule | First-match-wins per domain applies to domain entries only; `affected_actions` at Step 2h adds action entry independently |
| Article impact score < 7 | No change — cascade engine fires regardless of score; caller filters display |

```

  { actionCode: "VPB", domain: "banking" },

expected:
  chain.entries.find(e => e.level === "action" && e.affectedActions.includes("VPB")).sentiment === "bullish"
```
