# REQ-075: get_pipeline_health MCP Tool

status: READY_FOR_ARCHITECT
sprint: 075
po_vision: Give the operator a single MCP tool that answers "is the news pipeline working?"

## User Story

As a Vietnamese stock investor using Claude Desktop,
I want to call `get_pipeline_health` and see how many news rows were written today, when
the last row arrived, which sources contributed, and whether the VPS push endpoint was called,
So that I can detect silent pipeline failures from Claude Desktop without SSH access.

---

## Functional Requirements

### FR-1: Count rag_analyses rows for today and yesterday (GMT+7)

- Description: Query `rag_analyses` and return row counts bucketed by the Vietnamese market
  day (midnight–midnight in Asia/Ho_Chi_Minh = UTC+7).
- Input: Current wall-clock time (injected as a parameter in tests; `Date.now()` in production).
- Output:
  - `ragRows.today` — INTEGER count of rows where `created_at` >= midnight today (UTC+7).
  - `ragRows.yesterday` — INTEGER count of rows where `created_at` is in the previous day (UTC+7).
- Business rule: "Midnight UTC+7" = UTC timestamp `T` where `T mod 86400s == -7h mod 86400s`.
  Computed as: start-of-day-UTC+7 = `floor((nowMs + 7*3600*1000) / 86400000) * 86400000 - 7*3600*1000`.
  Both bounds computed server-side in TypeScript before being passed to SQLite as ISO strings.
  Do NOT use SQLite `datetime('now', '+7 hours')` — use pre-computed strings for testability.
- DDD layer: application

### FR-2: Last insert timestamp and staleness in minutes

- Description: Find the most recently inserted row in `rag_analyses` and report its
  `created_at` plus how many minutes have elapsed since then.
- Input: (same DB query)
- Output:
  - `ragRows.lastInsertedAt` — ISO 8601 string (e.g. `"2026-04-13T10:30:00.000Z"`), or `null`
    if the table has zero rows.
  - `ragRows.staleMins` — INTEGER: `floor((nowMs - lastInsertedAtMs) / 60000)`, or `null`
    if the table has zero rows.
- Business rule: A staleness of > 90 minutes during VN trading hours (09:00–11:30, 13:00–14:45
  ICT Mon–Fri) signals a likely pipeline failure. The tool reports the number only; the calling
  agent (Claude) interprets whether it is alarming given the trading window context.
- DDD layer: application

### FR-3: Per-source breakdown of today's rows (domain extraction from source_url)

- Description: Group today's `rag_analyses` rows by the hostname extracted from `source_url`,
  return a sorted array of `{ source: string; count: number }`.
- Input: Today's rows in `rag_analyses` (same time window as FR-1).
- Output:
  - `sources` — array of `{ source: string; count: number }`, sorted by `count DESC`.
    - `source` is the eTLD+1 hostname extracted from `source_url`
      (e.g. `"cafef.vn"`, `"vnexpress.net"`, `"baodautu.vn"`).
    - Rows with `source_url IS NULL` or empty string are grouped under `source: "(unknown)"`.
- Business rule: Use SQLite `substr` + `instr` to extract domain inline, OR extract in
  TypeScript post-query (preferred for testability). The TypeScript approach: call
  `new URL(sourceUrl).hostname` wrapped in try/catch; fallback to `"(unknown)"` on parse error.
- Edge case: If `sources` is empty (no rows today), return an empty array `[]`, not null.
- DDD layer: application

### FR-4: VPS push-news call count in last 24 hours

- Description: Count rows in `vps_push_log` where `service = 'news'` and
  `pushed_at >= now - 24h` and `status = 'ok'`.
- Input: DB query against `vps_push_log`.
- Output:
  - `vpsPushLast24h` — INTEGER count of successful news pushes in last 24h.
    Returns `null` (not 0) if the `vps_push_log` table does not exist yet
    (detected via `PRAGMA table_info` or try/catch on the query).
- Business rule: A count of 0 (table exists but no pushes) means the VPS `vn-news-fetch.service`
  has not pushed in 24h — strong signal of VPS-side failure. Null means the table was never
  created (pre-production environment).
- DDD layer: application (infrastructure call wrapped in try/catch)

### FR-5: Evening report last-run timestamp

- Description: Find the most recently modified `reports/YYYY-MM-DD-evening.json` file and
  return its mtime as an ISO string.
- Input: Filesystem glob of `reports/*-evening.json` relative to `process.cwd()`.
- Output:
  - `eveningReportLastRun` — ISO 8601 string of the file's `mtime`, or `null` if no evening
    report file exists yet.
- Business rule: Files are named `YYYY-MM-DD-evening.json`. Read directory listing, sort by
  mtime DESC, take the first entry. Use `statSync` (already imported in `systemTools.ts`).
- DDD layer: application (filesystem I/O)

### FR-6: Tool registration in registerSystemTools

- Description: Register `get_pipeline_health` in `registerSystemTools()` inside
  `src/interface/mcp/tools/systemTools.ts`. The tool takes zero required parameters.
- Input: No user parameters (the tool is a zero-argument diagnostic snapshot).
- Output: MCP tool response with `content: [{ type: "text", text: JSON.stringify(result, null, 2) }]`
  where `result` is the `PipelineHealthResult` object (see Data Contracts).
- Business rule: Tool count increments from 96 to 97. Update `docs/data/tool-registry.json`
  and `docs/data/project-stats.json`.
- DDD layer: interface

## Non-Functional Requirements

- Performance: All SQLite queries must complete in < 50 ms on the production DB (market.db,
  expected to be < 500 MB). Use indexed `created_at` column (index `idx_rag_created` already
  exists). No full table scans without index.
- Data freshness: The tool is a point-in-time snapshot — no caching. Each call hits SQLite
  directly.
- Language: Output is structured JSON (no prose). Claude Desktop renders it; no i18n needed.
- Error handling: If any sub-query fails, the corresponding field is `null` and the error is
  logged via `logger.warn`. The tool must not throw — it must always return a partial result.
- Testability: `getPipelineHealth` must accept injected `db`, `nowMs`, and `reportsDir` so
  unit tests can run without the real production DB or filesystem.

---

## Edge Cases and Data Quality

- [ ] Empty table: `rag_analyses` has 0 rows — `today=0`, `yesterday=0`, `lastInsertedAt=null`,
      `staleMins=null`, `sources=[]`.
- [ ] `vps_push_log` table absent (pre-production or fresh install) — return `vpsPushLast24h: null`,
      not an error.
- [ ] `source_url` is `null` or `""` for rows from the BCTC pipeline (financial reports) —
      group under `"(unknown)"`.
- [ ] `source_url` is a malformed URL (e.g. relative path, bare hostname) — `new URL()` throws;
      fallback to `"(unknown)"`.
- [ ] Midnight boundary crossing: test runs at 23:59 ICT and again at 00:01 ICT — today/yesterday
      counts must switch correctly.
- [ ] No evening reports directory or no `*-evening.json` files — `eveningReportLastRun: null`.
- [ ] Multiple evening report files — return only the mtime of the newest file (by mtime, not filename).
- [ ] Clock skew: `staleMins` can be negative if `created_at` is in the future (clock drift on
      VPS). Clamp to 0 minimum.

## Implementation Notes for Architect

### GMT+7 day boundary computation (TypeScript)

```typescript
// Do NOT use SQLite datetime() for timezone math — compute bounds in TS.
const OFFSET_MS = 7 * 3600 * 1000;
const todayStartUtcMs = Math.floor((nowMs + OFFSET_MS) / 86400000) * 86400000 - OFFSET_MS;
const yesterdayStartUtcMs = todayStartUtcMs - 86400000;
const todayStartIso = new Date(todayStartUtcMs).toISOString();
const yesterdayStartIso = new Date(yesterdayStartUtcMs).toISOString();
// today:     created_at >= todayStartIso
// yesterday: created_at >= yesterdayStartIso AND created_at < todayStartIso
```

### Domain extraction (TypeScript, post-query)

```typescript
function extractDomain(sourceUrl: string | null): string {
  if (!sourceUrl) return "(unknown)";
  try {
    return new URL(sourceUrl).hostname;
  } catch {
    return "(unknown)";
  }
}
```

### vps_push_log safety pattern

```typescript
try {
  const row = db.query<{ cnt: number }, [string, string]>(
    `SELECT COUNT(*) as cnt FROM vps_push_log
     WHERE service = 'news' AND status = 'ok' AND pushed_at >= ?`,
  ).get(since24hIso);
  vpsPushLast24h = row?.cnt ?? 0;
} catch {
  vpsPushLast24h = null; // table does not exist
}
```

### Evening report mtime (node:fs)

```typescript
import { readdirSync, statSync } from "node:fs";
import { join } from "node:path";

function getEveningReportLastRun(reportsDir: string): string | null {
  try {
    const files = readdirSync(reportsDir)
      .filter(f => f.endsWith("-evening.json"))
      .map(f => ({ f, mtime: statSync(join(reportsDir, f)).mtimeMs }))
      .sort((a, b) => b.mtime - a.mtime);
    if (files.length === 0) return null;
    return new Date(files[0]!.mtime).toISOString();
  } catch {
    return null;
  }
}
```
