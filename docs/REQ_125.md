# REQ-125: France Morning Briefing — TA Signal Detail

## Business Goal

The France user receives a morning Telegram digest before each VN trading day. Currently the TA section says "Tin hieu ky thuat (TA): N tin hieu" — a count with no actionable detail. Since the OHLCV pipeline is now healthy (8-10 rows per watchlist ticker post Sprints 121-124), `defaultComputeTa` returns real RSI and MA20 signals. Replace the count with a top-3 list of non-neutral signals so the user knows which watchlist stocks are overbought/oversold before the session opens.

## Scope

| Area | Detail |
|------|--------|
| IN | `franceSummaryJob.ts` — add `fetchTaSignals()` + update `formatFranceSummaryVI` |
| IN | TDD: 4 test cases covering formatted output, empty fallback, full job integration, crash safety |
| OUT | Evening summary, alert pipeline, VPS proxies, OHLCV aggregation |

## Acceptance Criteria

| ID | Criterion |
|----|-----------|
| AC-1 | `formatFranceSummaryVI` with `taSignals=[{code:"VHM",rsiStatus:"overbought",rsi14:78.2,priceVsMa20:"above"}]` → message contains "VHM" and "qua mua" |
| AC-2 | `formatFranceSummaryVI` with empty `taSignals` → message contains "Khong co tin hieu ky thuat" |
| AC-3 | `runFranceSummary` with DB containing ≥8 daily_ohlcv rows for a ticker → sent message includes ticker code + RSI/MA20 status |
| AC-4 | `runFranceSummary` with empty daily_ohlcv → no crash, sends with "Khong co tin hieu" |
| AC-5 | `bun tsc --noEmit` 0 errors, full suite 0 new failures |

## Key Design Decisions

- Max 3 non-neutral signals (overbought RSI>70, oversold RSI<30, or price vs MA20 if RSI neutral)
- Watchlist codes from `watchlist` table (same query as morning briefing movers)
- `alreadySentToday` dedup guard and all existing France summary behavior unchanged
- `TaSignalRow` type = subset of `TaSignal` (code, rsi14, rsiStatus, priceVsMa20, ma20)
- Sort by RSI deviation from 50 descending (most extreme signal first)
