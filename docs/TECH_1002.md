# TECH-1002: Anonymous SSC PDF Attribution

status: APPROVED_BY_ARCHITECT
req_ref: TASKS.md#1002 (Report 997)

---

## Problem Statement

BCTC PDF filenames downloaded from HOSE/HNX/UPCOM portals are frequently opaque
(e.g. `document.pdf`, `attachment_20250401.pdf`) and carry no stock ticker. This
breaks two downstream consumers:

1. **D-7c stranded detection** (`dataAuditJob.ts`) — uses a regex match against
   the filename to infer the ticker. Anonymous filenames produce zero regex matches,
   so the file is silently skipped and never flagged or re-parsed.

2. **`pdf_extracted_text` table** — OCR cache rows are keyed by filename only.
   There is no `action_code` column, so a cached row for `document.pdf` is
   unattributable when two different tickers download files with the same name.

3. **`financial_reports.pdf_path`** — always written as `NULL` today; the
   pipeline computes a local path but never persists it, making post-parse
   traceability impossible.

**Context**: SSC portal polling is disabled (`disableSscPolling=true`). The
primary download paths are HOSE (`hose.ts`), HNX (`hnx.ts`), and UPCOM. In
all three the `actionCode` is known at call time and can be injected into the
filename at the moment of download.

## Architecture Decision

The fix intercepts at the earliest possible point — the filename derivation
inside `fetchParseAndStoreBctc` — so that every downstream consumer (OCR cache,
audit job, `financial_reports` row) automatically sees a normalized filename.
This is a single-chokepoint change that respects the existing pipeline shape:
the use case already owns the filename computation; the domain layer is not
touched. An additive schema column for `action_code` on `pdf_extracted_text`
makes attribution explicit and survives renames on disk.

## Interface Contracts

### 1. `fetchParseAndStoreBctc.ts` — filename normalisation

Replace the current filename derivation block (the `basename` extraction + empty
fallback) with a deterministic normalised form:

```typescript
// Always produce: {ACTIONCODE}_{year}_{quarter}.pdf
// Example: VCB_2025_Q1.pdf
function normaliseFilename(
  url: string,
  actionCode: string,
  year: number,
  quarter: QuarterString,
): string {
  const canonical = `${actionCode.toUpperCase()}_${year}_${quarter}.pdf`;
  try {
    const raw = basename(decodeURIComponent(new URL(url, "https://example.com").pathname));
    // Keep the portal name only when it already contains the ticker,
    // so anonymous files ("document.pdf", GUIDs) are replaced.
    const upper = raw.toUpperCase();
    if (upper.includes(actionCode.toUpperCase()) && raw.toLowerCase().endsWith(".pdf")) {
      return raw; // already attributed
    }
  } catch {
    // URL parse failure — use canonical
  }
  return canonical;
}
```

After normalisation, write the resolved local path back into `report.source.pdfPath`
so `storeReport` persists it:

```typescript
const localPath = join(pdfDir, normalised);
// …existing writeFileSync / extractAndStorePdfPages calls use localPath…
report.source.pdfPath = localPath; // patch before storeReport()
```

`actionCode` is already available in the function scope at that point — no
new parameters are required.

### 2. `parseBctcReport.ts` — accept optional `pdfPath`

Extend `ParseBctcReportParams`:

```typescript
export interface ParseBctcReportParams {
  rawText: string;
  actionCode: string;
  period: FiscalPeriod;
  shares?: number;
  price?: number;
  previousReport?: FinancialReport;
  /** Absolute local path to the downloaded PDF — written to financial_reports.pdf_path. */
  pdfPath?: string;
}
```

In `parseBctcReport`, assign `params.pdfPath ?? null` to `report.source.pdfPath`
instead of the hardcoded `null`.

### 3. `schema.ts` — additive migration for `pdf_extracted_text`

Add an `action_code` column via `ALTER TABLE … ADD COLUMN IF NOT EXISTS`:

```sql
-- Inside initDatabase(), immediately after the pdf_extracted_text CREATE TABLE block:
ALTER TABLE pdf_extracted_text ADD COLUMN IF NOT EXISTS
  action_code TEXT NOT NULL DEFAULT '';
CREATE INDEX IF NOT EXISTS idx_pet_action_code
  ON pdf_extracted_text(action_code);
```

SQLite does not support `IF NOT EXISTS` on `ALTER TABLE`. Use the established
pattern already in the codebase: attempt the ALTER, swallow the "duplicate
column" error:

```typescript
try {
  db.exec(`ALTER TABLE pdf_extracted_text ADD COLUMN action_code TEXT NOT NULL DEFAULT ''`);
  db.exec(`CREATE INDEX IF NOT EXISTS idx_pet_action_code ON pdf_extracted_text(action_code)`);
} catch {
  // Column already exists on existing databases — safe to ignore
}
```

### 4. `pdfOcrWorker.ts` — write `action_code` on cache insert

`extractAndStorePdfPages(pdfPath, filename)` currently inserts rows without
an `action_code`. Add an optional third parameter:

```typescript
export async function extractAndStorePdfPages(
  pdfPath: string,
  filename: string,
  actionCode?: string,           // NEW — written to action_code column
): Promise<void>
```

`getCachedPdfText` stays unchanged — callers still look up by filename;
the `action_code` column is for attribution / audit only.

### 5. `dataAuditJob.ts` — D-7c stranded fallback

The existing D-7c regex match (`new RegExp(\`(^|[^A-Z])${c}([^A-Z]|$)\`)`)
remains as the primary attribution path for already-attributed filenames. Add
a secondary lookup against `pdf_extracted_text.action_code` for files where
the regex yields no match:

```typescript
// After regex fails to match any watchlistCode:
const row = db.query<{ action_code: string }, [string]>(
  `SELECT action_code FROM pdf_extracted_text
   WHERE filename = ? AND action_code != '' LIMIT 1`
).get(filename);
const matched = row?.action_code ?? null;
if (!matched) continue; // still unattributable — skip
```

This ensures that PDFs downloaded after the fix (which carry a normalised name)
are also attributable via the DB column, while legacy anonymous files gain
coverage through the `action_code` index.

## Acceptance Criteria

**Given** a HOSE/HNX/UPCOM PDF URL that resolves to an anonymous filename
(e.g. `document.pdf` or a GUID),
**When** `fetchParseAndStoreBctc` downloads the file for ticker `VCB` Q1 2025,
**Then** the file is saved to disk as `VCB_2025_Q1.pdf` and
`financial_reports.pdf_path` equals the absolute path to that file.

**Given** a PDF is downloaded and OCR-extracted,
**When** `extractAndStorePdfPages` is called with `actionCode = "VCB"`,
**Then** all rows inserted into `pdf_extracted_text` for that file have
`action_code = 'VCB'`.

**Given** a stranded PDF on disk named `document.pdf` with
`pdf_extracted_text.action_code = 'FPT'`,
**When** D-7c runs and the filename regex matches no watchlist code,
**Then** the audit job falls back to the `action_code` column, attributes the
file to `FPT`, and emits one `stranded_bctc_pdf` finding.

**Given** a file already named `HPG_2025_Q2.pdf` (ticker already in name),
**When** `normaliseFilename` is called,
**Then** the filename is returned unchanged (no double-attribution).

**Given** `parseBctcReport` is called with `pdfPath = "/data/pdfs/VCB_2025_Q1.pdf"`,
**When** the report is stored,
**Then** `SELECT pdf_path FROM financial_reports WHERE action_code = 'VCB'`
returns the non-NULL path.

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|---|---|---|---|
| ALTER TABLE fails on existing prod DB (SQLite no `ADD COLUMN IF NOT EXISTS`) | High | Low | Wrap in try/catch swallowing "duplicate column" error — established pattern in this codebase |
| Two tickers download a file with the same anonymous name in the same run | Low | Medium | `normaliseFilename` replaces anonymous names with `{TICKER}_{year}_{quarter}.pdf` — collisions structurally impossible |
| `pdfPath` param threaded incorrectly through callers that bypass step 2 (pdfTextOverride) | Medium | Low | `pdfPath` is optional with `?? null` fallback; existing tests using `pdfTextOverride` pass `undefined` — no regression |
| D-7c double-counting: a file attributed by both regex and `action_code` column | Low | Low | Regex match is the primary gate; the `action_code` lookup only runs when regex returns no match — mutually exclusive |
| Filename collision if portal truly serves same anonymous name for different quarters | Low | Medium | Normalised form includes year+quarter — `VCB_2025_Q1.pdf` vs `VCB_2025_Q2.pdf` are distinct |
