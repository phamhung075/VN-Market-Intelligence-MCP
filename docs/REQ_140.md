# REQ-140: fix(alert-digest-diacritics) — Proper Vietnamese in Weekday Alert Digest

status: READY_FOR_ARCHITECT
sprint: 140
po_vision: Fix unaccented Vietnamese text in assembleAlertDigest — every weekday evening the MARKET channel receives a garbled digest.

## User Story

As a Vietnamese stock investor using Claude,
I want the daily alert digest (sent to MARKET at 21:00 on weekdays) to display proper Vietnamese diacritics,
So that the text is readable and professional rather than garbled ASCII.

## Functional Requirements

### FR-1: Replace all unaccented strings in `formatAlertDigest()`

- Description: The exported function `formatAlertDigest` in `src/application/usecases/assembleAlertDigest.ts` builds the MARKET-bound message. All Vietnamese strings it emits must use proper diacritics.
- Input: `date`, `totalCount`, `criticalCount`, `highCount`, `stockBlocks` (unchanged contract)
- Output: Formatted string — all Vietnamese words carry correct diacritics
- Business rules (exhaustive string map):

| Current (broken) | Correct |
|---|---|
| `Tom tat canh bao` | `Tóm tắt cảnh báo` |
| `Khong co canh bao trong 24 gio qua.` | `Không có cảnh báo trong 24 giờ qua.` |
| `Tom tat canh bao (24 gio qua)` | `Tóm tắt cảnh báo (24 giờ qua)` |
| `Tong: N canh bao \| Nghiem trong: N \| Quan trong: N` | `Tổng: N cảnh báo \| Nghiêm trọng: N \| Quan trọng: N` |
| `N canh bao:` (per-stock label) | `N cảnh báo:` |
| `(va N canh bao khac)` | `(và N cảnh báo khác)` |
| `(khong co noi dung)` (null message fallback) | `(không có nội dung)` |

- Scope: Lines ~144–170 of the source file (inside `formatAlertDigest`) plus line 239 (`topMessages` null-message fallback). The `(khac)` group label (line 159) is a grouping key, not a MARKET string — it is out of scope for this sprint (separate issue).
- DDD layer: application

### FR-2: TDD test `src/__tests__/1394-alert-digest-diacritics.test.ts`

- Description: Five assertions written against the public `formatAlertDigest` export. Written RED first (Task 1394), turned GREEN by the fix (Task 1395).
- Input: Synthetic `StockAlertBlock[]` arrays passed directly to `formatAlertDigest` — no DB required.
- Output: Five `expect` assertions that fail on the unaccented implementation and pass after the fix.
- Test cases:

| ID | Given | Assert |
|---|---|---|
| T1 | `totalCount=1` | result contains `"Tóm tắt cảnh báo"` AND NOT `"Tom tat"` |
| T2 | `totalCount=0` | result contains `"Không có cảnh báo"` AND NOT `"Khong co"` |
| T3 | `totalCount=1`, `criticalCount=1` | result contains `"Nghiêm trọng"` AND NOT `"Nghiem trong"` |
| T4 | `totalCount=1`, one stock block with one alert | result contains `"cảnh báo:"` AND NOT `"canh bao:"` |
| T5 | `totalCount=4`, one stock block with overflow | result contains `"cảnh báo khác"` AND NOT `"canh bao khac"` |

- DDD layer: application (test only, no DB, no infra imports)

## Non-Functional Requirements

- Data freshness: not applicable (formatter only)
- Language: Vietnamese (MARKET output); internal logger lines remain English/unaccented (out of scope)

## Edge Cases & Data Quality

- [x] `message = null` on an alert row → fallback must become `"(không có nội dung)"` not `"(khong co noi dung)"` — covered by FR-1 line 239
- [x] `totalCount = 0` → zero-alert branch uses `"Không có cảnh báo trong 24 giờ qua."` — covered by T2
- [x] `overflow = 0` → overflow line not emitted — no change needed
- [x] `overflow > 0` → overflow line uses `"và N cảnh báo khác"` — covered by T5
- [x] `(khac)` grouping key — group label used as a sort/group key, NOT sent verbatim to MARKET in the per-stock header (label is `block.code` which equals `"(khac)"`); diacritics on this literal are deferred — see FR-1 scope note
