### FR-2: Backfill 25-Day market_prices Gap

**Description:**
Populate market_prices table with daily OHLCV for 2026-03-27 through 2026-04-20 (25 days) for all active stocks (HOSE/HNX/UPCOM). Use fallback chain: local cache → Yahoo Finance → cached snapshot.

**Input:**
- Stock list from watchlist table (market_prices.ticker unique)
- Date range: 2026-03-27 (last known update) to 2026-04-20 (today)
- Fallback sources: cache file / Yahoo Finance API

**Output:**
- market_prices table with ≥500 rows, updated_at >= 2026-04-20
- Backfill log (count of rows inserted per ticker, any failures)
- Notification to WORK channel: "Backfilled NN rows, last stale update 2026-03-27"

**Business Rule:**
- Do not overwrite existing rows; detect duplicates by (ticker, date, source)
- Use ticker names as-is (VNM, FPT, etc.) — already normalized in schema
- Set source='backfill' to distinguish from live pushes
- Timestamp all inserts with current time (2026-04-21)
- Run once per sprint (task 240c, integrated into priceBackfillService)

**Data Quality:**
- If Yahoo fails for a ticker → skip, log warning, continue with next
- If no fallback data available → skip ticker, do NOT insert zeros
- Validate OHLCV range: High >= Close >= Low >= 0, Volume > 0

**DDD Layer:** domain (priceBackfillService domain logic) + infrastructure (fetchers, DB writes)

**Pre-Confirmed Location:**
- `src/domain/services/priceBackfillService.ts` (NEW) — backfill logic, fallback chain

### FR-4: Briefing Freshness Gate — Suppress Send if Prices >24h Stale

**Description:**
Add data-quality guards to morning briefing and evening summary jobs: refuse to send briefing to MARKET channel if market_prices table's most recent update is >24h old.

**Input:**
- Briefing object (assembled, not yet sent)
- market_prices.updated_at timestamp

**Output:**
- If fresh (≤24h old): send briefing to MARKET as normal
- If stale (>24h old): suppress send, log "STALE DETECTED — suppressing send", alert WORK channel with diagnostic

**Business Rule:**
- Check freshness at tail-end of briefing assembly, just before send_telegram(channel="market")
- Freshness threshold: 24 hours (synchronized with SLA from Sprint 234)
- If stale: still persist briefing to JSON report file (for debugging), but DO NOT send to MARKET channel
- Escalation: send diagnostic message to WORK channel with last_update timestamp + age
- This gate applies to both assembleBriefing (morning 08:00 GMT+7) and assembleEveningSummary (evening 22:00 GMT+7)

**DDD Layer:** application/usecases (freshness check logic)

**Pre-Confirmed Locations:**
- `src/application/usecases/assembleBriefing.ts` — add freshness gate before send
- `src/application/usecases/assembleEveningSummary.ts` — add freshness gate before send

## Non-Functional Requirements

| Requirement | Spec |
|-------------|------|
| **Performance** | Backfill job completes in <10 min for 25 days × 200+ tickers. Watchdog check <1s. |
| **Data Freshness** | Backfilled prices reflect market close data; timestamps normalized to 2026-04-21. |
| **Language** | Alerts in English (WORK channel, operational); Vietnamese optional in MARKET digest. |
| **Observability** | Log every backfill row insert, every watchdog escalation, every freshness gate decision. |
| **Resilience** | Fallback chain: cache → Yahoo → skip. Do NOT fail entire job on single ticker error. |
| **Idempotency** | Backfill detects duplicates by (ticker, date, source); skip re-inserts. |

---

## Edge Cases & Data Quality

- [ ] **Empty price history:** Yahoo returns 0 rows for a ticker (e.g., newly listed stock) → skip, log, continue
- [ ] **Partial date range:** Yahoo has data for 2026-03-27 to 2026-04-10, missing 2026-04-11–04-20 → insert available rows, log gap
- [ ] **Vietnamese number format:** Prices from cache may use (1.234.567) format → normalize to decimal before insert
- [ ] **Network timeout during backfill:** If Yahoo times out → use circuit breaker, exponential backoff, eventually skip ticker
- [ ] **Concurrent writes during backfill:** Market data live-push happens concurrently with backfill → use INSERT OR IGNORE to avoid duplicates
- [ ] **Watchdog runs off-hours:** Watchdog skips staleness check after 08:59 UTC or on weekends → returns "off-hours"
- [ ] **SSH connection fails:** Cannot reach VPS during restart attempt → log error to WORK, continue with next check
- [ ] **Briefing stale during low-volatility markets:** Even if no prices pushed, briefing should suppress rather than send empty report
- [ ] **Market_prices table empty:** No rows at all → treat as "stale beyond threshold" → suppress briefing + alert WORK

**Then**

- [ ] Cooldown active for next 30 minutes (no repeat alerts)
- [ ] If SSH fails → WORK message includes error: "[SSH FAILED] Could not restart service. Error: [details]"

- [ ] JSON report still persisted to disk (for debugging)
- [ ] Diagnostic message sent to WORK: "[FRESHNESS GATE] Briefing suppressed. Prices stale 25 days. Last update: 2026-03-27."

## Risk & Mitigation

| Risk | Severity | Mitigation |
|------|----------|-----------|
| Yahoo API rate-limit during backfill | Medium | Use existing circuit breaker + exponential backoff; skip on exhaustion |
| Duplicate price inserts corrupt history | High | Use INSERT OR IGNORE + (ticker, date, source) unique constraint |
| SSH restart times out, leaving service hung | Medium | Set timeout 30s; if hung, escalate to WORK for manual intervention |
| Stale briefing gate suppresses legitimate reports | Low | Only suppress if age > 24h; if prices are updating live, gate passes |
| Watchdog cooldown masks recurring failures | Low | 30-min cooldown reasonable for market-hours; escalation to WORK logged each time |

### Freshness Gate Location

In `assembleBriefing.ts` and `assembleEveningSummary.ts`, after briefing object is built but before `sendTelegram(channel="market")`:

```typescript
const maxUpdatedAt = db.query(
  `SELECT MAX(updated_at) as latest FROM market_prices`
).get() as { latest: string | null };

const ageMs = Date.now() - (maxUpdatedAt?.latest ? new Date(maxUpdatedAt.latest).getTime() : 0);
const isStale = ageMs > 24 * 60 * 60 * 1000;

if (isStale) {
  logger.warn(`[freshness-gate] Briefing suppressed. Prices stale ${Math.round(ageMs / (60 * 60 * 1000))}h.`);
  sendTelegram(channel="work", `[FRESHNESS GATE] Briefing suppressed. Last price update: ${maxUpdatedAt?.latest}`);
  // Still persist JSON for debugging
  writeBriefingToFile(briefing);
  return; // Do NOT send to MARKET
}

await sendTelegram(channel="market", briefingText);
```
