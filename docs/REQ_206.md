## Functional Requirements

### FR-1: Implement formatGlobalSnapshotSection

- Description: Replace the 5-line RED stub in `morningBriefingJob.ts:47-51` with a real formatter that renders VIX, DXY, SP500, HangSeng as human-readable Telegram lines.
- Input: `{ vix: number; dxy: number; sp500: number; hangSeng: number; fetchedAt: string }` — matches the existing type signature already on the stub.
- Output: `string[]` — non-empty array when a snapshot is provided. Expected shape (exact labels TBD by Architect, must match 1511b test assertions):
  ```
  ["🌐 Thị trường toàn cầu:",
   "  VIX: 18.5",
   "  DXY: 104.2",
   "  S&P500: 5123",
   "  Hang Seng: 17800"]
  ```
- Business rule: Return `[]` only when the input object is null/undefined (guard at call sites). When a snapshot is provided, all four fields must appear in the output. `fetchedAt` is not rendered in the message body.
- Business rule: `eveningSummaryJob` and `franceSummaryJob` both call this function; if it returns `[]` the global snapshot section is silently absent from all digests — this is the current production bug.
- DDD layer: interface/scheduler (formatter lives in `morningBriefingJob.ts` alongside `formatCommoditiesSection`)

### FR-2: Fix test 1133 — foreignFlowAlertJob seeds daily_ohlcv not vnstock_trading_stats

- Description: `src/__tests__/1133-foreign-flow-alert-job.test.ts:30-116` builds an in-memory DB with `vnstock_trading_stats`. Production code (`foreignFlowAlertJob.ts:78-99`) reads `daily_ohlcv.foreign_net_vol` since sprint 1517b. The table mismatch causes all AC-1 through AC-6 assertions to receive zero rows → failures.
- Input (current): `makeDb()` creates `vnstock_trading_stats` + seeds `foreign_volume` via `seedForeignFlow()`.
- Output (required): `makeDb()` creates `daily_ohlcv` with columns `(code, date, open, high, low, close, volume, foreign_net_vol)`. Seed helper inserts rows with non-null `foreign_net_vol` to trigger HIGH signal threshold.
- Business rule: `foreignFlowAlertJob` queries `SELECT code, date, COALESCE(foreign_net_vol, 0) AS net_vol FROM daily_ohlcv WHERE code = ? ORDER BY date ASC LIMIT ?` — test seeds must satisfy this query to produce ≥1 HIGH signal.
- Business rule: HIGH signal threshold = cumulative `foreign_net_vol` sum over 5 days exceeds the production threshold constant. Use the same seeding strategy as `1517-foreign-flow-alert-ohlcv-source.test.ts` (confirmed GREEN).
- DDD layer: test-only change — no production code modified.
