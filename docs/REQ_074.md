# REQ-074: Fix RSS Parser — Atom 1.0 Entry Support

status: READY_FOR_ARCHITECT
sprint: 074
po_vision: Restore live news ingestion so rag_analyses receives items on every 15-minute
intelligence cycle and the evening report produces non-empty topStories.

## User Story

As a Vietnamese stock investor using Claude,
I want the news pipeline to ingest articles from Google News RSS and baodautu.vn,
So that the evening briefing shows real topStories instead of an empty array.

---

## Background & Root Cause

`parseRssFeed()` in `src/infrastructure/fetchers/rss.ts` selects only `$("item")` (RSS 2.0).
Google News RSS and baodautu.vn return Atom 1.0 feeds whose root elements differ structurally:

| Field        | RSS 2.0                              | Atom 1.0                                         |
|--------------|--------------------------------------|--------------------------------------------------|
| Entry tag    | `<item>`                             | `<entry>`                                        |
| URL          | `<link>` text node                   | `<link rel="alternate" href="...">` attribute    |
|              |                                      | or `<link href="...">` attribute                 |
|              |                                      | or `<id>` text node (last resort)                |
| Date         | `<pubDate>` (RFC 2822)               | `<published>` (ISO 8601), fallback `<updated>`   |
| Summary      | `<description>` or `<content:encoded>` | `<summary>`, fallback `<content>`              |
| Namespace    | None required                        | `xmlns="http://www.w3.org/2005/Atom"`            |

Because `$("item")` matches zero nodes in an Atom document, every HTTP 200 response from
Google News is silently parsed as 0 items. The intelligence cycle writes nothing to
`rag_analyses`, leaving evening reports with `topStories.length === 0`.

baodautu.vn `dau-tu-tai-chinh.rss` is also an Atom feed. Task 1185 is expected to close as
a free side-effect of this fix.

## Functional Requirements

### FR-1: Union-select entries for both RSS 2.0 and Atom 1.0

- Description: Replace `$("item")` with `$("item, entry")` so the same loop handles both
  feed formats. The two formats are mutually exclusive in practice — a document has either
  `<item>` or `<entry>` nodes, never both.
- Input: Raw XML string (UTF-8), either RSS 2.0 or Atom 1.0.
- Output: Array of `RssItem` with all fields populated.
- Business rule: Zero-item result on a non-empty Atom feed is a silent data loss bug. The
  fix must never silently return 0 items when the XML contains `<entry>` nodes with content.
- DDD layer: infrastructure

### FR-2: Atom URL extraction

- Description: For each `<entry>` node, extract the canonical URL using a priority chain:
  1. `<link rel="alternate" href="...">` attribute value.
  2. `<link href="...">` attribute value (any `<link>` that carries an `href` attribute,
     regardless of `rel`).
  3. `<id>` text node content (Atom mandates `<id>` as a unique IRI — acceptable fallback).
  4. Empty string (skip guard applies: entry with empty title AND empty url is dropped).
- Input: Cheerio element wrapping a single `<entry>` node.
- Output: String URL, possibly empty.
- Business rule: Google News Atom uses `<link rel="alternate" href="..."/>` (self-closing,
  no text content). A selector that calls `.text()` on `<link>` returns an empty string for
  self-closing elements. The fix must use `.attr("href")` instead of `.text()` when the
  element has an `href` attribute.
- DDD layer: infrastructure

### FR-3: Atom date extraction

- Description: For each `<entry>` node, extract publication timestamp using a priority chain:
  1. `<published>` text node (ISO 8601, e.g. `2026-04-13T07:30:00Z`).
  2. `<updated>` text node (ISO 8601 — present when `<published>` is absent).
  3. Empty string (acceptable; downstream normalizer already tolerates missing dates).
- Input: Cheerio element wrapping a single `<entry>` node.
- Output: String timestamp, possibly empty.
- Business rule: The existing `RssItem.publishedAt` field is typed as `string` with no
  format constraint. Returning the raw ISO 8601 string from Atom is correct — no conversion
  to RFC 2822 is required.
- DDD layer: infrastructure

### FR-4: Atom content extraction

- Description: For each `<entry>` node, extract article summary using a priority chain:
  1. `<summary>` text node (Atom standard summary field).
  2. `<content>` text node (full article body, present in some Atom feeds).
  3. Empty string.
- Input: Cheerio element wrapping a single `<entry>` node.
- Output: String, possibly empty. Decoded through existing `decodeHtmlEntities()`.
- Business rule: Consistent with existing RSS 2.0 extraction that falls back through
  `description` → `content:encoded` → `encoded`. Same decoding pipeline must apply.
- DDD layer: infrastructure

### FR-5: RSS 2.0 path unchanged — zero regressions

- Description: The changes to `parseRssFeed()` must not alter behaviour for RSS 2.0 feeds.
  All 14 existing tests in `021-rss-cafef.test.ts` plus tests in `022-rss-vnexpress.test.ts`
  and `023-rss-reuters.test.ts` must continue to pass.
- Business rule: Existing callers (`fetchCafeF`, `fetchVnExpress`, `fetchReuters`, etc.) pass
  their XML to `parseRssFeed()` without change. The function signature
  `parseRssFeed(xml: string): RssItem[]` is unchanged.
- DDD layer: infrastructure

### FR-6: Unit tests — RSS 2.0 fixture (existing shape, new test file)

- Description: Add a `buildMockAtomFeed()` helper and a new describe block in a new test
  file `src/__tests__/1188-rss-atom.test.ts` that covers the Atom 1.0 path.
  The RSS 2.0 fixture tests are already covered in `021-rss-cafef.test.ts` — do not
  duplicate them; the new file focuses exclusively on the Atom path.
- DDD layer: infrastructure

### FR-7: Unit tests — Atom 1.0 fixture (real Google News shape)

- Description: The Atom 1.0 fixture in `1188-rss-atom.test.ts` must reflect the actual
  Google News response shape:
  - Root element: `<feed xmlns="http://www.w3.org/2005/Atom">`
  - Entry URL via `<link rel="alternate" href="https://..."/>` (self-closing, no text)
  - Date via `<published>2026-04-13T07:30:00Z</published>`
  - Summary via `<summary>Article excerpt here</summary>`
  - Vietnamese content (titles mentioning VN-Index, HPG, VCB, etc.) to mirror production.
- The fixture must also cover the baodautu.vn shape where `<link href="..."/>` is used
  without a `rel` attribute.
- Minimum test coverage required:
  - Returns >= 1 item from an Atom feed fixture.
  - Each item has non-empty title, url, publishedAt, content.
  - URL is extracted from `href` attribute (not from `.text()`).
  - `publishedAt` comes from `<published>` when present.
  - `publishedAt` falls back to `<updated>` when `<published>` is absent.
  - `content` comes from `<summary>`.
  - `content` falls back to `<content>` when `<summary>` is absent.
  - URL falls back to `<id>` when no `<link href>` is present.
  - Empty Atom feed (no `<entry>` nodes) returns `[]`.
  - Mixed document with both `<item>` and `<entry>` nodes returns items from both.
- DDD layer: infrastructure

## Non-Functional Requirements

- Performance: `parseRssFeed()` is called in the 15-minute intelligence cycle scheduler.
  The union selector `$("item, entry")` adds negligible overhead — cheerio traversal is
  synchronous in-memory. No performance concern.
- Data freshness: No change. The fix restores data that was always fetched but discarded
  at parse time.
- Language: Feed titles and summaries arrive in whatever language the source uses (English
  for Google News, Vietnamese for baodautu.vn). No translation in this layer.
- Backward compatibility: `RssItem` interface unchanged. All callers unchanged.

## Edge Cases & Data Quality

- [x] Self-closing Atom `<link/>` — `.text()` returns `""`. Must use `.attr("href")`.
- [x] Atom `<link>` with no `rel` attribute (baodautu.vn shape) — must still extract `href`.
- [x] Entry with `<id>` only (no `<link>`) — use `<id>` text as URL last resort.
- [x] Entry with `<updated>` but no `<published>` — use `<updated>` as publishedAt.
- [x] Entry with neither `<published>` nor `<updated>` — publishedAt = `""` (acceptable).
- [x] Entry with `<content>` but no `<summary>` — use `<content>` as content field.
- [x] Mixed document with both `<item>` and `<entry>` nodes — union selector handles both.
- [x] Atom XML with namespace prefixes (`atom:entry`) — cheerio xmlMode strips namespace
      prefixes in selectors; test confirms behavior or explicit prefix handling added.
- [x] HTML entities in Atom `<summary>` — existing `decodeHtmlEntities()` already handles
      numeric and hex entities; same call applied to Atom content path.
- [x] Empty Atom feed body — returns `[]`, no crash.
- [x] Google News redirects — handled upstream in `reuters.ts` HTTP client (`maxRedirects: 5`).
      Not a concern inside `parseRssFeed()`.

## Acceptance Criteria

### AC-1: Atom fixture returns items

**Given** a valid Atom 1.0 XML string with 3 `<entry>` nodes
**When** `parseRssFeed(xml)` is called
**Then**

- Returns exactly 3 `RssItem` objects.
- No exception is thrown.

### AC-2: Atom URL from `<link rel="alternate" href>`

**Given** an Atom entry with `<link rel="alternate" href="https://news.google.com/articles/abc"/>`
**When** `parseRssFeed(xml)` is called
**Then**

- `item.url === "https://news.google.com/articles/abc"`.
- `item.url` is NOT an empty string.

### AC-3: Atom URL from `<link href>` without rel (baodautu.vn shape)

**Given** an Atom entry with `<link href="https://baodautu.vn/article-123.html"/>` and no `rel` attribute
**When** `parseRssFeed(xml)` is called
**Then**

- `item.url === "https://baodautu.vn/article-123.html"`.

### AC-4: Atom date from `<published>`

**Given** an Atom entry with `<published>2026-04-13T07:30:00Z</published>`
**When** `parseRssFeed(xml)` is called
**Then**

- `item.publishedAt === "2026-04-13T07:30:00Z"`.

### AC-5: Atom date fallback to `<updated>`

**Given** an Atom entry with `<updated>2026-04-13T08:00:00Z</updated>` and no `<published>` element
**When** `parseRssFeed(xml)` is called
**Then**

- `item.publishedAt === "2026-04-13T08:00:00Z"`.

### AC-6: Atom content from `<summary>`

**Given** an Atom entry with `<summary>Chỉ số VN-Index tăng 12 điểm</summary>`
**When** `parseRssFeed(xml)` is called
**Then**

- `item.content === "Chỉ số VN-Index tăng 12 điểm"`.

### AC-7: Atom content fallback to `<content>`

**Given** an Atom entry with `<content>Full article text here</content>` and no `<summary>` element
**When** `parseRssFeed(xml)` is called
**Then**

- `item.content === "Full article text here"`.

### AC-8: RSS 2.0 zero regressions

**Given** any existing test in `021-rss-cafef.test.ts`, `022-rss-vnexpress.test.ts`,
or `023-rss-reuters.test.ts`
**When** the full test suite runs after the fix
**Then**

- All pre-existing tests pass without modification.
- `bun test` exits with code 0.

### AC-9: Live smoke-test (post-deploy)

**Given** the server is restarted with `launchctl kickstart -k gui/$(id -u)/com.vn-market.mcp`
**When** the 15-minute intelligence cycle triggers `fetchReuters()`
**Then**

- Server logs show `[reuters] fetched RSS items` with `count >= 1`.
- The next `reports/YYYY-MM-DD-evening.json` has `topStories.length >= 3`.

### AC-10: Task 1185 auto-resolved

**Given** `parseRssFeed()` now handles Atom `<entry>` nodes
**When** the VPS pushes a baodautu.vn RSS response to the server
**Then**

- Items are written to `rag_analyses` (verified by log: `[pollNews] inserted N analyses`).
- Task 1185 is closed as "resolved by 1188" in TASKS.md.
