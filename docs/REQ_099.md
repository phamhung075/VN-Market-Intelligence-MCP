## User Story

As a Vietnamese stock investor living in France,
I want a curated Vietnamese-language market recap in my MARKET Telegram channel when I wake up at 09:00 CET,
So that I can act on overnight VN session signals before my Paris workday starts — without checking the WORK channel.

## Functional Requirements

### FR-1: Query top 3 price movers

- Description: Fetch up to 3 watchlist stocks with the largest absolute price move in the last `windowHours` hours from `market_prices`.
- Input: `db` (SQLite), `cutoff` ISO-8601 string derived from `nowFn() - windowHours`
- Output: `MoverRow[]` — `{ code: string, change_pct: number }`
- Business rule:
  - SQL: `SELECT code, change_pct FROM market_prices WHERE updated_at >= ? AND change_pct IS NOT NULL ORDER BY ABS(change_pct) DESC LIMIT 3`
  - If no rows OR `change_pct` column absent (SQLite schema drift) → return `[]`, set `moverCount = 0`, log warning — never throw.
  - Positive `change_pct` rendered as `+3.5%`, negative as `-2.1%` (one decimal place, Vietnamese convention).
- DDD layer: scheduler

### FR-2: Query top 3 alerts by severity

- Description: Fetch up to 3 most severe alerts triggered in the last `windowHours` hours from the `alerts` table.
- Input: `db`, `cutoff` ISO-8601 string
- Output: `AlertRow[]` — `{ severity: string, message: string }`
- Business rule:
  - SQL: `SELECT severity, message FROM alerts WHERE triggered_at >= ? ORDER BY CASE severity WHEN 'critical' THEN 0 WHEN 'high' THEN 1 WHEN 'warning' THEN 2 ELSE 3 END ASC LIMIT 3`
  - `severity` values map to label: `critical` → `[CRITICAL]`, `high` → `[HIGH]`, `warning` → `[WARNING]`, other → `[INFO]`.
  - `message` truncated to 100 chars to keep message compact.
  - If no rows → return `[]`, set `alertCount = 0`.
- DDD layer: scheduler

### FR-3: Count TA signals for the session

- Description: Count how many TA alert rows (RSI/BB) were inserted in the last `windowHours` hours.
- Input: `db`, `cutoff` ISO-8601 string
- Output: `number` — the raw count (`taCount`)
- Business rule:
  - SQL: `SELECT COUNT(*) AS cnt FROM alerts WHERE triggered_at >= ? AND json_extract(signals_json,'$[0].type') IN ('ta_overbought','ta_oversold','ta_bb_breakout_up','ta_bb_breakout_down')`
  - Result is additive context for the investor — not a delivery mechanism (taAlertNotifierJob handles delivery).
  - If query fails → return `0`, log warning.
- DDD layer: scheduler

### FR-4: Silent skip when all sources empty

- Description: Return `{ sent: false, moverCount: 0, alertCount: 0, taCount: 0 }` without sending any Telegram message when all three data sources return empty.
- Input: Results from FR-1, FR-2, FR-3
- Output: `FranceSummaryResult` with `sent: false`
- Business rule: Send condition — `moverCount > 0 OR alertCount > 0 OR taCount > 0`. If all are zero, return silently with no Telegram call. No "no data" placeholder message is sent.
- DDD layer: scheduler

### FR-5: Format Vietnamese compact Telegram message

- Description: Compose a UTF-8 string from the three data sections with a Vietnamese header.
- Input: `MoverRow[]`, `AlertRow[]`, `taCount: number`, `nowFn: () => Date`
- Output: Single formatted string
- Business rule:
  - Header (always present when message is sent): `"Phiên VN sáng nay {YYYY-MM-DD}:"` — date derived from `nowFn()`, UTC+7 timezone offset applied (`+7*3_600_000`).
  - Price section (only when `movers.length > 0`):
    ```
    Biến động giá:
      VCB: +3.5%
      HPG: -2.1%
    ```
  - Alert section (only when `alerts.length > 0`):
    ```
    Cảnh báo (N):
      [HIGH] USD/VND: 26302 — cao bất thường
      [WARNING] VCB: RSI=74.2 quá mua
    ```
    where `N` = `alerts.length`.
  - TA count line (only when `taCount > 0`): `"Tín hiệu TA hôm nay: {taCount}"`
  - Sections are joined with a blank line between them.
  - No trailing newline.
- DDD layer: scheduler

### FR-6: Send to MARKET channel

- Description: Deliver the formatted message to the MARKET Telegram channel with persistence metadata.
- Input: Formatted string from FR-5
- Output: `boolean` — `true` on successful send
- Business rule:
  - Call injected `sendFn` (defaults to `sendTelegramMarket`).
  - Persist metadata: `{ from_agent: "france-summary", message_type: "france_summary" }` — passes through `sendTelegramMarket`'s `options.persist` field.
  - On send failure (exception) → log warning, return `{ sent: false, moverCount, alertCount, taCount }`. Do NOT rethrow.
  - Replaces the current `sendTelegramWork` call in line 158-159 of the existing file.
- DDD layer: scheduler

### FR-7: Update cron registry metadata

- Description: Update `docs/data/cron-registry.json` to reflect the new channel and content description.
- Input: `docs/data/cron-registry.json`
- Output: Job entry for `franceSummaryJob` updated — channel field changed to `MARKET`, content description changed to `"curated VN digest: top 3 movers, top 3 alerts, TA signal count"`.
- Business rule: `schedulerFileCount` does NOT change (file already exists; this is a rewrite, not a new file). Do NOT touch `project-stats.json`.
- DDD layer: n/a (data file)

## Non-Functional Requirements

- Performance: Three lightweight SQLite queries (index on `updated_at` / `triggered_at` already present). Total query time < 50 ms on prod DB.
- Data freshness: Default `windowHours = 8` captures the full VN morning session (09:00–15:30 GMT+7 = 02:00–08:30 UTC). Job fires at 07:00 UTC (09:00 CET).
- Language: All user-facing text in Vietnamese. Labels (`[HIGH]`, `[CRITICAL]`, `[WARNING]`) remain uppercase Latin — established convention in the codebase and unambiguous across languages.
- Idempotency: No dedup guard needed — cron fires once daily at 07:00 UTC. Existing `jobs.ts` cron expression unchanged.
- Error isolation: Each of the three DB queries is wrapped individually. One query failure does not abort the others — partial data is still sent if at least one source returns rows.

## Edge Cases & Data Quality

- [ ] `change_pct` column absent from `market_prices` (schema drift on fresh DB) → catch SQLite error, return `moverCount = 0`, log warning, continue to alerts + TA
- [ ] All three sources return empty → silent skip, `sendFn` never called (FR-4)
- [ ] `updated_at` in `market_prices` uses VN-server timestamp format without timezone — cutoff computed from `nowFn()` in UTC ISO-8601 matches stored strings; no timezone conversion needed (same convention as existing queries throughout codebase)
- [ ] `message` field in `alerts` is NULL → render as empty string, alert line still appears with severity label
- [ ] TA alerts counted by FR-3 may overlap with alerts fetched by FR-2 — this is intentional: FR-2 surfaces the alert text, FR-3 counts signal volume. No dedup between sections.
- [ ] `sendFn` throws (network timeout, Telegram API 5xx) → log warning, return `sent: false` with counts preserved; no retry inside job — next day's cron handles recovery
- [ ] `nowFn()` injected as far-future date in tests → cutoff computed correctly because `cutoff = nowFn().getTime() - windowHours * 3_600_000`; test rows inserted at arbitrary timestamps still match
