## What is new vs. prior cycles

The prior two cycles confirmed the upstream MCP server was healthy (HTTP 406 with proper JSON-RPC error message) and that the only failure was the missing Cowork client-side registration. As of this 18:09Z cycle, the upstream TLS certificate fails authority validation. This is a separate failure layer that ops must also address. Possible causes:

1. Certificate genuinely expired or got rotated to an unbundled chain.
2. Reverse-proxy / load-balancer reconfigured between 04:36Z and 18:09Z (commit `7ec93b8d` at ~06:30 was around the same window — worth correlating).
3. Sandbox web-fetch trust store divergence vs. the actual cert chain (less likely — `ERR_CERT_AUTHORITY_INVALID` typically means the chain itself is broken, not just the client).
