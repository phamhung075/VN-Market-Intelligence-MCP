# REQ-116: fix(ta-adaptive): Adaptive RSI/MA Periods in defaultComputeTa

status: READY_FOR_ARCHITECT
sprint: 116
po_vision: Fix taSummary empty every night — production daily_ohlcv has 10 trading days but defaultComputeTa returns null for < 15 candles.

## User Story

As a Vietnamese stock investor using Claude,
I want TA signals (RSI, MA) to appear in the evening report as soon as 8 trading days of OHLCV data exist,
So that I receive actionable close-of-day signals from day 8 onward instead of waiting for 15 full days.

## Functional Requirements

### FR-1: Lower candle guard from 15 to 8 (primary path)

- Description: `defaultComputeTa` currently returns `null` when `daily_ohlcv` has fewer than 15 rows. The guard must be lowered to 8, matching the minimum candles needed for `computeRSI` with an adaptive period of at least `n - 1 = 7` deltas.
- Input: `rows: CandleRow[]` from `SELECT date, close FROM daily_ohlcv WHERE code = ? ORDER BY date ASC LIMIT 60`
- Output: `TaSignal | null` — `null` only when `rows.length < 8`
- Business rule: `if (rows.length < 8) return null` — replaces current `< 15` guard
- DDD layer: application

### FR-2: Adaptive RSI period (primary path)

- Description: Instead of hard-coding `computeRSI(prices, 14)`, pass `Math.min(14, rows.length - 1)` as the period. This ensures `computeRSI` always receives at least 7 when `rows.length >= 8`, and falls back to the standard RSI(14) once 15+ candles exist.
- Input: `prices: number[]`, `period = Math.min(14, rows.length - 1)`
- Output: RSI value in `[0, 100]` or `null`
- Business rule: `computeRSI(prices, Math.min(14, rows.length - 1))` — period is clamped, never exceeds 14
- DDD layer: application

### FR-3: Adaptive MA period (primary path)

- Description: Instead of hard-coding `computeMA(prices, 20)`, pass `Math.min(20, rows.length)`. This ensures MA always has enough data while still computing MA(20) when 20+ candles exist.
- Input: `prices: number[]`, `period = Math.min(20, rows.length)`
- Output: MA value or `null`
- Business rule: `computeMA(prices, Math.min(20, rows.length))` — period is clamped, never exceeds 20
- DDD layer: application

### FR-4: Same adaptive logic on fallback path (intraday ticks)

- Description: The fallback branch (query `market_prices_history` when `daily_ohlcv` has fewer than 8 rows) applies the identical adaptive period logic. The fallback guard is also lowered from `< 15` to `< 8`.
- Input: `fallbackRows: CandleRow[]` from `GROUP BY DATE(fetched_at)` on `market_prices_history`
- Output: `null` when `fallbackRows.length < 8`; otherwise `TaSignal` computed with adaptive periods
- Business rule:
  - `if (fallbackRows.length < 8) return null`
  - `computeRSI(fbPrices, Math.min(14, fallbackRows.length - 1))`
  - `computeMA(fbPrices, Math.min(20, fallbackRows.length))`
- DDD layer: application

### FR-5: TDD test suite (task 1346 — written before fix)

- Description: Test file `src/__tests__/1346-ta-adaptive-period.test.ts` covering 4 cases, written against the pre-fix code so that TC-2, TC-3 fail before the fix and pass after.
- Test cases:

| TC | Candles | Expected result |
|----|---------|-----------------|
| TC-1 | 10 candles in `daily_ohlcv` | non-null `TaSignal` (RSI with period 9, MA with period 10) |
| TC-2 | 7 candles in `daily_ohlcv` | non-null `TaSignal` (RSI with period 6, MA with period 7) |
| TC-3 | 6 candles in `daily_ohlcv` | `null` (below minimum of 8) |
| TC-4 | 15+ candles in `daily_ohlcv` | non-null `TaSignal`; RSI period = 14, MA period = 20 (unchanged behavior) |

- DDD layer: application (test only, no production code changed in task 1346)
