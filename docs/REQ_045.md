## User Stories

### US-1: So sanh tai chinh voi nganh
As a Vietnamese stock investor,
I want the system to automatically fetch financial data (PE, PB, ROE, D/E) for all major stocks in the same sector as my watchlist stocks,
So that AI agents can tell me whether my stock is trading at a premium or discount vs its sector peers.

**Acceptance Criteria:**
- For each watchlist stock, sector peers from `sectorPeers.ts` have their vnstock financials synced
- Peer data uses relaxed staleness thresholds (24h for financials, 12h for trading stats)
- Rate limit safe: max 5 peer syncs per intelligence cycle, 3 data types each = 15 extra calls

### US-2: So sanh dong tien nuoc ngoai
As a Vietnamese stock investor,
I want the system to track foreign investor flow (buy/sell volume) for sector peers,
So that AI agents can detect if foreign buying is stock-specific (good signal) or sector-wide (weaker signal).

**Acceptance Criteria:**
- Trading stats (including foreign buy/sell volume) synced for sector peers
- `foreignFlowAnalyzer.ts` can compare a watchlist stock's flow vs peer flow
- Sector-wide foreign flow context included in analysis

### US-3: MCP tool truy van so sanh nganh
As an AI analysis agent (Report Analyzer, Market Watcher),
I want a single MCP tool `get_sector_comparison(code)` that returns my watchlist stock's metrics alongside all peer metrics and sector medians,
So that I can make richer analysis in one call without manually querying each peer.

**Acceptance Criteria:**
- Tool returns: target stock metrics, peer metrics, sector median, valuation tier (premium/discount/inline)
- Includes: PE, PB, ROE, D/E, foreign net buy/sell, price change %
- Vietnamese output format for agent consumption

### US-4: Uu tien dong bo watchlist truoc
As a system operator concerned about rate limits,
I want sector peer sync to always run AFTER watchlist sync, with lower priority and longer staleness,
So that watchlist data is always fresh and peer data is best-effort.

**Acceptance Criteria:**
- Watchlist sync runs first (existing behavior unchanged)
- Peer sync runs second, capped at MAX_PEER_SYNCS_PER_CYCLE = 5
- If rate limit budget exhausted, peer sync skips gracefully
- Peer staleness: financials 24h, trading_stats 12h, balance_sheet 24h
- Skip: officers, shareholders, events, cash_flow for peers (not needed for comparison)

## Functional Requirements

### FR-1: Peer Sync Function (`syncSectorPeers`)
- Input: watchlist entries (code + domain)
- Resolves sector peers via `getContextStocksForWatchlist()`
- For each peer (max 5 per cycle): fetch financials, trading_stats, balance_sheet if stale
- Uses existing `vnstockBridge.ts` functions and `vnstockStore.ts` storage
- Returns: { synced: number, skipped: number, apiCalls: number }

### FR-2: Sector Comparison Query
- Input: stock code (must be on watchlist)
- Reads watchlist stock's domain from DB
- Fetches stored vnstock data for target + all peers in same sector
- Computes sector medians using `sectorValuationComparator.ts`
- Returns structured comparison with Vietnamese labels

### FR-3: Intelligence Cycle Integration
- Step A3 extended: after watchlist sync, run peer sync
- Peer sync has its own timeout (2 min)
- Budget tracking: count API calls from watchlist sync, compute remaining budget for peers

### FR-4: Agent Workflow Update
- Report Analyzer: use `get_sector_comparison` to benchmark BCTC findings against peers
- Market Watcher: use `get_sector_comparison` to contextualize price anomalies
- Digest Writer: include sector comparison highlights in weekly digest

---

## Non-Functional Requirements

### NFR-1: Rate Limit Safety
- Total vnstock API calls per cycle: watchlist (max 28) + peers (max 15) = 43 < 60/min
- Inter-request delay: 1.5s (existing DELAY_MS)
- Graceful degradation: if peer sync exceeds budget, skip remaining peers

### NFR-2: Storage Efficiency
- Peer data stored in existing vnstock_* tables (no new tables)
- Peer data distinguished by being present in vnstock tables but NOT in watchlist table
- Staleness tracked via existing vnstock_fetch_log table

### NFR-3: No Alert Generation for Peers
- Peer stocks NEVER generate alerts
- Peer data is read-only context for watchlist stock analysis
- Alert pipeline remains unchanged (only watchlist stocks trigger alerts)

---

## Out of Scope
- Adding peer stocks to watchlist automatically
- Sending Telegram alerts for peer stock movements
- Fetching peer intraday/orderbook data (too expensive for context-only use)
- Changing existing sector peer definitions (sectorPeers.ts content unchanged)
