## §1 Goal & Scope

Rewrite `apps/stock-price/` from TS/Bun to Go 1.22, eliminating the `bun:sqlite` crash vector
(dynamic-import CGO teardown under macOS VirtioFS). The service keeps the same HTTP API, same
JSON envelope, and same 3-tier waterfall semantics. No functional change visible to callers.

**DDD layer map (TS → Go):**

| TS source | Go package |
|---|---|
| `domain/models.ts` — PriceQuote, DailyOHLCV, TierResult | `pkg/domain/models.go` |
| `domain/services.ts` — ResolvePriceService (concurrent allSettled) | `pkg/domain/services.go` |
| `domain/repositories.ts` — PriceFetcherPort, PriceHistoryPort | `pkg/domain/ports.go` |
| `infrastructure/fetchers.ts` — Tier1/Tier2 HTTP + Tier3 SQLite + SQLitePriceHistoryRepo | `pkg/infrastructure/fetchers.go` |
| `application/usecases.ts` + `dtos.ts` — FetchPriceUseCase, PriceHistoryUseCase | `pkg/application/usecases.go` |
| `interface/handlers.ts` — POST /price/fetch, GET /price/history/:code, GET /health | `pkg/interface/http/router.go` |

**3-tier waterfall:** all 3 tiers launched concurrently (Go: `errgroup` or `sync.WaitGroup` +
`chan`). First non-nil result in tier order wins. Tier3 = SQLite read from `market.db` (readonly)
then writes successful quotes to `stock_price.db` (write-only cache). Semantics mirror
`Promise.allSettled` — a tier panic/error does not abort the others.

**Dual-DB SQLite reads:**
- `market.db` — opened readonly (`?mode=ro&_journal_mode=WAL`) for Tier3 fallback read.
  Writer = mcp-server. This service never writes to `market.db`.
- `stock_price.db` — opened read-write for `saveQuote` cache writes. Isolated to this service.

**Module path:** `github.com/vn-market-intelligence/stock-price`

## §2 Acceptance Criteria

**AC-1 Dockerfile builds cleanly.**
Multi-stage `golang:1.22-alpine` + `apk add gcc musl-dev` (CGO for `mattn/go-sqlite3`) →
final stage `alpine:3.19`. `docker build` exits 0 with no CGO errors.

**AC-2 /health returns 200 with correct shape.**
`GET /health` returns HTTP 200 `{"status":"ok","service":"stock-price","port":5000}` — byte-identical
to TS handler (handlers.ts line 16).

**AC-3 /price/fetch byte-identical JSON.**
`POST /price/fetch {"code":"VCB"}` returns JSON with all fields present:
`code`, `price`, `volume`, `change`, `changePercent`, `source`, `latencyMs`, `fetchedAt`.
Field names, types, and optional-absent semantics identical to `FetchPriceResponse` DTO.

**AC-4 /price/history/:code byte-identical JSON.**
`GET /price/history/:code?days=N` returns `{"code":"VCB","history":[...]}` where each element
has `date`, `open`, `high`, `low`, `close`, `volume`. Field names match `DailyOHLCV` DTO exactly.

**AC-5 Tier waterfall fall-through semantics.**
- Tier1 success → returns quote with `source:"hose"`.
- Tier1 null, Tier2 success → returns quote with `source:"hnx"`.
- Tier1+2 null, Tier3 hit → returns quote with `source:"cache"`.
- All tiers nil/error → HTTP 404 `{"error":"Price not available for <CODE>"}`.

**AC-6 Tier3 cache hit/miss paths verified.**
- Cache hit: SQLite query returns row → result returned with `source:"cache"`.
- Cache miss: `market_prices` table has no row for code → Tier3 returns nil, waterfall falls to
  404 (assuming T1+T2 also nil).
- `saveQuote` writes to `stock_price.db` table `market_prices_cache` after any successful fetch
  (fire-and-forget; write failure does not fail the request).

**AC-7 market.db readonly DSN enforced.**
Tier3 fetcher and `SQLitePriceHistoryRepository.getHistory` open `market.db` with DSN including
`?mode=ro`. Any accidental write attempt returns SQLite error, not a silent no-op.
Verified by test that attempts `INSERT` on the readonly connection and expects an error.

**AC-8 Concurrent write safety on market.db (R4).**
Integration test: mcp-server Vitest suite runs concurrently with Go service making Tier3 reads
from `market.db`. No `SQLITE_BUSY` / `SQLITE_LOCKED` errors under WAL mode + readonly DSN.
Test fixture: open one `database/sql` writer + one `database/sql` `?mode=ro` reader concurrently
for 100 iterations; all reads must succeed without error.

**AC-9 Go test suite parity with TS Vitest (2 files / 204 LOC).**
`go test ./...` table-driven tests cover all 13 TS scenarios verbatim:
- Unit (resolve-price-service.test.ts, 7 cases): T1-wins, T2-fallback, T3-fallback,
  all-nil throws, all-throw throws, saveQuote called after success, correct code in quote.
- Integration (fetch-price-usecase.test.ts, 6 cases): FetchPriceUseCase correct shape,
  code uppercased, propagates error; PriceHistoryUseCase returns history, uppercases code,
  empty for unknown.
Same fixture values as TS (VCB price:88000, change:-1000, changePercent:-1.12, etc.) to allow
diff-by-inspection.

**AC-10 mcp-server Vitest suite unchanged.**
`apps/mcp-server` Vitest suite passes at same count as pre-migration baseline. No changes to
`clients.ts`, `BASE_URLS.stockPrice`, or `FetchPriceRequest`/`PriceSnapshot` interfaces.

**AC-11 api-gateway 9/9 aggregation healthy.**
`GET localhost:4000/health` reports `stock-price: {status:"ok"}` among 9 services. No degraded
entry for stock-price.

**AC-12 code uppercased before fetch.**
`POST /price/fetch {"code":"vcb"}` produces `code:"VCB"` in the response. Mirrors usecase.ts
`request.code.toUpperCase()`.

**AC-13 /price/history days validation.**

## §4 Non-Functional Requirements

**NF-1 CGO Dockerfile.**
Dockerfile: stage 1 = `FROM golang:1.22-alpine AS builder` + `RUN apk add --no-cache gcc musl-dev`
+ `CGO_ENABLED=1 go build`. Stage 2 = `FROM alpine:3.19` + copy binary. No `-cgo` disabled flag.

**NF-2 WAL + readonly DSN for market.db.**
DSN: `file:/path/to/market.db?mode=ro&_journal_mode=WAL&_busy_timeout=5000`.
`_busy_timeout=5000` gives WAL readers 5s grace under mcp-server concurrent writes.
`stock_price.db` DSN: `file:/path/to/stock_price.db?_journal_mode=WAL`.

**NF-3 Structured logging.**
All log output via `log/slog` with JSON handler. Fields: `level`, `msg`, `service:"stock-price"`,
`tier` (on fetcher calls), `latency_ms`, `error` (on failure). Matches Go api-gateway convention.

**NF-4 Internal port 5000, external port 5010.**
`docker-compose.yml` mapping: `"5010:5000"`. Service listens on `:5000` internally. No change to
`BASE_URLS.stockPrice = http://localhost:5000` in mcp-server — Docker network resolves correctly.

**NF-5 Timeout parity.**
Tier1 + Tier2 HTTP fetchers: 3s timeout per request (matching TS `AbortSignal.timeout(3000)`).
Use `http.NewRequestWithContext` + `context.WithTimeout`.

**NF-6 Go module path.**
`go.mod` module = `github.com/vn-market-intelligence/stock-price`. Same pattern as
`github.com/vn-market-intelligence/api-gateway` (Phase 1 precedent).

## §7 Risks

**R4 (brief §8, HIGH priority for this service):**
`market.db` is written by mcp-server (scheduler cron jobs) while Go stock-price reads it via
Tier3. SQLite WAL mode permits concurrent readers + one writer. Risk = `SQLITE_BUSY` if WAL
checkpoint contends with reads. Mitigation: `?mode=ro` DSN prevents Go from being counted as a
writer; `_busy_timeout=5000` adds reader retry. Test AC-8 validates under load.

Spec-level finding: the TS source (`fetchers.ts` line 84) already uses `{ readonly: true }` on
the `bun:sqlite` `Database` constructor — the readonly invariant pre-exists and must be preserved
in Go. Any DSN that omits `?mode=ro` is a regression.

**R-SPEC-1 (new — from source inspection):**
`mcp-server/clients.ts` `PriceSnapshot` interface declares `timestamp: string` but the Go service
will return `fetchedAt: string` (matching TS `FetchPriceResponse`). The field name mismatch exists
today in TS and is apparently tolerated (mcp-server maps fields at call site). Developer must
verify the actual field mcp-server reads from the response before assuming parity — or confirm
`PriceSnapshot.timestamp` is never used downstream. This is a clarification, not a blocker; if
the field is unused, AC-3 passes as-is.

**R-SPEC-2 (new — from source inspection):**
TS `handlers.ts` uses `GET /price/history/:code` (path param) while `clients.ts` calls
`GET /price/history?code=X&days=N` (query param). These are different routes. Developer must
confirm which route shape the Go service should implement — path-param (as in handlers.ts)
or query-param (as called by clients.ts). Both should be supported or clients.ts must be read
more carefully. This is a clarification for architect/developer before implementation starts.
